# 삭제 상태의 관심 영역 전송

정적 액터의 삭제 기록은 늦게 접속하거나 재접속하는 클라이언트가 원래 장면의 액터를 다시 만들지 않도록 서버에 남겨요. 이 기록을 공간 색인의 전역 항목으로 넣지 않고, 최초 스냅샷에 별도로 포함해요.

기존 연결에는 새 삭제를 기존 state 메시지로 보내요. 내부 삭제 버전과 연결별 숫자 watermark로 이미 보낸 정적 삭제의 반복 전송을 막아요. watermark는 한 묶음의 비교가 끝난 뒤 갱신하므로 pending Map의 버전 순서와 무관하게 모든 새 삭제를 보내요. 버전은 전송 JSON에 추가하지 않아요.

ID를 재생성한 뒤 다시 삭제하면 새 버전을 보내요. 영구 보존할 필요가 없는 동적 prefab 삭제는 기존처럼 서버 상태와 공간 색인에서 회수해요. 정적 기록은 별도 Map에서 기존 row 참조만 보관하며, 연결마다 삭제 ID 집합이나 row 사본을 만들지 않아요.

`check-network-deletions-1325.mjs`는 격리된 실제 WebSocket으로 정적 삭제 2,000개, 관심 위치 32회 변경, 늦은 접속·재접속, ID 재생성/재삭제, 같은 묶음의 여러 삭제, 동적 삭제를 검증해요. 관심 위치 변경 구간에서 삭제 재전송과 응답 바이트가 0인지 확인해요. 이 수치는 게임 FPS·서버 전체 메모리나 권위 서버/예측 구현 완료를 뜻하지 않아요.

최초 정적 숨김 검색, 실제 전역/밀집 액터, peer별 state 직렬화·전송 비용, 장면 세대와 권위·예측은 계속 별도 잔여예요.

## 같은 복제 상태의 직렬화 공유

`SharedStatePackets`는 한 번의 broadcast 안에서만 같은 row 참조와 청크 순서를 비교해 완성된 JSON 패킷을 재사용해요. 연결마다 다른 관심 영역은 그대로 판정하고, 해당 연결이 이미 받은 번호보다 새 번호인 패킷만 공유해요. 혼합된 관심 영역 때문에 이전 청크보다 번호가 작아지면 다시 생성해요. 프로토콜의 state/sequence/states 형식은 같아요.

공유하는 문자열과 row 참조는 broadcast 지역 객체에만 보관해요. 한도는 `min(stateBudgetBytes, 1MiB)`이고, 한도에 들어가지 않는 패킷은 보관하지 않아요. 영구 캐시·연결별 패킷 사본·타이머는 추가하지 않아요. 실제 전송과 WebSocket의 인코딩·소켓 버퍼 비용은 남아 있어요.

`server.inspect().stateSerialization`은 누적 생성 패킷 수, 재사용 횟수, 최대 공유 바이트와 상한을 보여줘요. `check-network-packets-1330.mjs`는 실제 연결 9개·공유 상태 129개에서 생성 3회/재사용 24회, 연결별 소유권 범위와 증가하는 번호, 1MiB를 넘는 전체 전송에서 공유 상한을 확인해요. 패킷 수 감소를 전체 CPU 시간·FPS·전체 heap 감소로 해석하지 않아요.


관심 후보·초기 숨김·대기 변경은 동기 iterator로 넘겨 spread/map/filter 중간 배열 복사를 줄여요. 초기 스냅샷은 비동기 전송 전에 기준 상태를 배열 하나에 확정해요. 전송 도중의 변경과 기준 상태가 섞이지 않게 하는 소유 경계예요. 후속 검사는 열 번째 늦은 접속의430개 전체 상태와136개 정적 숨김까지 확인해요. 초기 정적 월드 전체 순회, 서로 다른 관심 영역과 소켓 인코딩 비용은 별도 잔여예요.
