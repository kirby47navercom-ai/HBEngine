# 141–144 — 복잡 노멀맵 컴파일·기하 접근·캐시·진단

## 141 — 노멀 그래프의 반복 평가

WebGPU의 기본/코팅 노멀 함수에서 재질 평가 결과와 변환된 법선 후보를 TSL 변수로 확정한다. UV 보간, 텍스처 설명자·보간 좌표도 반복 식 대신 지역 변수로 공유한다. 샘플·해상도·재질 연산·법선 강도를 줄이지 않는다. 원래 UV+Shift 파라미터+덧셈+텍스처+normalMap 그래프를 사용한다.

같은 생성기 진단에서 WGSL의 노멀 재질 함수 호출은12곳에서1곳으로, 소스는73,552B에서70,630B로 줄었다. 소스 크기와 호출 수는 컴파일 결과의 구조 증거이며 프레임 속도 배수로 해석하지 않는다. 실제 세 렌더러 검사에서는 기존 RPC 제한을 유지한 채 텍스처 그래프를 통과했다.

## 142 — 고정 기하 레코드 접근

GLSL과 생성 HLSL의 고정 슬롯을 `hbGeometryRecord0..5`로 읽는다. 위치0–2는 검증과 인스턴스 변환을 공유하고, 재질·스칼라3–5는 직접 읽는다. 논리6vec/공유 물리5vec와 기존 주소 계약을 유지한다. 노멀·접선·곡면 가이드의 중첩 함수에서 불필요한 범용 슬롯 분기를 반복하지 않는다. 별도 위치 저장소·추가 GPU 이미지·읽기 동기화는 없다.

## 143 — 네이티브 소스와 바이트코드 재사용

같은 광선 프로그램 명령/키이면 프레임마다 큰 HLSL 문자열을 다시 만들지 않는다. 단계별 현재 소스 번호와 변형 키가 같으면 기존 컴퓨트 셰이더를 유지한다. 공유 바이트코드 캐시는 단순8항목 제거에서 최근 사용 순서와8MiB 계상 예산으로 바꾼다. 계상 비용은 복제된 키2개·바이트코드·항목당128B 여유분이다. 컨테이너/할당자의 실제 총 메모리가 정확히8MiB라는 의미는 아니다. 초과 단일 항목은 기존 캐시를 바꾸지 않고 건너뛴다. 디스크 캐시와 새 의존성은 없다.

실제 D3D 장면에서 캡처 반복 동안 소스 생성/컴파일 횟수가 증가하지 않았고, 여러 재질 장면을 방문한 뒤 동일 그래프 재방문의 네 설정 준비는216/154/124/238ms였다. 이 수치는 설정 호출·캡처·준비를 포함한 해당 머신의 한 번 측정이다. 초기 실행과 다른 드라이버의 보장을 뜻하지 않는다. 전체 검사 후 캐시 계상값은1,375,296B/8,388,608B였다.

## 144 — 사람과 AI가 읽는 준비 진단

기존 `hbDiagnostics()`의 `pipelinePreparation`에 현재 단계·경과 시간·단계별 시간을 추가한다. 단계는 post/path/normal-guide/lens-motion-guide/spatial-filter-N/temporal-filter/caustic-photons다. 최신 준비1건만 보관하고 무한 로그는 만들지 않는다. 네이티브의 `shaderCompilation`에는 compilations/cacheHits/cacheMisses/cacheEvictions/cacheBytes/cacheBudgetBytes/lastCompileMS/totalCompileMS/sourceBuilds를 노출한다.

`tools/editor-automation.mjs`의 기존 엔진 스키마에 같은 읽기 전용 계약을 등록한다. 머테리얼·컴포넌트 편집은 기존 C++/블루프린트/편집기/AI 공용 속성과 revision 검사를 유지한다. 별도 AI 전용 상태나 편집 경로는 없다. 준비 중 캡처는 현재 준비가 끝난 프레임을 반환하고, 준비가 이미 실패한 경우에도 실패를 전달한다. 실패 후 래스터 fallback을 정상 경로 추적 캡처처럼 반환하지 않는다. 준비는 드로를 발생시키지 않으며 렌더러 상태를 비동기 대기 전에 복원한다.

## 검증과 시간의 의미

CPU28개 묶음·환경34개·네이티브4,097광원/분산 필터 일치, 실제 D3D11·WebGL2·WebGPU의141/138/134/125/128, D3D 래스터131/135와 재방문을 검증했다. C++ 호출·모프 변경 픽셀·선택 이력 해제·오류0/종료0/서버 해제를 포함한다. 실제 복잡 노멀 텍스처의 변경 채널은664/844/858개다. 기존138의 균일 교란 대체 장면과 새141의 텍스처 그래프 증거를 구분한다.

해당 실행의 설정 순서별 준비 시간(ms, 반올림):

| 렌더러 | 경로 활성화 | 노멀 필터 활성화 | 곡면 가이드 활성화 | 시간 필터 활성화 |
|---|---:|---:|---:|---:|
| D3D11 | 5,588 | 2,696 | 130 | 4,491 |
| WebGL2 | 7,967 | 3,838 | 68 | 8,590 |
| WebGPU | 4,109 | 1,053 | 186 | 9,043 |

원본 결과 JSON의 `timings`는 같은 속성의 해제 시간이 덮어썼다. 검증 원장은 각 실행 로그의 여섯 순차 기록을 값/순서와 함께 보존하고, 재현 도구는 이제 배열로 누적한다. 픽셀·자원·통과 조건은 바뀌지 않았다. WebGPU의 시간 필터 준비 중 lens-motion-guide가 약8.56초였으며 여전히 초기 컴파일 병목이다. 이번 수정은 복잡 그래프의 기존 시간 초과를 해소한 지정 재현 증거이며 모든 그래프가 즉시 준비된다는 주장으로 확대하지 않는다. 전체 게임 FPS·모바일 실기기·이전 애니메이션 노멀 표본/mip 보존·전역 곡면 역해·거친 다중 로브·DFAO/Lightmass/HWRT와 기존 엔진 전 분야 목표는 별도 누적 원장을 유지한다.
