# 모델 내장 이미지와 재질의 공동 저장

모델 가져오기 재질 추출은 외부 이미지 외에 GLB BIN 버퍼 뷰, glTF data 이미지 URI, glTF data/외부 버퍼 안의 PNG/JPEG/WebP도 지원해요. 그래프를 만들기 전에 원본 편집 미리보기에서 읽은 이미지 바이트 SHA와 원본 모델 SHA를 확인하고 대상 이미지 경로를 계획해요. 일반 게임 모델 로딩에는 이 편집용 이미지 해시 계산을 추가하지 않아요.

GLB는 헤더/JSON을 읽고 필요한 BIN 구간만 seek해요. 전체 GLB 사본을 메모리나 디스크에 만들지 않아요. 외부 버퍼는 선택한 이미지 구간만 읽고 그 구간의 SHA를 다시 확인해요. GLB 원본 SHA 검증은 전체 파일을 스트리밍하므로 파일 크기에 비례하는 I/O는 남아 있어요. 한 번의 추출은 이미지 합계 16MiB예요. JSON과 복구 기록의 기존 메모리 예산을 지키는 단위이며 씬 오브젝트 개수 제한은 아니에요.

이미지는 `T_Embedded_<SHA256>.<확장자>`로 저장해 같은 내용은 재사용해요. 기존 같은 경로의 바이트가 다르면 덮어쓰지 않아요. 새 이미지와 재질은 같은 저장 큐/복구 묶음에서 게시해요. 생성 중 원본·읽은 이미지·프로젝트가 바뀌거나 저장이 실패하면 새 파일과 인덱스를 함께 복원해요. 외부에서 바뀐 파일은 보존하고 해결이 필요한 기록을 남겨요.

바이너리 행은 복구 journal v2의 canonical base64와 **실제 바이트 SHA**를 사용해요. 예전 텍스트 journal v1도 그대로 읽고 복구해요. 내장 이미지 추출의 기록은 복구용 임시 기록으로 사용하고 성공/완전한 rollback 뒤 지워 이미지 복사본을 계속 쌓지 않아요. 외부 충돌로 복구가 끝나지 못한 경우에는 필요한 기록을 보존해요. 이 v2 기록을 기존 텍스트 파일 묶음 Undo로 해석하지 않으며, 그런 요청은 파일 변경 전에 명시적으로 거절해요.

AI의 `modelimport.extractMaterial` 명령과 사람 버튼은 같은 경로예요. 내장 이미지가 있으면 `/api/asset/model-images`로 계획하고 `/api/asset/model-material`로 검증·저장해요. 계획/기본 dryRun 응답은 경로·인덱스·SHA·바이트 수만 포함하며 base64와 바이너리를 되돌리지 않아요. 문서·미리보기 수명을 비동기 계획 뒤 다시 확인해요. 지원 밖 코덱·URI·버퍼 범위·불일치 SHA는 게시 전에 거절해요. 원본 재질/텍스처 객체는 바꾸지 않아요.

소유자: `prepareModelImages`, `publishModelMaterial`, `hashModelEmbeddedImages`, `commitAssetBatch`, `recoverAssetTransactions`. 검사: `node tools/check-model-images-2464.mjs`. 소유 임시 프로젝트에서 바이트·dedup·중간 실패·외부 충돌 보존·v1/v2 복구·사람/AI 공용 생성 경로·네 대상 content/cook 경로를 확인해요. 새 GPU 렌더·실제 창·기기/설치와 모든 이미지 디코더 동등성의 증명은 아니에요.
