# 원격 프리팹 에셋 교체

같은 네트워크 루트 ID의 프리팹 에셋이 바뀌면 기존 실행 인스턴스를 종료하고 새 인스턴스를 생성해요. 호스트의 에셋·루트·로컬 ID를 함께 확인해요. 위치만 바뀐 패킷으로는 다시 만들지 않아요. 기존 SceneDestroy/SceneSpawn과 Blueprint EndPlay/BeginPlay, C++ 수명 경로를 사용해요.

삭제 전에 로컬 생성 카탈로그의 프리팹, 활성 NetworkReplica 루트, NetworkSession 중첩 여부와 루트의 로컬 ID를 검사해요. 잘못된 요청이면 기존 인스턴스를 유지하고 실패를 기록해요. 에셋/로컬 ID가 수정되면 다시 처리하고 해당 교체 오류만 해제해요. 동일한 잘못된 에셋의 위치 패킷마다 삭제를 반복하지 않아요.

변경된 루트만 대기 Set에 넣어요. 교체 중 같은 ID가 다시 바뀌어도 새 대기 항목을 유지해요. 루트 사이에서 기본4ms 작업 예산으로 양보하고 이후 프레임에 남은 항목을 처리해요. 오브젝트 수 제한이 아니에요. 한 루트의 사용자 콜백이나 비동기 로더를 강제로 중단하는 시간 제한은 아니에요. 작업이 없을 때 추가 시계 조회/비동기 교체 단계를 실행하지 않아요.

비동기 제거 뒤에는 예전 객체와 같은 등록 항목만 정리해요. 재접속·삭제·다른 에셋·같은 ID의 새 객체가 들어오면 그 상태를 존중해요. 새 에셋의 자식에 아직 남아 있는 예전 에셋의 변환·속성·소유권·전송 권한을 적용하지 않고, 늦은 자식 삭제로 새 루트를 없애지 않아요. 새 에셋의 일치하는 상태가 오면 정상 반영해요.

`runtime.network`의 요약/페이지에 `replacements`, `replacing` 개수와 `replacementPending`, `replacing`, `localMatchesSource`를 추가해요. 기존 ID/이름/에셋 메타데이터와 페이지32/최대128/검색어160 계약을 유지해요. nativeProperties·변환·접속 키를 읽거나 노출하지 않아요. 문제를 조사할 때 `kind:remote`와 `kind:failures`를 구분하면 현재 수신 상태와 실패한 생성 요청을 볼 수 있어요.

검사에서는 이미 로드된 A→B, 예전 자식 상태/권한/전송/삭제, 사전 검사 실패, 비동기 제거 중 C로 재변경·삭제·접속 해제·같은 ID 교체, 시간 예산에 남은 항목, 씬 원본 보호를 대조해요. 실제 로컬 소켓→공용 실행 서비스→A EndPlay/B BeginPlay를 한 번씩 확인하고, 잘못된 루트 로컬 ID의 요청도 기존 A를 유지하다 올바른 B 요청으로 복구해요. 실제 숨긴2D 편집기에서는 BP 접속·A→B·B 삭제/같은 ID 재생성과 페이지 진단을 최종 설치 검사로 확인해요.

씬에 원래 배치된 객체의 클래스 마이그레이션, 새 네트워크 epoch/장면 전환 프로토콜, 전용 권위 서버, 일반 원격 풀 정책, 부착 참조·예측은 원장에 남아요. 임의 사용자 콜백의 외부 부작용을 되돌리는 기능이나 인터넷 지연·실기기 FPS 검증으로 확대하지 않아요.
