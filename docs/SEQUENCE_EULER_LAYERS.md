# 가져온 클립의 Euler 축 레이어

가져온 애니메이션의 `.rotation[x/y/z]`·숫자 인덱스 키는 같은 모델 노드의 해당 축만 소유해요. 액터 루트, 모델 자식, 골격 뼈가 공용 시퀀스 채널에서 이 규칙을 사용해요. 예를 들어 X 클립과 Y 클립을 다른 디렉터에서 재생하면 둘 다 반영하고, Y를 중지하면 Y만 공용 기준 자세로 돌아와요. 이름/UUID 별칭은 실제 노드 정체성을 공유해요.

같은 노드에서 같은 Euler 순서를 사용하는 부분 회전은 축별 우선순위·시작 순서·override/normalized·weight 0 인계·Stop/Seek/복원을 적용해요. 여섯 Euler 순서를 지원하며 원래 보간기에서 읽은 각도를 보존해 90도를 넘는 키도 정규 Euler 분해 때문에 다른 축의 180도 회전으로 바꾸지 않아요. normalized 축은 승자 각도 주위의 가까운 각도 차이를 섞어서 +179/-179도가 0도로 돌아가지 않아요.

전체 직접 회전·Transform 회전·전체 Euler/Quaternion 클립·녹화 골격 자세는 모든 회전 축을 소유해요. 더 강한 부분 축은 그 축만 덮고 나머지는 전체 자세에서 받아요. 부분 Euler 레이어가 없으면 기존 hemisphere Quaternion 혼합을 그대로 사용해요. 골격 위치/크기·다른 뼈·recorded poseWeight 처리도 기존 경로를 유지해요.

시퀀스 파일·원본 키 버퍼·SDK 형식은 바꾸지 않아요. Blueprint 재생과 C++ 명령 재생이 같은 런타임 처리로 들어가요. 추가 evaluator·timer·전체 포즈 키 베이크는 만들지 않고 활성 필드에만 작은 축 메타데이터를 보관해요.

한 필드에 서로 다른 Euler 순서의 부분 표본이 겹치면 기존 전체 방향 중재를 사용해요. 회전된 시퀀스 원점을 루트 회전에 곱하면 축이 섞이므로 그 결과도 전체 방향으로 소유해요. 붙은 자식/뼈의 로컬 축은 원점에 중복 변환하지 않아요. 이 두 경우의 일반적인 축 공간 투영, 추가 unmanaged AnimationMixer action과 외부 setter/notify rollback은 남아 있어요. Euler gimbal 특성을 없애는 기능은 아니에요.
