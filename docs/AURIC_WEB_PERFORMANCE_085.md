# Auric Loop 웹 UI 비용과 원본 그림 게시

2026-10-11. 대상은 기존 공개 main(a19fcf7), weapon-socket(355289f) 두 버전이다. 사용자 게임 원본·미커밋 자료·사용자 앱·브라우저는 검사나 수정에 사용하지 않았다.

## 원인과 수정

메인의 타이틀 연출은 매 프레임 위치·크기·투명도를 수십 번 변경한다. 공용 WidgetSystem은 매 호출마다 전체 위젯 에셋을 복사·검증하고 DOM과 C++용 전체 UI 스냅샷을 다시 만들었다. CPU 샘플에서 immutableNativeSnapshot과 이 호출 경로가 가장 큰 비용이었다.

- 연속된 C++ uiSet 호출은 화면/스냅샷 갱신을 묶는다. 다른 엔진 호출·읽기·폰트 로드는 갱신 경계이며, 이후 호출 실패 시에도 먼저 성공한 쓰기를 반영한다.
- 변경한 요소의 속성만 복사하고 기존 슬롯·속성 범위 검사로 검증한다. 위젯 로드는 전체 구조·계층·중복 ID 검증을 유지한다. 같은 값의 쓰기는 재갱신하지 않는다.
- C++ UI 스냅샷의 JSON 정규화·분리·동결을 한 번만 수행한다. 기존 통신·검증·클록·저장 경로는 유지한다.

공개 HTTPS에서는 처음 쓰는 스프라이트 메타데이터와 프레임을 개별 다운로드하느라 추가로 멈췄다. 웹 빌드는 이미 cook된 작은 이미지(각 512KiB 이하)와 스프라이트/애니메이션 JSON을 game.resources.bin으로 묶고 시작 시 한 번에 받는다. 더 큰 이미지는 기존 URL로 로드한다. 개별 파일도 남겨 경로 호환성을 유지하므로 게시 파일 총용량을 줄였다는 뜻은 아니다. 이는 에셋 수 제한도 아니다. 현재 게시하기로 한 에셋만 묶으며 목록의 경로·크기·순서·중복과 원본 SHA를 검증한다. 파일 URL은 Blob URL로 연결하고 일반 페이지 종료 때 해제하되, 뒤로/앞으로 캐시에 보관된 페이지는 리소스를 유지한다. 묶음이 없는 이전 웹 패키지도 실행한다.

이전에는 사용자의 공개 제외 선택에 따라 대체 SVG를 사용했지만, 원본 화면을 임의로 바꾼 결과에 대해 사용자가 기존 그림을 그대로 GitHub에 게시하도록 지시했다. 최종 게시에서는 메인 55개·무기 소켓 116개를 원본 바이트 그대로 복구하고 Assets/UI/Web 대체 파일과 리다이렉트를 제거했다. 무기 소켓의 글자 슬롯도 해당 게임 원본 좌표로 돌렸다. 원본 게임 코드·미커밋 자료·앱 설치본은 수정하지 않았다. 이 기록은 과거 제외 선택을 현재 게시 정책으로 다시 적용하지 않기 위해 남긴다.

## 근거

격리 Chrome 1280×720, 동일한 메인 타이틀·동일한 대체 그림, 09b9569 런타임 사본과 수정본을 순차 비교했다. 각 5초 CPU 샘플이며 초기 로딩을 제외했다. 이 CPU 비교는 원본 그림을 복구하기 전이며 최종 원본 그림의 FPS와 동일시하지 않는다.

| 메인 타이틀 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| 프레임 작업 평균 | 274.45ms | 27.41ms |
| 프레임 간격 평균 | 296.97ms | 30.41ms |
| 측정 FPS | 3.37 | 32.89 |
| UI 전체 동기화 누적 | 3501.50ms | 392.60ms |

프레임 작업 평균은 약 90% 감소했다. UI 동기화 누적은 프레임 수가 서로 다르므로 호출당 성능 배수로 해석하지 않는다. 작업 시간은 CPU/await/WebGL 제출 시간이고 GPU 표시 시간·일반 창·사용자 PC 전체 부하 보장이 아니다. 120fps 합격으로 표시하지 않는다.

리소스 묶음을 포함한 로컬 실제 입력 검사에서 메인 거점은 약 63fps, 무기 소켓 거점은 약 64fps였다(각 3초, 다른 시각의 순차 실행). 두 버전의 시작·선택·이동·공격, 각각 144/158개 UI 이미지, 실행 오류와 HTTP 오류 0을 확인했다. 선택 검사는 두 버전 모두 명시적 1번 검 캐릭터로 맞춘다. 타이틀 종료 시점을 가정해 무조건 두 번 클릭하지 않는다. 실제 공개 서버 결과와 로컬 결과를 섞지 않는다.

회귀 검사: `node tools/check-ui-state-cache.mjs`, `node tools/check-native-transport.mjs`, `node tools/check-ui-layout.mjs`, `node tools/check-web-resources.mjs`, `node tools/check-web-build.mjs`, `git diff --check`. 쓰기 묶음·읽기 경계·오류 복구·잘못된 값 불변·동일 값 재사용·C++ JSON/델타·실제 거점 실행을 확인했다. 리소스 검사에서는 한 번 다운로드·한글 경로·잘못된 테이블/해시 거절·종료/뒤로 캐시 수명·공개 제외 자료 불포함·2D/3D 내보내기 전체 파일 SHA를 확인했다. 기존 Wasm 바이너리를 사용했으며 재컴파일하지 않았다.

증거는 `native/build/auric-pages-084/perf-controlled-before.json`, `perf-controlled-after.json`, `local-qa.json`, `public-qa.json`, `original-assets-proof.json`, `public-images-qa.json`, `final-public-proof.json`이다. 게시 파일 전체 SHA 목록은 각 공개 game.hbpack.json에 있다. 최종 공개 서버의 171개 원본 그림 SHA가 해당 게임 원본과 일치하며, 임의 대체 파일은 0개인지 확인했다.
