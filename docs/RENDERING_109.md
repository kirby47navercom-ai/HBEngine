# 109 — 광선 텍스처 밉·LOD와 기능별 셰이더

경로 추적의 1차 표면·반사·굴절, 기하 GI와 투과 그림자의 머테리얼 평가에 텍스처 풋프린트를 전달해요. D3D11·WebGL2·WebGPU가 같은 포장 형식과 필터 설정을 사용해요. 기존 머테리얼 그래프, C++·블루프린트·AI의 자료형별 파라미터 API를 유지해요.

## 제작과 동작

카메라의 한 픽셀 크기에서 시작한 광선 원뿔을 거리·확산·거칠기·굴절에 따라 넓혀요. 교차점의 접평면에 투영하고, UV·월드 좌표와 좌표 연산의 인접 값을 계산해서 텍스처 LOD를 선택해요. 그래프의 등록 번호를 재사용하기 전에 좌표의 선행 연산을 구하므로, 다른 머테리얼 계산에 미분용 등록 값을 만들지 않아요.

실제 텍스처의 `minFilter`, `magFilter`, `generateMipmaps`를 따르며, 밉을 사용하지 않는 설정은 0단계를 유지해요. 최근접·선형 공간 필터와 최근접·선형 밉 선택을 구분해요. RGB는 선형 색 공간으로 바꾼 뒤 평균을 내고, 알파에는 색 변환을 적용하지 않아요. 홀수 크기는 가장자리 면적을 가중해요. 큐브 면과 배열 레이어는 섞지 않으며, 볼륨은 깊이도 줄여요. 기본 배열·볼륨 에셋의 기존 선형/밉 비활성 설정을 자동으로 바꾸지는 않아요.

기존 C++ 호출로 그래프 파라미터를 바꿀 수 있어요. 블루프린트와 AI도 같은 속성·파라미터 경로를 사용해요.

```cpp
hb::Materials::SetFloat(target, "Scale", 16.f);
hb::Components::SetBool(post, "PostProcessVolume", "pathTracingEnabled", true);
```

위 `Scale`은 사용자 머테리얼의 스칼라 파라미터 이름이에요. 검사 장면에서도 C++ 호출로 반복 배율을 바꾸고 실제 실행 영상의 분산을 비교해요.

## 자원과 컴파일

이미지·버전·색 해석별 밉 캐시를 재사용하고 텍스처 변경 시 다시 만들어요. 109에서는 오브젝트 이동 때 CPU 밉을 재사용하지만, 통합 BVH atlas의 텍스처 데이터는 다시 포장·업로드해요. 후속 [110 자원 갱신](RENDERING_110.md)은 같은 크기의 자원을 재사용하고 DirectX·WebGL 전송 구간을 줄여요. CPU 재포장과 WebGPU 전체 업로드는 남아 있어요.

큰 2D·큐브·배열 체인은 원본 픽셀 저장량의 약 1/3, 정육면체 볼륨은 약 1/7을 추가해요. 가늘거나 작은 이미지에는 이 비율이 적용되지 않아요. CPU 선형 밉, 포장 데이터, 임시 배열, GPU atlas와 패딩은 각각 추가 저장량이에요. 경로 추적·기하 GI를 쓰지 않는 기본 장면에는 이 경로를 만들지 않아요. 자동 GPU→CPU 읽기는 추가하지 않았어요.

WebGL은 실제 텍스처 자료형·필터에 맞는 샘플러를 생성해요. WebGL과 D3D11은 분석 광원이 없으면 해당 조명 함수를 제외하고, 광원이 켜지면 셰이더를 바꿔요. WebGL의 화면 후처리 전용 장면에서는 BVH·광선 머테리얼·매질 소스를 제외해요. D3D11도 실제 GI·경로 추적·HDRI 유무를 컴파일 조건과 캐시 키에 반영해요. 기하 GI만 쓰는 장면은 경로 적분기 진입을 제외해요. 활성화한 HDRI·발광 조명과 조명 기능은 유지해요.

## 검증과 경계

[검사 기록](research/RENDERING_109.json)에 공용 계산·캐시·생성 파일, 네이티브 하드웨어와 세 Windows 실행기의 098–107·109 회귀를 묶어서 기록해요. 검사 실패와 해결 과정도 구분해요. 109는 직접 표면·월드 좌표·반사·굴절의 밉 유무 비교와 실제 실행기의 텍스처 배율 변경, 분석 광원 켜기/끄기를 확인해요. 배열·큐브·볼륨은 CPU 밉 체인을 확인했으며, 109의 실제 광선 픽셀 비교는 2D 텍스처예요. [설치 영수증](research/USER_INSTALL_109.json)은 별도로 저장해요.

광선 원뿔은 보수적인 근사이며 곡률을 포함한 완전한 광선 미분은 아니에요. 등방성 밉 필터로, EWA/이방성 필터와 큐브 면 경계의 연속 필터는 포함하지 않아요. 이미지 값으로 다시 만든 좌표의 미분은 0으로 처리해요. 알파 컷아웃의 교차 판정은 0단계 필터를 유지하며, 밉별 알파 커버리지 보존은 포함하지 않아요. 사용자 지정 수동 밉 체인, HDRI 배경의 별도 밉, 2D 스프라이트 광선 BVH는 이 변경 범위에 없어요. 실게임 FPS·120/60 유지·실제 휴대폰 성능을 이 검사로 확인했다고 해석하지 않아요.

## 읽은 근거

[PBRT 4 이미지 텍스처](https://pbr-book.org/4ed/Textures_and_Materials/Image_Texture)의 필터·LOD 지정 구역과 [텍스처 샘플링](https://pbr-book.org/4ed/Textures_and_Materials/Texture_Sampling_and_Antialiasing)의 접평면·UV 변화량 계산 구역을 대조했어요. HBEngine의 원뿔 근사를 PBRT의 전체 광선 미분이나 EWA 구현과 같다고 주장하지 않아요.

[NVIDIA의 광선 LOD 연구 소개](https://research.nvidia.com/publication/2019-03_texture-level-detail-strategies-real-time-ray-tracing)는 원뿔과 광선 미분을 비교하는 초록만 읽었어요. 연결된 책·논문 전체를 읽었다는 근거로 쓰지 않아요. 설치된 Three r180의 필터 상수, 텍스처 기본값과 WebGL 셰이더 변환 구역도 대조해요. 원문 SHA와 실제 읽은 구역은 검사 기록에 남기며, 전체 Unreal·Unity 본문/API 조사 완료를 대신하지 않아요.
