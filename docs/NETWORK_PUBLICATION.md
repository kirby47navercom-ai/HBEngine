# 복제 전송의 순환·직렬화·바이트 예산

2026-10-22. 전송 예산에 먼저 도달하면 항상 Map의 앞에서 다시 시작하던 경로를 `NetworkPublication`의 순환 커서로 바꿨어요. 앞쪽 오브젝트가 계속 움직여도 뒤쪽 대상이 영구히 밀리지 않아요. 새 오브젝트 한도를 정한 변경이 아니고, 기존 갱신당512상태·패킷당128행 예산에서 대상 선택을 순환시킨 변경이에요. 세계 전체 배열이나 두 번째 ID 색인을 복제하지 않아요. 등록·삭제 사이에서도 살아 있는 Map을 순회하고, 빈 월드·새 welcome·Dispose 때 커서를 해제해요.

변경 감지용 상태 JSON을 패킷 본문과 전송 성공 stamp에도 재사용해요. 같은 상태를 패킷용·stamp용으로 다시 직렬화하지 않아요. 전송이 일부 실패하면 기존 resync 정책으로 stamp를 비우고 순환을 이어가요. 원래 상태 검증·소유권·RPC·관심 영역·서버 메모리 예산은 유지해요.

한글 같은 다중 바이트 속성은 128행이어도 서버의 WebSocket maxPayload 4MiB를 넘을 수 있어요. 패킷은 행 수와 UTF8 바이트를 함께 제한해요. 보통 작은 패킷은 코드 단위당 최대3바이트 상한으로 검사하고, 그 상한이 예산에 닿을 때만 정확한 UTF8 길이를 확인해요. 한국어·이모지·단독 surrogate와 랜덤 UTF16을 Node Buffer 길이와 대조했어요. 외부 전송 규약은 같은 JSON `type/state/rows`이고 다른 send/RPC 경로도 기존 호출을 사용해요.

`tools/check-network-publication-1568.mjs`는 실제 NetworkWorld와 이전 발행 식의 격리 참조를 대조해요. 계속 움직이는1,025개는3갱신에서 모두 발행됐고 이전 식은512개에 머물렀어요. 8행 속성 읽기는48회에서32회로 줄었고 보낸 값은 같았어요. 이 계수는 전체 FPS나 인터넷 지연 수치가 아니에요.

실제 로컬 WebSocket 서버/클라이언트에서도1,025개 복제 상태의 도달과 적용을 확인했어요. 유효한 한글15,000자 속성128행은2패킷으로 나뉘었고 가장 큰 payload는4,151,321바이트였어요. 4,194,304바이트 한도 안에서 마지막 행의 내용까지 도달했어요. 실제 전화기·손실 네트워크·전용 권위 시뮬레이션·예측 입력/재시뮬레이션 검증과는 구분해요.

기존 공유 패킷7경우, 관심 영역11경우(10만 분산후보 색인 포함), 삭제·재접속7경우도 묶어서 통과했어요. 전역 강참조 캐시·워커·타이머·GPU 리소스는 추가하지 않았어요. 커서는 NetworkWorld의 기존 Map에 연결되고 갱신의 상태/JSON 배열은 기존512예산 안에만 유지돼요. 설치본 검사는 `--implementation-root`로 같은 제품 코드를 실제 소켓에서 확인하며 소유 검사 폴더에 영수증을 남겨요.
