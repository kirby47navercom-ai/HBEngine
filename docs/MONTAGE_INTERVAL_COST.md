# 몽타주 구간 선택과 루트 모션 합성 비용

2026-10-22. `MontageClipIndex`는 슬롯당 평균 32개 이상인 몽타주를 Play 시점에 준비해요. 슬롯 개수만으로 색인을 끄던 8슬롯 조건을 없앴어요. 작은 몽타주, 슬롯당 클립이 적은 데이터와 같은 슬롯의 겹침이 있는 잘못된 데이터는 기존 순회로 실행해요. 겹친 클립의 오류도 기존처럼 실제 샘플 때 발생해요.

일반 시간 샘플은 슬롯마다 활성 클립을 선택한 뒤 재사용 배열을 원본 순서로 정렬해요. 같은 소스 클립을 여러 슬롯에서 써도 원래 샘플 순서를 유지해요. 구간은 끝 제외이고, 몽타주 전체 길이에 정확히 도달한 마지막 프레임은 기존과 같이 마지막 클립을 포함해요. 빈 구간·뒤로 탐색·소스 오프셋·재생률도 유지해요.

루트 모션 범위는 각 슬롯의 정렬된 시작/끝을 이진 탐색해 교차 후보만 찾고 원본 순서대로 합성해요. 후보가 전체의 1/4보다 많으면 기존 전체 순회로 처리해 큰 탐색에서 후보 정렬이 커지지 않게 해요. 중첩된 범위 방문 중에는 원래 경로로 들어가 외부 방문의 재사용 배열을 덮어쓰지 않아요. Dispose는 색인 소유를 해제해요. 전역 캐시·워커·타이머·GPU 리소스는 추가하지 않았어요.

`appendMotion`은 기존 Three 객체 계산의 벡터 회전, 단위 회전에서 델타까지의 SLERP, Hamilton 곱과 정규화를 스칼라로 수행해요. 임시 Quaternion 생성 3곳, Vector3 생성 1곳, 값의 slice 1곳을 없앴어요. 전역 공유 scratch는 없고 출력 버퍼와 입력 버퍼가 같아도 동작해요. 이 수는 코드에서 없앤 명시적 생성 호출 수이며 heap/FPS 측정치가 아니에요.

검증: `tools/check-montage-index-root-1549.mjs`의 1,200개 수치·가중치·입출력 별칭 경우와 1,000회 연쇄 합성을 이전 Three 객체 식과 대조했어요. 64클립·2슬롯의 희소 마지막 샘플에서 원본 start 읽기는 132회에서 2회였고, 범위 후보는 2개였어요. 실제 컴파일된 애니메이션 프로그램의 두 슬롯·루트 추출·기존 액터 위치·포즈 메모리 재사용도 확인했어요.

기존 몽타주·루트 모션·교체·notify·포즈 비용 검사를 함께 실행했어요. 2D/3D의 30/60/120 고정 스텝, 중력·벽·부모·일시정지·seek·fade·루트 tail·스프라이트·기존 위치 보존을 포함해요. 오래된 몽타주 검사 하나는 Actor 기본 블루프린트에 MeshRenderer가 자동 생성된다고 가정하고 있었어요. 제작 정책을 바꾸지 않고 검사 fixture에 의도한 MeshRenderer를 명시해 기존 검증 목적을 유지했어요.

`tools/check-montage-index-1551-window.mjs --package`는 소유한 숨긴 창에서 64클립 에셋을 저장하고 Blueprint Play/Pause/126.5초 Seek를 실행해요. 원래 `[10,3,0]` 위치를 보존하고 이어지는 노드까지 도달했으며 같은 저장 Windows D3D11 게임에서도 통과했어요. 실제 모바일·전체 게임 FPS·모든 애니메이션 기능 완료를 주장하지 않아요.

1627 이후 제작 일정의 고정256클립 제한을 없앴어요. 겹침은 슬롯별 참조만 정렬하여 인접 구간을 검사하며 원본 순서를 유지해요. 256개 무작위 경우는 기존 모든 쌍의 검사와 같고, 실제 검증기가8192클립/256슬롯을 받아요. 512클립의 slot 읽기는261632회에서512회였어요. 서로 다른 원본 소스64개 예산과 다른 문서 예산은 별개의 잔여예요.

9/16/64/256슬롯의 point/gap/final/range/원본 순서/비가환 루트 합성을 기존 실행과 대조했어요. 전체 범위는 바로 기존 순회로 가서 이진 쿼리도0회예요. 4096클립/64슬롯의 희소 sample start 읽기는8320→64회였어요. 실제16슬롯/512클립 프로그램의 포즈 버퍼/루트16개/원래 위치도 유지돼요.

슬롯 이름은 플레이어 수명 동안 읽기 전용 배열로 재사용해 runtime snapshot의 매 프레임 배열 복사를 없애요. 단독 apply도 첫 활성 슬롯에서 바로 반환하므로 전 슬롯을 배열로 복사하지 않아요. dispose는 이름 배열을 해제해요. 새 전역 색인·워커·타이머·GPU 자원은 없어요. 자료구조/비교 횟수이며 통제 FPS·총 힙 개선 수치가 아니에요. 새 슬롯별 색인 준비의 추가 메모리는 입력에 비례해요.

제작·저장→Blueprint Play/Pause/62.5초 Seek→실제16슬롯→같은 저장 Windows 게임은 tools/check-montage-slots-1630-window.mjs의 후속 최종 설치 영수증으로 확인해요.
