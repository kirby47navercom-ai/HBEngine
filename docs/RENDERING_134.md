# 134–137 — 변형 법선 이력·그림자 의존성·장면 하늘 캡처·모프 가져오기

## 134: 뼈대와 모프의 이전 표면

기존 `pathTracingCurvedFilter`와 시간 필터가 함께 켜졌을 때만 변형된 삼각형의 이전 정점 법선을 저장한다. 강체 인스턴스의 96B 행렬 이력은 유지한다. 변형 삼각형은 48B GPU 기록과 안정적인 source ID로 이전 법선을 찾는다. 현재 교차점의 무게 중심 좌표로 현재/이전 부드러운 법선을 보간하고, 두 방향 사이의 최소 회전으로 이전 가이드 법선을 구한다. GLSL·TSL·네이티브 HLSL은 같은 주소 계약을 사용한다.

노멀만 움직이는 모프도 이력을 진행시킨다. 한 번 정상 확정한 프레임만 다음 이력으로 사용하며, 실패·비활성·재질/위상 무효화에서는 이력을 비운다. 거의 반대인 법선·퇴화한 표면은 이력 재사용을 거부한다. 이전 노멀맵의 텍스처 애니메이션이나 접선 축의 임의 비틀림을 정확히 복원하는 기능은 별도 작업이다. 법선맵 교란에는 기저 법선의 최소 회전을 적용한다.

별도 이미지 타깃·GPU 읽기·새 조작 옵션은 추가하지 않는다. 읽기 전용 `renderer.rayGeometry.deformedNormalTriangles/deformedNormalBytes`로 실제 추가 저장을 확인한다.

## 135: 실제 변경 자원에 따른 그림자 갱신

캐스터가 사용하는 메시·재질 프로그램·텍스처·인스턴스·변형 버퍼의 변경 번호를 추적한다. 재질 파라미터와 포즈 변경도 해당 자원으로 기록한다. 광원별로 캐스터의 변경 번호를 비교해서 관련 레이어만 갱신한다. 관계없는 텍스처를 업로드하거나 다른 오브젝트의 재질 값을 바꾸었다는 이유로 모든 그림자를 다시 그리지 않는다. 시간에 의존하는 셰이더 캐스터는 계속 매 프레임 갱신한다.

드로의 직렬화된 값은 기존 캐시와 공유하고 실제 캐스터만 의존성을 보관한다. 해제된 자원과 삭제된 드로는 추적에서도 제거한다. 반사 프로브의 onChange 판정은 그림자 판정과 분리해서 그림자를 만들지 않는 오브젝트의 이동도 반사에 반영한다.

## 136: DirectX 장면 하늘 환경광

SkyLight의 `source: scene`도 DirectX 일반 래스터 환경광·반사에 연결한다. 기존 하늘 돔과 구름을 별도 큐브맵으로 렌더하고 기존 GGX/SH9 필터를 재사용한다. 큐브맵 여섯 면은 제출 프레임마다 한 면씩 렌더한다. 여섯 면이 완성된 뒤 필터링하고 기존 결과를 교체하므로 미완성 면을 화면에 노출하지 않는다. 필터링 자체는 완성 프레임에서 수행한다. 새 캡처를 준비하는 동안 기존 완성 큐브맵을 유지한다.

기존 자동 캡처·해상도·환경 재캡처 버튼을 사용한다. C++/블루프린트는 `Components.SetFloat(target,"SkyLight","captureVersion", nextVersion)`으로 명시적인 재캡처를 요청할 수 있다. AI는 같은 속성을 revision 검사로 수정한다. `indirectIntensity`만 바꿀 때는 완성 큐브맵의 세기만 바꾸고 다시 캡처하지 않는다. 밝기 0·출처 해제·장면 종료는 준비 중인 큐브맵까지 해제한다.

`skySceneCaptures`, `skySceneFaces`, `skyCapturePending`, `skyCapturePendingBytes`는 읽기 전용 진단이다. 하늘/구름 캡처이며 일반 장면 물체는 기존 ReflectionProbe를 사용한다. 광도 데이터가 GPU에 머물며 CPU 이미지 재포장이나 자동 읽기를 추가하지 않는다. 자동 캡처는 기존 환경 속성 변경 판정과 간격을 사용한다. 구름의 모든 프레임 애니메이션과 필터 단계를 나누는 추가 시간 분산은 후속 최적화다.

## 137: 노멀 전용 모프 호환

노멀·색상 채널만 있고 위치 모프가 없는 모델에는 로딩 시 항등 위치 채널을 보충한다. 상대 모프는 영점, 절대 모프는 원본 위치를 사용한다. 보충 대상들은 하나의 불변 배열을 공유하며 기존 위치 모프·이름·애니메이션 연결은 보존한다. FBX·glTF 로딩 경로에서 처리하고 프로젝트 원본을 다시 저장하지 않는다. 브라우저 렌더러가 위치 모프 선언을 전제로 노멀 모프 셰이더를 만드는 문제를 엔진의 가져오기 경계에서 처리한다.

## 지정 자료와 검증 범위

[Epic의 Sky Lights](https://dev.epicgames.com/documentation/unreal-engine/sky-lights-in-unreal-engine?lang=en-US)의 수동/자동 캡처와 프레임 분산 부분, [Temporal Upscalers](https://dev.epicgames.com/documentation/unreal-engine/temporal-upscalers-in-unreal-engine?lang=en-US)의 이전 프레임 대응·시각화 부분을 대조했다. [Khronos glTF 모프 규격](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#meshes-morph-targets)과 현재 설치된 Three의 모프 처리 코드를 추가 비교 대상으로 등록했다. 전체 엔진 문서·연결 API·규격 분석 완료를 뜻하지 않는다.

검증 원장은 `docs/research/RENDERING_134.json`, 사용자 설치 기록은 `USER_INSTALL_134.json`이다. 작은 재현 장면의 픽셀·자원 검증과 실제 게임 전체 프레임 속도 측정은 구분한다.
