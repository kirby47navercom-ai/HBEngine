# C++ 값 타입 조회와 선언 묶음

`snapshotNativeMetadata`가 검증하고 전체를 동결한 실행 메타데이터만 약한 키로 색인해요. 구조체는 정규 이름, enum은 정규 이름과 선택적인 원본 경로로 조회해요. 같은 enum 이름에 원본이 여러 개면 원본을 지정하지 않은 조회는 계속 모호함으로 처리해요. 새 전역 타입 저장소나 영구 색인 파일을 만들지 않아요.

새 색인은 처음 해당 종류를 읽을 때 한 번 준비해요. 이후 배열을 다시 순회하지 않아요. 변경 가능한 제작 메타데이터와 외부에서 단순히 동결한 객체는 기존의 현재 값 조회를 유지해요. 선언을 고쳐도 오래된 이름 색인이 남지 않아요.

구조체 필드 표시와 객체 참조 방문 계획은 선언뿐 아니라 메타데이터 묶음에도 속해요. 기존에는 같은 부모 선언 객체를 서로 다른 묶음에서 쓰면 첫 묶음의 자식 타입과 참조 계획을 재사용할 수 있었어요. 새 코드는 검증된 실행 스냅샷의 소속 정의에만 묶음별 계획을 보관해요. 외부·변경 중인 선언은 계획을 새로 읽어요. 원본 객체 값은 수정하지 않고 필요한 경로만 사본으로 바꾸는 계약과 기본값 reset을 유지해요.

이전 커밋의 실제 `native-records.js`로 문자열 자식과 객체 참조 자식을 가진 두 유효한 선언 묶음을 대조했어요. 이전 코드는 두 번째 필드도 문자열로 표시하고 Actor 참조 방문을0번 했어요. 새 코드는 두 번째 정의를 선택하고 참조를1번 바꿔요. 변경 가능한 선언의 string→object 수정도 반영돼요.

512개 구조체·514개 enum의 마지막 타입을 각2000번 읽는 통제 검사에서 이전 정의 방문은1024000/1028000회였고, 준비 후 새 코드의 두 표 순회는0회였어요. 1000개 record 배열 검증, enum 원본 모호함, 읽기 전용 필드 계획의 재사용/reset, 객체 참조의 사본·원본 보존도 확인해요. FPS·총 힙·전체 컴파일 시간 수치가 아니에요.

타입 전용 에셋 편집기·프로젝트 전역 registry·타입 ID/스키마 마이그레이션은 후속 제작 기능이에요. 이번 색인은 그 기능을 완료했다는 뜻이 아니에요. `check-native-type-index-1653.mjs`와 기존 record/enum/C++ 창 검사의 최종 설치 영수증을 따라요.
