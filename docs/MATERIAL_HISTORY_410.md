# 머테리얼 입력·노멀·밉 이력

기존 머테리얼 그래프와 C++/블루프린트 설정을 그대로 사용해요. 사람과 AI의 편집·검증·Undo 경로는 같아요.

## 노멀맵

`Normal Map` 노드는 RGB를 부호 있는 탄젠트 XYZ로 변환하고 XY에 강도를 적용한 뒤 정규화해요. 필터링된 반대 방향 노멀이 정확히 상쇄되거나 강도0에서 길이가0이 되면 중립 노멀 `[0,0,1]`을 반환해요. CPU 평가, 일반 GL/GPU 머테리얼, 광선 GL/GPU 및 생성된 HLSL이 같은 규칙을 사용해요. 노멀을 sRGB 색으로 해석하거나 인코딩된 RGB 자체를 정규화하는 규칙은 아니에요.

이는 길이0의 결과가 미정이라고 명시한 [Microsoft HLSL normalize](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx-graphics-hlsl-normalize)와 정규화 수식을 설명한 [GLSL 4.60 §8.5](https://registry.khronos.org/OpenGL/specs/gl/GLSLangSpec.4.60.html#geometric-functions)를 대조해 정한 HB의 명시적 정책이에요. 이 두 문서의 해당 구역만 추가로 읽었으며 전체 문서/API 분석 완료를 뜻하지 않아요.

## 이전 프레임

이전 삼각형, 바리센트릭 UV, 스무스 노멀·탄젠트, 월드 위치, 카메라·시선, 머테리얼 시간과 픽셀 콘 폭을 함께 평가해요. 월드 입력을 사용했다는 이유만으로 생산자가 이력을 일괄 거부하던 가드를 정리했어요. 이전 포즈가 없거나 퇴화한 경우의 거부와 예전 패킷의 `-2` 표식 해석은 유지해요.

물리·코팅 분기와 IOR 비교, 나머지 표면 값의 허용오차를 유지해요. 값이 달라지면 재투영 이력을 거부해요. 채널별 비교로 NaN·무한대가 최댓값 계산에서 숨는 경우도 거부해요. 코팅 가이드가 관찰하지 않는 ZW 값은 계속 비교에서 제외해요. 불투명도·발광·CPU 전용 애니메이션과 투과 머테리얼의 전역 초기화 조건도 유지해요.

## 비용과 조회

GL 알파 판정은 사용하지 않는 필드와 0번 밉에서 불필요한 좌표 미분 그래프를 생성하지 않아요. 큐브맵의 명시적 LOD는 유지해요. TSL의 알파 그래프는 실제 필요할 때 생성해요. 추가 GPU 타깃, 텍스처, 지속적인 읽기 회수나 프레임별 CPU 작업을 추가하지 않았어요.

AI는 기존 `engineSchema().raySurfaceHistory`와 `.normalDecode`에서 같은 불변 계약을 조회할 수 있어요. 실제 GPU 성능 수치는 기존 프로파일러의 선택적 GPU 보기를 사용해요.

동일 그래프의 한 번 순서 비교에서 소스 크기만 줄었고 GL 준비 시간은 약2초로 비슷했어요. 드라이버 캐시·컴퓨터 부하를 통제한 벤치마크나 초기 컴파일 목표 달성으로 해석하지 않아요. 전역 곡면 역대응·변경된 투명 경로, 거친 복합 로브·참여 매질의 footprint 등은 누적 원장에 계속 남겨요.
