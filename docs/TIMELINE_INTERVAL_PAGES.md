# 많이 겹친 구간 편집

한 행의 화면 범위에 구간이 64개보다 많으면 행 이름 아래에 **이전/개수/다음**을 표시해요. 64개씩 편집하며 모든 구간은 그대로 남아 있어요. 다른 도구나 AI에서 특정 항목으로 이동하면 그 구간이 있는 페이지를 열어요. 현재 선택을 유지한 채 다른 페이지를 탐색할 수 있고, 구간 이동·늘이기·문서 실행에는 원래 데이터와 검증을 사용해요. 키는 기존 커브/개요 표시를 유지해요.

페이지 변경은 보기 상태예요. 문서 값·dirty·revision·Undo·재생 시각은 바꾸지 않아요. 기존 고정 높이 행 가상화 안에 들어가며 구간 버튼 위에 페이지 컨트롤을 겹쳐 놓지 않아요. 문서 편집으로 행을 다시 만들 때 색인도 새로 만들고 오래된 전역 캐시를 남기지 않아요.

AI 읽기는 timeline.row.items.read를 사용해요.

    {"path":"Assets/Owned.hbsequence.json","row":"Track0","range":{"start":2,"end":3},"offset":64000,"limit":64,"expectedRevision":"현재 revision"}

정확한 total, items, nextOffset, previousOffset을 반환해요. limit은 1~256이며 기본 64예요. selection에 구간 ID를 주면 해당 구간을 포함하는 페이지를 반환해요. 반환 항목은 복사본이고 interval 항목만 포함해요. 키 편집은 기존 커브 API를 사용해요. 조회 순서는 시작 시각, 같으면 원래 작성 순서예요. 기존 전체 query와 row.items는 원래 작성 순서와 전체 항목을 유지해요.

기존 시간 구간 색인에 최소 끝 시각을 필요한 때만 추가해요. 한 하위 트리가 모두 화면 범위에 겹치면 개수를 한 번에 세고 이전 페이지 전체를 건너뛰어요. 선택 페이지용 ID 색인도 필요한 때 한 번 만들어요. 초기 색인 생성은 여전히 전체 구간을 읽고 정렬하며, 불규칙하게 엇갈리는 범위는 많은 노드를 볼 수 있어요. 최악의 경우까지 일정 시간이라고 주장하지 않아요.

소스 검사는 65,536개가 모두 겹친 행의 늦은 페이지·정확한 개수·선택 이동·실제 마크업/버튼/AI 핸들러를 확인해요. 실제 창·모바일 터치기기·가변 행 높이·모든 겹친 라벨의 동시 표시·게임 실행 FPS 검증은 별도예요. hb schema --local --section timelineIntervalPages로 계약을 읽어요.
