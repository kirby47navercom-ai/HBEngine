# 곡선의 실제 값·정규화·쌓기 보기

시퀀스 곡선 툴바의 **곡선 보기**에서 실제 값, 정규화, 쌓기를 선택해요. 모드와 숨긴 채널은 문서 보기 상태이고 키·핸들·오브젝트 바인딩·재생 값·문서 revision을 바꾸지 않아요. Undo로 제작 값을 되돌려도 모드와 채널 숨김은 유지해요.

- 실제 값: 기존처럼 공통 축에서 원래 수치를 그려요.
- 정규화: 표시된 각 스칼라 채널의 범위를 -1~1에 대응시켜 서로 다른 크기의 곡선을 겹쳐 비교해요. 원래 값이 같은 상수 채널은 0에 표시하고 단위 배율을 사용해요. 극도로 작은 범위의 역수도 무한대가 되지 않게 처리해요.
- 쌓기: 채널마다 정규화된 레인을 나눠 이름·축을 표시하고, 그래프 안에서 세로로 스크롤해요. 채널을 숨기면 남은 레인을 다시 배치해요. SVG의 높이와 좌표계를 함께 늘리므로 글자·키·포인터 좌표가 같은 기준을 사용해요.

정규화 범위는 키와 각 구간의 가중 Bezier 제어점이 이루는 범위예요. 키 사이의 핸들 오버슈트를 버리지 않으려고 제어점 범위를 포함해요. 키 사이 실제 극값보다 넓을 수 있으며, 범위 밖 반복·선형 외삽까지 항상 -1~1 안에 넣는 기능은 아니에요. 그래프 이동·확대로 확인할 수 있어요.

보기 전환, 전체 맞춤, 숨김 변경은 변환 계수를 다시 계산해요. 값·탄젠트 편집과 드래그 중에는 계수를 유지해 커서가 움직이는 동안 기준이 흔들리지 않게 해요. 키·핸들의 화면 위치, 역변환, 드래그, 범위 선택, 값 축 휠 확대가 같은 변환을 사용해요. 숫자 입력과 재생·C++ 스냅샷은 항상 실제 값이에요. 전체 맞춤을 다시 누르면 바뀐 값에 범위를 맞춰요.

여러 곡선을 함께 드래그하면 같은 화면 이동량을 곡선마다 실제 값으로 환산해요. 예를 들어 100~200 곡선과 -10~10 곡선을 정규화한 뒤 화면 값 0.2만큼 위로 옮기면 각각 실제 값 10과 2만큼 이동해요. 시간 스냅·상대 간격·한 번의 Undo는 기존 다중 곡선 편집과 같아요. 탄젠트 핸들은 화면 기울기 대신 원래 단위/초의 기울기를 저장해요.

AI는 `schema.sequenceCurveView`와 `curveViewLayout`/`curveChannelBounds`의 소유자를 조회해요. `sequence.curve.view`에 path를 주면 현재 모드를 읽고, `mode:absolute|normalized|stacked`를 주면 바꿔요. expectedRevision으로 다른 제작 문서와의 충돌을 막고, dryRun은 모드도 바꾸지 않아요. 잘못된 모드·자료형·revision은 상태를 보존해요. 보기 변경은 Undo/문서 dirty/revision을 만들지 않으며, 실제 값 변경은 기존 `sequence.curve.tool` 또는 문서 편집으로 해요.

기존 TimelineEditor·SVG·RAF를 재사용해요. 범위 준비는 보기 맞춤 시에 하고, 실제 값 보기에서는 키 범위 스캔을 추가하지 않아요. 런타임 타이머·워커·GPU 버퍼·영구 캐시를 추가하지 않아요. 레인 수가 늘면 편집기 SVG 표시 비용은 늘어나므로 게임 FPS 향상으로 계산하지 않아요.

근거는 1883에서 읽고 등록한 [Epic Curve Editor, UE5.8의 View Modes 및 키 편집](https://dev.epicgames.com/documentation/unreal-engine/animation-curve-editor-in-unreal-engine) 118–146의 재사용이에요. 이번에는 새 본문·API 읽기나 전체 분석 gate 승격을 하지 않았어요. 제어점 범위와 상수 배율·역변환 계약은 HBEngine 구현 결정이에요. 키별로 서로 다른 채널 축을 동시에 선택하는 기능은 별도로 남겨요.
