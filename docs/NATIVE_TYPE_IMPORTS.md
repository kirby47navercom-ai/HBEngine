# 블루프린트 타입 가져오기

C++ 클래스를 연결하지 않은 블루프린트에서 **클래스 기본값 → 타입 라이브러리**로 에셋을 추가해요. 라이브러리에 선언한 구조체·열거형을 변수, Make/Break/Set, 함수·매크로 인자와 출력, 배열에서 기존 타입 편집기로 사용해요. C++ 빌드 버튼은 표시하지 않고, Play·내보내기에서도 이 블루프린트 때문에 네이티브 모듈을 만들지 않아요.

원본은 경로만 저장해요. 파생 메타데이터와 C++ 코드·타입 표를 BP마다 복제해 저장하지 않아요.

```json
"native": {
  "version": 1,
  "sourceReference": true,
  "typeLibraries": ["Assets/Shared.hbtypes.json"]
}
```

`document.get`·`document.patch`·`document.save`와 문서 revision 규칙은 동일해요. AI도 같은 원본을 수정해요. 변수·핀에서 쓰는 이름은 `<라이브러리 namespace>::<C++ 심벌>`이에요. Actor 참조는 기존 `self`/Actor ID 규칙을 사용해요.

## 실행과 수명

- 프로젝트·작업공간·실행기·패키징이 같은 `createNativeTypeImportResolver`를 사용해요. 명시적 파일 목록을 읽고 라이브러리 ID/namespace 중복, 타입·기본값·전체 예산을 검증해요. 잘못된 import를 C++ 기본 파일 경로로 대체하지 않아요.
- 읽기 작업마다 파일·생성 메타데이터를 한 번 준비하고 조합을 공유해요. 실행 메타데이터는 검증 후 동결해요. 같은 BP를 쓰는 여러 Actor의 메타데이터는 공유하고, 변수 값과 Actor 참조는 각 인스턴스에 속해요.
- 편집 작업공간은 라이브러리별 최근 자료와 BP의 현재 조합을 보관해요. 과거 import 조합을 모두 쌓는 캐시는 만들지 않아요. 여러 import를 바꾼 Undo/Redo는 이미 읽은 자료에서 조합을 다시 만들어요. 다음 prepare는 원본을 새로 읽어요.
- 기존 문서 폴링이 라이브러리 파일 변경도 확인해요. 읽는 사이 사람이 문서를 바꾸면 이전 작업으로 덮어쓰지 않아요. 새로운 Worker·타이머·상시 프로젝트 스캔은 추가하지 않아요.
- BP 자식은 부모의 타입을 상속해요. 자식에서 부모와 다른 native/type 소스를 재정의하는 기존 금지 규칙은 유지해요. C++ 부모에 별도 라이브러리를 섞는 확장은 포함하지 않아요.
- 패키징은 경로가 가리키는 JSON을 포함하고, 같은 파서로 타입/참조를 검증해요. 순수 BP import의 native 모듈 수는0이에요. 구조체 값이 SetMembers/Break를 지나 Actor를 이동시키는 실제 게임으로 확인해요.

이 방식은 명시적 import예요. 독립 enum/struct 에셋, 모든 프로젝트 타입의 자동 발견, 임의 삭제·이름/타입 이관은 별도 잔여 항목이에요. 파일 목록32개와 원본 합계8MB, 기존 합성 구조체512개·필드/기본값 예산을 유지해요.

1913–1915: [에셋 간 타입 참조](NATIVE_TYPE_DEPENDENCIES.md)의 imports·전이 의존 필드·생성 include·상위 기본값/소비자 원자 이관을 지원해요. 독립 enum/struct 에셋과 명시적 의존은 구현됐고 프로젝트 전역 자동 발견·파괴적 변경은 별도예요. 기존 잔여 설명 중 에셋 종류·에셋 간 참조는 이 기록으로 갱신해요.
