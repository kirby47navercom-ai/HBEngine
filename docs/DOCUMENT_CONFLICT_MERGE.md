# 외부 변경과 복구 초안 합치기

열린 에셋의 외부 변경 창에서 **합치기**를 선택해요. 마지막 저장 기준·내 편집·현재 디스크의 세 값을 비교해 서로 다른 오브젝트 속성의 변경을 합쳐요. 같은 속성을 양쪽에서 바꿨거나 삭제와 수정이 겹치면 속성별로 내 편집/디스크를 선택해요. 배열·텍스트는 통째로 선택하며 배열 인덱스나 그래프 연결을 추측해 합치지 않아요. 비교 창에서 전체 원문도 볼 수 있어요.

모든 충돌 선택과 에셋 형식 검증을 통과한 결과만 **한 번의 Undo가 가능한 초안**으로 반영해요. 파일은 일반 저장 때 기록해요. 이때 비교했던 디스크가 저장 CAS 기준이므로 그 후 외부에서 다시 바꾼 파일을 덮지 않아요. 준비 중 문서 교체·이름 변경·추가 편집·기준/복구 초안 변경은 거절해요. 다시 시작한 복구 문서는 원래 저장 기준을 별도로 유지하고, transient 대화창 열림 상태는 복구 저장에서 제외해요.

AI는 `document.conflict.merge`에 `path`, 필수 `expectedRevision`, 선택 `choices`, `dryRun`, `includeData`를 전달해요. `choices`는 JSON Pointer 키와 `mine`/`disk` 값이에요. 루트 텍스트 충돌의 키는 빈 문자열이에요. `dryRun:true`는 기본적으로 충돌 목록·미해결 개수·검증 결과만 반환하고 `includeData:true`일 때 복사된 후보 데이터를 포함해요. 실제 반영에서 미해결 충돌은 `DOCUMENT_MERGE_CONFLICT`, 오래된 문서는 `REVISION_CONFLICT`로 거절해요. 저장은 `document.save`로 따로 해요. 실행 중/파일 묶음 작업 등의 기존 편집 제한도 적용해요.

`DocumentMergeSession`과 `planDocumentMerge`를 사람용 창과 AI가 공유해요. 골격/머테리얼/C++ 정의 등 각 에셋의 일반 검증·저장 경로는 유지해요. 이 기능은 열린 텍스트/JSON 문서의 초안 충돌 해결이며 바이너리 write-ahead journal 충돌 UI·임의 배열 ID 합치기·줄 단위 C++ 병합·전원 차단 내구성 검증은 별도 잔여예요.

검사: `node tools/check-document-merge-2495.mjs`. 실제 앱 함수/소유 DOM 이벤트·복구 재시작·파일 CAS를 확인하며 새 GUI/설치 실행을 뜻하지 않아요.

예전 복구 기록에 원래 기준이 없으면 독립 속성을 추측하지 않고 문서 전체 충돌로 표시해요. 명시적으로 내 편집/디스크를 선택해야 하며 한쪽 변경을 자동으로 덮지 않아요. 같은 문서의 열린 충돌 창은 AI 해결 후 닫고 다른 모달의 편집 잠금은 유지해요.
