# 배열·큐브·볼륨 디스크 밉

기존 텍스처 속성 창의 **디스크 밉 사용**을 배열·큐브맵·볼륨에도 연결해요. 작성한 이미지별 전체 밉 체인을 사용하며 실행에서는 initialMip부터 작은 밉까지 먼저 읽어요. 선명한 밉 요청이 생겼을 때만 더 큰 이미지를 읽어요. 큐브는 여섯 면, 배열은 일정한 층 수, 볼륨은 밉마다 XYZ를 절반으로 줄여요. 홀수 크기는 내림하고 최소1을 유지해요.

```json
"streaming": {"enabled":true,"width":512,"height":512,"depth":16,"initialMip":4}
```

depth는 배열/큐브/볼륨에서 필수이고 큐브는6이에요. 기존2D 파일은 depth 없는 형식을 그대로 사용해요. 현재 범위는 RGBA8 작성 밉이에요. 커버리지·노멀 재처리·composite·topMip/maxSize 등의 변환이 필요한 설정은 일반 가져오기를 사용해요. 원본·가져오기·슬라이스 편집으로 메타데이터가 오래되면 디스크 모드를 꺼요.

사람의 버튼은 현재 미리보기 크기를 사용하고 정보가 없으면 첫 이미지의 실제 크기만 읽어요. 문서 identity/preview key를 다시 확인한 뒤 기존 편집·Undo에 기록해요. 다른 문서로 바뀌거나 현재 뷰를 닫으면 소유 요청을 취소해요. 미리보기 자체는 아티스트가 모든 원본을 검사하는 기존 처리 경로를 유지해요.

실행은 기존 materialResidentMip 노드, hb::Materials::SetResidentMip, 선택적인 TextureStreaming 풀을 공유해요. -1은 수동 요청 해제이며 풀이 없으면 원래 밉0을 복구해요. 논리 LOD는 원본 기준이고 실제 업로드는 선택한 밉 꼬리만 사용해요. 장치의 크기/층 수 한도를 캡처해 초기·후속 요청 모두 이미지 읽기 전에 검사해요. 더 작은 상주 밉으로 표현 가능한 큰 논리 원본은 유지해요. 임의의 새 오브젝트/층 수 제한을 추가하지 않아요.

밉 하나의 읽기는 요청자끼리 공유하고 면·슬라이스는 순서대로 디코딩해요. 면 하나라도 실패하면 후보 전체를 거절하고 기존 바인딩을 유지해요. 마지막 소유자가 해제되면 불필요한 픽셀과 진행 중 읽기를 바로 해제해요. 큐브 얼굴 뷰와 파생 캐시도 정리해요. 새 워커·타이머·디스크 캐시 사본을 추가하지 않아요. ND 보고서는 중복 경로 목록 대신 개수만 담아요.

AI 계약은 engine.schema.textureDiskMips version2와 기존 residency 계약이에요. reads는 이미지 시도 수, levelReads는 공유 작업 수, decodedBytes는 보유 RGBA 자료예요. 전체 CPU/GPU 힙이나 드라이버 정렬 비용은 아니에요. 외부 파일 불변 스냅샷·디스크 소스 영역쓰기·자동 쿠킹·HDR/raw/압축 스트리밍은 별도예요.

검사: check-layered-disk-2838의18개·기존2D791 gate·기존 layered-import20개. check-layered-disk-2841-cpp는 현재 SDK로 실제3메서드/9호출/9쓰기를 컴파일하고 세 종류의 선명/거친/해제를 실제 VM·서비스·바인딩으로 실행해 모든 RGBA와 최종0 lease를 확인해요. 소유 Image/Canvas·가짜 GPU queue 자료 대조이며 실제 창/GPU 픽셀·모바일 장치·설치본 검사는 아니에요.
