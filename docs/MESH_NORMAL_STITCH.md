# UV 경계의 노멀 잇기

UV를 나누며 정점 ID가 갈라져 조명이 끊기는 경우, 메시의 **노멀 → UV 경계 노멀 잇기**를 사용해요. 기존 용접 오차가 위치 허용 거리이고, 최대 각도는 서로 이어도 되는 노멀 방향 차이예요. 선택 정점을 seed로 삼아 같은 위치의 경계 복사본을 포함하고, 선택이 없으면 전체 열린 경계를 확인해요.

정점·간선·UV0·보조 UV·색상은 합치거나 이동하지 않아요. 같은 위치 묶음 안에서 각도 조건을 만족하는 노멀을 인접 면적에 따라 평균해요. 작성한 노멀이 있으면 그 방향을 존중하고, 없으면 원래 면 벡터를 사용해요. 뾰족한 경계는 각도별로 유지해요. 거리나 각도가 연쇄로만 이어지는 모호한 묶음·반대 노멀·비다양체/뒤집힌 경계는 임의로 섞지 않고 거부해요. 새 비교에는 2백만 회의 저작 예산을 적용해요.

실제 이을 값이 없으면 노멀 필드를 새로 만들지 않고 문서도 바꾸지 않아요. 기존 한 번의 Undo·검증·dryRun·저장을 사용해요. AI는 `world.mesh.edit`에 `operation:"stitchNormals"`, 선택 `vertices`, `tolerance`, `maxAngle`을 넣어요. `hb schema --local --section meshNormalStitch`에서 계약을 읽어요.

메시의 위치·인덱스·속성 구성이 같고 노멀·UV·색상만 바뀐 경우에는 기존 `BufferGeometry`와 버퍼를 유지해요. float32 값이 달라진 행만 쓰고, 기존 최대 64개 누적 변경 범위를 사용해요. 다른 속성의 version이나 대기 중인 업로드 범위를 지우지 않아요. 전체 문서 검증과 배열 대조 비용은 여전히 있어요.

위치·인덱스·UV/색상 채널 구성이 달라지거나 작성 노멀을 제거하는 경우, 버퍼가 외부에서 교체됐거나 tangent/morph 데이터가 있는 경우에는 변경 전에 기존 재생성 경로로 넘겨요. 조명 계산을 생략하거나 해상도를 낮추는 방식은 사용하지 않아요. `meshAttributeUpdate`에 조건과 검증 범위가 있어요.

재료별 smoothing group·임의 곡면 seam 자동 대응·전체 비다양체 복구는 별도예요. 실제 Three 속성/범위 대조는 GPU 업로드 픽셀·실제 창·전체 게임 FPS 검증을 대신하지 않아요.
