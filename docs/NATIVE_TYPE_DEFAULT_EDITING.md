# 중첩 타입 기본값 편집

라이브러리 안에서 자식 구조체에 필드를 추가하면 부모의 단일 값과 배열 기본값에도 새 멤버가 채워져요. 기존 수치·문자열·enum 숫자·Actor `null` 값은 유지해요. 더 바깥 구조체의 배열까지 같은 규칙으로 반영해요. 새 필드 행은 바로 펼쳐져요.

아직 저장하지 않은 필드의 이름은 UUID를 기준으로 대응해 기본값의 키를 바꿔요. 미저장 필드를 삭제하면 그 멤버를 부모 기본값에서도 제거해요. 미저장 필드의 자료형을 바꾸면 부모의 해당 값은 새 선언 기본값으로 바뀌어요. 저장된 필드의 이름·타입·배열 여부·순서·삭제를 막는 기존 보호는 유지해요.

이 기능은 **현재 편집 중인 라이브러리의 기본값**에 적용해요. 이미 저장한 BP 변수·장면·프리팹의 인스턴스 값은 자동 이관하지 않아요. 참조 BP가 새 모양과 맞지 않으면 저장을 거절하고 라이브러리와 생성 헤더를 모두 유지해요. 참조 문서를 함께 수정하는 작업은 기존 checked-batch 경로를 사용해요.

`reconcileNativeTypeDefaults(previous,next)`는 스키마가 같으면 입력 `next`를 그대로 반환해요. 표시 이름·설명·값만 바꾸는 편집에 새 기본값 복사를 추가하지 않아요. 스키마가 바뀌면 새 결과를 만들고 이전 자료와 초안을 수정하지 않아요. 알 수 없는 키나 기존 필드의 누락·잘못된 리터럴을 조용히 고치지 않고 기존 컴파일러 검증에 넘겨요. 순환·중첩·배열·기본값 예산을 유지해요.

## C++ 기본값과 편집기 갱신

명시적 구조체 초기화를 읽을 때는 그 타입의 멤버 기본값에서 시작해요. 포함하는 필드의 별도 초기값이나 구조체 배열 전체를 요소의 기본값으로 사용하는 오류를 수정했어요. 실제 C++17 부분 초기화·중첩 구조체 배열 프로그램의 결과 `[4,2,3,2,5,2,6,2]`와 리플렉션 결과를 대조해요. 기존 값 프로토콜·네이티브 ABI를 추가하지 않아요.

C++ BP가 사용하는 리플렉션 구조체·enum의 실제 헤더 경로도 기존 문서 폴링에서 확인해요. 주 헤더·CPP가 그대로여도 포함된 타입 헤더가 바뀌면 include closure를 읽어 속성을 갱신해요. 읽는 사이 사용자 문서가 바뀌면 이전 준비 결과로 덮어쓰지 않아요. 새 타이머를 만들지 않아요. 리플렉션 선언이 없는 임의의 include 전체 감지·빌드 캐시 identity 일반화는 별도 잔여 항목이에요.
