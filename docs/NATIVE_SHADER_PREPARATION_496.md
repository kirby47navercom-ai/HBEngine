# 네이티브 셰이더 준비

Windows 편집기·게임 실행기는 화면 효과 셰이더를 단일 워커에서 준비해요. 준비 중에는 래스터 화면과 C++·블루프린트 실행을 유지하며, 필요한 단계가 모두 준비된 다음 경로 추적과 필터를 사용해요. 새 GPU 자원이나 자동 읽기 검사는 추가하지 않아요.

C++ SDK는 기존 동기 방식이 기본이에요. 선택적으로 `renderer.setAsyncShaderPreparation(true)`를 켜고 `renderer.shaderPreparationInfo()`로 상태를 읽을 수 있어요. 자체 루프를 멈춘 경우 `renderer.pollShaderPreparation()`가 준비된 바이트코드를 받아요. 렌더 컨텍스트·Present·셰이더 장치 생성은 기존 소유 스레드에서 수행하고 워커는 소스/바이트코드만 처리해요.

경로·가이드·공간 필터·광자·시간 필터·보조 가이드별 대기/컴파일/준비/실패 상태가 프로파일러에 나와요. AI도 `engine.schema.nativeShaderPreparation`와 동일한 실행 진단을 읽어요. 준비 중 샘플과 이전 프레임 이력을 승인하지 않으며 취소·소스 변경 뒤 오래된 작업은 새 렌더러 상태에 적용하지 않아요.

작업 큐와 기존 메모리 바이트코드 캐시는 각각8MiB예요. 큐가 차면 다음 확인 때 다시 제출하며 같은 요청을 합쳐요. 호출자가 버린 대기 작업은 취소하고 진행 중인 FXC는 안전하게 끝내요. 워커는 유휴1초 후 종료해요. 캡처는 별도 상태 확인을 통해 기다릴 수 있고 오류/취소 시 대기를 해제해요.

이번 실제 C++ 게임에서는 준비 중22프레임/23화면 출력, C++ 변경4.21ms, 기능 중지62.65ms를 관찰했어요. 고정 성능 보장이나 FPS 수치는 아니에요. 최초 FXC 자체 비용과 다른 래스터 자원 생성의 동기 준비는 별도 개선 대상이에요. 근거와 남은 항목은 [작업 기록](research/ENGINE_WORK_496.json)에 연결해요.
