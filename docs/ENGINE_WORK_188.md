# 188 — 전용 제작창의 공용 단축키와 분리 창 입력

머테리얼/함수/레이어, 커브/트랜스폼 애니메이션, 애니메이션 그래프, 행동 트리/FSM, 몽타주/시퀀스, 2D 리그, 타일맵, 스프라이트/스프라이트 애니메이션의 기존 실제 조작56개를 단축키 설정에 등록했다. 기존 명령까지 총111개다. 9개 전용 문맥을 구분하며 같은 키를 서로 다른 창에서 사용할 수 있다. 프로필·충돌 처리·내보내기/가져오기·AI revision/dryRun을 그대로 공유한다.

머테리얼 복사/잘라내기/붙여넣기/복제/삭제/전체 선택·프레이밍/노드 미리보기, 커브 키 추가/삭제/프레이밍/재생, 그래프 선택 삭제·미리보기·프레이밍, 시퀀스 프레임/키 경계/처음/끝/재생, 몽타주 알림 구간과 시작/끝 핸들 이동, 리그 도구·클립보드·뼈/정점 편집, 타일 도구를 기존 제작 명령에 연결했다. 새로운 별도 그래프나 실행기를 만들지 않았다.

관리되는 제작창은 예전 고정 키 처리로 우회하지 않는다. 혼합 공간·애니메이션 알림 차트는 자기 키를 먼저 소유해 부모 그래프 노드를 잘못 삭제하지 않는다. 독립 사용/블루프린트 내부 타임라인은 기존 입력 계약을 유지하고 Escape 취소도 보존한다. 입력·IME·대화상자·비행·게임 중 문맥을 구분한다. notify 명령은 실제 선택한 구간/핸들에서만 실행한다. 프레임/구간 이동과 위젯 nudge는 키를 누른 채 반복할 수 있고 복제·재생 토글은 반복하지 않는다. 기존 명시적 사용자 키가 새 기본 키와 겹치면 사용자 값을 보존하고 새 암묵적 기본 키만 해제한다.

분리한 실제 창은 로컬 고정 키 처리 전에 주 창의 공용 해석기에 키를 전달한다. 처리한 키는 원래 이벤트도 중단한다. 새 창의 저장/Undo/Redo 버튼은 가짜 Ctrl 키가 아니라 소유 문서 명령을 호출하므로 저장 키를 Alt+S로 바꿔도 버튼이 작동한다. 포인터 편집 뒤 몽타주 핸들 포커스를 복구하고, 머테리얼 비동기 붙여넣기는 문서 전환/종료/게임 시작 뒤 늦은 결과를 버린다. 공용 키 검색에서 프로필/키 배열 반복 복제를 줄였으며 새 타이머·의존성·GPU 읽기를 추가하지 않았다.

CPU8개·기존 단축키6개와 머테리얼/타임라인/알림/UI/API/분리 창 프레임 회귀를 묶어 검사했다. 실제 Editor에서는 머테리얼/함수 복제와 삭제/조합키 우회 거절·Undo/Redo, 커브 키 편집, 2D 리그/타일 도구, 애니메이션 노드 삭제,30fps 스텝, 몽타주 핸들 정확한10/60초 이동·끝 보존, 입력/IME, 실제 새 HWND의 재지정 키·저장/Undo/Redo, 설정 복원·저장·오류0/종료0을 확인했다. 최종 키 반복 검사는 설치 영수증에 따로 기록한다. [근거](research/ENGINE_WORK_188.json).

대조한 공식 본문은 [Unreal Material Editor UI](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-engine-material-editor-ui)의218–278 조작/키 구역과 [Unity Shortcuts Manager](https://docs.unity.com/en-us/engine/6000.0/manual/unity-editor/editor-navigating-managing/shortcuts-manager)의319–360 문맥/충돌 및400–431 기본 프로필/도구 입력 설명이다. 문맥·프로필·키 소유권을 HB의 기존 편집기 구조에 적용했다. 연결 API/미디어와 전체 엔진 조사 gate로 확대하지 않는다.
