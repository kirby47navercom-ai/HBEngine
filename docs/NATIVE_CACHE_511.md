# C++ 빌드 캐시와 설치 용량

사용자 설치본의 C++ 모듈은 `HBEngine/Cache/NativeModules`에 저장해요. 설치 파일이 있는 `Versions/<버전>`에는 새 빌드 캐시를 만들지 않아요. JSON 의존 헤더도 `HBEngine/Cache/Dependencies`에서 공유해요. 다른 위치에 직접 배치한 설치본은 로컬 앱 데이터의 `HBEngine/Cache`를 사용해요.

공용 캐시는 설치 경로별 소유자를 구분하고 전체 최근 모듈 32개를 보존해요. 편집기에서 참조하거나 빌드·실행 중인 모듈은 추가로 보호해요. 32개는 재생성할 수 있는 캐시 보존 수이며 게임 오브젝트나 C++ 함수 개수의 제한이 아니에요. 업데이트가 이전 설치를 정리하면 그 설치의 참조 없는 모듈도 정리해요.

빌드가 실패하거나 취소되면 생성한 임시 소스와 오브젝트 파일을 정리해요. 정상 실행 파일을 게시한 빌드의 생성 소스는 디버거를 위해 보존해요. 프로젝트에 작성한 원본 C++ 파일은 이 정리의 대상이 아니에요. 같은 모듈을 동시에 빌드하면 먼저 완성한 실행 파일을 유지해요.

`NativeHost.inspectResources().nativeCache`에서 캐시 경로·소유자·참조 수와 정책을 확인할 수 있어요. 이 정보는 요청할 때 조회하고, 프레임 처리에는 캐시 파일 조회나 정리 작업을 추가하지 않아요. 소스 체크아웃은 기존 `native/build/plugins` 경로와 캐시 키를 유지해요.

설치 경로를 소유자 키에 포함하므로 새 설치 버전은 디버거 소스 경로가 일치하는 실행 파일을 새로 빌드해요. 사용자 프로젝트·저장 데이터·SDK 전체나 실행 중인 모듈을 용량 정리 대상으로 삼지 않아요.
