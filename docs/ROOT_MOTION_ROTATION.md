# 루트 모션 회전 가중치와 정규화 버퍼

2026-10-22. `weightMotionRotation(out,value,weight)`는 `out[3..6]`에 단위 회전에서 입력 회전까지의 가중 SLERP를 쓰고 위치 `out[0..2]`는 유지해요. 기존 임시 Quaternion 식과 같은 0/1 가중치·최단 회전·작은 각도 정규화·외삽을 사용해요. 입출력 버퍼가 같아도 동작해요.

`appendMotion`과 몽타주의 루트 가중치 복원이 이 공통 함수를 사용해요. 복원 경로의 Quaternion 생성 두 곳을 없앴고, `state.normalizedMotion`은 처음 필요한 시점에 56바이트 버퍼 하나를 만든 뒤 슬롯·틱에서 재사용해요. 몽타주 상태가 끝나면 상태와 함께 수명이 끝나요. 전역 scratch·강참조 캐시·워커·타이머·GPU 리소스는 없어요. 다른 프레임 Map·출력 버퍼 생성은 별도 경로에 남아 있어요.

`tools/check-root-normalization-1564.mjs`는 1,500개 회전/가중치와 1,500개 입출력 별칭 경우를 이전 Three 식과 대조해요. 0 회전·아주 작은 각도·역가중치 외삽도 포함해요. 실제 gameplaySystems의 정규화 식만 이전 코드로 바꾼 격리 참조와 비교했고, warmup 3틱 뒤 12틱의 길이7 Float64Array 생성은 이전 36개·현재24개였어요. 재생 시간은 같았어요. 전체 heap·GPU·게임 FPS 검사가 아니라 격리 Node 프로세스의 생성자 계수예요.

묶음 검사는 앞선 1,200개 append 수치/별칭+1,000회 합성, 실제64클립 애니메이션/루트, 2D/3D 30/60/120 스텝·벽·중력·부모·몽타주 tail·seek·교체·notify 제어를 포함해요. 같은 저장64클립 프로젝트의 실제 편집기와 Windows D3D11에서 paused126.5·원래 `[10,3,0]` 위치·후속 노드 도달도 통과했어요.
