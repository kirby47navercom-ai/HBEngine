# 타일맵 변경 좌표 모으기

실행 중 타일 변경 좌표는 레이어별 keyed Map에 추가하고, 렌더/충돌 처리 단계에 들어갈 때 분리된 배열로 한 번 만들어요. 매 쓰기마다 지금까지의 변경 목록을 다시 복사하던 누적 비용을 없애요. 같은 좌표는 중복되지 않고 최초 순서를 유지해요. 레이어 전체 변경은 다음 처리가 끝날 때까지 개별 셀 변경보다 우선해요.

렌더 훅에는 기존 `Map<layerId, cells[] | null>` 형태를 전달해요. 배열과 좌표 사본을 전달하므로 비동기 렌더 중 추가 편집이나 훅의 배열 수정이 대기 중 변경 목록을 바꾸지 않아요. 렌더 중 추가 편집은 기존 revision 비교를 통해 다음 처리로 남아요. 렌더 실패도 dirty 상태를 지우지 않아요. 해제/풀 재사용의 기존 수명 경계를 유지해요.

이 변경은 변경 좌표 수집 비용을 줄여요. 실제 점유 타일 JSON 배열 복사·동결/검증, 전체 새 맵 로드, 디스크 청크, GPU/충돌 총비용은 별도예요. 셀·오브젝트 수 제한을 새로 두거나 품질을 낮추지 않아요. BP/C++의 기존 `SetTile`, 묶음 쓰기와 같은 `RuntimeTilemaps`를 사용하며 `schema.tilemapChanges`에서 범위를 조회해요.
