# GPU 물리 머테리얼과 카메라

직교 카메라에서는 평평한 면을 화면 가장자리에서 보더라도 시선 방향이 같아요. 원근 카메라에서는 픽셀의 표면 위치에서 카메라를 향하는 방향을 사용해요. 금속·투명 코팅·광택·이방성·얇은 막·환경 반사·굴절이 같은 규칙을 읽어요. 카메라를 움직이거나 투영 방식을 바꾸기 위해 머테리얼을 다시 만들 필요는 없어요.

작성한 머테리얼은 기존 그래프와 속성을 그대로 사용해요. 게임에서는 `hb::Materials::SetFloat(target,"Roughness",value)` 같은 C++ 함수와 그 선언에서 생성된 블루프린트 노드가 같은 실행 서비스로 연결돼요. 카메라 이동·회전도 기존 Scene 함수를 사용해요. 새 JS 전용 제작 명령은 필요 없어요.

`gpu-camera-view.js`는 머테리얼 변환 지점과 엔진의 NodeMaterial 제작 지점에 한 번씩만 연결해요. 셰이더 빌더가 소유한 시선 변수에 투영 방식에 맞는 방향을 넣고 나서 물리 속성과 조명을 계산해요. 의존 패키지의 전역 노드나 여러 카메라가 공유하는 머테리얼에 특정 카메라의 값을 저장하지 않아요. 반사 캡처의 원근 카메라도 같은 머테리얼을 사용해요.

얇은 막 간섭의 XYZ→RGB 변환은 명시적인 행별 내적으로 계산해요. TSL의 JS 행렬 생성과 GLSL 생성자의 행·열 관례 차이를 피하고, 다중 산란에는 현재 GL 물리 모델과 같은 얇은 막 입력과 평균 반사율을 사용해요. 두께 0은 막 효과를 끄며 가중치는 0~1로 제한해요. 이 보정이 모든 렌더러의 모든 조명 모델을 동일하게 만든다는 뜻은 아니에요.

원본 PhysicalNodeMaterial의 볼륨 굴절과 엔진의 레이어 굴절 모두 같은 월드 시선을 사용해요. 원본 모델의 거칠기/DFG 에너지와 엔진 레이어의 Schlick 에너지는 기존 정책을 유지해요. 원본 볼륨 연결은 Three 0.180의 빌더 소유 호출 형태를 검사하며, 의존 버전에서 형태가 달라지면 명시적인 오류로 재검토를 요구해요.

강제 WebGL 폴백의 명시적인 텍스처 읽기는 READ 프레임버퍼와 픽셀 패킹 설정을 복원한 뒤 GPU 완료를 기다려요. 기다리는 동안 다른 프레임이 그려져도 그 새 상태를 덮지 않고, 성공·실패 모두 임시 프레임버퍼와 픽셀 버퍼를 해제해요. 엔진 전체 WebGPU 컴퓨트 실행의 자동 GL 폴백 지원과는 별도 기능이에요.

AI는 `schema.cameraView`, WebGPU 실행 진단의 `renderer.cameraView`, `hb context "머테리얼" --symbol attachGPUCameraView`로 계약과 소유자를 찾을 수 있어요. 작성 데이터·C++/노드 API·트랜잭션·Undo 형식은 유지돼요. 새 GPU 텍스처·타깃·엔진 소유 버퍼나 운영 픽셀 읽기는 추가하지 않아요. 기존 카메라 행렬을 셰이더에서 읽으므로 백엔드별 uniform 단계 배치는 달라질 수 있어요. 프레임별 머테리얼 순회는 없고, 명시적 폴백 읽기에서만 상태 조회 비용이 생겨요.

지정 GPU/실행 검사는 [검증 기록](research/GPU_PHYSICAL_VIEW_1148.md)과 후속 설치 영수증을 확인해요. 경로 추적 이력·모든 임의 로브 조합·전체 FPS·GL 복잡 그래프 초기 지연은 이 변경의 완료 주장에 포함하지 않아요.
