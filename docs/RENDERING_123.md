# 123 — 모션 정점 경량화·실패 시 원본 보존

이전 포즈 정점을 정확한 크기의 Float32Array에 직접 포장한다. 큰 가변 배열과 그 복제를 제거하며 기존12float/삼각형 형식·모션 유효 비트·변경 행·기하/필터 누적 키를 유지한다. 모션 필터가 꺼져 있으면 이 배열을 만들지 않는다. 새 텍스처·읽기·설정·에셋 계약은 없다.

수정 전에는 이전 포즈에 NaN이 있어도 포장이 성공하고 재사용 중인 atlas를 먼저 바꾸는 문제가 재현됐다. 이제 이전 포즈의 모양·유한 값·float32와 정점 차이의 범위를 **atlas나 재사용 머테리얼 블록을 쓰기 전에** 검사한다. NaN·Infinity·빈 기록·좌표 길이 오류·float32 초과·차이 overflow6사례에서 실패 뒤 원본 바이트가 같다. Float32Array 이전 정점도 기존과 같이 받는다. 이전 포즈가 없으면 현재 포즈를 포장하고 유효 비트0을 유지한다.

성공 프레임 확정 시 같은 삼각형 ID 구성이면 이전 포즈 Map을 재사용하고 바뀐 포인트 참조만 갱신한다. 삼각형 수가 같아도 오브젝트가 교체되어 ID가 달라지면 Map을 재구성해 오래된 ID를 제거한다. 모든 프레임의 큰 쌍 배열과 Map 복제를 피하며, 실패 프레임은 기존처럼 이력을 비우고 다시 준비한다. 프레임 성공 전에는 이전 이력을 갱신하지 않는다.

122 이전 코드와 transport/후보 목록/모션의8배치 전체 바이트가 같았다. 32인스턴스/5,376삼각형 준비 입력의12교대쌍 포장 중앙값은14.19→6.87ms였다. 이 비교는122와123을 합친 포장 변화이며 수집·전송·렌더·게임 FPS를 포함하지 않는다. 실제 D3D11 실행 창에서는119 공용 검사로 카메라/오브젝트 모션, 정적 원본 누적, 수동 무효화·재질 변경·실패 거부, 이차 반사/굴절 렌즈를 확인했다. CPU8개 묶음과 기존 sparse upload/SDK/AI 계약을 대조했다. [증거와 설치](research/RENDERING_123.json).

셰이더·CB·네이티브 실행파일은121과 같으므로 재컴파일하지 않는다. 변경된 실행 스크립트와 검사·문서를 동기화하고 설치 명세를 다시 검증한다. 사용 중인 창·원본 게임은 건드리지 않고 검증 후 이전 Versions 사본을 정리한다. 월드 교차 기록 전체 공유와 곡면/비스듬한 이차 필터 등 기존 누적 작업은 유지한다.
