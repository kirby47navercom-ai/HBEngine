# 시퀀스 클립 조회와 미리보기 준비 비용

`SequenceSampler.clipById`는 유효한 시퀀스의 고유 클립 ID를 현재 배열에서 찾아요. BP 오브젝트 조회와 같은 숫자 슬롯 검증 함수를 재사용하되 트랙별 소유자를 분리해요. 슬롯의 현재 ID가 다르면 기존 선형 탐색으로 복구해요. 재정렬·교체·삭제·재생성·이름 변경·배열 교체를 관측하며, 없는 ID는 영구 캐시하지 않아요. 캐시는 현재 클립 배열 길이 이내의 ID→숫자 인덱스이고 클립 객체를 따로 붙잡지 않아요. ID를 생략하면 준비하지 않으며 첫 클립만 찾으면 인덱스를 만들지 않아요. 구간/이벤트 정렬과 오디오·애니메이션의 재생 시각은 유지해요.

실제 이전 Git `363a9d9`의 메서드와 대조한 256개 ID 레코드·2048조회·16ID 계측에서는 ID 읽기가508928→6009회였어요. getter로 작업량을 세는 진단이며 FPS·실제 프레임 시간은 아니에요. 누락 조회는 기존과 같은 호출당 한 번의 탐색이고 최초 첫 레코드 확인1회만 더해요. 중복 ID를 가진 잘못된 에셋의 탐색 의미를 일반화한 것은 아니에요.

`GameplayPreviewSource`는 시퀀스·몽타주·애니메이션 그래프 미리보기의 소스 비교를 맡아요. `AssetDocuments`의 저장 후 `dirty=false`이며 같은 데이터 객체·같은 saved 표식인 경우에만 최초 JSON 서명을 재사용해요. 데이터는 WeakRef로 확인하고 문서 본문을 강하게 캐시하지 않아요. 편집 중, 저장 표식/dirty 정보가 없는 독립 문서, 데이터 교체·다시 저장은 기존 JSON 비교를 수행해요. 일반 편집은 app의 changed가 dirty를 설정하고, 이름 변경도 AssetDocuments.rename이 dirty를 설정해요. 이 계약 밖에서 clean 객체를 직접 변경하면서 dirty를 갱신하지 않는 호출은 캐시 대상 계약에 포함하지 않아요.

본문 서명과 대상·그래프·씬 메타데이터를 따로 비교하므로 큰 본문을 매번 합치거나 이스케이프하지 않아요. 본문이 같은 재저장·no-op 데이터 교체는 미리보기를 다시 만들지 않아요. 원본 비교와 동일한 무효화 조건을 따르며, 뒤로 스크럽할 때의 시뮬레이션 재생성은 유지해요. 미리보기를 닫으면 서명과 WeakRef를 해제해요. 전역 색인·상주 작업자·타이머·GPU 버퍼를 추가하지 않아요.

16384키 문서의40스크럽 계측은 본문 직렬화40→1회였어요. dirty 상태8표본은8회를 유지했어요. 문서 변경을 확인하는 비용을 생략한 결과로 설명하지 않아요. 작업량 계측과 실제 창의 미리보기·클립 전환/패키지 실행 근거는 후속 ENGINE_WORK·USER_INSTALL 영수증에서 구분해요. 저장되지 않은 큰 문서의 직렬화, 역방향 시뮬레이션 재생, 실제 FPS·전체 heap 비용은 별도예요.
