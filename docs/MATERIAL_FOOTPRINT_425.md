# 비선형 좌표와 스무스 노멀의 밉 폭

절댓값·최솟값·최댓값·클램프·반올림·소수 부분·부호·단계·삼각함수·제곱근·길이·정규화의 변화량을 직접 계산해요. 큰 입력에 작은 값을 더한 결과를 다시 빼는 대신, 경계 통과와 두 입력의 변화량을 계산하므로 작은 밉 폭을 유지해요. 스칼라와 벡터의 길이·정규화 및 기존 epsilon 동작도 구분해요.

스무스 노멀에서 UV를 만드는 그래프는 삼각형의 기본 무게와 픽셀 폭의 무게를 따로 계산해요. 큰 월드 점에 폭을 합치는 계산을 피하고, 이전 프레임에서는 저장된 스킨·모프·인스턴스·노멀 변환으로 복원한 노멀을 사용해요. DirectX 생성 코드의 새 함수 이름도 이전 문맥으로 함께 바꿔요.

실제 GL·WebGPU·DirectX의 28개 연산·485조건에는 큰 좌표의 경계 통과, 정확한 곱 교차항, 0·epsilon 정규화와 스칼라 입력이 있어요. 작은 정규화 변화량에는 별도의 1e-12 기준도 적용해요. 좌표 1천만의 스무스 노멀 UV는 넓은 밉에서 중립 노멀, 좁은 밉에서 원래 방향을 반환해요. 이동·반전 이후 이전 포즈 17조건도 기존 오차 기준으로 대조해요.

AI가 읽는 `engineSchema().raySurfaceHistory.uvFootprint`에 안정 연산과 노멀 문맥을 함께 기록해요. 저장 그래프·IR·출력·샘플러·레지스터 예산을 유지하며 추가 GPU 타깃·텍스처·uniform·운영 readback은 없어요.

나눗셈·거리·회전·반사·눈 UV는 [후속 좌표 계산](COORDINATE_OPERATIONS_435.md)으로 이어져요. 거듭제곱·노이즈 등 아직 명시하지 않은 비선형 연산은 기존 fallback을 사용해요. 극단적인 중간값 범위, 작성 UV·시간 자체가 표현되지 않는 경우, 텍스처가 생성한 좌표의 변화량 0 근사도 남아 있어요. 전역 곡면·투명 경로 역대응과 참여 매질은 별도 원장에 유지해요. 초기 컴파일 지연이나 모든 렌더링 기능이 완료됐다는 뜻은 아니에요.
