# 127 — WebGPU 파이프라인·교차·프레임 준비

공유 교차 기록을 쓰는 WebGPU 경로를 실제 실행에서 대조한다. 기본 편집기 UI나 문서 ID를 바꾸지 않고 내부 포장과 셰이더 준비 비용을 줄인다. 세부 검사 결과는 124 묶음 원장에 함께 기록한다.

## 셰이더와 주소 계약

고정된 record 슬롯은 전용 함수로 읽는다. BVH·인스턴스 행렬은 prefix의 물리 주소를 직접 사용하고, 광원·transport·머테리얼·UV·텍스처·모션·포즈·광자 대상은 suffix 논리 주소에서 삼각형 개수만큼 뺀다. 선택 포인터의 읽기는 유효성 분기 안에 둔다. HDRI는 별도 atlas라서 이 변환을 적용하지 않는다. 공개 문서나 C++ 코드가 내부 atlas를 직접 변경하지 않게 기존 계약을 유지한다.

공유 기하의 무게중심 좌표는 TLAS 역변환으로 점을 로컬 공간에 옮겨 구한다. 세 정점을 각각 월드 공간으로 복원하는 경로를 제거한다. 역변환은 이미 저장한 forward 행렬 바로 앞의 세 float4를 재사용한다. 포인터·정수·용량 검사를 유지하고 별도 행렬이나 텍스처를 추가하지 않는다.

설치된 Three r180의 explicit-layout 함수 캐시는 builder 종류를 기준으로 공유하지만 uniform 번호는 각 builder에 속한다. 함수 본문은 실제 builder마다 새로 바인딩하고 같은 builder에서는 재사용한다. 실제 WGSL 생성 검사에서 앞에 mat3·vec3·float uniform을 추가한 재빌드와 불투명/투과·기본/추가 셰이딩을 대조한다. 함수명 중복, 잘못된 swizzle, 범용 슬롯 디코더 재유입을 거부한다.

불투명 재질은 굴절 bounce 분기를 생략한다. 양수 투과율과 실행 중 투과 값을 쓸 수 있는 그래프는 투과 경로를 유지한다. 0.5 미만의 투과율도 지원 대상이다. 이 선택은 기존 머테리얼에서 계산하며 사람이 별도 내부 최적화 flag를 편집할 필요가 없다.

추가 셰이딩은 상수 접기 이후 coat·anisotropy·sheen·iridescence의 실제 값과 원본 store 채널을 함께 판정한다. 시간·좌표·텍스처를 통한 동적 쓰기는 현재 값이 0이어도 유지한다. 재질별 결과를 장면에서 합치고 메인·광자·가이드와 view key에 동일하게 전달한다. SDK/파라미터의 0↔양수 변경은 기존 재질 캐시를 갱신한다. Specular/IOR와 방향 샘플의 UV 접선 회전값은 유지하며 사람이 별도 최적화 설정을 만들지 않는다.

## 탐색과 필터 수정

BVH의 lower·upper·meta를 노드 이동 전에 고정한다. TSL 지연 식으로 남겨 두면 BLAS로 이동한 뒤 meta를 새 노드에서 다시 읽어 하위 기하를 건너뛸 수 있다. path bounce의 교차점·법선·앞뒷면·색·물리 값도 방향이나 원점을 바꾸기 전에 고정한다.

렌즈 전용 보조 RTT는 CoC와 이차 깊이를 출력한다. 이전 조건은 시간 필터가 켜져야 이 출력을 만들었지만 렌즈 필터는 시간 필터 없이도 이를 사용한다. 시간 행렬·이력 재투영은 계속 시간 필터 조건에서만 생성한다.

## 준비와 자원

선택한 path 파이프라인은 비동기로 준비하고 준비 중에는 raster 화면을 표시한다. 원본 RTT, 가이드, 보조 RTT와 필터를 명시적인 소유 순서로 한 번씩 그린다. 모든 타겟과 이력 크기는 컴파일 전에 현재 drawing buffer 크기로 확정한다. 준비 중 1×1 타겟을 바인딩했다가 첫 프레임에 크기를 바꾸어 오래된 텍스처를 복사하는 오류를 방지한다.

광자 RTT도 소유 파이프라인 준비에 포함한다. 화면 RTT만 화면 크기로 조정하고 광자는 기존 128×16 float 타겟을 유지한다. 새 경로를 계산할 때만 광자 타겟을 갱신하고 점진 샘플 한도에 도달한 프레임에서는 재사용한다. 광자의 hit·색·물리 값도 방향/원점 변경 전에 고정한다.

Three r180의 createRenderPipelineAsync wrapper는 성공만 전달한다. HB는 동기 descriptor 생성 구간에서 native promise도 관측하고 device method와 renderer 상태를 즉시 복원한다. native 거부는 준비 오류로 전파한다. 취소된 준비는 다음 필터를 시작하지 않는다. 비동기 화면 캡처는 준비가 끝난 실제 프레임을 다시 캡처하며 일반 WebGL/DirectX 캡처는 기존 경로를 유지한다.

`renderer.pipelinePreparation`은 진행·완료 수·취소·오류를 읽기 전용으로 제공한다. 실제 문서 수정은 공용 schema와 revision 검사를 사용하는 기존 AI 명령으로 처리한다. 꺼진 경로에서 WebGPU 전용 모듈을 불필요하게 불러오지 않는다. 새 의존성·자동 GPU 읽기·곡면 전용 타겟·오브젝트 개수 제한을 추가하지 않는다.

## 증거 범위

비공개 검사에서 WGSL 검증 13.4ms와 이후 driver pipeline 지연을 구별했다. 로컬 보간 후 그 단계를 넘어가 타겟 크기와 탐색 값 고정 문제를 재현하고 수정했다. 이 관측은 전체 게임 FPS나 모든 GPU의 첫 컴파일 시간을 보장하지 않는다. 원본 샘플 수·해상도·검사 deadline·픽셀 기준을 유지하며 실제 세 실행 경로와 CPU/네이티브 결과를 묶는다. 비공개 hook·성능 추적·GPU 읽기 코드는 제품에 포함하지 않는다.
