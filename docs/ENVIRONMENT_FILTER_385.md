# HDRI 베이크 필터와 각도 정밀도

오프라인 HDRI 간접광 베이크가 실시간 경로 추적과 같은 구면 면적 가중 밉 계산을 사용해요. 기존 `sphericalEnvironmentMips`의 공개 경로와 패킹 결과는 유지하고 계산 소유만 워커에서도 읽을 수 있는 순수 모듈로 옮겼어요. Float·Half·NPOT 여섯 크기의 전체 패킹 바이트를 동결한 이전 구현과 대조했어요.

베이크에서는 조회한 단계만 캐시하고 원본 픽셀 배열을 재사용해요. 512×256 검사에서는 전체 밉 체인의 추가 픽셀 699,056바이트 대신 2,800바이트를 보관했어요. 이 값은 유지하는 TypedArray의 논리 저장량이며, 프로세스 최대 RAM이나 실행 FPS 측정값이 아니에요. 임시 중간 단계의 생성량도 `stats.environmentFilter.generatedTexels`로 구분해요. 반복 조회에는 새 단계가 만들어지지 않아요.

필터는 기존 방사휘도 적분기의 확산 광선 퍼짐 0.5를 사용하고, 위도에 따른 각도 footprint·삼선형 밉·극점 행 평균을 계산해요. 회전과 flipY를 보존해요. 이는 정확한 카메라 차분·이방성 footprint나 머테리얼 텍스처 전체의 LOD 베이크를 구현한 것은 아니에요. HDRI가 아닌 기존 입력은 종전 경로를 유지해요.

실제 GPU 대조에서 현재 장치의 동적 `acos(0)`이 약 0.0000675라디안 다른 값을 반환했어요. WebGL과 직접 번역한 D3D 샘플러가 같은 오차를 보였고, 기본 `atan2`도 모든 조건에서 충분히 정확하지 않았어요. 이 결과를 모든 드라이버의 성질로 일반화하지 않아요. 읽기 전용 진단값을 보존하고, HDRI 각도를 같은 다항식으로 계산하도록 연결했어요. 위도도 두 축의 길이를 사용하여 극점에서 `1-y²`의 소실을 피하도록 바꿨어요.

[NIST DLMF 4.24.3](https://dlmf.nist.gov/4.24#E3)의 arctan 거듭제곱급수 지정 수식과 대조했어요. 옥탄트·반각 범위 축소로 입력 절댓값을 `tan(π/8)` 이하로 만들고 15차까지 계산해요. 여기서 교대 급수의 다음 항 크기는 `|t|^17/17` 이하예요. 부동소수점 연산의 실제 오차는 별도로 검사해요. NIST의 나머지 본문·복소 분기·연결 참고 문헌 전체를 읽었다는 의미는 아니에요.

CPU 기준과 실제 WebGL·WebGPU·D3D 샘플러를 백엔드당 392개 조건으로 대조했어요. 극점·이음매·모든 사분면·범위 축소 경계·회전·분수 밉이 포함돼요. 기존 4e-5 조건을 유지했고 최종 최대 색 오차는 약 2.47e-6이에요. 실제 HDRI 파일을 사용한 인간 베이크·Undo/Redo·픽셀 미리보기·세 게임의 정적 이동 무효화와 복원도 검사해요. 파란 하늘 돔과 빨간 HDRI로 소스 우선순위를 구분해요.

WebGL에서 필터를 켰다 끌 때, 셰이더 준비용 임시 래스터 프레임을 실패로 기록해 정적 경로 추적의 64개 표본을 버리던 문제도 고쳤어요. 준비 대기에는 투영만 복원하고 마지막 성공한 카메라·시간의 유효성을 유지해요. 임시 오브젝트 모션은 게시하지 않아요. 실제 렌더 오류와 카메라·광원·장면·명시 버전 변경의 초기화는 유지해요. 실제 C++/BP 게임에서 필터 및 시간 필터 전환 전후 32×32 원본 픽셀의 완전 동일성과 광원 변경 반응을 검사해요.

작은 태양·달 원반은 확산 반사 이후의 방향 선택에 반영해요. 기존 코사인 반구와 두 원반의 `cos^n` 분포를 하나의 혼합 분포로 사용해요. 원반의 구면 적분 파워와 하늘 배경으로 배분량을 정하며 원반 확률은 최대 0.5예요. 기여는 `cosθ / (π × 혼합 PDF)`로 보정하고, 원반 방향이 표면 아래이면 기여가 0이에요. 코사인 성분이 모든 기여 방향을 계속 덮어요. 추가 광선·가림 우회·강제 밝기 보정은 없고, 이후 기하 반사의 기여에도 같은 가중치를 적용해요. 선택 HDRI·원반 없는 하늘·일반 기존 입력의 코사인 수열은 유지해요.

[PBRT 4판 2.2.3](https://pbr-book.org/4ed/Monte_Carlo_Integration/Improving_Efficiency)의 balance heuristic과 single-sample model 지정 본문·수식 2.16을 대조했어요. 나머지 장·연결 논문 전체 분석은 아니에요. 파워 기반 배분은 HB의 설계 선택이에요. 독립 해석값 `0.55 × 색 × 2π/(n+2)`와 실제 한 번 반사 베이크를 검사하고, 밝은 7,000차 원반의 32개 표본/64회 회전 조건에서 평균제곱오차가 약 24.358에서 0.002905로 줄었어요. 이 수치는 지정한 원반 조건이며 임의 장면의 품질·FPS 보장이 아니에요. 일반 하늘 조건에서는 코사인 확률이 0.9999보다 커 불필요한 원반 표본 배분을 억제해요.

이전 네이티브 렌즈 검사에는 원근 카메라라고 선언하면서 단위 투영 행렬을 넣던 입력 오류가 있었어요. 실제 원근 VP·역 VP·near/far를 제공하도록 검사 데이터만 고쳤어요. 같은 실행 파일과 기존 조건에서 시간 필터 2,436개 채널의 변화를 확인했으며 제품의 잘못된 카메라 거부는 유지해요. 원래 실패와 재개 구간의 결과는 각각 보존해요.

추가 GPU 이미지·버퍼·상수 필드·자동 readback·의존성은 없어요. 혼합 방향과 HDRI 필터는 기존 베이크 워커·공유 페이지·Undo·저장·세 패키지 실행기를 사용해요. `skyBake` 읽기 계약과 `stats.environmentSampling`에 선택 방식과 비용을 공개해요. 구름 기하 캡처·HDRI 중요도 표본·방향성 및 차트별 라이트맵 필터·고급 매질·전역 곡면 역대응과 누적 원장의 다른 항목은 이어서 구현해요.
