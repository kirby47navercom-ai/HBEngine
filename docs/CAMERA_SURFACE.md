# 카메라와 머테리얼 시선

직교 카메라에서는 화면의 어느 픽셀에서도 카메라를 향하는 방향이 같아요. 원근 카메라에서는 표면에서 카메라 위치를 향하는 방향을 사용해요. View Direction 노드와 기본 시선 입력을 사용하는 Fresnel이 이 규칙을 공유해요. 저장된 노드나 사용자 C++·블루프린트 호출은 바꾸지 않아도 돼요.

DirectX 래스터에는 카메라의 월드 방향을 전달해요. 카메라 위치는 안개·거리·다른 계산을 위해 그대로 유지해요. SDK의 SceneFrame.viewDirection은 xyz가 관찰자 방향, w가 직교1/원근0이에요. 기본값은 기존 원근 동작이고, 반사 캡처는 원근으로 전환한 뒤 기존 프레임을 복원해요. 기존 세 드로 상수 버퍼에 float4 하나씩만 더하며 새 텍스처·버퍼 객체·읽기 작업은 만들지 않아요.

주변광과 반구광의 입력은 조사도예요. DirectX의 확산 반사는 기본 색상 × 조사도 × (1−금속도) / π에 AO·불투과 비율을 곱해요. 완전한 금속에는 주변광의 확산 성분을 더하지 않아요. 이전 DirectX의 주변광으로 맞춘 장면은 밝기가 낮아질 수 있으며 광원 값이나 저장 에셋을 자동으로 바꾸지 않아요.

네이티브 노멀 그래프는 브라우저와 공용 보호 수식을 사용해요. 중립·0·음수Z·면적 없는 UV·큰 유한 중간값을 처리하고, D3D 화면Y의 미분을 GL 관례에 맞춰 변환해요. 값이 큰 경우 최대 성분으로 먼저 나눠 제곱 길이의 오버플로를 피하고, 유효하지 않은 프레임에서는 기하 노멀을 사용해요. 일반 에셋 리터럴의 기존±10000 제한은 유지해요.

AI는 schema.nativeSurfaceProgram의 cameraView·normalFrame·resources와 심볼 검색으로 같은 계약을 읽어요. 실제 근거와 설치는 ENGINE_WORK_1141.json 및 후속 설치 영수증에서 확인해요. WebGPU 내장 물리조명 모델 전체의 직교 시선, 프로브 방사광·추가 로브의 모든 조합과 전체 셰이딩 동등성은 이 노드/네이티브 검사만으로 주장하지 않아요.
