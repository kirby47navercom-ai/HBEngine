# FBX 정수 식별자 보존

편집기 미리보기와 게임이 함께 사용하는 `loadModel`은 FBX를 로더에 넘기기 전에 `prepareFbxIdentifiers`를 호출해요. JavaScript 안전 정수 범위를 넘는 ID가 있으면 서로 다른 인접한 64비트 ID도 구별하도록 임시 번호를 배정해요. 원본 파일과 sourceHash는 그대로이고, 메시의 `hbModelSource.objectId`에는 원래의 정확한 십진 문자열을 연결해요. 가져오기·재가져오기 sidecar의 `sourceObjectId`와 기존 오버라이드 연결 방식도 유지해요.

- ASCII와 32/64비트 노드 헤더의 바이너리 FBX를 처리해요. Objects의 ID, Connections 양 끝, BindPose의 PoseNode/Node 참조에 같은 대응표를 사용해요.
- 시간·정점·인덱스 배열과 일반 속성 값은 바꾸지 않아요. ASCII 주석·문자열 안의 숫자도 ID로 취급하지 않아요.
- 모두 안전 정수이면 원래 바이트를 그대로 반환해요. 변환이 필요할 때만 바이트 사본을 만들어요. 바이너리는 길이·오프셋을 유지하고 ID 위치만 수정해요.
- 중복 객체 ID, 범위를 넘는 ID, 잘못된 노드 길이를 거절해요. 가져오기 설정을 조용히 다른 메시로 적용하지 않아요.

이는 공용 Three 모델 로더의 ID 연결 보완이에요. 모든 DCC 파일·애니메이션 레이어 지원, 별도 네이티브 헤드리스 FBX 임포터의 완성을 뜻하지 않아요. C++ SDK·실행 파일은 변경하지 않아요.
