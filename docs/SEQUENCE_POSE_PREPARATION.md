# 시퀀스 골격 준비와 포즈 조회 비용

골격 트랙을 다른 모델·여러 대상으로 재생해도 같은 로드 문서의 키 검증과 정렬·뼈 이름 레이아웃은 한 번 준비해요. `SkeletalPoseProgram`이 자료 준비를 맡고, `SkeletalPoseTrack`이 대상별 Quaternion·뼈 바인딩과 샘플링을 맡아요. 배열을 직접 넘기는 기존 생성자는 매번 새로 검증하므로 외부 호출의 경계 검증을 생략하지 않아요.

실행 서비스의 `SequencePosePlayback`은 문서 키 배열을 weak key로 프로그램을 재사용하고, 모델과 프로그램을 weak key로 바인딩을 재사용해요. 다른 트랙이나 모델로 돌아올 때는 실제 대상의 뼈 이름과 계층을 다시 확인해요. 새 모델·빈 골격·뒤로 탐색·중복 이름 오류와 원래 포즈 복원을 유지해요. 이때 모든 키의 값 검증과 이름 문자열 준비를 다시 수행하지 않아요. 활성화할 때 대상의 이름 검증까지 없애지는 않았어요.

같은 대상의 골격 트랙이 여러 개일 때 처음 복원 기준 포즈를 한 번만 캡처해요. 캡처는 컴포넌트·모델 변경을 적용하기 전에 수행해요. 이를 변경 뒤로 미뤄 원래 골격 포즈를 잃지 않아요. 겹친 시퀀스·기본/복원/유지 정책과 BP·C++ LevelSequence 실행은 기존 공용 채널을 사용해요.

`runtime.sequencePose`와 `hbPlayerDebug.sequencePose`의 `offset/limit`는 반환할 뼈의 벡터만 복사해요. 전체 뼈 수와 이름의 유효성은 계속 확인하며, 페이지 밖의 중복·빈 이름도 오류로 처리해요. 반환 자료는 독립 복사본이에요. 기존 응답에 `sampling` 진단이 추가됐어요.

진단에는 `programsCompiled`, `keysValidated`, `poseRowsValidated`, `layoutsPrepared`, `bindingsCreated`, `bindingsRevalidated`, `samples`, `baselineCaptures/Rows`, `restorations`, `queries`, `queryRowsCopied`, `activeTargets`가 있어요. 명시적 조회에서만 응답하며, 자동 GPU 읽기·추가 작업자·타이머·디스크 캐시는 없어요. 모델/문서가 사라지거나 런타임이 종료되면 참조가 해제될 수 있어요.

독립 대조는 Git `1bbdc4f`의 원래 `SkeletalPoseTrack`을 실제로 실행했어요. 128뼈×120키의 포즈가 경계·보간·뒤로 탐색에서 같고, 빈/변경 레이아웃의 단계 전환도 같아요. 16대상×20회×2트랙에서 원래 생성자 640회·검증 포즈 행9,830,400개에 비해 현재 준비는 2회·30,720행이고 바인딩 객체는 32개예요. 재활성화 이름 검증608회는 유지해요. 128뼈 중2뼈 조회에서는 벡터 배열6개를 복사하고, 이전 전체 캡처는384개를 복사해요. 이는 특정 경로의 작업 횟수이며 전체 메모리·FPS나 모바일 실기기 측정은 아니에요.

복원 시 전체 골격을 검증·적용하는 비용, 뼈별 독립 소유권·가중 혼합, Animation Graph·몽타주 내부 상태 복원은 별도 잔여 범위예요. 공개 `captureSkeletalPose`와 Take 녹화의 독립 스냅샷 계약은 바꾸지 않았어요.
