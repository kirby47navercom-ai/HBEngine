# 122 — CPU 광선 데이터 포장 경량화

기하 atlas의 노드·삼각형·광원·머테리얼·발광 목록 크기를 먼저 계산하고 Float32Array 하나에 직접 기록한다. 기존의 큰 가변 JavaScript 배열과 이를 다시 복제하던 Float32Array 변환을 제거한다. 광선 머테리얼 UV/법선 블록도 필요한 크기를 먼저 계산하여 typed array에 직접 기록한다. 최종 atlas·GPU 형식·셰이더 주소·변경 행 업로드·기존 소유권은 유지한다.

순금속·동적 거칠기·코팅·박막 머테리얼의 32인스턴스/5,376삼각형 검사에서 transport/후보 목록/모션의8가지 조합 모두 변경 전 코드와 모든 atlas 바이트·주소가 같았다. 정적 포장은 같은 버퍼와 변경 행0을 유지하고, 이동/이전 정점은 변경 행에 포함한다. 유효하지 않은 UV는 이전 atlas를 수정하기 전에 거부한다. 빈 장면도 기존 배치를 유지한다.

변경 전 두 소스는 개발용 `native/build`에만 잠시 보관한다. `check-rendering-122 --baseline native/build --record`는 같은 준비된 삼각형으로 교대로 실행한12쌍의 중앙값을 기록한다. 수치는 수집·GPU 전송·렌더링·게임 FPS를 제외한 포장 비용이다. 이번 최초 대조는12.58→7.78ms였으며 최종 묶음의 실제 수치는 [121 통합 기록](research/RENDERING_121.json)의 `packing.baseline`을 따른다. 가변 배열의 엔진별 내부 용량을 추정해 메모리 절감 바이트로 보고하지 않는다.

새 의존성·설정·텍스처·디스크 캐시·GPU 읽기·오브젝트 개수 제한을 추가하지 않는다. 같은 에셋/속성/SDK/BP/AI 문서 계약을 사용한다. 전체 월드 교차 정점 공유와 기하 수집 비용은 이 변경의 완료 범위가 아니다.
