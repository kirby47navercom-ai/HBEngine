# 하늘 간접광 베이크와 렌더러 일치

하늘 액터의 선형 방사휘도를 정적 간접광 베이크에 사용해요. HDRI가 선택되어 있으면 기존 HDRI 입력을 우선하고, 그 외에는 현재 하늘 돔의 천정·수평선·해질녘 색과 태양·달 원반, SkyLight 색·간접광 세기를 사용해요. 노출·톤 매핑·안개를 광원 에너지에 섞지 않아요. 워커에는 숫자와 배열만 전달하고 결과는 기존 Half/gzip 라이트맵과 같은 Undo·저장·패키징 경로로 들어가요.

편집기의 기존 **간접광 베이크**를 사용해요. AI는 `lighting.bake`를 그대로 호출하고 `engineSchema().skyBake`에서 입력 우선순위와 자원·제한을 읽을 수 있어요. 선택 후 바뀐 소스와 오래된 revision은 기존 보호를 유지해요. 정적 베이크 뒤 광원이 바뀌면 다시 베이크해야 해요.

DirectX의 일반 하늘과 하늘 캡처에도 별도의 달 원반을 연결했어요. 기존 패킷에 달 필드가 없으면 검은색으로 처리해요. C++ 상수 버퍼 끝에 두 float4(32바이트)를 추가하고, 이전 필드 순서는 유지해요. WebGL·WebGPU의 기존 돔 입력은 동결한 이전 구현과 대조해요.

[Unity 6.0 환경광](https://docs.unity3d.com/6000.0/Documentation/Manual/lighting-ambient-light.html)의 지정 본문은 화면의 하늘 재질을 환경 조명의 원본으로 사용하는 제작 흐름을 설명해요. [Unreal Sky Lights](https://dev.epicgames.com/documentation/en-us/unreal-engine/sky-lights-in-unreal-engine)의 지정 본문에서는 포착한 하늘과 조명·반사의 관계, 정적 베이크와 재포착·간접광 세기·방향성·캡처 해상도를 구분해요. HB에서도 화면용 하늘과 베이크용 단순 색 혼합의 차이를 없애되, 각 실행 경로의 검증은 별도로 남겨요. 전체 문서·API를 분석하거나 두 엔진의 모든 하늘 기능을 구현했다는 의미는 아니에요.

이 경로는 해석적인 하늘 돔을 사용해요. 실제 구름 기하를 포함하는 베이크 캡처, 작은 원반의 중요도 표본, 방향성 라이트맵·Bent Normal·DFAO·하드웨어 RT는 추가 구현 대상이에요. 실시간 캡처의 구름과 베이크의 돔을 같은 기능으로 계산하지 않아요.
