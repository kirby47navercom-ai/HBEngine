# 설치 간 C++ 재사용과 기본 래스터 준비

C++ 실행 파일은 의미 지문으로 찾고 실제 보관 경로는 별도로 두어요. 실행 참조를 먼저 게시한 뒤 코드 색인을 확인하며 경쟁 빌드는 이미 완성된 결과를 사용해요. 설치가 바뀌어도 컴파일 당시 사용자 소스·SDK 전체 입력·작업 폴더를 보존하므로 옛 Versions 폴더에 디버깅 경로를 의존하지 않아요. SDK 전체 내용 확인과 실제 사용 헤더·전처리 조건은 별개로 유지해요.

툴체인 지문은 실제 GCC가 선택한 컴파일·링크 도구, 시작 오브젝트, 라이브러리와 컴파일러 런타임 파일을 확인해요. 표준 헤더 변경은 의존성 계획을 다시 계산하게 해요. 확인할 수 없는 커스텀 환경은 새 버전별 빌드를 사용해요. 디버그 정보는 전체 -g를 유지하고 Windows의 번들 LLDB19 호환을 위해 DWARF4를 선택해요. 배치 소스·인자·지역 변수 정보 검증을 라이브 브레이크포인트/스텝 실행 검증으로 표현하지 않아요.

기본 래스터의 VS·PS·ShadowPS는 SceneRenderer 다섯 번째 생성자 인자로 선택할 수 있어요. 기존 SDK 호출은 동기로 유지하고, 데스크톱의 asyncShaderPreparation은 이 생성자와 기존 단일 8MiB 준비 큐를 연결해요. 작업자는 바이트코드만 만들고 장치 셰이더·정점 레이아웃은 렌더 소유 스레드에서 채택해요. 장치 거부는 한 번 새 컴파일로 재시도해요.

준비 중에는 clear와 Present를 유지하고 기본 그리기, 의존 그림자/반사 캡처, 화면 시간 이력을 승인하지 않아요. 보류된 2D 마스크의 캐시도 취소해서 첫 완료 프레임에서 다시 그려요. shaderPreparation.raster.stages의 raster-vertex/raster-surface/raster-shadow를 사람의 프로파일러와 AI의 같은 계약으로 읽어요. raster.basePending은 기본 셰이더 때문에 보류된 경우를 구분해요.

실제 DirectX 검사596은 컴파일러를 막은 상태의 초기화 반환·clear/그리기0·준비후 동기 픽셀 동일·취소/실패/재시도·상태 조회와 유휴 종료를 확인했어요. 기존553/556과 2D 마스크 재전송 검사를 함께 유지해요. 생성자31ms는 해당 격리 검사의 단일 관찰이며 전체 cold 시작 시간·GL 링크·게임 FPS 측정이 아니에요. ParticleRenderer 초기 셰이더와 프로브 필터, 미적중 Device.compile 등의 준비 비용은 이 변경에 포함하지 않아요.

기계 판독 근거는 ENGINE_WORK_595.json과 ENGINE_WORK_600.json, 전체 잔여 정본은 ENGINE_STATUS.json이에요. 전체 Unreal/Unity 본문·API 분석 완료로 계산하지 않아요.
