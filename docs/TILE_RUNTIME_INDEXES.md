# 런타임 타일 변경과 색인 공유

타일 데이터는 기존 JSON 배열과 순서를 유지해요. 단일/묶음 쓰기는 마지막 좌표 값을 선택하고 현재 sourceIndex와 같은 요청을 먼저 제거해요. 같은 값만 다시 쓰면 배열 복사·dirty·청크 재생성을 하지 않아요.

실제 실행 변경은 내부 256슬롯 청크와 변경 청크의 디렉터리 사본을 만들어요. 셀 조회는 최대 16단계의 변경 색인을 사용한 뒤 다시 평탄화해요. 삭제는 빈 슬롯을 남겨 뒤의 모든 셀을 이동하지 않고, 빈 슬롯이 절반과 한 청크를 초과하면 압축해요. 이 단계 수는 내부 색인의 조회 비용을 제한하는 값이며 맵·오브젝트 개수 제한이 아니에요. 이전 타일 배열이나 월드 스냅샷을 색인에 보관하지 않아요.

사각형 청크·등각 대각 띠의 그룹도 변경된 그룹만 상속해요. 렌더·충돌 갱신은 해당 그룹의 후보 셀을 사용하고, 자동 타일 갱신은 영향을 받은 좌표의 내부 레코드만 바꿔요. 전체 재생성, 개별 타일 정렬, 레이어 정렬, 경계 이웃과 확장 규칙의 기존 결과를 유지해요. 삭제는 배열 순서를 보존하고 원본/다른 레이어/대기 중인 렌더 스냅샷을 수정하지 않아요.

`setRuntimeTiles`, `tile-runtime-storage.js`, `immutableNativeLazyRecord`, `tileCellsForChunks`가 소유자예요. 기존 C++/BP Tilemap 명령과 `runtime.tilemap.inspect`가 같은 런타임을 사용해요. `schema --section tileRuntimeIndex`에 비용 범위가 있어요.

`tiles`를 읽는 렌더/충돌·검증·저장·네이티브 전송 소비자에게는 버전마다 한 번 만든 기존의 보통 불변 JSON 배열을 돌려줘요. 중간 개별 쓰기·조회·동결은 이 배열을 펼치지 않아요. 청크 디렉터리 복사·16단계 색인 평탄화·삭제 압축·실제 전체 공개/검증/네이티브 JSON 직렬화 비용은 남아 있어요. 디스크 청크 저장 형식을 추가하거나 이 비용을 모두 없앤 구현은 아니에요. 새 파일 캐시·작업자·타이머는 없어요.

## 연속 C++ 점 쓰기의 공용 묶음

기존 native 명령 패킷에서 로드가 끝난 같은 소유자·대상·레이어의 연속 tileSet을 공용 tileSetMany 처리로 묶어요. 서로 다른 셀의 0 이상 인덱스만 합치며, 읽기/강제 반영·다른 명령·소유자/대상/레이어 전환·같은 셀 재수정·지우기는 순서 경계예요. 삭제 후 재삽입의 저장 순서와 중간 수정 후 원래 값으로 돌아간 변경 상태도 보존해요.

좌표·인덱스가 잘못된 지점 전의 정상 구간까지만 반영하고 그 지점은 원래 명령의 오류로 처리해요. 로드 전/퇴역·풀 반환·비활성·다른 에셋으로 바뀐 대상은 기존 로드·수명 경로를 사용해요. 원래의 불변 JSON 배열·네이티브 교환 형식과 C++/블루프린트 함수는 바꾸지 않아요. 기존 요청당 65536셀 예산은 큰 패킷을 여러 구간으로 나누며 전체 맵/오브젝트 수를 제한하거나 셀을 버리지 않아요.

소유한 4096셀 예제의 서로 다른 64셀 쓰기에서 불변 런타임 맵 공개가 직렬64회→패킷1회였어요. 이 값은 FPS·OS RAM·GPU 시간을 측정한 결과가 아니에요. 이전 기록은 당시 전체 점유 배열 복사가 필요했던 구현의 맵 공개 횟수예요. 현재는 BP 개별 쓰기와 삭제도 내부 청크를 사용해요. 반복되는 전체 공개·디스크 청크·전체 렌더/충돌 비용은 남아 있어요.

일반 저작 함수에 가변 배열을 직접 주는 기존 호출은 변경 없는 타일 참조와 보통 배열 반환을 유지해요. 실행기가 검증·동결한 레이어에만 내부 청크를 적용해요. 표시만 바꾸는 버전은 같은 타일 저장과 이미 펼친 배열을 공유하고, 전체 지우기는 이전 점유 배열을 펼치지 않아요. 편집 도구의 가변 전체 배열 복사·정렬은 별도 비용이에요.
