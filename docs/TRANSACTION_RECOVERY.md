# 저장 묶음 충돌 복구

일반 파일·모델 사이드카 이름 변경은 `rename:UUID`로 같은 창과 API에 연결돼요. 바이너리 본문을 복제하지 않는 위치/ID/리다이렉트 기록과 명시적 복구 선택, 완료 기록 압축은 [파일 이름 변경 복구](ASSET_RENAME_RECOVERY.md)에 있어요. 이름 변경이 대기 중이면 인덱스를 보존하기 위해 이 복구를 먼저 처리해요.

미완료 v1 텍스트/v2 바이너리 공동 저장 기록에 외부 변경이 있어도 프로젝트를 열고 읽을 수 있어요. 충돌이 남은 동안 일반 에셋 쓰기는 보류돼요. 콘텐츠 창의 명령 검색에서 **저장 묶음 복구**를 열거나 최초 충돌 알림의 복구 창을 사용해요.

파일마다 저장 전, 저장 시도, 현재 디스크의 존재 여부·크기·SHA-256을 비교하고 선택해요. 외부 충돌에는 기본 선택을 주지 않아요. 충돌이 없는 행은 저장 전으로 되돌리는 기존 복구 원칙을 사용해요. 현재 디스크 보존은 외부 변경이나 삭제를 유지해요. 이미지는 해석하거나 다시 인코딩하지 않아요. 이전 텍스트 경로에 UTF-8이 아닌 바이트가 생겼어도 복원용 기준을 원문 그대로 보존해요.

AI는 `project.recovery.inspect`로 대기 ID를 읽고, `transaction`, `offset`, `limit`으로 해당 묶음을 조회해요. 기본 32행, 최대 128행이며 바이너리 본문은 응답에 담지 않아요. `project.recovery.resolve`는 `transaction`, `expectedRevision`, `choices:{"Assets/...":"before|after|disk"}`, `dryRun`을 받아요. 기준은 해당 기록과 페이지 밖 파일까지 포함한 모든 현재 파일 해시예요. 미리보기는 파일을 쓰지 않으며 미선택 충돌을 알려줘요. 일반 문서 초안 Undo와 별개의 디스크 공동 복구예요.

선택 적용도 현재 디스크 원문을 기준으로 자식 write-ahead 기록을 만들어요. 중간 실패/재시작은 이 기준으로 되돌리고 원래 충돌을 남겨요. 자식이 이미 확정된 뒤 부모 상태를 기록하기 전에 종료되었다면 재시작이 결정을 마무리해요. 자식 복구 자체에 새 외부 변경이 있으면 부모는 대기하고 자식의 명시적 결정을 먼저 받아요. 자식에서 새로 선택한 디스크 보존이 부모의 이전 선택에 다시 덮이지 않아요. 기록·에셋 ID를 함께 보존하고, 파일이 바뀌면 전체 기준 확인이 적용을 거절해요.

저장 기록은 각각 32 MiB까지, 변경할 현재 파일의 롤백 기준은 파일당 16 MiB까지예요. 디스크 보존에는 추가 바이너리 복사본이 필요 없어요. 완료 기록의 원문을 유휴 메모리에 누적하지 않으며, 복구에 필요한 프로젝트 기록을 엔진 설치본/프로필 백업으로 복제하지 않아요.

검사: `node tools/check-transaction-recovery-2576.mjs`. 소유 임시 프로젝트의 실제 바이트·저장 기록·재시작·CAS·사람 위젯·서버 핸들러를 확인해요. 실제 GUI/하드웨어 전원 차단/다중 프로세스 파일 잠금의 검증을 뜻하지 않아요. 단일 WriteIntent 외부 내용/ID 충돌도 같은 창에서 `write:UUID`로 조회해요. 이 기록에는 이전 본문이 없어서 현재 디스크 보존만 명시적으로 선택할 수 있어요. 파일 본문을 다시 쓰지 않고 현재 에셋 ID/외부 삭제를 유지해요. 동일 경로의 서로 다른 저장 ID도 자동으로 덮지 않아요. 공동 저장 충돌과 함께 남으면 두 결정이 모두 끝나야 일반 쓰기가 열려요. 기존 임시 데이터가 예상 해시와 다르면 남겨서 알려줘요. 임의 바이너리 병합은 별도 잔여예요.
