# 191 — 2D·3D ORCA 군중 회피와 공용 제작·실행

기존 경로 탐색/단순 밀어내기와 별개로, ORCA 원문의 속도 반평면 제약과 선형 계획을 자체 구현했다. 현재 관측 속도·원반 반지름·예측 시간·이웃 거리와 우선순위를 사용하고 모든 에이전트의 같은 프레임 월드 스냅샷을 먼저 풀어 적용 순서 의존을 줄인다. XY/XZ 평면·층 높이·정지/비협조 대상·겹친 위치·실행 중 설정/중지/풀 반환을 처리한다.

NavigationAgent의 로컬 회피 속성은 기존 Inspector·문서 Undo·타입 스키마와 AI 문서 편집을 공유한다. 기본 simple을 보존하고 orca/none을 선택한다. maxNeighbors16은 에이전트별 품질 예산이며0은 지정 범위의 전체 이웃이다. 전역 에이전트 제한은 추가하지 않았다. 재사용 KD 인덱스/작업 버퍼는 축소·월드 종료 때 정리하며 새 의존성·상시 타이머·GPU 읽기가 없다.

C++ Navigation::ConfigureAvoidance/GetSteeringVelocity/GetPreferredVelocity와 동일3개 블루프린트 노드는 같은 서비스를 사용한다. 기존 MoveTo/Stop/GetStatus/GetPath를 유지하고 경로/속도 반환 배열은 외부 수정으로 상태가 손상되지 않는다. 실제 게임 진단의 navigation과 actor.gameplayDebug.navigation에서 속도·희망 속도·이웃·실행 불가 여부/인덱스 바이트를 읽는다. ORCA를 쓰는 이동 컴포넌트는 두 물리 백엔드에서 풀린 평면 속도를 즉시 목표로 삼고 기존 simple 가속은 유지한다.

CPU8개 묶음은 정면/교차·24방향·정지 대상·우선순위·겹침·KD 최근접/높이·입력/순서/수명·부모 월드 이동·두 이동 백엔드·BP·실제 C++를 검사했다. 실제 편집기 속성/0이웃/Undo/저장·노드 표시는 확인했고, DirectX XY와 WebGPU XZ 패키징 게임에서 C++와 BP가 설정한4명이 모두 도착했다. 최소 간격은 각각0.60001599/0.60001606으로 지름0.6을 유지했으며 오류0/종료0이다. 캡처를 직접 검토했다. [검사/출처/한계](research/ENGINE_WORK_191.json).

1,000개 Node solve 표본에서 정적 작업 버퍼는 약99KB였다. 워밍업 뒤 성긴 장면 약6–8ms, 밀집16이웃 약14–15ms이며 전체 게임 프레임/PC120·모바일60을 보장하지 않는다. NavMesh 경계 투영·carving·Mass/Detour·비평면 이동·가속/혼합 물리 부모 제약은 별도 잔여다. 원문은 지정 본문/수식 구역을 읽은 것이며 외부 전체 분석으로 계산하지 않는다.
