# 렌더 자원의 소유권과 반복 장면 해제

2026-10-06: 기본 도형의 지오메트리와 고유 머테리얼은 오브젝트가 소유한다. 같은 도형 제작기가 공유하는 7개 머테리얼은 제작기가 소유하며, 외부에서 전달한 표면 머테리얼은 호출자가 소유한다. 광원과 모델에 포함된 광원의 그림자 맵도 해당 오브젝트가 소유한다.

오브젝트 재구성·삭제는 기존 `sceneRendering.dispose`의 자원 집합을 사용한다. 부모를 재구성해도 별도 자식 Actor의 자원은 해제하지 않는다. 게임의 장면 종료는 모든 오브젝트를 해제한 뒤 제작기의 공유 머테리얼을 해제한다. 에디터 제작기는 페이지 수명 동안 공유 머테리얼을 유지한다. 중복 지오메트리/광원 순회 해제는 제거했다.

## 확인한 결과

- `node tools/check-render-resources.mjs`: 고유·공유·외부 머테리얼, 중복 해제, 부모/자식 Actor, 광원 그림자 맵을 확인한다.
- 실제 에디터 `authoring-window-Z88w0y`: 118개 검사, 오류 0. 완전한 도형 장면 20회 생성/해제 후 GPU 프로그램 5개·참조 9개·지오메트리 4개·텍스처 1개가 시작 값과 동일하다.
- 같은 에디터에서 수정 전 `4e3ea51`의 원문 제작기를 대조했다. 20회 후 프로그램은 9개, 머테리얼 참조는 369개다. 지오메트리와 텍스처 수만 확인하면 이 참조 누락을 놓친다.
- 배포 Player `authoring-window-z4KIxU`: 117개 검사, 오류 0. 같은 20회 반복 후 자원 수가 동일하다. 기존 2D 조명/그림자·노멀·마스크와 실제 C++/BP 검증도 포함한다.
- 실제 Auric 기능 통합 `features-window-Py2rT4`: 1,000발·적 30개, 600프레임, 59.509fps/작업 p95 12ms. 93개 Spawn, 20개 소리, HUD 3해상도, 6장면, 입력 유지, F12·60초 초기화도 통과했다.

이 결과는 전체 프로세스 메모리 증가량이나 8시간 안정성 통과를 뜻하지 않는다. 프로그램 참조 누락은 재현됐으며, 다른 메모리 원인을 분리하는 자연 GC 진단을 계속한다. 진행 중인 두 8시간 검사는 이전의 고정된 패키지이며 이 수정의 검사가 아니다.

현재 게임 검사 사본 `checker-pMImZr`의 `check_demo.mjs` SHA는 `c2609e75ae8334bdb5751e458eb925e11099a447b606639744396bde9312fd65`다. 웨이브 2의 해골 6마리 처치 검사가 실패했다. 동일 게임/검사기 사본과 동일 생성 API로 수정 전 `4e3ea51`을 실행해 같은 실패를 확인했다. 새 렌더 해제 변경의 회귀로 처리하지 않으며, 현재 게임 검사 전체 통과로 기록하지 않는다. 최초 기준 엔진 추출에서 생성 API 누락으로 실패한 시도도 별도 보존했다. 원본 게임/검사기는 수정하지 않았다.
