# 경로 추적 표면 확장과 설치 용량 관리

경로 추적에 코팅과 별도 코팅 노멀, 반사 색·강도, 천 표면의 Sheen, UV 방향에 따른 비등방성 반사, 박막 간섭을 연결했어요. 기존 머테리얼의 속성과 그래프, `hb::Materials::SetScalar`·`SetVector`를 그대로 사용하며 실제 C++ 호출로 픽셀 변화도 확인해요. 분석해 둔 다른 렌더링 작업과 엔진 작업은 기존 원장에서 이어가요.

직접 광원, 발광 면, HDRI 샘플링과 경로의 다음 반사 방향에 같은 BRDF와 혼합 PDF를 사용해요. GGX와 Charlie 분포를 독립 수치 적분으로 확인하고, 네이티브 렌더러에서는 128개 샘플의 균일 환경 조명으로 에너지와 비등방성 회전 결과를 비교해요. 디노이저는 날카로운 코팅·비등방성 반사를 흐리지 않도록 원본 픽셀을 유지해요.

일반 표면은 기존 5개 필드를 유지하고 확장 표면만 10개를 사용해요. 추가 헤더 비용은 머테리얼당 160바이트예요. 새 텍스처·라이브러리를 설치하지 않으며 표면 기능이 없는 셰이더에는 확장 계산을 넣지 않아요. 일반 glTF/Three 물리 머테리얼의 추가 텍스처 9종도 채널·색 공간·노멀 스케일·박막 두께 범위를 반영해요. 필드 상위 비트가 잘려 서로 다른 셰이더가 캐시에 겹치지 않도록 네이티브 캐시 키도 보완해요.

`HBEngine/Versions`에는 새 설치본을 검증하고 전환한 뒤 이전 설치 사본을 정리해요. 실행 중인 버전과 사용자 프로젝트는 보호하고, 사용자가 바꾼 파일만 별도로 보존해요. 복사 실패 시 이번 설치의 임시 폴더도 지워요. 전체 설치본을 백업으로 계속 쌓지 않아요. [설치 정리 정책](INSTALL_RETENTION_114.md)과 검사·설치 증거는 별도 기록해요.

검사는 고유 프로젝트·프로필로 격리하고, 렌더링 변경을 묶어서 기존 장면과 함께 검증해요. 검사 뒤 재생성 가능한 패키지·브라우저 프로필·오래된 컴파일 캐시를 정리하고 원본 게임·캡처·보고서는 보존해요. 사용자 창을 열거나 재시작하지 않아요.

이번 수식은 [PBRT의 미세 표면 분포·정규화·마스킹 설명](https://www.pbr-book.org/4ed/Reflection_Models/Roughness_Using_Microfacet_Theory)과 [Filament의 코팅·비등방성·Charlie 표면 설명](https://google.github.io/filament/main/filament.html)의 해당 구역을 참고했어요. 전체 책·링크·강의의 분석 완료를 뜻하지 않아요. 읽은 범위와 원문 SHA256은 증거 기록에 남겨요.

박막은 세 파장 근사이며 코팅·Sheen의 감쇠도 보수적인 근사예요. GGX는 전체 NDF 샘플링을 사용해요. 거친 굴절 BTDF, 전체 스펙트럼·편광·다중 박막, BLAS/TLAS, 경로 추적 코스틱, 모든 이차 반사의 디노이징까지 구현했다는 의미는 아니에요. 이 검사로 전체 게임 FPS·모바일 실기기 성능을 주장하지 않아요.
