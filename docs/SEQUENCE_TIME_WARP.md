# 하위 시퀀스 시간 리매핑

Shot 또는 Sub-Sequence 구간을 선택하고 속성의 **시간 리매핑 → 사용**을 켜요. 구간 시간과 원본 시간을 숫자로 편집하고 시간 키를 추가하거나 삭제할 수 있어요. 선형 구간에서 같은 원본 시간을 연속 키에 지정하면 그 사이에서 하위 시퀀스가 멈춰요. 작은 곡선에서 속도 변화와 정지·역방향 구간을 볼 수 있어요. **방향 뒤집기**는 원본 경과 값의 부호를 한 번에 바꾸며 소스 시작을 기준으로 진행 방향을 반전해요. 한 번의 Undo로 되돌릴 수 있어요. 끄면 기존 소스 시작·시간 배율만 사용해요.

구간 시간은 증가해야 하며 원본 시간은 증가·감소하거나 유지할 수 있어요. 감소하는 구간은 역방향으로 재생해요. 첫 키는 `(0,0)`이고 키는 2~256개예요. 구간 시간은 0~86400초, 원본 경과 시간은 -86400~86400초이고 구간 기울기와 지원 시간·배율 범위의 양 끝 연장이 유한한 수여야 해요. 값이 너무 가파라 무한대가 되는 입력은 거절해요. 양 끝에서는 마지막 구간의 기울기로 연장해요. 실제 하위 시간은 `sourceStart + remap(parentTime-start) * rate`이며 기존 반복 또는 끝 유지가 뒤에 적용돼요. 키가 없는 기존 파일은 그대로 동작해요. 같은 시간에 머무는 동안 이벤트를 다시 발동하지 않고, 실제 통과한 곡선·Shot·반복 경계로 나눠 이벤트를 전달해요. 역방향 방문의 콜백은 역순 작성 순서로 전달하며 방향을 바꾸는 같은 경계는 재발동하지 않아요. 반복 시간은 음수에서도 항상 0 이상인 하위 시점으로 환산해요. Pause·Seek의 이벤트 억제 규칙도 유지해요.

왼쪽 가장자리를 잘라내면 소스 시작과 시간 키를 함께 이동해 남은 부분의 원본 시점을 보존해요. 다시 왼쪽으로 확장할 수도 있어요. 반복 구간은 음수 또는 여러 주기를 지난 소스 시작을 보존해요. 반복을 끈 구간에서 원본 시작 이전으로 확장하는 리매핑은 거절해요. 오류는 문서·Undo를 바꾸지 않아요. 일반 구간 이동은 곡선을 그대로 옮겨요. 중첩 구간도 같은 매핑을 재귀적으로 적용해요.

AI는 `sequence.section.edit`의 `section.timeWarp:[{time,value},...]`를 사용해요. `timeWarp:null`은 곡선 제거예요. `operation:trimStart, section:{start}`는 남는 소스 시점을 보존하는 앞부분 자르기예요. 일반 update의 start 변경은 구간 이동이에요. 기존 expectedRevision·dryRun·한 번의 Undo·저장 계약을 공유하고 `schema.sequenceTimeWarp`에서 형식과 한계를 조회해요. Blueprint 및 C++ LevelSequence Play/Seek/Stop도 같은 저장된 구간을 평가해요.

시점 조회는 정렬된 불변 키를 이진 탐색하며 매 프레임 키를 복사하거나 정렬하지 않아요. 이벤트를 평가할 때 실제로 지나간 경계만 나눠요. 새 워커·타이머·GPU 자원·영구 캐시는 없어요. 사용자 정의 점프 이벤트 정책과 경쟁 레이어의 정규화 혼합, 오디오의 피치 유지 시간 늘이기·표본 단위 곡선 경계 예약, 외부 장치 동기화는 별도 구현 항목이에요. 소스 검증과 실제 창·설치 대기 상태는 ENGINE_WORK_1966에서 구분해요.

`runtime.sequenceTree`의 페이지 결과는 localRate·mappedRate·direction으로 현재 위치의 명목 재생 방향을 보여줘요. mappedRate는 작성된 루트 시퀀스 시간에 대한 비율이고 실제 일시정지 여부는 paused로 따로 조회해요. 중첩 구간과 끝 유지를 반영하며 수치 범위를 넘는 비율은 null과 rateOverflow로 명시해요. 요청한 행의 경로·기준점만 복사하고 시간 키 전체를 응답에 싣지 않아요.

시퀀스 오디오는 루트 배율, 게임 또는 비배율 시간의 비율, 중첩 구간의 기울기, 오디오 클립 배속을 함께 적용해요. 뒤로 가는 구간은 PCM 파형을 실제로 거꾸로 재생하고 정지 구간은 소리를 멈춰요. 오디오 클립 자체의 **역방향**도 켤 수 있으며 원본 시작에서 거꾸로 움직여요. 애니메이션·몽타주 클립에는 이 오디오 전용 필드를 허용하지 않아요.

소리를 읽는 동안 바뀐 탐색·속도·정지도 재생 시작 전에 적용해요. PCM 끝에 도달해도 시퀀스의 음성 연결은 클립 종료까지 유지하므로, 같은 클립 안에서 방향을 바꿔 다시 재생할 수 있어요. 일반 효과음의 자동 해제는 유지해요. 뒤집은 PCM은 실제 역재생이 필요할 때만 만들고 활성 음성끼리 약한 참조로 공유해요. 유휴 역재생 캐시는 추가하지 않지만, 활성 역재생 클립에는 원본 한 벌만큼의 PCM 메모리가 추가로 필요할 수 있어요. 일반 디코딩 캐시의 32MiB 한도는 유지해요.

오디오를 포함해 Take를 녹화하면 관리 중인 시퀀스 음성의 방향·배속·탐색 변경과 정지를 클립 구간에 반영해요. 역방향 반복은 양수 배속과 reverse:true인 구간들로 저장해 다시 재생해요. 녹화 가능한 배속 절댓값은0.001~100이며, 이 범위 밖의 녹화는 오류로 알리고 게임 소리는 계속 재생해요. 녹화 종료 오류도 녹화 상태를 해제해요. 프레임에서 관찰한 큐이며 PCM 표본 정렬이나 장치 동기화는 보장하지 않아요. 배속에 따라 음높이도 바뀌고, 긴 스트리밍 소리의 역방향 디코딩·피치 유지 시간 늘이기는 남아 있어요.

AI는 schema.sequenceAudio로 저장·재생·메모리·녹화 계약을 조회해요. 기존 런타임 오디오 조회의 rate는 실제 PCM 배속이고 sequenceRate·sequenceParked는 시퀀스가 요청한 속도와 정지 상태예요. PCM 재생은 공용 엔진 오디오 흐름을 사용하며 Windows 네이티브 출력 연결을 그대로 이용해요. 실제 WebView 출력·C++ 창·설치 검사는 사용 중 설치본을 보호하기 위해 소스 검사와 구분해요.

구현 참고: [W3C Web Audio AudioBufferSourceNode](https://www.w3.org/TR/webaudio/#AudioBufferSourceNode)와 AudioBuffer 공유·재생 위치 계약을 참고했어요. 전체 문서 분석 완료나 장치 품질 검증으로 계산하지 않아요.

각 시간 키의 **다음 구간**에서 선형·삼차·계단을 고를 수 있어요. 삼차는 Hermite 보간이며 들어오는·나가는 기울기를 따로 지정해요. 입력을 비우면 이웃 키로부터 자동 기울기를 구해요. 첫 키의 시간과 값은0,0으로 유지하면서 보간·기울기는 편집할 수 있어요. 양 끝 바깥은 끝 기울기를 따른 선형 연장이에요. 삼차에서 값이 같은 두 키도 기울기가 있으면 사이에서 움직일 수 있고, 움직임 전체의 원본 값 범위도±86400초 안이어야 해요.

키 사이에 있는 정지점·방향 전환점을 미리 풀어 이벤트 방문을 나눠요. 한 구간에서 두 번 방향을 바꿔 같은 이벤트를 세 번 통과하면 세 번 전달해요. 같은 반복 끝을 접하고 되돌아오는 경우에는 끝 이벤트를 중복 발동하지 않아요. 기울기와 오디오 배속, AI의 방향 조회도 같은 곡선을 사용해요. **시간 키 추가**는 곡선을 유지하면서 나누고, 앞부분 자르기는 자동 기울기를 고정한 뒤 이동시켜 남는 곡선을 보존해요.

저장 키에는 interpolation:linear|cubic|step, inTangent/outTangent을 선택적으로 적어요. 기울기 단위는 구간1초당 원본 경과 초예요. 기존 선형 파일을 바꿀 필요는 없어요. 검증할 때 약한 참조의 준비 프로그램에 계수·전환점·범위를 만들며 재생 중에는 정렬이나 근 찾기를 반복하지 않아요. 실제 창·C++·설치 검증은 사용 중 여부를 확인한 뒤 진행하며, 소스 검사 통과와 구분해요.

**계단**은 다음 키 직전까지 왼쪽 값을 유지하고, 키 시점에 새 값으로 이동해요. 이 점프는 조용한 탐색처럼 처리해서 건너뛴 원본 시간과 도착 키의 이벤트를 실행하지 않아요. 점프 뒤 실제로 진행한 구간의 이벤트는 정상 전달해요. 거꾸로 통과할 때도 같은 원칙을 적용하며 반복 한 바퀴를 통째로 건너뛰어도 중간 이벤트를 실행하지 않아요.

계단의 양쪽 극한을 이벤트 방문과 구분하고, 표시되는 시점은 오른쪽 값으로 일관되게 정해요. 작은 점프라도 기존 오디오 드리프트 허용치와 별개로 새 위상에 맞추고 이 신호를 중첩 음성까지 전달해요. 정지해 있는 다음 프레임마다 탐색을 반복하지 않아요. 앞부분 자르기·키 추가는 계단의 점프 위치도 보존해요. 임의 점프 콜백 정책·장치 동기화·표본 단위 예약까지 구현했다는 뜻은 아니에요.

선형 시간 곡선은 가벼운 키 시각 목록만 준비해요. 일반 재생에서는 삼차용 구간 객체를 만들지 않고, 화면 편집에 필요할 때만 만들어요. 이 구조와 준비 프로그램 재사용은 소스 검사로 확인했으며 실제 프레임 시간·RAM 감소를 측정한 주장은 아니에요.
