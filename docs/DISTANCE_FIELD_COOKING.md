# 거리장 미리 굽기와 패키지 재사용

빌드에 포함된 장면에서 PostProcessVolume의 거리장 AO를 켜면 패키징이 정적 도형·OBJ·glTF·GLB 거리장을 미리 만들어요. 별도 셰이더나 C++ 코드를 작성하지 않아도 Windows·웹·모바일의 같은 콘텐츠 단계가 사용해요. 머테리얼·컴포넌트 설정은 기존 사람용 상세 패널과 C++/블루프린트 Components 함수·AI 문서 편집을 유지해요.

기하의 펼친 삼각형을 Float64로 정규화해 SHA-256을 계산해요. 인덱스·그리기 범위·정점이 달라지면 키가 바뀌고, 같은 자료의 다른 인스턴스·OBJ/glTF는 공유해요. 빌드 캐시 키는 생성 코드 소유자 지문과 해상도도 포함해요. glTF 외부 버퍼를 실제로 읽어 기하를 만들므로 파일 이름이나 수정 시각만으로 캐시를 재사용하지 않아요.

프로젝트의 기존 Library/CookCache를 함께 써요. JSON과 거리장을 합친 기본 보관 예산은128MiB예요. 체크섬이 틀린 항목은 임시 파일에 다시 만든 뒤 교체하고, 취소·실패 경로도 임시 파일과 보관 예산을 정리해요. 생성 결과는 원본 에셋이 아니므로 다시 만들 수 있어요.

패키지에는 __HBGenerated/DistanceFields/index.json과 바이너리만 넣어요. 기본32MiB는 목록과 자료를 합친 크기이고, 객체 개수 제한은 아니에요. 예산을 넘는 자료는 제외하고 런타임 생성을 유지해요. 생성 경로와 사용자 에셋이 겹치면 덮어쓰지 않고 빌드를 거부해요. AO를 쓰지 않는 프로젝트에는 이 목록을 추가하지 않아요.

실행기는 첫 요청 때만 목록을 읽고 각 필드는 필요할 때 읽어요. 파일 크기·SHA·기하 지문·바이너리 헤더·유한값·격자·유효 해상도·현재 예약 예산을 확인해요. 실제 요청에 맞는 자료만 채택하고, 빠짐·손상·기하 변경·다른 LOD는 기존 소유 작업자 생성으로 돌아가요. 볼륨은 기존 뷰포트 소유·교체·취소·해제 규칙을 따라요. 런타임 디스크 쓰기나 별도 GPU 패스·영구 볼륨 캐시는 없어요.

AI와 사람은 빌드 보고서 distanceFields에서 fields/cacheHits/baked/packageBytes/deferred/unsupported를 확인할 수 있어요. 실행 진단 distanceFields.cooked의 hits/misses/rejected/bytesRead/lastError는 그 뷰포트에서 읽은 자료예요. bytesRead는 목록·렌더러/GPU 메모리·드라이버 힙을 포함하지 않아요. 기하 지문·바이너리 검사는 최초/교체 작업에만 수행해요.

현재 미리 굽기는 요청한 상한 해상도를 저장해요. 다른 카메라 LOD·예산에 맞춰 축소한 해상도는 없으면 실행 중 생성해요. FBX·압축 확장·월드 에셋·변형체·마스크/투명 및 편집기 쿠킹·전역 거리장은 별도 범위예요. glTF/GLB의 오프라인 기하 로드는 기존64MiB 원본·128MiB 의존 버퍼 제한을 유지하고, 거리장 작업 입력은 기존8MiB예요. 이 기능의 자동 패키지 연결은 모바일 실기기 실행 검증을 의미하지 않아요.
