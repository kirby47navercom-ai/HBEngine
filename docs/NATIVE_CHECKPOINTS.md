# 네이티브 상태 복구 비용 — 1490–1495

CPP worker의 호출 묶음은 실패한 함수의 공개 상태·좌표를 복구하고 앞서 성공한 호출을 유지해요. 컴파일러가 실제 저장 타입을 확인한 엔진·표준 값 형식에서, 기존 객체의 반사 속성 읽기는 상태 복사 없이 조회해요. 속성 쓰기는 기존 수신 객체 하나의 상태를 저장해요. 임의의 C++ 함수는 다른 객체도 바꿀 수 있으므로 전체 native 객체와 일반 액터 좌표의 복구 상태를 유지해요. BlueprintPure 표시만으로 이 보호를 생략하지 않아요. 수신 객체가 없어 생성자가 실행될 수 있는 경우도 전체 저장 경로를 사용해요.

자료형 이름만 믿지 않고 실제 필드 타입을 재귀적으로 대조해요. 같은 이름의 사용자 Vec3·String·Array가 변환이나 대입에서 사용자 코드를 실행하면 전체 저장 경로를 유지해요. 수신 객체의 실제 클래스가 다르거나 등록되지 않은 속성인 경우도 보수적으로 처리해요. 사용자 정의 JSON 변환이 다른 액터를 바꾼 뒤 예외를 던지는 읽기·쓰기 검사가 이 보호를 확인해요. 형식이 다르다는 이유만으로 기존 C++ 사용을 거부하지 않아요.

구조체 복구 값은 std::optional로 첫 저장 시점에 만들어요. 액터 생성 시점부터 기본 구조체의 문자열·배열을 복구용으로 한 번 더 만들지 않아요. 일반 C++ 함수 실행에서는 여전히 현재 구조체·배열을 복사해요. 변화를 찾으려고 값을 매번 전부 비교하는 후보는 진단에서 더 느렸으므로 채택하지 않았어요.

## 실제 검사

`tools/check-native-record-checkpoint-1490.mjs`는 이전 생성기 f2c326f와 현재 생성기로 만든 C++를 직접 실행해요. 내부 할당·속성 대입 계수는 검사 코드에만 들어가요. 두 액터가 각각128개 구조체와 원소마다64개 중첩 피해값을 가진 조건에서32번 조회할 때 Items 복사는64회에서0회,32번 쓰기는64회에서32회로 줄었어요. 실패한 사용자 C++ 함수는 두 액터의 값·중첩 배열·좌표를 복원해요. 실패한 읽기 때문에 직전에 성공한 쓰기까지 되돌리지 않는 것도 확인해요.

검사 fixture의 기본 문자열/배열을 포함한 생성 시 할당은4회546B에서2회273B로 줄고 wrapper 자체는360B에서376B로16B 늘었어요. 이 숫자는 fixture의 직접 측정이며 엔진 전체 heap이나 FPS 수치가 아니에요. Windows DLL 내부의 문자열 할당이 실행 파일의 new 계수에 잡히지 않는 측정 오류를 피하려고 두 비교 실행 파일을 모두 정적 링크해요. 시간 표본은 보고서에 남기며 같은 증거로 전체 게임 프레임 개선율을 주장하지 않아요.

## AI·프로파일러 조회

CPP 결과의 기존 transport에 다음 수치가 추가돼요. 모두 해당 호출 묶음의 누적 개수이며 ms와 구분해요.

| 필드 | 의미 |
|---|---|
| checkpointCells | 저장한 native 객체 수의 합 |
| checkpointPlainActors | 저장한 일반 액터 좌표 수의 합 |
| checkpointReadSkips | 기존 객체의 상태 저장을 생략한 속성 읽기 호출 수 |
| checkpointTargetWrites | 기존 수신 객체만 저장한 속성 쓰기 호출 수 |
| checkpointFullCalls | 전체 저장 경로를 사용한 호출 수 |

기존 checkpointMs는 상태 저장 준비의 시간이에요. 패키지 debug inspect의 nativeTransport에서 원본 수치를 읽고, 편집기 profiler snapshot의 frames[].nativeCounters에서 프레임별 합을 읽어요. nativePackets는 기존 ms 항목만 유지해요. 예전 worker처럼 새 계수가 없는 응답과도 호환돼요. 유효하지 않은 계수는 프로파일러에 넣지 않고 기록 중인 기존 프레임에 숫자만 더해요. 새 타이머·worker·GPU 리소스·영구 색인은 없어요.

`hb context "C++ 체크포인트" --symbol "HB_checkpointMode"`는 생성기 소유자, nativeCheckpointSafety는 타입 검증 소유자, nativeCounters는 프로파일러 소유자로 안내해요. 생성된 worker 본문이 기존 native 빌드 캐시 키에 포함돼 다음 빌드에서 새 동작이 반영돼요. 사용자 C++ 함수의 전체 저장, 장면 직렬화·변경분 순회·결과 수집·큰 변경 배열 복사는 계속 별도의 비용이에요.
