# 텍스처로 만든 UV와 밉

텍스처의 R/G 등을 다른 텍스처의 UV로 연결하면 경로 추적과 이전 프레임 가이드에서도 그 좌표 변화가 전달돼요. 2D·배열·볼륨·큐브 샘플 모두 기존 노드로 구성해요. 큰 폭과 작은 폭을 항상같은밉으로읽던경로를바로잡았어요. 새 GPU 자원이나 자동 읽기 검사는 추가하지 않아요.

필요한 텍스처 조상만 두 방향으로 다시 읽으며, 그 샘플에 들어오는 footprint는 고정해요. 일반 표면 출력은 추가로 읽지 않아요. 유한 차분이므로 매우 작은 값이나 큰 UV, 불연속의 정밀 한계는 남아 있어요. 수학 차분45연산과같은안정정밀도로취급하지않아요. 이미지·샘플러변경의기존이력거부정책도유지해요.

Windows의 완성된 노드 머테리얼은 기본 맵 읽기와 샘플러가 겹치지 않아요. C++ SDK에서 완성된 표면 프로그램을 만들 때는 `SceneRenderer::createSurfaceProgram`을 쓸 수 있어요. 기존부분확장인 `createProgram`은기존방식을유지해요. 사람과AI가읽는 `engine.schema.nativeSurfaceProgram`에 입력 소유와 기존하드웨어/시스템 예약이 나와요.

검사에서는네형식모두현재/이전과세GPU경로오차0,밉폭차이1을확인했어요. 이전설치본은같은폭차이가0이었어요. 독립두샘플러의필터를바꾸면실제D3D픽셀이[188,0,0]과[0,188,0]으로바뀌었어요. 실제제작그래프와2D/3D기본실행기검증은[작업기록](research/ENGINE_WORK_510.json)에연결해요.
