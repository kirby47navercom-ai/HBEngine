# 190 — 미연결 시간 노드의 기하 재준비 제외

Time/Panner가 그래프에 있다는 이유만으로 정적인 광선 기하를 매 프레임 다시 준비하던 경로를 고쳤다. 기존 컴파일 결과의 실제 동적 opcode를 사용하고, 같은 호출의 머테리얼 Map과 기존 WeakMap 캐시를 재사용한다. 숨은 머테리얼·기존 수집 제외 대상도 같은 소유 규칙을 적용한다. 레거시 수집에서 컴파일할 수 없는 자료는 기존 보수적 경로를 유지한다.

정적 UV 그래프의 미연결 Time/Panner는 필수 이전 포즈 준비 뒤 같은 아틀라스/텍스처·필터 키를 재사용한다. 실제 Time 연결/해제는 같은 프레임에 인식하고, 살아 있는 노멀·색/발광·마스크 투명도·물리 재질 값은 계속 갱신한다. 월드/시점 의존 그래프는 이전 보수적 거절을 유지해 안전성을 바꾸지 않는다. 원본 재질 구조를 임의로 지우거나 사용자가 성능 플래그를 저장하게 하지 않는다.

변경 전 같은6프레임에서 미연결 Time/Panner는 기하 build 카운터가1→6이었다. 변경 후1을 유지한다. 1,000개 인스턴스/786432B 아틀라스의 Node CPU prepare/commit 표본은 변경 전 미연결 Time에서 워밍업 뒤 약68–87ms, 변경 후 약0.02–0.06ms였다. 첫 준비와 포즈 이력 준비는 여전히 약91ms/11ms였고, 게임 전체 프레임·GPU 렌더·PC120/모바일60 보장과 구분한다. 1,000개는 측정 표본이며 엔진 오브젝트 수 제한을 추가하지 않았다.

CPU5개와187의 기존 이력7개,106/138/189 관련 회귀를 검사했다. 실제 DirectX·WebGPU 패키징 게임은 미연결 Time이 있는 재질에서 BVH refit/rebuild 수가 프레임 사이에 고정됐다. DirectX는 아틀라스 전송 횟수/바이트도 유지했다. 실제 연결된 Time의 DirectX 게임은 계속 움직이며 같은 프로그램/아틀라스를 재사용했다. 모든 실행은 오류0/종료0이다. [근거](research/ENGINE_WORK_190.json).

새 캐시·의존성·상시 타이머·GPU 읽기를 추가하지 않는다. AI와 프로파일러는 기존 renderer.bvh, rayGeometry, raySceneUpdates/Bytes 진단을 사용한다. 외부 문서/API 전체를 새로 분석했다는 기록이나 전체 엔진 완료율을 올리지 않는다. 설치는 다음 기능과 묶어서 반영한다.
