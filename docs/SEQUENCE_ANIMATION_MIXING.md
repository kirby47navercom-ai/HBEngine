# 시퀀스 애니메이션 혼합

시퀀스의 기존 **혼합: 정규화**, **가중치** 설정을 사용해요. 같은 우선순위의 호환되는 애니메이션 클립이 각자 자기 시각에서 평가돼요. C++ `hb::LevelSequence::SetWeight/SetBlendMode/SetPriority`와 기존 블루프린트 노드도 같은 경로예요. 기본 `override`는 기존 승자 선택을 유지해요.

- 가져온 모델의 애니메이션은 대상별 하나의 제어된 THREE 믹서에서 섞여요. 같은 클립도 서로 다른 소스 시각으로 재생할 수 있어요. 재생 슬롯만 분리하고 원래 키 트랙·타입 배열은 공유해요. 빠진 슬롯은 중지하고 믹서에서 해제해요. 특정 속성이 없는 액션은 THREE 일반 액션의 원래 포즈 기여 규칙을 따라요.
- HB 애니메이션의 위치·회전·크기는 각 클립에 작성된 필드끼리 섞여요. 벡터는 볼록 가중 평균, 회전은 공통 반구를 맞춘 단위 쿼터니언 평균이에요. 혼합에서 빠진 필드와 최종 복원 대상 필드는 캡처한 원래 값으로 돌아가요. 이전 재생기가 있으면 보관한 인스턴스와 시각을 재개해요.
- 정규화된 모든 애니메이션 가중치가 0이면 원래 재생을 재개하면서 공유 캡처를 보관해요. 다시 양수가 되면 그 재생기를 다시 보관해요. 최종 Stop은 캡처를 정리해요. `keep`, `restore`, `forceRestore` 정책은 계속 적용돼요.
- 가져온 클립과 HB 변환 클립은 서로 다른 혼합 계열이에요. 가장 강한 소유자가 선택한 계열 안에서 호환되는 클립만 섞여요. 스프라이트 프레임은 이산 선택이에요. `runtime.animationPlayback`의 `rows[].blend`에서 `kind`, 각 `layers`의 소스·시각·정규화 가중치, 제외된 `excluded` 계열을 확인할 수 있어요. 0 가중치의 정규화된 스프라이트도 소유권을 양보해요.

AI 편집은 기존 `document.patch`의 revision·dryRun·Undo·Save 계약을 사용해요. `hb context --symbol SequenceAnimationMixing`으로 소유 코드를 찾을 수 있어요. 별도 스키마·API·타이머·워커는 추가하지 않아요.

HB 변환 클립은 직접 TRS·Transform 컴포넌트와 같은 필드 소유권으로 중재돼요. 가져온 믹서의 루트·오브젝트 바인딩, 별도 skeletalPose 뼈 및 렌더러 속성 트랙의 남은 별칭 중재는 별도예요. 외부에서 관리하는 추가 액션, 임의 notify·비동기 setter의 부수효과 되돌리기도 별도예요. FPS·힙 절감 수치는 측정 전이에요.
