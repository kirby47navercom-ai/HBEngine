# 194 — 광선 프로그램의 표면 필드별 특화

광선 프로그램 메타데이터에 사용하는 표면 필드 번호를 기록해, 노멀 셰이더에 다른 재질의 발광·투명도 프로그램까지 생성되던 비용을 줄였다. 같은 프로그램을 여러 필드가 공유하면 필드 목록을 합친다. 기본5/확장10필드 재질의 혼합, 캐시된 재질 계획의 불변성, 필드만 바뀌는 네이티브 소스 무효화를 유지한다. 프로그램 키·명령·GPU 아틀라스 배치는 그대로이며 새 캐시나 런타임 GPU 읽기를 추가하지 않는다.

WebGPU는 해당 필드의 함수만 생성하고 이전 노멀의 시간 의존성도 노멀 프로그램에서만 판단한다. GL·HLSL은 상수 필드 분기와 기존 공개 실행 래퍼를 함께 생성한다. 옛 메타데이터는 모든 필드에 쓰이는 것으로 보수적으로 처리한다. 잘못된 필드 자료는 JS·C++ 파서에서 거부한다.

노멀+발광 표본의 노멀 WGSL은45117→29725바이트, 노멀+발광+마스크 비교는53909→29725바이트였다. GL 전체6프로그램 링크는 두 실행 순서에서 기존2649–2681ms, 필드 특화2144–2172ms였다. 같은 패킷에 불필요한 프로그램 정의를 더한 비교이며, 실제 다중 재질 게임 전체 성능 측정은 아니다. 단일 노멀 그래프의29725바이트는 바뀌지 않으므로 Complex141의7–9초 초기 지연 전체 해결로 계산하지 않는다.

CPU6군·GL/GPU 픽셀·실제 하드웨어 D3D 컴파일·장시간 시간 노멀·새 네이티브 플레이어 게임·관련 회귀를 확인했다. 실제3백엔드 표본의 최대 노멀 오차는약5.93e−8이다. [실행 근거](research/ENGINE_WORK_194.json). 설치는195–196과 묶어서 전환한다.
