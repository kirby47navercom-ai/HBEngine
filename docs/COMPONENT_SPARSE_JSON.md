# 큰 입자 배열의 C++·공용 명령 전송

Cloth의 격자·3D 로프와 Rope2D의 `massWeights`, `pinWeights`, `pinOverrides`, `motionLimits`, `distanceTethers`는 실제 입자 토폴로지에 맞춘 전용 JSON 검증을 사용해요. 전체 격자를 칠한 데이터가 일반 게임 JSON의 배열 4,096개·문자열/텍스트 제한에 걸려 C++→공용 실행으로 전달되지 않는 경로를 보완해요.

기존 `hb::Components::SetText(target, component, property, json)`을 그대로 사용해요. C++는 해당 컴포넌트의 토폴로지로 전송 예산을 정하고, 지정된 필드의 정확한 행 구조·번호·중복·범위를 확인한 뒤 명령을 넣고 로컬 스냅샷에 반영해요. 새로 추가된 선택 배열 속성이 예전 스냅샷에 없더라도 등록된 입자 속성이면 설정할 수 있어요. 같은 C++ 호출 안에서 `GetText/Get`으로 쓴 값을 읽을 수 있고, 실제 게임 컴포넌트에는 기존 명령 재생 순서로 적용해요.

예산은 `max(262144, 입자 수 × 128)`바이트예요. 유효한 행은 고정 ASCII 키와 숫자/Bool만 사용해요. 물리 컴포넌트의 기존 규격을 그대로 따르며 새 물리 수용량을 선언하지 않아요. 일반적인 256×256 격자는 65,536입자의 전체 작성 배열을 전달할 수 있어요. 최대 거리 쌍은 여전히 전송 예산 안의 고유한 쌍이어야 해요.

네이티브 응답 검증도 이 등록된 속성만 별도로 확인해요. 같은 응답에 앞선 가로·세로·로프 입자 수 변경이 있으면 사설 검증 상태에 순서대로 반영하고, 원본 오브젝트를 수정하지 않은 채 뒤의 배열을 검증해요. 실제 적용은 기존 공용 컴포넌트 검증·수명 경로를 다시 거쳐요.

다른 게임 JSON·임의 구조체·일반 문자열·블루프린트 인라인 문자열의 기존 제한은 유지해요. 이 변경은 큰 작성 배열의 전송을 연결하며 65,536입자 물리의 장시간 속도·메모리나 GPU 성능을 보장하지 않아요.
