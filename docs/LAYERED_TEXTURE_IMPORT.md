# 배열·큐브·볼륨 텍스처 가져오기

텍스처 배열·큐브맵·볼륨 에셋의 기존 속성 창에서 **용도, 색 공간, 밉 생성, 상위 밉 제외, 최대 크기, 알파 커버리지**를 편집해요. 노멀 용도에는 녹색 반전·하위 밉 정규화도 있어요. 저장·Undo·AI 문서 패치는 같은 자료를 사용해요.

새 에셋은 명시적 `import` 기본값을 가져요. 기존 `import` 없는 파일은 원래 로더를 유지해요. 기존 파일에서 **가져오기 설정 사용**을 선택하면 공용 처리를 켜고 **원본 처리 사용**으로 되돌릴 수 있어요. 자동으로 기존 에셋을 다시 쓰지 않아요.

```json
"import": {
  "role": "normal",
  "colorSpace": "auto",
  "flipGreen": true,
  "normalizeNormals": true,
  "mipmaps": true,
  "topMip": 0,
  "maxSize": 0
}
```

배열은 각 층, 큐브는 여섯 면의 색·커버리지를 독립적으로 처리해요. 볼륨은 XYZ 면적 가중 필터로 깊이까지 줄여요. 홀수 크기도 원래 영역 비율을 사용해요. 색상 밉은 선형 공간에서 평균한 뒤 sRGB로 저장하고, 노멀은 정규화한 중간 업로드 값을 다음 밉의 원본으로 사용하지 않아요. 볼륨 커버리지는 전체 voxel, 배열·큐브는 각 층·면을 기준으로 유지하며 양자화 오차를 보고해요.

작성한 `mips:[{images:[...]}]`가 있으면 크기와 마지막 1 크기까지의 완전한 체인을 검증해 그 이미지를 처리해요. 자동 밉으로 덮어쓰지 않아요. `mipmaps:false`이면 선택한 밉 하나를 업로드해요. `topMip/maxSize`는 볼륨 깊이에도 적용하고, 배열의 층 수는 줄이지 않아요. 실제 장치의 크기·층 수 한도를 확인해요.

미리보기는 에셋 뷰 하나의 결과를 공유해 면·슬라이스 전환마다 다시 디코딩하지 않아요. 창의 Image/Canvas를 사용하고 뷰를 닫으면 소유 작업을 취소해요. 실행 로더, 기존 단일 밉 워커, Three 데이터 텍스처, WebGPU 업로드 어댑터와 네이티브 전송 자료는 같은 RGBA8 밉을 사용해요. 새 워커나 매 프레임 합성을 추가하지 않아요. 전송 실패로 원본 버퍼를 잃으면 이미지에서 다시 읽고 로컬 처리로 복구해요.

AI 계약: `engine.schema.layeredTextureImport`. 가져오기 결과의 `report`에는 원본/최종 크기, top mip, 저장 byte, 커버리지 오차와 worker 여부가 있어요.

현재 범위는 이미지 디코딩 RGBA8이에요. HDR/raw/GPU 압축·RDO·다차원 디스크 밉 스트리밍과 큐브 면 사이 seamless footprint는 별도예요. 가짜 GPU queue를 통한 실제 어댑터 데이터 대조를 실제 GPU 픽셀 검사로 계산하지 않아요. CPU 디코딩의 실제 메모리 비용도 그대로 있어요.

검사: `tools/check-layered-import-2816.mjs` 20개. 소유 이미지/DOM·실제 Three·프로젝트 저장·실제 단일 worker thread·취소/복구·전송 payload를 대조해요. 사용자 창·설치본·실기기는 사용하지 않았어요.
