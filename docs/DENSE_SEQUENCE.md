# 대형 시퀀스 키 편집

시퀀스는 트랙당 65,536키를 지원해요. 전체 키 예산은 기본262,144개로, 이전의 최대256트랙×1,024키 문서를 그대로 받을 수 있어요. `keyBudget`를 명시하면 전체 예산을1~1,000,000 범위에서 정할 수 있어요. 왼쪽 **키 예산**에서 설정하며 실제 키 수보다 낮추면 편집을 거절해요. 오브젝트 수 제한과는 별도의 제작 데이터 예산이에요.

개요 타임라인은 가로8px 구간마다 시간상 첫·끝 키, 전체 양 끝과 선택 키를 표시해요. 원본 배열·값·키 인덱스는 바꾸지 않아요. 겹쳐서 표시하지 않은 키도 데이터·실행·AI 조회에서 유지해요. 오른쪽 속성은32키씩 표시하고 이전/다음과 **키 번호로 이동**으로 정확히 접근해요. 이동 버튼은 속성창 위에 고정되고 선택한 키의 입력칸을 실제 보이는 위치로 스크롤해요. 번호는1부터, API 인덱스는0부터예요. 키 선택과 페이지 이동은 에셋을 수정하거나 Undo를 만들지 않아요.

이전/다음 키 조작은 키·클립·시퀀스 구간 경계를 스트리밍으로 순회하며, 전체 시간을 임시 배열로 펼치지 않아요. 재생은 기존의 한 번 정렬한 키와 이진 검색을 그대로 사용해요. 곡선 편집기와 키 클립보드도 새 트랙 예산을 사용해요.

AI는 `sequence.keys.read`에 `path`, `track`, `offset`, `limit`를 주어 페이지로 읽어요. 기본100키·최대1000키이고 `values=false`이면 시간·보간만 받아요. 응답의 `index`는 원본 배열 인덱스이며 `nextOffset`이null이면 끝이에요. 조회는 `revision`·`dirty`·Undo를 바꾸지 않고, 선택한 `expectedRevision`이 다르면 거절해요. 수정은 기존 `sequence.curve.edit`, `sequence.curve.tool`, `sequence.curve.keys`와 revision/dryRun/Undo를 공유해요.

실제65,536키 문서의 창 검사에서 개요204마커·속성32키·전체1095요소를 만들었고 마지막 키 수정/Undo, 이전 페이지, 높은 인덱스 AI 조회/복사, 저장·복구 flush·실제 재생을 확인했어요. 최근 열기 관찰은약0.80초예요. CPU 모델은10001회 이진 샘플의 오차0, 전체 관찰약6.2ms였고, 게임 프레임 속도 수치가 아니에요.

Undo 기록은 변경하지 않은 하위 데이터를 공유하고 복원할 때 분리해요. 현재 문서 순회와 변경된 배열의 저장 비용은 남아 있어요. 측정·호환성·진단은 [문서 이력](DOCUMENT_HISTORY.md)을 봐요. 다중 곡선 가중 편집, 키 예산의 무제한화, 원시 Take의 최대 표본 수와 최종 에셋 키 예산을 같게 만드는 작업은 이 범위에 포함하지 않아요. 큰 문서의 저장·복구·자동화 바이트 정책은 [대형 제작 데이터 저장](LARGE_AUTHORING_STORAGE.md)을 봐요.

32행을 넘는 시퀀스·몽타주는 세로 스크롤의 전체 길이를 유지하면서 보이는46px 행과 앞뒤3행을 만들어요. 키 개요와 구간 표시용 복사도 해당 행에서만 만들어요. 슬롯·Shot/Sub-Sequence의 묶음은 한 번 순회해 구성하고, 화면 밖의 전체 구간을 매 행마다 다시 필터·복사하지 않아요. 한 행 안에 몰린 클립/구간의 가로 가상화와 비고정 높이는 아직 별도 과제예요. 스크롤·크기 변경 시 현재 입력 포커스를 가능한 범위에서 유지하고 키·구간 드래그 중에는 행 교체를 미뤄요. 행 검색은 이름·ID·종류·대상을 찾고 원본 순서를 유지해요. 선택한 행이 화면 밖이면 이동해 보여줘요. `↑/↓`는 이전/다음 행, `Ctrl+F`는 행 검색이며 중앙 단축키 설정에서 재지정할 수 있어요. 입력칸 편집·IME·실행 중 격리 규칙을 공유해요. 몽타주 알림 행을 선택하면 해당 알림 속성을 열어요. 슬롯 ID에 `slot:` 접두사를 사용하여 `Sections/Notifies` 행과 같은 이름의 슬롯도 구분해요. 에셋의 슬롯 이름과 실행 경로는 바꾸지 않아요.

`sequence.tracks.read`는 `query/type/target`, `offset/limit`으로 트랙의 원본 인덱스·ID·이름·종류·대상·키/클립 수만 읽어요. 기본100·최대256행이에요. `sequence.editor.navigate`는 트랙 ID와 선택적 원본 키 인덱스로 실제 편집기를 이동해요. 요청 트랙을 가리는 검색은 해제하고 해당 행·속성·키가 보이게 해요. 둘 다 문서 값·dirty·revision·Undo를 바꾸지 않고 선택적 expectedRevision을 검사해요. 탐색 명령은 작업창과 선택 상태를 바꿔요.

두 편집기의 전체 행은 `timeline.rows.read`로 읽어요. `path`, 선택적 `query/offset/limit/expectedRevision`을 받고 기본100·최대256행의 ID·이름·종류·개수와 원본 행 인덱스만 반환해요. 키 값·클립 본문·함수는 반환하지 않아요. `timeline.editor.navigate`에 이 행 ID인 `row`와 선택적 `item` ID를 주면 슬롯 클립·몽타주 알림·시퀀스 하위 구간도 정확히 열어요. 요청을 가리는 검색은 해제하며 문서 값·dirty·revision·Undo는 바꾸지 않아요. 시퀀스 키 항목 ID는 `트랙ID:원본인덱스`이고 존재하지 않는 인덱스는 거절해요. 기존 `sequence.*` 명령은 유지해요.

조작 참고는 [Unreal Sequencer 단축키의 Timeline and Track Navigation](https://dev.epicgames.com/documentation/en-us/unreal-engine/sequencer-hotkeys-in-unreal-engine)와 [Unity Timeline1.8의 Content view 탐색](https://docs.unity.cn/Packages/com.unity.timeline%401.8/manual/clip-pan-zoom.html)이에요. 이번 변경은 행 생성·검색·선택 경로에 한정하며 두 제품의 모든 탐색·줌 기능을 이 문서로 구현 완료했다고 해석하지 않아요. 기존 HBEngine 재지정 프로필과 프레임/재생 단축키를 유지해요.

이벤트 트랙은 재생 준비 때 원래 배열 순서를 담은 Uint32 인덱스를 만들고, 각 시간 구간은 이진 검색으로 찾은 후보만 방문해요. 정렬되지 않은 원본과 같은 시간의 중복도 기존의 배열 실행 순서를 유지해요. initial/endExclusive와 Seek의 무이벤트 규칙도 유지해요. 인덱스는 이벤트 키당4바이트이며 일반 숫자 트랙에는 추가하지 않아요. 비어 있지 않은 구간의 임시 후보는 해당 키당4바이트이고 비동기 이벤트가 재진입해도 다른 구간과 공유하지 않아요. 65,536키의 빈 구간10000회 관찰에서 시간 필드 접근320002회·약6.44ms였어요. 매 프레임 전체 키를 훑는 방식과 구분한 CPU 관찰이며 게임FPS 수치가 아니에요.
