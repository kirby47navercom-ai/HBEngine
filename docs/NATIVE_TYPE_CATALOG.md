# 프로젝트 자료형 찾기와 적용

BP의 **변수 추가 → 프로젝트 자료형**에서 타입 에셋을 찾고 선언을 선택해요. 기존 변수의 속성에서도 **프로젝트 자료형 선택**으로 바꿀 수 있어요. 구조체 편집기의 미저장 새 필드에도 같은 선택기가 있어요. 변수·필드의 자료형과 필요한 `native.typeLibraries` 또는 `imports` 참조를 한 편집에 반영해서 Undo 한 번으로 함께 되돌려요.

목록은 프로젝트의 `.hbenum.json`·`.hbstruct.json`·`.hbtypes.json` 파일을 자동으로 찾아요. 먼저 이름·경로·종류만 보여주고, 에셋을 선택하면 선언 UUID·정규 이름·표시 이름을 보여줘요. 목록 검색 때문에 모든 본문을 읽거나 모든 코드를 빌드하지 않아요. 검색과 페이지 이동은 문서·revision·Undo를 바꾸지 않아요.

실제 적용할 때 선택한 에셋의 명시적 의존성을 읽고 자료형·기본값을 검증해요. 구조체 변수는 공유 선언 기본값, 열거형 변수는 첫 선언 값, 배열은 빈 배열로 시작해요. 같은 타입·컨테이너를 다시 선택하면 기존 값을 보존해요. 저장된 구조체 필드의 ABI 변경, C++·상속 BP의 자동 include 수정은 거절해요. 그런 원본의 지원 범위는 기존 C++ 생성 헤더/상속 편집 흐름을 따라요.

선택한 원본에 미저장 편집·디스크 충돌이 있으면 먼저 저장하도록 알려요. 목록을 연 뒤 원본이 바뀌거나 준비 중 대상 문서가 바뀌면 적용 전에 거절해요. 원본 기본값을 무조건 복사해 기존 값을 덮는 기능은 아니에요.

AI는 다음 순서로 같은 기능을 사용해요.

1. `project.types.read {query, offset, limit}`: 프로젝트 타입 에셋 목록을 읽어요. 기본32개·최대128개, 검색어160자까지예요.
2. `project.types.read {source}`: 저장된 에셋의 선언 목록과 `sourceRevision`을 읽어요. 기본값·전체 필드 배열은 응답에 포함하지 않아요.
3. `project.types.apply {path, expectedRevision, source, sourceRevision, declarationId, ...}`: BP에는 새 변수 `name` 또는 기존 `variableId`, 타입 에셋에는 미저장 `fieldId`를 지정해요. `container`는 BP의 `single`/`array`, `dryRun:true`는 원본을 바꾸지 않고 준비·검증해요.
4. 반환된 대상 revision으로 기존 문서 저장·파일 묶음 API를 사용해요. 적용 자체가 디스크 저장은 아니에요.

전체 계약은 `schema.nativeTypeCatalog`에 있어요. 목록 조회는 선언의 로컬 형태만 확인하고 적용·준비·저장에서 전체 참조를 확인한다는 경계는 [에셋 간 타입 참조](NATIVE_TYPE_DEPENDENCIES.md)와 같아요. 새 상주 스캔·Worker·타이머·런타임 전역 레지스트리는 없어요. 필요할 때 파일 목록과 선택한 타입을 읽는 비용은 있어요.

이 기능은 타입 **에셋**의 프로젝트 검색·선택·작성 경로예요. 임의 C++ 헤더 전체의 자동 발견, 일반 객체 identity·다형성 레지스트리, 파괴적 이관·ABI 교체는 별도예요.1652의 기존 선택 문서 읽기를 재사용한 HB 자체 설계이며 전체 Unreal·Unity 분석/구현 완료를 뜻하지 않아요.
