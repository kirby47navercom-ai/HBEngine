# 198 — 검사 엔진의 동일 Node 사본 정리

검사 프로젝트 안에 복제된 Engine/baseline-engine의 runtime/node.exe도 정리 대상으로 식별한다. 엔진 package.json·HBEngine.exe·tools/hb.mjs가 있는 사본만 검사하고, 현재 공용 Node와 크기·SHA256이 정확히 같은 파일만 선택한다. 소스·다른 런타임·수정된 바이너리·node_modules는 삭제하지 않는다. 계획에는 원본 경로·Node 버전·해시·논리 바이트를 남겨 재현할 때 복원할 수 있게 한다.

삭제 직전 PowerShell은 검증된 native/build 검사 경로와 엔진 표식을 다시 확인한다. 해당 Engine의 어느 경로라도 실행 파일/명령행에서 사용 중이면 Node 사본을 보존한다. 계획 뒤 파일이 바뀌었으면 건너뛰고, 파일·상위 경로의 링크도 기존처럼 거부한다. 현재 사용자 설치본·프로필과 무관한 격리 검사 경로만 대상이다. 모든 프로세스 시작 경쟁을 원천 봉쇄하는 잠금 서비스는 아니다.

이미 등록한 현재 검사 정리는 전체 tools 재검색을 생략하고, 정리할 출력이 없는 node_modules 내부 순회도 피한다. 스트림 해시를 사용해 전체 실행 파일을 메모리에 복사하지 않는다. 새 의존성·상시 서비스·프로세스 강제 종료는 추가하지 않는다.

실제 자식 Node가 형제 tools 경로를 사용하는 동안 보존, 종료 후 동일 파일 정리, 원본 SHA 보존, 계획 이후 변경/알 수 없는 실행 파일 보존, 소스/근거 보존을 확인했다. 기존 범위 거부·패키지 명세 보존 회귀도 통과했다. 검사는 공간을 추가 점유하지 않는 하드링크를 사용했고 논리91694408바이트 제거를 실제 디스크 절약으로 계산하지 않았다. 첫 테스트의 Program Files 직접 하드링크 권한 거부와 제한된 PowerShell의 Get-FileHash 부재를 반영해 사용자 소유 개발 사본/안전한 복사 fallback 및 .NET 스트림 해시를 사용한다. [근거](research/ENGINE_WORK_198.json).

이후 모든 검사 프로세스 종료와 사용자 구버전 런타임 종료를 확인한 구간에 과거 검사 정리를 실행했다. 동일 Node 사본41개/논리3759470728바이트를 정리했고 실패·사용 중 경로 삭제0이었다. C: 여유 관찰값459301703680→463056703488바이트(약3.75GB 증가)를 논리 제거 바이트와 별도로 기록한다. 소스·재현 프로젝트·근거와 변경된 파일은 유지했다. 사용자 설치 전환은 최신 묶음의 별도 영수증으로 확인한다.
