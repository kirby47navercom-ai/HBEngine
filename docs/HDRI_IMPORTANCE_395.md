# HDRI 베이크 방향 표본

선택 HDRI의 밝은 영역도 확산 반사 이후의 방향 선택에 반영해요. 베이크가 실제로 평가하는 `spread=0.5` 필터 RGB를 최대 64×32 격자에서 읽고, 휘도와 정확한 구면 셀 면적을 곱해 분포를 만들어요. 행과 행 안의 열을 각각 조건부 CDF로 뽑고, 셀 안에서는 구면 면적에 균일하게 분포해요. 회전과 flipY를 표본 생성과 PDF 조회 양쪽에 적용해요. 코사인 반구를 최소 0.5 확률로 남기고 전체 혼합 PDF로 기여를 보정해요. 이후 기하 반사의 기여도 같은 보정을 사용해요.

원본 이미지나 또 다른 전체 밉 체인을 보관하지 않아요. 기존 필터를 재사용하며 분포 표·행 면적은 베이크당 최대 16,648바이트예요. 필요한 첫 반사에서 한 번만 만들고, 광선을 추가하지 않아요. 512×256 조건에서 조회된 필터 밉은 2,856바이트이고 반복 방향 요청은 표를 재생성하지 않았어요. 이는 TypedArray 보관량이며 전체 프로세스 최대 메모리나 FPS 측정은 아니에요. 원반 없는 하늘·상수/검은 HDRI의 기존 코사인 방향 수열은 유지해요. 검은 차폐물 때문에 반사가 끝나면 사용하지 않는 분포를 생성하지 않아요.

[PBRT 4판의 ImageInfiniteLight](https://pbr-book.org/4ed/Light_Sources/Infinite_Area_Lights)에서 이미지 휘도 분포의 방향 표본과 구면 PDF 변환을 설명하는 지정 구역을 읽고 대조했어요. PBRT의 equal-area octahedral 매핑을 HB의 lat-long에 그대로 적용하지 않아요. HB는 행마다 `2π/너비 × (cosθ위−cosθ아래)`인 정확한 셀 면적을 사용해요. [단일 표본 혼합 모델](https://pbr-book.org/4ed/Monte_Carlo_Integration/Improving_Efficiency)의 전체 PDF 합도 유지해요. 나머지 장·portal·참고 논문과 전체 엔진/API 분석 완료를 뜻하지 않아요.

검사는 NPOT·회전·뒤집기 12조건의 PDF 적분·같은 표본의 생성/조회 PDF·상수 함수의 π 적분·방향 길이·가중치 상한·원본 불변을 포함해요. 실제 한 번 반사 베이크는 독립 구면 적분 기준과 대조하고 검은 차폐물의 결과 0도 확인해요. 실제 사람 조작으로 UV1·HDRI 베이크·저장·Undo/Redo·AI 충돌 거부·미리보기와 세 패키지 실행기의 이동 무효화·복원까지 연결해요.

품질 탐색에서 원본 밝기만 쓴 분포와 1차원 flatten 분포는 현재 필터에 불리했어요. 채택한 필터 RGB·2차원 조건부 분포·각도 수열의 지정 32표본/64회 회전 조건은 MSE 12.8735에서 11.3237로 줄었어요. 최초 탐색의 **4배 감소 목표는 미달**이며 결과 JSON에도 `originalFourfoldTargetMet:false`로 남겨요. 해당 목표를 통과한 것으로 바꾸거나 일반 장면/FPS 향상으로 확대하지 않아요. 추가 저표본 효율은 원장에 남겨 계속 진행해요.

이전 표시 검사에서는 선형 빨강 약 54.78을 넣어 WebGL AgX의 고휘도 탈색이 발생했어요. 기존 빨강 우세 조건을 유지하고 HDRI 검사 입력을 1/8로 줄여, 분포·베이크와 표시 색 검사 범위를 분리했어요. 제품의 톤 매핑이나 오차 허용을 바꾸지 않았어요. 원래 실패 캡처도 보존해요.
