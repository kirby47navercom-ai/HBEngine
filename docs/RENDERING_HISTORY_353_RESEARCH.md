# 이전 표면과 투명 경로의 다음 구현 대조

2026-10-18 선택 본문/API 대조예요. 전체 Unreal/Unity 문서나 전체 기능을 분석했다는 기록이 아니에요.

[NVIDIA NRD README](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md)의 입력/PSR/주의 구역(593–633, 746–778, 959–975행)을 읽었어요. 표면의 이동뿐 아니라 이전 깊이, 월드 노멀과 거칠기, 이력 신뢰도와 반사 경로의 가상 위치가 별도로 필요해요. 평면 거울의 연속 반사 뒤 표면을 대신 쓰는 경우에도 그 표면의 머테리얼 값과 가상 공간의 노멀·깊이·이동은 같은 대상이 아니에요. 곡면에서는 추가 보정 없이 재투영 오차가 생길 수 있어요. NRD의 코드나 라이브러리를 도입한 것은 아니에요.

[Unity HDRP 17.0.4 모션 벡터](https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@17.0/manual/Motion-Vectors.html)의 본문114–155행을 읽었어요. 객체/카메라 이동을 구분하고, 투명체가 뒤 물체의 이동을 덮어쓸 때 잔상이 생길 수 있다고 설명해요. 투명체의 표면 이동을 기록하는 것만으로 굴절 뒤 대상의 이동을 재현했다고 볼 수 없어요. 연결된 Frame Settings/재질/렌더러 API 전체는 아직 이 읽기에 포함하지 않았어요.

HB는 이미 committed 삼각형/정점 노멀/UV·현재와 이전의 위치·시점·노멀맵·pixel cone을 분리해요. 남은 구현은 이전 표면 필드의 평가와 반사·굴절 분기의 재생을 실제 가이드에 연결하는 것이에요.

1. 이전 시간·월드/시점·UV 미분 문맥에서 물리 값, 코팅, 색·발광 등 필요한 표면 필드를 평가해요. IR/필드 키/저장 형식을 유지하고 필요한 필드만 생성해 최초 준비 비용의 증가를 줄여요.
2. 현재 IOR/거칠기나 TIR 분기를 이전 프레임에 그대로 적용하지 않아요. 중첩 매질의 이전 상태와 경로별 문맥을 분리하고, 분기가 달라졌거나 이전 기하를 복원할 수 없으면 잘못된 이력을 섞지 않아요.
3. GL/WGSL/생성 HLSL의 같은 포즈·카메라·밉/필터·시간·투명 분기를 직접 비교하고 실제 C++/BP 장면에서 확인해요. 복잡한 곡면의 전역 역해와 거친 복합 로브까지 이 단계만으로 완료 처리하지 않아요.

335–344 mixed-frame GL 실험의 17문맥/가이드 출력 일치는 위 작업의 일부 입력 대조 근거예요. 전체 준비/실행 비용의 이득을 확인하기 전에는 기본 경로로 연결하지 않아요. 단독 캐시 적중이나 작은 이미지의 일치도 전체 렌더링 완료로 계산하지 않아요.
