# PCM 로드 대기열과 종료 수명

`AudioRouting`이 사용하는 `AudioPCMCache`는 같은 URL의 대기 요청을 합치고, 서로 다른 URL은 기본 두 개씩 다운로드·디코딩해요. 나머지는 URL과 요청 상태만 대기하므로 동시에 많은 디코더를 시작하지 않아요. 재생 음성 수를 제한하거나 소리를 생략하는 기능은 아니에요.

기존 32 MiB PCM LRU 보관 예산과 캐시 공유를 유지해요. 한 클립이 보관 예산보다 크면 재생은 가능하고 캐시에 보관하지 않아요. 실패한 요청은 캐시를 오염시키지 않고 같은 URL로 다시 요청할 수 있어요.

실행을 종료하면 대기·진행 중인 호출자를 즉시 거절하고 fetch를 취소해요. 플랫폼에서 이미 실행 중인 decodeAudioData는 취소할 수 없으므로, 그 결과를 캐시에 게시하거나 새 플레이어로 만들지 않아요. BufferedAudioPlayer를 dispose하면 원본 PCM 참조를 해제하고 마지막 재생 시간/길이 조회는 유지해요. 역재생 PCM은 기존 WeakRef 공유 방식을 사용해요.

`runtime.audio.pcmCache`에 보관 bytes·항목·대기·진행 요청 수와 예산을 반환해요. 이는 `runtime.audio` 응답의 pcmCache 필드이며 별도의 실행 명령이 아니에요. `schema --section audioPCMCache`로 계약을 읽을 수 있어요.

예산은 보관 캐시의 PCM 수치예요. 살아 있는 음성·역재생 PCM·이미 실행 중인 디코드와 OS/코덱 메모리까지 포함한 엔진 총 RAM 상한을 뜻하지 않아요. 실제 장치/코덱별 회수·품질 검증은 별도예요.
# 믹서 편집기 미리듣기

열린 `AudioMixerEditor`마다 첫 재생에서만 별도 오디오 컨텍스트를 만들어요. PC 미리듣기는 기존 스트리밍 경로와 공용 `AudioRouting` 미디어 노드를 재사용해요. 긴 곡 전체를 PCM으로 바꾸도록 강제하지 않아요. 모바일의 기존 버퍼 재생은 유지하며 같은 편집기 안에서는 예산 내 PCM을 공유해요.

정지는 음성·DSP 그래프·미터 타이머를 해제하고 컨텍스트를 suspend해요. 로딩 중에는 같은 버튼에 **취소**, 재생 중에는 **정지**를 표시해요. 편집기를 닫으면 컨텍스트·미디어 풀·PCM 캐시도 해제해요. 정지·문서 닫기·새 재생 뒤에 끝난 오래된 resume/play/decode는 새 재생을 덮어쓰지 않아요. 여러 편집기의 미리듣기와 게임 믹스 녹음은 각각의 소유권을 유지해요. 컨텍스트/노드 재사용은 실제 장치의 음질·OS 메모리 회수 증명을 뜻하지 않아요.
# 개별 로딩 취소와 대기열

`AudioPCMCache.read(context,url,{signal})`은 같은 URL의 다른 대기자를 유지하며 해당 호출만 취소해요. 취소 가능한 대기자가 모두 나가고 일반 대기자도 없을 때만 공용 작업을 중단해요. 큐에 있던 작업은 다운로드하지 않고 제거해요. 이미 플랫폼 디코더에 들어간 작업은 실제로 끝날 때까지 동시 실행 수에 포함하며, 결과를 캐시에 올리지 않아요. `abandonedActive`로 이 상태를 구분해요.

대기열은 연결 목록으로 넣기·꺼내기·개별 취소 때 배열 전체를 이동하지 않아요. 기존 동시 2개·retained PCM 32 MiB 예산과 일반 호출의 동일 pending Promise 공유는 유지해요.

공용 소리 명령은 정지·같은 핸들 교체·연결된 액터 제거/풀 반환·월드 종료에서 해당 로딩을 취소해요. 에셋 이름을 찾는 도중의 정지와 이전 요청의 늦은 응답도 구분해, 정지 뒤에 소리가 새로 시작되거나 이전 클립이 새 요청을 덮어쓰지 않아요. 정상 취소는 재생 실패로 기록하지 않아요. 믹서 편집기 미리듣기도 같은 개별 취소를 사용해요. `audioState.resolving`은 에셋 탐색 중인 요청 수예요. 실제 기기 소리·OS 메모리 회수는 별도 검증 범위예요.
