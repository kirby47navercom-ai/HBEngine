# 편집 월드의 수동 EQS 검사

환경 질의 에셋을 열고 장면의 대상을 고른 뒤 **편집 월드 질의**를 눌러요. 플레이를 시작할 필요 없이 기존 단계 선택·투영/검사별 통과/실패·점수·뷰포트 표시를 사용해요. 열린 미저장 EQS·NavMesh·타일맵 초안도 기존 에셋 읽기 경로에서 받아요. 실행 중에는 기존 런타임 질의로 연결해요.

AI는 `editor.eqs.run({target,asset,context?,visualize?,stage?,debugLimit?,offset?,limit?,failed?})`, `editor.eqs.read`, `editor.eqs.view`를 사용해요. `runtime.eqs.*`의 프레임 장벽과 게임 실행 조건은 유지해요. 조회 페이지를 수정해도 보관한 진단은 바뀌지 않아요. 진단 표본·페이지/표시 예산은 기존 EQS와 같고 실제 후보 검사를 줄이지 않아요.

`EditorEnvironmentQuery`는 장면을 복사하고 공용 `engineOperations.eqsRun`·NavMesh 투영·실제 Rapier 2D/3D ray 질의를 호출해요. 충돌 검사가 있을 때만 복사본의 메시/타일 충돌·물리 재질·정적 질의 월드를 준비해요. Actor/Blueprint/C++·Widget·음성·시뮬레이션을 시작하지 않으며 원본 오브젝트에 `gameplayDebug`를 쓰지 않아요. 검사가 끝나면 물리 월드와 서비스 자원을 해제하고 복사한 진단만 보관해요.

장면/에셋 편집 세대, 원본 배열과 대상/기준의 객체 정체성, 풀 활성, 플레이 상태를 검사해요. 변경·숨기기·새 요청은 이전 결과를 폐기해요. 취소할 수 없는 에셋/WASM 준비는 끝까지 기다려 정리한 뒤 다음 요청의 장면 복사본을 만들어요. 동시에 큰 월드 복사본을 여러 개 준비하지 않아요. 임의 에셋 I/O 자체를 중단했다고 주장하지 않아요.

현재는 명시적으로 누르는 수동 검사예요. 전용 TestingPawn 액터·편집 중 자동 재질의·실제 창 표시/장시간 성능 확인은 별도예요. 물리 결과 검사는 소유한 장면의 실제 CPU 질의 백엔드에서 수행하며 DirectX 픽셀·기기 성능 검사를 뜻하지 않아요.
