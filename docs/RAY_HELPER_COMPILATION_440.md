# 좌표 보조 함수의 컴파일 범위

GL·DirectX 셰이더는 머테리얼 패킷의 기존 연산 목록을 이용해 필요한 좌표 변화량 보조 함수만 전처리해요. 보조 함수가 호출하는 함수도 함께 남겨요. 같은 공유 수식에서 호출 관계를 한 번 계산하므로 플랫폼별 의존 목록을 따로 관리하지 않아요. 누락·순환 의존이나 잘못된 생성 함수는 준비 단계에서 거부해요.

실제 DirectX 전처리의 12조건에서 기본 UV·시간·더하기·곱하기 조합은 보조 함수 10개에서 0개로, 보조 라이브러리의 전처리 결과는 4,580바이트에서 254바이트로 줄었어요. 나눗셈·제곱근·길이·정규화·반사·눈 UV의 필요한 의존 함수는 남았어요. [D3DPreprocess의 출력 계약](https://learn.microsoft.com/en-us/windows/win32/api/d3dcompiler/nf-d3dcompiler-d3dpreprocess)에 따라 전처리된 텍스트를 확인했으며, 이 값은 전체 셰이더 크기나 GPU 실행 시간이 아니에요.

다섯 그래프의 GL·WebGPU 현재/이전 밉과 DirectX의 10개 현재/이전 패킷도 대조해요. 이 변경은 기본 수식·샘플러·기하·프레임 이력을 바꾸지 않아요. 내부 진단용 `HB_RAY_DERIVATIVES_ALL`은 전체 보조 라이브러리를 선택할 수 있어요.

같은 밉 그래프의 GL 전체 준비를 한 번 ABBA로 비교한 값은 전체 선택 2,617·2,572ms, 제한 선택 2,636·2,881ms였어요. 이 비교에서 전체 준비 시간의 개선 근거를 얻지는 못했어요. 드라이버 캐시와 컴퓨터 부하도 통제하지 않았으므로 전처리 결과 감소와 실제 준비 시간은 구분해요.

추가 GPU 자원·uniform·운영 readback·디스크 캐시는 없고 프레임마다 함수 목록을 다시 계산하지 않아요. AI는 기존 `engineSchema().raySurfaceHistory.uvFootprint.helperCompilation`에서 같은 계약을 조회해요. 복잡 그래프의 초기 준비, 현재·이전 노멀 평가와 다른 렌더링 작업은 이어서 줄여야 해요.

후속 [네이티브 가이드450](NATIVE_GUIDE_PREPARATION_450.md)에서는 전체 셰이딩 목록 대신 실제 좌표 의존으로 보조 함수를 더 좁혀요. 기존 전체 opcode standalone 방식도 호환해요.
