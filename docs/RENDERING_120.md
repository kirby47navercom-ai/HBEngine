# 120 — 거친 코스틱·점진 반경·WebGPU 누적 보존

기존 GPU 광자 캐시에 거친 유리와 순금속의 GGX 가시 법선 샘플링을 연결한다. 가시 법선 importance 표본의 BSDF×코사인/PDF는 G2/G1로 상쇄하여 같은 값을 두 Smith 마스킹 계수로 계산한다. 독립적인 전체 BSDF/PDF844사례와 최대 오차6.7×10⁻¹⁶으로 대조한다. 유리는 미세면 Fresnel로 반사와 굴절을 선택하고 BSDF·코사인·PDF로 광속을 전달한다. 광원에서 출발하는 중요도 전달이므로 카메라 방사휘도용 IOR 제곱을 적용하지 않는다. 중첩 매질, 전반사, 흡수와 기하 법선의 반구 검사를 유지한다. 금속은 GGX 반사·Fresnel·마스킹을 사용한다. 같은 광원→경계→확산 경로를 카메라 직접광과 발광/HDRI 연결에서 중복 계산하지 않는다. 매끄러운 경계의 기존 처리와 코스틱 비활성 경로는 유지한다.

후처리의 `pathTracingCausticProgressive`는 기본 꺼짐이다. 켜면 기준 반경 R과 유지율 α(`pathTracingCausticAlpha`, 기본2/3, 범위0.1–1)를 사용해 k번째 광자 배치의 반경을 `max(0.0001, R × (1+k)^((α−1)/2))`로 줄인다. k는 누적 샘플 수/프레임당 샘플 수이다. α=1이면 반경을 유지한다. 반경·유지율·transport 변경과 실패는 원본 누적을 초기화하고, 매 프레임 도출되는 반경만으로 누적을 초기화하지 않는다. 수집 커널은 현재 반경의 면적으로 정규화한다.

이 방식은 고정 메모리 배치 밀도 추정이다. 픽셀별 SPPM의 광자 개수·flux·가시점을 저장하는 알고리즘과 구분한다. 기존1024경로·32KiB 캐시와 샘플 상한을 유지하므로 무한 시간의 불편 추정 수렴을 주장하지 않는다. 거친 부분 금속·부분 투과 혼합은 기존 카메라 경로에 남고, 거친 광자는 순금속 또는 완전 투과 경계를 사용한다. 금속의 추가 코팅·sheen·비등방성 광자 전달은 아직 기본 GGX 전달과 구분한다.

WebGPU는 필터·후처리 셰이더 그래프가 바뀔 때 원본 누적 텍스처·샘플 상태·프레임 상태·기하 캐시의 소유권을 다음 그래프에 넘긴다. 이전 그래프는 자신의 필터·광자·패스 자원만 해제한다. transport·렌즈·카메라·크기·장면·실패 변경은 기존 누적 키로 계속 거부한다. 창을 닫거나 경로 추적을 끄면 넘겨받은 자원도 해제한다. GPU 복사나 CPU 읽기를 추가하지 않는다. WebGL 광자 셰이더는 광선·매질·환경 샘플링과 광자 함수만 생성하고, 카메라 패스는 광자 생성과 경로 전용 모드의 불필요한 GI 함수를 제외한다. 반구 표본 등 실제 호출 의존성은 유지한다. 코스틱이 없는 WebGPU 그래프에는 광자 소유권 분기·분류를 생성하지 않아 복잡한 노멀 머테리얼 셰이더 준비 비용을 피한다. 광자의 경계 위치·입사 방향·반사 판정은 진행 방향을 갱신하기 전에 고정해 같은 경계의 매질 판정이 바뀌지 않도록 한다.

사람용 상세 속성·C++ `Components::SetBool/SetFloat`·블루프린트 공용 컴포넌트 속성·`engineSchema()`가 같은 두 속성을 사용한다. AI는 `document.get`의 revision과 대상 ID `test`를 사용하는 `document.patch` 또는 기존 `files.apply`로 편집한다. 실패한 묶음은 원본을 보존한다. 동적으로 도출한 반경은 저장 에셋을 바꾸지 않는다. 새 의존성·설치 백업·GPU 읽기는 없다.

`tools/check-rendering-120.mjs`, 실제 세 렌더러의 `tools/rendering-120-fixture.mjs`와 네이티브118의 공용 검사기를 사용한다. 실제 실행·회귀 결과와 설치 대조는 별도 기계 기록에 남긴다. 누적16프레임은 첫 준비/렌더 요청1회와 이후15프레임 요청으로 구분하며 각 요청의30초 제한과 총64샘플·해상도·픽셀 판정값을 유지한다. 기존의 한 요청 안에 첫 컴파일과16프레임을 모두 묶은 검사에서 혼합 광원의 준비29.5초·이후 약0.13초/캡처를 관찰했다. 이 수치는 경로 추적 검사 장면의 준비/캡처 비용이며 게임 FPS가 아니다. 초기 컴파일 비용이 작다고 주장하지 않는다. 실행 전 검사는 통과로 계산하지 않는다.

참고한 구역은 [PBRT의 거친 유전체 샘플링과 importance/radiance 차이](https://www.pbr-book.org/4ed/Reflection_Models/Rough_Dielectric_BSDF)의 자체 샘플링·평가 구역, [광자 밀도 추정과 점진 반경](https://www.pbr-book.org/3ed-2018/Light_Transport_III_Bidirectional_Methods/Stochastic_Progressive_Photon_Mapping)의16.2.2절과 반경 갱신 구역이다. 연결된 전체 API·Unreal/Unity 전체·실제 휴대폰·게임 전체 FPS 검증과 구분한다.
