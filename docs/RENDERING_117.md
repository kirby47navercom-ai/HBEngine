# 렌더링 117 — 두 단계 BVH·GPU 코스틱·이차 표면 필터

오브젝트 이동, 광원 변경, 유리와 거울을 함께 다룬 변경이에요. 기존 프로젝트 형식과 머테리얼의 `Transmission`, `IOR`, `ClosedVolume`을 그대로 사용해요.

## 기하 갱신

동일한 로컬 기하의 BVH(BLAS)를 여러 인스턴스가 공유해요. 장면 BVH(TLAS)는 인스턴스 경계와 역변환을 가리키며, 광선을 로컬 공간으로 옮겨 탐색해요. 방향을 다시 정규화하지 않아 비균일 크기에서도 광선의 거리 매개변수가 유지돼요. 실제 교차와 머테리얼·UV·닫힌 매질 ID는 기존 월드 삼각형 기록을 사용해요. 따라서 BVH 노드는 공유하지만 월드 교차 기록까지 압축한 구조는 아니에요.

이동은 로컬 정점과 BLAS를 재사용하고, 변형·스킨·모프는 해당 기하의 경계를 다시 맞춰요. 분할 품질이 나빠지면 기존 품질 기준으로 재구축해요. 바뀌지 않은 오브젝트의 월드 삼각형도 재사용해요. 삭제·토폴로지·재질·텍스처·매질 번호 변경은 해당 캐시를 무효화해요. 크기가 0인 인스턴스는 제외하고, 비정상 수치는 이전 atlas를 손상시키기 전에 거부해요. 옛 단일 BVH 패킷도 읽을 수 있어요. 인스턴스가 하나면 기존 단일 트리와 셰이더를 사용해 준비 비용을 줄여요. 발광 표면이 없으면 발광체 샘플링과 PDF 코드를 제외해요. 실제 기존 텍스처 장면의 동일 입력에서 D3D 최적화 수준 3 컴파일은 14,306ms/142,176바이트에서 7,219ms/91,660바이트로 줄었어요. 응답 제한 15초와 최적화 수준은 그대로예요. 다중 인스턴스 패킷은 품질 비트 20으로 두 단계 셰이더를 선택하고, 전체 품질 마스크는 0–2,097,151의 정수만 받아요.

64개 동일 모델의 검사에서는 단일 트리 8,191노드가 두 단계 구조 318노드로 줄었어요. 로컬 정점 호출은 115번이고, 한 오브젝트 이동 때 추가 정점 호출은 0번, 월드 기하 재수집은 1개, 재사용은 63개예요. 이 수치는 해당 검사 장면의 자료구조 비용이며 게임 전체 FPS가 아니에요.

## 코스틱

Post Process Volume의 경로 추적에서 **코스틱**을 켜요. 광원 경로를 128×16 RGBA32F 캐시에 기록한 다음 표면에서 수집해요. 프레임마다 1,024개 광원 경로의 위치·도달 표면과 광속을 기록해요. 캐시는 뷰포트마다 32KiB이며 기본값은 꺼짐이에요. 켜진 상태에서만 만들고 세기 0/비활성/뷰포트 폐기 시 해제해요. 누적 샘플 한도에 도달하면 광원 경로 계산도 멈춰요. CPU 읽기나 디스크 캐시를 추가하지 않아요.

태양광·점·스포트 광원에서 출발한 광선이 매끄러운 유리와 금속을 거쳐 확산 표면에 도달해요. 광원·삼각형 면적의 샘플 확률, 투영 면적, Fresnel·전반사, 닫힌 중첩 매질과 흡수를 적용해요. 광속 전파에는 카메라 방사휘도의 IOR 제곱 보정을 넣지 않아요. 같은 경로의 직선 투과 음영을 중복 더하지 않도록 분석 광원 연결도 조정했어요. 법선·표면 평면·수집 거리로 다른 표면의 광자가 새는 것을 제한해요.

설정은 `pathTracingCaustics`, `pathTracingCausticSamples`(수집 샘플 1–64), `pathTracingCausticRadius`, `pathTracingCausticStrength`예요. 같은 컴포넌트 속성을 편집기·블루프린트의 컴포넌트 Get/Set·C++ `Components`·AI 원자 작업에서 사용해요. 설정 변경은 경로 이력을 초기화해요.

코스틱은 유한 반경의 밀도 추정이므로 작은 반경에서는 노이즈가 늘고 큰 반경에서는 무늬가 퍼져요. 면 광원·HDRI에서 출발하는 코스틱, 거친 표면 광원 경로, 점진 반경 축소·공간 해시·완전한 양방향 MIS는 포함하지 않아요. 기존 면 광원/HDRI 카메라 경로 추적은 유지해요.

## 이차 표면 디노이저

유리·금속·날카로운 코팅에서 중앙 광선을 따라 실제로 보이는 다음 표면을 찾아요. 반사 연쇄에서는 법선을 역순으로 반사시켜 같은 공간에서 비교해요. 주 표면과 이차 표면을 서로 섞지 않고, 법선·이차 거리·밝기 차이로 필터 경계를 보호해요. 첫 이차 구간의 거리를 사용하며 전체 경로 길이를 누적하지 않아요. 닫힌 매질, 전반사, 불완전한 탐색·배경·예산 종료를 처리해요.

최종 표시만 필터링하고 몬테카를로 이력에는 원본을 저장해요. 필터 세기 0은 원본과 같아요. 시간 재투영 NRD 통합·곡률 보정·확산/반사 신호 분리·확률적 렌즈 심도 필터는 포함하지 않아요. 렌즈 심도와 가이드가 없는 경로는 원본으로 유지해요.

## 검증과 근거

최종 검사·설치 자료는 [기계 기록](research/RENDERING_117.json)과 별도 설치 영수증에 있어요. 초기에 전체 화면에서 광원 경로를 반복해 WebGPU가 중단된 실패도 보존해요. 작은 GPU 광자 패스로 분리한 뒤 같은 전체 해상도에서 다시 검사해요. 광자 RTT에는 별도 함수 인스턴스를 사용해 Three r180의 여러 셰이더 빌더 간 바인딩 공유를 피했어요. 기본 구의 바닥 피벗도 검사 위치에 반영했어요. 검사 제한 시간을 늘리거나 해상도를 낮추지 않아요.

읽은 근거는 지정 구역이에요: [NVIDIA의 TLAS 갱신](https://developer.nvidia.com/rtx/raytracing/dxr/dx12-raytracing-tutorial/extra/dxr_tutorial_extra_refit)의 본문 앞부분 1–16행, [PBRT의 광자 밀도 추정](https://www.pbr-book.org/3ed-2018/Light_Transport_III_Bidirectional_Methods/Stochastic_Progressive_Photon_Mapping)의 16.2.2절 선택 구역, [NRD의 이차 거리·PSR 지침](https://github.com/NVIDIA-RTX/NRD)의 Hit distance와 Primary Surface Replacements 구역이에요. 개념을 참고한 자체 구현이며 DXR·OptiX·NRD 라이브러리를 설치하거나 통합한 것은 아니에요. 연결된 전체 API·코드·그림과 Unreal·Unity 전체 문서 분석으로 계산하지 않아요.
