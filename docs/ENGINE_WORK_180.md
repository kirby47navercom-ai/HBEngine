# 180 — C++ 물리 질의 재사용과 배포 크기 절감

C++ 호출마다 만들던 질의 전용 Rapier 월드와 형상을 게임 세션별로 재사용한다. 여러 C++ 클래스가 월드 하나를 공유하며 각 질의는 승인된 객체·인수·호출당128회 제한을 다시 검증한다. 불변 스냅샷 설치와 질의를 직렬화해 동시에 서로 다른 좌표를 조회해도 섞이지 않는다. 같은 함수에서 직접 바꾼 Transform도 반영한다. 게임 시뮬레이션을 대신 진행하지 않는다.

유휴 월드는 백엔드당 하나만 보관한다. 활성 호출에 별도 총 개수 제한을 추가하지 않는다. reset은 해당 세대를 무효화하고 이전 호출 소유자가 끝나면 해제한다. 마지막 C++ 모듈 해제·호스트 종료·웹/모바일 페이지 종료도 정리한다. NativeHost 자원 진단과 C++ 응답 transport의 physicsQueryMs/physicsQueryCount/physicsCacheReused로 AI와 사람이 비용을 확인할 수 있다.

같은8192삼각형 C++ 함수/worker/Node 프로세스에서 캐시 보관을 번갈아 비교했다. 준비된 RPC는 약16–17ms에서8.9–9.7ms, 물리 질의 구간은 약9–10ms에서1.8–2ms였다. 초기 라이브러리 준비와 전체 스냅샷 전달/복제 비용은 별개로 남아 있다. 이 표본을 게임 FPS나 휴대폰 성능으로 환산하지 않는다.

Windows·모바일·웹 게임 패키지는 설치된 Three의 공식 최소화 배포 파일을 공용 함수로 수집한다. 런타임 URL·MIT 표기·GL/WebGPU의 공용 core 정체성을 보존하고 에디터 원본과 게임 그림은 바꾸지 않는다. 해당 라이브러리4개는2592217바이트 줄었고 모바일 검사 패키지는15145959→12553711바이트가 됐다. 기존15MB 검사 기준은 그대로다.
