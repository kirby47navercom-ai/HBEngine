# 구조체·열거형 라이브러리

콘텐츠 브라우저의 **만들기 → 데이터 → 구조체·열거형 라이브러리**에서 생성해요. 하나의 `.hbtypes.json` 안에 관련 열거형과 구조체를 함께 제작해요. 중첩 값과 배열을 쓰는 여러 구조체를 한 헤더로 관리해요.

- 라이브러리 편집기에서 선언·필드를 추가하고 C++ 이름, 표시 이름, 설명, 기본값을 편집해요. 열거형은 명시적인32비트 값·비트 플래그·숨김 항목을 지원해요.
- 필드는 기본 값 타입, 같은 라이브러리의 열거형·구조체, 배열을 지원해요. Actor/Hit의 선언 기본 참조는 `null`이에요. 블루프린트 인스턴스에서는 기존 Actor ID/`self` 참조를 사용해요.
- 저장은 원본과 `Source/HBGenerated/Types_<라이브러리ID>.hpp`를 기존 트랜잭션으로 함께 반영해요. 생성 헤더를 직접 수정했다면 덮어쓰지 않고 충돌을 알려요. 원본·헤더 중 하나만 저장된 상태를 성공으로 보고하지 않아요.
- 생성 헤더를 사용자 C++ 헤더에서 `#include "HBGenerated/Types_<라이브러리ID>.hpp"`로 포함해요. 실제 이름과 namespace는 편집기 상단과 원본의 `id`·`namespace`로 확인해요. 공개 `HB_PROPERTY`·`HB_FUNCTION`에 `<namespace>::<구조체>`를 쓰면 기존 Make/Break/Set, 변수·인자·출력·배열·인스턴스 편집, C++ 빌드와 패키징에서 같은 정의를 사용해요.

표시 이름·설명·기본값은 바꿀 수 있어요. 저장된 UUID, namespace, C++ 심벌, 필드 타입·배열 여부·기존 순서, enum 숫자는 조용히 바꾸지 않아요. 새 선언과 필드는 추가할 수 있어요. 기존 제작 값에는 [새 필드 이관](NATIVE_TYPE_MIGRATION.md) 규칙으로 기본값을 채우고 원본·생성 헤더·연관 문서를 기존 checked-batch로 함께 저장해요. 자동 삭제·이름/타입 이관은 이 기능에 포함하지 않아요.

## 소유와 비용

`native-type-assets.js`가 JSON→헤더→기존 리플렉션 파서 검증을 소유해요. 별도의 C++ ABI나 BP 값 체계를 만들지 않아요. `native-type-asset-write.mjs`가 원본/생성 헤더의 원자적 쓰기와 외부 변경 검사를 연결해요. 프로젝트 저장 큐·트랜잭션 복구·Source include closure·네이티브 빌드/게임 패키징 경로를 재사용해요.

UUID는 타입·필드·enum 항목에 따로 남고, 숫자 enum 값과 C++ 심벌을 표시 이름과 구분해요. 문서 API로 사람이 편집하는 원본을 AI도 읽고 수정할 수 있어요. 추가 런타임 타이머·Worker·GPU 자원·전역 타입 DB는 없어요. 기존 헤더100KB/기본값·배열·중첩 예산을 유지해요.

중첩 구조체의 새 멤버와 미저장 필드 편집은 [기본값 편집 규칙](NATIVE_TYPE_DEFAULT_EDITING.md)을 사용해요.

이 기능은 C++에 연결하는 공유 타입 제작 경로예요. C++ 클래스 없이 사용하는 제작 경로는 [블루프린트 타입 가져오기](NATIVE_TYPE_IMPORTS.md)에 연결해요. 별도 enum/struct 에셋, 프로젝트 전역 자동 발견, 임의 스키마 이관·다형 클래스/참조 identity는 누적 원장에 남겨요. 기존 `HB_STRUCT`·`HB_ENUM` 소스와 값·Actor 참조 계약은 유지해요.

근거는 [1652 연구 메모](research/TYPE_DATA_ASSETS_1652.md)의 선택 본문과 기존 구현이에요. Unreal·Unity 전체 문서/API 분석 완료를 뜻하지 않아요.
