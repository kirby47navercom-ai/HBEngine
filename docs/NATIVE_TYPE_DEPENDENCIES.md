# 에셋 간 구조체·열거형 참조

구조체·열거형 편집기의 **가져온 자료형**에서 다른 타입 에셋을 추가해요. 필드의 자료형 목록에는 직접 가져온 에셋과 그 의존 에셋의 선언이 `namespace::이름`으로 표시돼요. 필드는 기존 `typeId`를 그대로 참조해요. 선언을 복사하거나 다른 에셋의 필드를 현재 파일에 붙이지 않아요.

```json
"imports": ["Assets/Types/E_State.hbenum.json", "Assets/Types/F_Damage.hbstruct.json"]
```

자체 라이브러리·개별 구조체·개별 열거형 모두 사용할 수 있어요. BP는 상위 에셋만 `native.typeLibraries`에 넣으면 그 의존 타입도 사용할 수 있어요. 다이아몬드 의존성과 BP에서 상위·하위를 함께 가져오는 경우에는 같은 경로의 선언을 한 번만 합쳐요. ID·namespace가 같은 별도 에셋은 오류예요.

생성 C++ 헤더는 UUID가 유지되는 의존 헤더를 `#include`하고 원래 namespace의 자료형을 사용해요. 기존 `HB_STRUCT`·`HB_ENUM`, 값 record·배열·Actor ID 계약과 C++ codec을 공유해요. 패키징은 실제 참조한 타입 에셋과 헤더를 포함해요.

하위 구조체에 멤버를 추가해 저장하면 상위 에셋의 단일·배열 기본값, 생성 헤더, BP·장면·프리팹·시퀀스의 기존 선언 값이 같은 저장 계획에 들어가요. 기존 값은 보존하고 새 멤버만 채워요. 연관 문서에 미저장 편집이나 생성 헤더에 외부 수정이 있으면 저장을 거절해요. 미리보기의 plan revision·CAS와 한 묶음 Undo/Redo를 사용해요. 파일·폴더 이동 뒤 기존 프로젝트 redirect도 읽을 수 있어요.

AI는 같은 `document.get`/`document.patch`/`document.save`와 파일 묶음 API를 사용해요. `schema.nativeTypeDependencies`에 계약이 있어요. 패치는 로컬 선언·값의 형태를 확인하고, 준비·저장·실행·패키징에서는 전체 의존성을 읽어 누락·순환·중복·실제 기본값 자료형을 검증해요. 로컬 패치 성공을 전체 import 검증 성공으로 해석하지 않아요. 예를 들어 존재하지 않는 import는 저장 전에 거절되고 원본 파일은 유지돼요.

직접·전체 의존성은 각각32개, 깊이16, 원본 합계8MB와 기존 합성 선언/값 예산을 유지해요. 작업 단위 Map만 사용하고 새 Worker·타이머·상주 전역 레지스트리는 만들지 않아요. 의존 그래프 읽기와 생성 헤더 검증은 저장·준비 비용이며 FPS 향상으로 계산하지 않아요.

프로젝트 전체의 자동 타입 발견, 저장된 심벌·자료형의 파괴적 변경, 임의 C++ 스키마 이관, 실행 중 ABI 교체는 별도예요. 기존1652의 선택 문서 읽기를 재사용한 HB 자체 계약이며 두 엔진의 전체 기능/API와 동일하다는 뜻은 아니에요.

1919–1921: [프로젝트 타입 선택](NATIVE_TYPE_CATALOG.md)에서 타입 에셋 목록을 자동 발견하고 BP 변수/미저장 구조체 필드에 필요한 참조와 함께 적용해요. 임의 C++ 헤더·런타임 전역 레지스트리와 구분해요.
