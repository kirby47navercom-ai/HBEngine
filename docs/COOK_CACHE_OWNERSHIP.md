# 쿠킹 캐시 공유와 임시 파일 소유권

JSON 최소화 캐시 v3의 키는 버전·대상 플랫폼·원본 바이트 SHA예요. 파일 경로가 달라도 이 세 값이 같으면 같은 디스크 항목을 사용해요. 한 번의 cook에서도 같은 내용을 다시 파싱하거나 읽지 않아요. 반환 Map의 각 JSON Buffer는 독립적이므로 한 경로의 수정이 다른 경로를 바꾸지 않아요. 불투명 파일은 기존 디스크 descriptor/Buffer를 그대로 통과시켜요. 원본 에셋을 바꾸거나 GPU 압축 형식을 새로 만드는 변경은 아니에요.

캐시 본문의 SHA를 확인하고 잘림·손상은 원본으로 재생성해요. 기본128MiB/사용자 지정 LRU 예산을 유지하며 0이면 반환 데이터만 유지하고 캐시 파일을 지워요. v2 파일은 보통 LRU 항목으로 남아 예산에 따라 제거돼요. 전체 캐시를 복사하거나 백업하지 않아요. 잘못된 예산·시작 전 취소는 폴더를 만들기 전에 거절해요.

새 임시 이름은 내용 키·PID·호스트 식별 해시·UUID를 담아요. 게시 전 취소/오류는 자기 임시 파일을 정리해요. 중단된 임시 파일은 기본1시간이 지났고 같은 호스트의 프로세스가 종료됐으며 일반 파일의 identity/크기/수정 시각이 그대로일 때만 지워요. 실행 중 PID·다른 호스트·최근 파일·소유자를 알 수 없는 과거 형식은 보존해요. 캐시 이름의 디렉터리/링크를 본문으로 읽거나 LRU로 지우지 않아요.

여러 저장이 같은 결과를 게시할 때 Windows가 파일 사용 충돌을 반환하면, 기존 파일의 digest와 실제 본문이 이번 결과와 모두 같은 경우에만 그 결과를 재사용해요. 다른 결과나 검증 실패를 성공으로 숨기지 않아요. 사용자 에셋 저장/트랜잭션을 대신하는 기능은 아니에요.

신규13개는 동일100경로/플랫폼·소스 분리/독립 Buffer/손상 복구/취소·예산/8동시 저장/실제 child 강제 종료/소유권별 임시 보호/기존 LRU를 확인해요. 모든 프로젝트는 소유 test-artifacts에 격리돼요. 배포기 전체 검사(보호된 실행기 파일 포함)·SDK·GUI/GPU·기기·FPS를 새로 실행한 것은 아니에요. 모델/텍스처 압축·RDO·전체 종속 쿠킹은 별도예요.
