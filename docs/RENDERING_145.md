# 145–150 — 초기 준비·가상 경로·머테리얼 계획·취소·프로파일러·C++ 진단

## 145 — 반복 노멀과 좌표 계산

복잡 UV+Shift+텍스처+normalMap 장면의 WebGPU 시간 필터 준비를 다시 측정했다. 수정 전 설정 호출/캡처/준비는8,767ms였다. 주변 광선의 노멀·방향·굴절 결과를 지역 변수로 고정하고, 이전 위치 보간은 검증된 공용 barycentric 함수를 사용한다. 이전 법선의 행렬·기하 로드와 투영 결과도 공유한다. 렌즈가 없는 변형에서는 실제 차분 수와 같은2칸을 선언하며, 렌즈에서는4칸을 유지한다. 기존 표본·최대 반사/굴절 횟수·해상도·픽셀/시간 제한을 유지한다.

지정 생성 WGSL의 노멀 호출 지점은11→2, 위치 슬롯1 접근은15→4, 소스는68,865→58,086B로 줄었다. 최종 실제 WebGPU 시간 필터 설정은2,528ms, 그중 lens-motion-guide 준비는2,026.8ms였다. 같은 재현의 첫 경로 추적 활성화는3,728ms였다. 서로 다른 준비 단계를 혼동하지 않으며 전체 최초 실행이2초 미만이라는 뜻이 아니다. 드라이버 내부 캐시를 강제로 지운 측정도 아니다.

## 146 — 역순 배열 대신 누적 변환

가상 경로 복원의 기존 평면 변환을 `F(p)=plane+S*(p-plane)`로 둔다. 반사에서 `S=I-2nnᵀ`, 굴절에서 `S=eta*I`다. 기존 코드는 평면·법선·eta·종류를 저장한 뒤 마지막 지점에서 역순으로 적용했다. 새 코드는 순방향에서 `(A,t)←(A*S, t+A*(plane-S*plane))`를 누적하고 마지막에 `A*p+t`를 계산한다. 곱셈 순서는 같으며 이전/현재의 두 경로와 법선 반사 복원에 같은 방법을 쓴다. 곡면과 매질 분기 판정은 기존 계산을 유지한다.

GLSL·생성 HLSL·TSL에 공통 수학을 적용한다. 이전/현재 경로의 평면4배열·eta/종류2배열, 역순 루프를 제거한다. 해당 선언의 스칼라는224→24개다. 이는 셰이더 지역 값 선언 비교이며 실제 레지스터·스필·총 GPU 메모리의 바이트 측정은 아니다. 추가 이미지·버퍼·CPU↔GPU 전송은 없다. 기존16bounce·8mirror 거부 기준도 유지한다.

독립 검사는 기존 역순 반사/굴절 계산을 기준으로0/1/2/3/4/8/12/16단계를 대조한다. WebGL·WebGPU 실제 float32 회수의24성분 최대 오차는약1.31e-6이다. 이 회수는 격리된 검사에서만 수행한다. 실제 경로 추적·모프·렌즈/시간 필터는 기존125/134/138/141 재현으로 별도 검증한다. 전역 곡면 역해를 새로 해결했다는 의미는 아니다.

## 147 — 공유 머테리얼의 CPU 검사

한 번의 `rayShaderPlanForScene()` 순회에서 같은 가시 머테리얼은 한 번만 검사·합산한다. 메시/인스턴스 수와 BVH 모드 판단은 계속 모든 객체를 센다. 다음 순회에서 속성·그래프·샘플러·텍스처를 다시 확인하므로 편집 변경을 누락하는 장기 버전 캐시는 없다. 가시성/2D/helper 제외 조건과 프로그램 충돌 검사를 유지한다.

4,097개 실제 Three 메시가 머테리얼 하나를 공유하는 CPU 재현에서 서명 조회는4,097→1회였다.12번 교대 쌍·각3회 호출의 순회당 평균은6.06→0.102ms였다. 이 값은 계획/서명 단계만의 측정이며 전체 장면 FPS나 모든 고유 머테리얼 장면의 성능으로 확대하지 않는다. 함수 결과의 독립 구버전 대조와 transmission 변경/복원도 검사한다. 객체 제한을 추가하지 않는다.

## 148 — 오래된 준비 대기 취소

`cancelGPUPathPreparation()`은 오래된 준비의 대기자를 즉시 깨운다. `waitForGPUPathPreparation()`과 캡처는 현재 준비를 다시 확인한다. 이전 드라이버 작업 자체를 강제 중단하는 API가 아니며, 늦게 도착한 결과/실패는 취소된 작업의 종료 처리로 회수한다. 현재 작업의 실패는 그대로 전달한다. 화면/옵션 교체와 종료에서 같은 취소 함수를 사용한다. 기존 렌더러 상태 복원·준비 중 무드로 계약을 유지한다.

한 준비당 취소 Promise 하나만 보관한다. 실패를 숨기는 재시도·대기 시간 연장·GPU 읽기·디스크 캐시는 없다. 이전 작업이 아직 끝나지 않은 상태에서 대기가 해제되고, 늦은 거절도 처리되며, 최신 화면이 재캡처되는 것을 검사한다.

## 149 — 사람과 AI의 같은 프로파일러

기존 프로파일러 안에 셰이더 준비 표를 추가한다. 현재 상태·단계·시간과 네이티브 컴파일/재사용/8MiB 계상 캐시를 보여준다. GPU 실행 시간과 CPU/드라이버 준비 대기를 혼동하지 않도록 표기한다. 별도 HUD·메인 화면 안내·새 창/타이머는 없다. 가시 프로파일러의 기존 갱신을 사용한다.

`profiler.read`와 JSON 내보내기의 `rendering[]`는 같은 제공자를 사용한다. 프레임 기록을 켜지 않아도 최신 상태를 읽고, 프레임300개 제한과 별개로 렌더러당 최신 준비만 조회한다. 같은 렌더러를 공유하는 창은 중복 집계하지 않는다. 진단은 머테리얼/컴포넌트/블루프린트의 revision·Undo·저장 데이터를 수정하지 않는다. 기존 C++ 게임 코드와 머테리얼 API는 유지한다.

## 150 — 실제 C++ 빌드 결과 조회

`native.build` 응답에 실제 `compiler`와 `workerProtocol`을 추가한다. 기존 built/path/owner와 빌드/검증 흐름은 유지한다. 파생 빌드 메타데이터를 저장 에셋에 복제하지 않고 현재 빌드 결과에서 읽는다. 외부 C++ 소스 참조만 저장된 그래프의 연결은 기존 `blueprint.connect`가 workspace의 해석된 메타데이터를 사용한다. 사용자와 AI가 같은 타입/연결 검증을 사용하며 별도 AI 저장 모델은 없다.

오래된 검사 도구가 저장 데이터에 클래스 목록/workerProtocol이 남아 있다고 가정하던 부분을 이 공용 API로 대조하도록 바꿨다. 수정 전 같은 실행에서2D 물리·입력·일시정지·장면 전환·복구는 통과했고, 이후의 오래된 C++ 검사 가정에서 실패했다. 실패를 보존하고 실제 BeginPlay·입력·재실행과 편집 원본 복원까지 다시 확인한다.

## 증거와 다음 작업

소스·수치·실제 실행·UI·설치 결과는 `docs/research/RENDERING_145.json`, `USER_INSTALL_145.json`에 분리해서 기록한다. 초기 수정에서 렌즈 없는2칸 배열의 사용되지 않는 CoC 분기에 고정 인덱스2/3이 남아 WGSL 검증에 실패했다. CoC 코드 생성 자체를 렌즈 변형에 한정해 수정했고 실패 기록을 보존한다. 허용 오차나 시간 제한을 늘리지 않는다.

프로파일러 검사는 프레임 기록 없이 준비 표/AI 값을 읽고 장면 revision 보존·수정/Undo/저장을 확인한다. 처음에는 기존 EDITOR_BUSY 거부와 복원 문서 저장 누락에 걸렸고, 마지막 화면 검사에서는 빈 차트가 작은 창의 표를 가리는 문제를 찾아 고쳤다. 빈 차트/요약을 접고 첫 행이 실제 패널 안에 완전히 들어오는지 검증한다. 단순 DOM 문자열 검사만으로 화면을 통과 처리하지 않는다.

남은 초기 비용은 WebGPU 가이드 약2초와 첫 path 준비, WebGL 경로/시간 필터의 드라이버 컴파일이다. 이후 우선순위는 GL 비동기 준비/동일 단계 진단, 이전 애니메이션 노멀 표본·mip 보존, 전역 곡면 역해와 거친 다중 로브다. 기존2D·제작 도구·게임 시스템·C++/BP·플랫폼·배포·실기기·경량화 목표와 corpus/API 분석 gate는 계속 유지한다. 이번 검사로 전 분야 완료를 선언하지 않는다.
