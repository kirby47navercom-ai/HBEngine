# C++ 의존 캐시와 광원 타일 준비

GCC의 [전처리 옵션 본문](https://gcc.gnu.org/onlinedocs/gcc/Preprocessor-Options.html) 중 `-M/-MM/-MF/-MT/-MQ/-MD/-MMD` 구역을 읽었어요. `-MM`은 시스템 헤더에서 간접 포함한 파일도 제외할 수 있으므로 시스템 의존성까지 보고하는 `-MD`를 사용해요. 원문 지문·읽은 구역·미독 연결 문서는 `CORPUS_MANIFEST.supplemental572`와 `native/build/research-572/reading.json`에 있어요. 전체 매뉴얼이나 Unreal·Unity 전체 본문/API 분석 완료로 계산하지 않아요.

`nativeSDKFingerprint`의 기본 전체 파일·내용·경로 해시는 유지해요. 새 캐시는 실제 worker와 모든 사용자 소스의 전처리를 해당 최적화 옵션으로 실행해요. include 목록뿐 아니라 전처리 결과 지문도 사용해, 파일을 include하지 않고 `__has_include`로 존재만 검사한 분기도 감지해요. 임시 생성 디렉터리 이름은 지문에서 정규화해요. 변하지 않은 SDK와 소스 조합은 작은 의존 계획을 재사용하고 전처리 프로세스를 다시 실행하지 않아요.

일반적인 절대 경로 GCC 실행 파일은 내용 지문도 키에 포함해요. 커스텀 include 환경·지원하지 않는 발견·잘못된 출력은 이전의 전체 SDK 지문으로 돌아가요. 이것이 전체 컴파일러 설치·표준 라이브러리·외부 선택 파일을 모두 감시한다는 뜻은 아니에요. 그 범위는 잔여 분석에 유지해요.

v4 모듈 키를 사용하고 기존 v3 실행 파일·디버깅 소스·참조 보호는 보존해요. 실제 모듈은 기존 최근32개/실행·참조 보호 정리를 유지하고, 의존 계획은 별도로32개/2MiB 안에서 원자 게시해요. 전처리 결과는 한 번에 한 번역 단위씩 처리하고32MiB를 초과한 결과는 채택하지 않아요. 결과와 임시 생성 파일은 처리/취소/실패 뒤 정리해요. 중단된 소유 프로세스의 임시 디렉터리는 다음 발견 때 정리하고 살아 있는 프로세스의 것은 보존해요. SDK 원문을 계획 캐시에 복사하지 않고 프레임 중 파일 작업도 추가하지 않아요.

실제293 검사에서 값17→31의 같은 크기·mtime 헤더 변경은 새로 컴파일됐고, 사용하지 않는 렌더링 헤더 수정은 같은 실행 파일을 재사용했어요. 최종 관찰은 변경 빌드10499.2ms, 미사용 헤더 수정604.9ms, 동일 입력 재방문43.8ms예요. 한 번씩의 빌드+함수 실행 관찰이며 게임 FPS나 통계적 속도 보장은 아니에요.567은 여러 번역 단위·최적화·Make 경로 이스케이프·조건부 include와 존재 전용 분기·보수적 복귀·취소·계획 상한을 검사해요.

광원 타일의 `Cull` 바이트코드도 기존 단일 지연 워커에서 만들고 소유 렌더 스레드에서 GPU 셰이더로 채택해요. GPU 생성 거부 시 새 컴파일로 한 번 재시도해요. 이 작업은 장치·컨텍스트·렌더러 포인터를 워커에 전달하지 않아요. 준비 중이거나 준비 실패 시 전체 광원 fragment 경로를 사용하므로 광원을 생략하지 않아요. 같은 조명을 그리므로 이 최적화 준비만을 이유로 시간 이력을 막지 않아요. 기본 동기 SDK 호출도 유지해요.

569는 실제 DirectX에서513개 광원의 준비를 막아 두고 기준 전체 광원 영상과 픽셀을 비교해요. 대기 중 카메라/광원 변경, 준비 후 같은 픽셀, 정적 dispatch 재사용, 비활성/취소/재활성, 유휴 워커·큐0을 확인했어요. 읽기 회수는 검사에서만 수행하고 자동 GPU readback은 추가하지 않아요. 진단은 `shaderPreparation.raster.lightCulling`과 기존 `hbDiagnostics`에 있어요. AI에는 `engine.schema.nativeSDKPlans`, `nativeShaderPreparation.lightCulling`, 빌드 응답의 `sdkUsed`를 제공해요.

Windows PE 디버그 섹션 압축은 지원되지 않았어요. 처음의 절대 Unicode 경로 실패와 상대 경로 재검사에서 확인한 미지원 결과를 구분해 기록했어요. 원본 모듈 지문을 보존하고 두 임시 EXE만 정리했으며 압축을 제품 최적화로 세지 않아요. 기본 래스터/다른 셰이더의 최초 동기 준비·전체 GL/FXC 시간과 누적 엔진 원장의 다른 작업은 이 변경으로 완료 처리하지 않아요. 실제 설치·게임 실행 결과는 별도 설치 기록에 연결해요.
