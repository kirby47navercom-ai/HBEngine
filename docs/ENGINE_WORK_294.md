# 294 · 프로젝트 저장 내구성

- 일반 파일/인덱스 저장에도 flush:true·고유 배타적 임시 파일·성공 교체 후 회수 정책을 적용했어요. 기존 고정 .tmp 잔여 파일을 따라가거나 덮어쓰지 않아요.
- 별도 프로젝트에서 ENOSPC/EPERM·큐 복구·이전 임시 파일 보존·flush 이후 rename 전 실제 소유 Node 종료와 재열기7조건을 확인했어요. 기존17조건 그룹 저장/복구/외부 충돌과 효과 종속 저장5조건도 통과했어요.

검증 범위:

- flush/원자적 rename 개별 저장의 검사예요. 물리적 전원 차단·디스크 컨트롤러 캐시·모든 파일시스템·구버전 이행을 재현한 검사가 아니에요.
- 일반 파일과 인덱스 둘의 단일 transaction 보장은 추가하지 않았어요. 교체 완료 뒤 index 기록 실패/중단의 안정 ID 복원도 잔여로 유지해요.
- 주인님 설치본이 실행 중이어서 설치 전환과 무거운 후속 검사는 보류해요. 소유한 숨김 Node만 종료했어요.
