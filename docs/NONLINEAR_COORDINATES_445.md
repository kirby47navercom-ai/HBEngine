# 비선형 머테리얼 입력의 밉 이력

거듭제곱·Exp2·Log2·Smoothstep·노멀 디코딩·Fresnel·원형/선형 그라디언트에서도 픽셀 폭을 상대 변화량으로 전달해요. 현재 프레임과 저장된 이전 프레임이 같은 수식을 사용해요. 값에 작은 폭을 더한 뒤 원래 값을 빼는 과정에서 폭이 0으로 사라지는 문제를 줄여요.

작은 지수·로그 변화는 log1p/expm1 항등식과 작은 구간의 다항식으로 계산해요. 큰 변화는 원래 연산을 사용해 로그·지수를 왕복할 때의 오차를 피하고, 로그/분모/지수의 기존 경계를 유지해요. Smoothstep은 제한된 좌표의 유한 변화에 대한 3차 항까지 계산해요. 노멀은 강도를 임의로 제한하지 않으며 길이가 0인 디코딩의 중립값도 유지해요. Fresnel과 그라디언트에는 단위 벡터·경계·반지름·각도의 변화가 포함돼요.

실제 GL·WebGPU·DirectX에서 40연산 699조건을 독립 배정밀도 기준과 대조해요. 기존 573조건의 기준은 유지하고 새 sub-ULP 조건은 1e-10을 사용해요. 큰 거듭제곱 출력 약 6,305인 새 조건만 작성 때부터 2e-3 절대 기준을 사용하며, 최종 오차는 약 8.5e-4였어요. 이것을 작은 출력의 오차 기준으로 확대하지 않아요. 그래프와 텍스처 샘플러 검사는 수학식 검사와 별도로 현재/이전 패킷·밉 폭을 대조해요.

기존 연산 목록으로 필요한 보조 함수와 의존 함수만 선택해요. 새 함수가 이름 규칙을 벗어나 라이브러리에서 조용히 빠지는 경우도 거부해요. 추가 GPU 자원·uniform·운영 readback이나 프레임별 소스 분석은 없어요. AI의 `engineSchema().raySurfaceHistory.uvFootprint.stableOperations`도 같은 연산을 공개해요.

노이즈·체커 좌표는 아직 shifted-input 경로를 사용해요. 표현할 수 없는 작성 UV/시간, 극단적인 중간 범위, 0 벡터에 대한 원래 normalize/pow의 미정의 구간을 포괄하는 정확성 주장은 하지 않아요.

별도의 `ray-mixed-normal-context.js`는 초기 컴파일을 줄이기 위한 실험이에요. 공통 그래프 본문과 현재/이전 기하 문맥을 공유하고 가이드의 노멀 호출을 묶어요. 17포즈×3문맥의 GL 원본 대조와 한 번의 준비 ABBA는 통과했지만, 기본 렌더러에는 적용하지 않았어요. DirectX·TSL·전체 가이드 영상과 부하를 통제한 준비 시간까지 확인한 뒤 채택할 대상이에요.
