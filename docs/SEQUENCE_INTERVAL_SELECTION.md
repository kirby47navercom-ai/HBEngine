# 재생 중 시퀀스 구간 선택

2026-10-22. `IntervalSelectionIndex`는 Play 때 캡처한 클립들에서 시간별 승자를 한 번 준비하고, 재생/Seek에서는 이진 탐색으로 선택해요. 구간은 `[start, start+duration)`이고 겹친 클립은 기존 배열에서 먼저 나온 클립이 이겨요. 클립이 32개 미만이면 원래 순서의 간단한 순회를 유지해요. 우선순위가 달라지는 경계만 저장하고 같은 승자의 연속 구간은 합쳐요. 포인트 조회는 배열 생성·정렬·전체 클립 순회를 하지 않아요.

`SequenceSampler`의 audio/animation 트랙은 이 색인을 소유해요. 활성 클립의 ID 조회는 교체/종료 때만 원래 배열을 확인해요. 키프레임·회전·이벤트 샘플러와 같은 Play 캡처 수명을 사용하며, 에셋을 편집하고 다시 재생하면 새로 만들어요. Stop 뒤 전역 캐시에 남기지 않아요. 새 워커·타이머·GPU 리소스·파일 접근은 없어요.

`SequenceSectionSampler`는 muted를 제외한 shot만 준비해요. 선택 순서는 기존과 같은 row 오름차순, start 내림차순, ID 오름차순이에요. 한 부모를 샘플링할 때 현재 샷을 한 번 선택해서 모든 자식이 공유하고, 자식의 이벤트 범위를 나눌 샷 경계도 한 번 정렬해 둬요. 매 자식마다 모든 샷을 filter/sort하거나 경계 전체를 flatMap/정렬하지 않아요. 순수 함수 `selectedShot`, `sectionRanges`는 비교 기준과 기존 호출 호환을 위해 남아 있어요.

sourceStart·rate·loop·mute·샷 우선순위·끝 제외·첫 이벤트·동일 시간 구간·뒤로 Seek의 의미를 보존해요. 이 색인은 이길 클립/샷 한 개를 고르는 재생용이에요. 편집기에서 겹친 클립을 모두 표시하는 `TimelineIntervalIndex`와 역할이 달라요. 원본 에셋 형식이나 제작 한도를 늘리는 변경은 없어요.

검증은 `tools/check-sequence-interval-selection-1541.mjs`를 사용해요. 65,536개 희소 구간의 마지막 클립 조회에서 전체 항목 방문 0·이진 비교 16회였고, 모두 겹친 경우에도 원래 첫 클립과 한 승자 구간을 유지했어요. 이는 순수 알고리즘 스트레스이며 실제 에셋 제작 한도나 FPS 수치가 아니에요. 실제 유효한 64클립 게임 데이터의 앞/뒤 Seek·끝의 stopSound·오프셋·Stop 소유권 해제도 검사했어요. 음향 호출 훅 검사와 실제 기기 소리 검증은 구분해요.

묶음 검사에는 기존 15개 중첩/loop/우선순위 경우, 실제 애니메이션 채널 소유권 3경우, 이벤트 색인의 140경우, 저장 프로젝트의 Windows D3D11 중첩 재생을 포함해요. 몽타주 클립/루트모션 조회, 겹친 구간의 편집기 표시 밀도, 더 큰 애니메이션 제작 기능은 별도 잔여예요.
