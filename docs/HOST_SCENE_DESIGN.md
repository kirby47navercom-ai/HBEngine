# C++ 호스트 장면 전환 설계 (2026-11-14)

## 목표

- 1만 개 1000FPS, 10만 개 240FPS 이상.
- 변하지 않은 오브젝트에는 프레임 작업이 없어야 해요(JS도 C++도 오브젝트마다 도는 일이 없어야 해요).
- AI가 다루는 쪽(게임 로직, 편집기, 블루프린트 연결)은 JS에 그대로 둬요. 매 프레임 많은 오브젝트를 도는 핵심만 C++로 내려요.

## 현재 구조와 한계

- C++: 창, D3D11·D3D12 그리기, 셰이더, 그리기 기록 보관(`SceneRenderBridgeCore`).
- JS(내장 V8): 장면 트리(three.js), 행렬 갱신, 화면 밖 판정, 묶음, 정렬, 그리기 목록(`order`), 그림자 캐스터 목록, 프로브 캡처 목록.
- 그래서 오브젝트가 많으면 JS가 매 프레임 전부를 한 번씩 건드려요. 오브젝트 하나에 아무리 짧게 걸려도 1만 개면 수 ms가 나와요.

## 단계

### 1단계: 호스트 정적 집합(컬링·인스턴스 그리기)

- **JS**
  - 깨끗한 정적 그룹 가운데 묶음 후보인 메시(불투명, 같은 상태 키)를 정적 집합으로 올려요. 같은 상태 키와 렌더 순서·그림자 여부가 집합 키예요.
  - 집합은 구성원 행(월드·노멀·색·UV)과 경계 구를 바이너리로 한 번 보내요.
  - 올린 그룹은 이후 순회에서 속성 하나로 건너뛰어요. 그리기 목록에는 집합 ID 하나만 들어가요.
- **승격과 강등**
  - 그룹이 정적으로 깨끗한 상태가 일정 프레임 이어지면 올려요.
  - 강등 조건: 오브젝트 변경 알림(리비전 구독), 표시·행렬 갱신 표시·부모 변경, 장면에서 빠짐(순회 중 못 봄), 검증 모드·정적 끄기, 반사 프로브 존재(1단계 제외).
  - 강등된 그룹은 다음 프레임부터 원래 경로로 그려요.
- **C++(브리지 공용, D3D11·D3D12 모두)**
  - `cullSet` 자원: 행과 경계 구를 보관하고, 전체 행 인스턴스 버퍼(`#all`)를 만들어요.
  - 매 프레임 메인 패스: 뷰·투영 절두체로 경계 구를 판정해요. 보이는 행만 모은 인스턴스 버퍼(`#view`)로 인스턴스 그리기를 한 번 해요. 보이는 목록이 같으면 다시 올리지 않아요.
  - 그림자 패스는 `#all`을 그려요(절두체 밖은 래스터에서 잘려요).
- **같아야 하는 것:** 화면 픽셀(메인·그림자). 불투명 집합은 렌더 순서 구역 맨 앞에 그려요(깊이 판정이라 결과 같음).

### 2단계: 반사 프로브·2D 정렬

- 프로브 캡처 목록에 집합을 넣어요(프로브 영향 범위 판정을 호스트에서).
- 2D는 정렬 결과가 보이므로, 정렬 키가 변하지 않은 구간을 호스트에 두고 바뀐 항목만 다시 정렬해요.

### 3단계: 변환·물리 호스트화

- 움직이는 오브젝트의 변환을 호스트 배열에 두고, JS는 바뀐 것만 써요(행렬 갱신·전송 비용 제거).
- 물리를 네이티브(C++) 물리 엔진으로 옮겨 WASM 경계 비용을 없애요.

## 검증

- 1단계: 정적 집합 켜기·끄기의 D3D12 화면 픽셀 비교(그림자 포함), 강등 시나리오(이동, 숨김, 머테리얼 변경, 제거), 리비전 검증 게임 5종.
- 측정: 3D 1만·10만 개(프로브 없는 장면 포함), 2D 1만 개.

## 진행 (2026-11-14)

### 1단계 구현

- **C++ 브리지**(`native/desktop/SceneRenderBridge.hpp`, D3D11·D3D12 공용)
  - `cullSet` 자원: 행(인스턴스 176바이트)과 경계 구를 바이트로 받아 보관해요. 전체 행 버퍼 `#all`, 보이는 행 버퍼 `#view`를 만들어요.
  - 그리기의 `cullSet`: 메인 패스 전에 뷰·투영 절두체로 구를 판정해요. 보이는 목록이 바뀔 때만 `#view`를 다시 올려요. 보이는 행이 없으면 그리지 않아요.
  - 그림자·프로브 패스는 `#all`로 그려요.
  - 통계: `cullSets`, `cullUploads`, `cullVisible`. 해제는 `release.cullSets`.
- **JS**(`prototype/native-scene-renderer.js`)
  - 승격 대상: 깨끗한 정적 그룹 가운데 모든 그리기가 불투명 묶음 후보이고 2D 노드가 없는 그룹. 같은 리비전으로 30번 인코딩된 뒤 대기열에 들어가요.
  - 대기열 적용: 256개 이상 모이거나 가장 오래된 항목이 60번 지나면 적용해요. 이번 인코딩에 방문한 그룹만 옮기고, 그 그리기는 이번 프레임 목록에서 빼요(이중 그리기 방지).
  - 집합 키: 묶음 상태 키 + 렌더 순서 + 그림자 여부. 집합이 바뀌면 행·구를 바이트로 한 번 보내요.
  - 순회는 소유 그룹을 속성 하나로 건너뛰어요. 강등 조건: 변경 알림(구독), 표시·행렬 갱신 표시·부모·부모 단위행렬 변화, 순회 중 못 봄, 반사 프로브, 검증 모드, 정적·묶음·호스트 끄기(`renderer.hbHostStatic=false`, 실행기 `HB_HOST_STATIC=0`).
  - 그림자 수신 판정: 수신 구성원이 있는 집합이 있으면 수신자가 있다고 봐요.
  - 반사 프로브 수집은 호스트 소유 그룹의 하위 트리를 걷지 않아요. 2D 준비는 표시 색 개수를 쓰지 않는 네이티브 렌더러(`hbDisplayCounts:false`)에서 호스트 소유 그룹을 건너뛰어요.
- **검사**
  - `check-host-static-sets`(신규): 켜기·끄기 170프레임. 컬링한 메인 패스가 매 프레임 같아요. 그림자 캐스터는 상위 집합이고, 늘어난 행은 그림자 절두체 밖에만 있어요. 이동·숨김·머테리얼 변경·제거·카메라 이동을 포함하고, 그룹 198개를 옮겨요. 변경 알림 처리를 끄는 변이(100프레임)와 표시 검사를 끄는 변이(110프레임)를 잡아요.
  - `check-native-mesh-batch-gpu host`(신규 모드): 실제 D3D12 150프레임 화면이 켜기·끄기에서 픽셀 차이 0이에요(태양·점광 그림자 포함, 집합 5개, 보이는 행 272개).
- **측정**(3D 1만 개, 반사 프로브 없는 장면, 400프레임, 교대 2회): 끄기 98.7·111.4ms → 켜기 43.2·55.3ms.
- **남은 큰 비용**(켜기 프로파일)
  - 게임 서비스 틱의 오브젝트 전체 순회 8회(컴포넌트 조회, 오브젝트마다 await)
  - 장면 행렬 갱신 호출(프레임당 여러 번, 그룹마다)
  - 화면 밖 칸 구성원 검증(오브젝트마다)
  - 물리 단계
- 다음: 컴포넌트 색인으로 서비스 순회 제거, 화면 밖 그룹도 호스트로 승격, 반사 프로브 장면 지원(2단계).
