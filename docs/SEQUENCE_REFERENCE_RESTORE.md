# 시퀀스 참조 복원

시퀀스가 제어하던 오브젝트 참조는 ID와 실제 대상의 수명을 함께 보관해요. 예를 들어 원래 `Enemy`를 가리키던 변수를 시퀀스가 다른 대상으로 바꾼 뒤, 원래 적이 삭제되고 새 적이 같은 `Enemy` ID로 생겨도 종료 시 그 새 적을 연결하지 않아요. BP/C++의 참조 값은 `null`, 컴포넌트의 참조 텍스트는 빈 문자열로 복원해요. 제어 직전부터 없던 대상이 나중에 생겨도 같은 규칙이에요. 삭제 처리 중인 대상도 복원하지 않아요.

이 규칙은 BP 변수, 반영된 C++ 속성, `hit.actor`, 중첩 반영 구조체·배열 안의 참조에 적용돼요. 일반 문자열은 유지해요. `self`인 BP/C++ 참조는 캡처할 때 해당 오브젝트로 정규화해요. 원래 자료형·클래스 제한 검증도 복원 시 그대로 적용해요.

컴포넌트의 `objectReference` 속성과 전체 컴포넌트 상태 녹화에도 적용돼요. 예를 들어 카메라의 추적 대상·플레이어 제어기의 폰·반사 프로브의 프록시가 같은 ID의 새 오브젝트로 바뀌지 않아요. 컴포넌트가 시퀀스 중 제거되었다가 원래 상태로 돌아오는 경우도 포함해요. 컴포넌트 종류·순서·일반 속성은 기존 복원 계약을 유지해요.

복원은 최종 종료에만 일어나지 않아요. 상위 우선순위 시퀀스가 종료되어 가려져 있던 하위 레이어가 다시 보이거나, 우선순위 변경으로 승자가 바뀔 때도 그 샘플이 보관했던 참조를 확인해요. 일시정지·같은 키의 반복 평가에서는 마지막 참조 토큰을 재사용하므로 다음 프레임에 새 대상에 다시 연결되지 않아요. 명시적인 새 Seek나 작성된 참조 샘플 변경은 현재 대상을 새로 캡처해요. `keep`은 기존처럼 마지막 값을 유지하므로 종료 시 별도의 복원 쓰기를 하지 않아요.

사람의 기존 시퀀스 편집, JSON/AI 문서 편집, C++·BP의 Play/Pause/Seek/Stop은 모두 같은 런타임 경로를 사용해요. 자산 형식·추가 설정은 필요하지 않아요. `engineSchema().sequenceOwnership.referenceState`에서 범위·빈 참조·수명 계약을 조회할 수 있어요.

적용된 배열·벡터·구조체와 보관된 샘플도 분리해요. 게임 코드가 BP 배열이나 C++ 구조체를 수정하거나 물리 계산이 위치·회전·크기 배열을 직접 바꿔도, 가려진 하위 레이어의 마지막 샘플이나 공유 원래 값까지 바뀌지 않아요. 직접 TRS 트랙과 Transform 컴포넌트 트랙은 같은 채널·복사 규칙을 사용해요. 숫자·불리언 등 단일 값에는 이 복사를 추가하지 않아요. 이는 관리되는 필드 값의 격리이며 게임 시뮬레이션의 과거 상태를 모두 복구하는 기능은 아니에요.

참조를 가진 샘플과 해당 필드의 공유 원래 값에만 비공개 약한 토큰을 만들어요. 소유자·대상·필드별 마지막 샘플 하나를 약한 캐시에 보관하고 같은 샘플의 매 프레임 참조 맵 생성은 생략해요. 토큰이 보관하는 참조 맵은 재생 수명 동안 유지되고, 외부에 적용하는 배열·구조체·컴포넌트 값과 분리돼 있어요. 외부 코드가 적용된 값을 바꿔도 보관된 원래 참조는 바뀌지 않아요. 월드 전체 복사·상주 타이머·worker·디스크 이력을 추가하지 않아요. 전체 메모리나 FPS 개선을 측정했다는 뜻은 아니에요.

임의의 비동기 외부 setter, notify 콜백의 부작용, 반영되지 않은 사용자 C++ 값의 복원은 별도의 잔여 범위예요. 이 기능은 원래 게임 시뮬레이션을 되감거나 임의의 코드를 취소하는 기능이 아니에요.
