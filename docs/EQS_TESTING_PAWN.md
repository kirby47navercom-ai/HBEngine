# 편집 월드의 EQS 테스트 오브젝트

**만들기 → AI → EQS Testing Pawn**을 배치하고 환경 질의 에셋과 선택적 기준 오브젝트를 지정해요. 기존 오브젝트에도 **EQS Testing Pawn · 환경 질의 테스트** 컴포넌트를 붙일 수 있어요. 테스트 오브젝트를 선택한 정지 상태의 장면 뷰에서만 평가해요. 스크립트·UI·오디오·게임 시뮬레이션은 시작하지 않아요.

**변경 시 자동 질의**는 장면·에셋의 저작 revision이나 선택이 바뀐 뒤 지정한 대기 시간에 한 번 실행해요. 변경이 없으면 반복 실행하지 않아요. 기존 편집기 프레임 루프를 사용하며 별도 타이머·백그라운드 프로세스가 없어요. 대기 중 편집은 합치고, 화면이 숨겨지거나 플레이·선택/월드가 바뀌면 늦게 끝난 결과를 표시하지 않아요. 액터를 직접 돌리지 않고 기존 `EditorEnvironmentQuery`의 복사한 월드·공용 EQS·항법·query-only 2D/3D 충돌 경로를 써요.

결과는 기존 점수/실패 후보와 단계 시각화를 사용해요. 수동 질의나 **숨기기**를 사용하면 현재 자동 질의를 중단하며, 다음 저작 변경이나 선택 변경 전까지 다시 켜지지 않아요. 질의 오류는 해당 revision에 한 번 표시하고 매 프레임 재시도하지 않아요.

AI는 `scene.place`/`scene.placeBatch`의 `key:"eqsTester"`, 기존 컴포넌트/문서 편집과 같은 제작 데이터로 설정해요. `editor.eqs.tester.read`는 선택 테스트의 대기·실행·준비·오류 상태를 반환하고, 기존 `editor.eqs.read`/`view`가 결과 페이지와 단계를 조회해요. `schema.editorQueryTester`에서 계약을 조회해요. 직접 메모리를 수정하는 확장은 저작 revision도 갱신해야 자동 재평가돼요.

게임 빌드 검사에서는 원본을 수정하지 않고 장면/프리팹 사본의 테스트 컴포넌트만 종속 검색 전에 제거해요. Windows·웹·Android·iOS 공용 경로예요. 일반 오브젝트·다른 컴포넌트·부모/참조는 유지해요. 게임 블루프린트 정의에 테스트 컴포넌트를 넣으면 빌드가 명시적으로 거절해요. 실제 실행에 사용할 환경 질의 에셋은 일반 게임 자산 정책을 유지해요.

현재 자동 대상은 선택한 테스트 하나예요. 다수 테스트의 병렬 스케줄·큰 장면의 전체 복사/질의 비용, 실제 분리 창·GPU 시각화 품질 검증과는 구분해요.
