# 데이터로 확장하는 편집기 도구 API

기존 `.hbeditortool.json`과 도구 편집·Undo·명령 실행 흐름을 유지해요. 사용자나 AI가 도구의 입력·버튼·명령 템플릿을 바꾸면 같은 도구 창에서 사용해요. 임의 JavaScript를 실행하는 진입점은 추가하지 않아요.

도구 파일의 `version`은 기존처럼 1이에요. 호환성을 명시하려면 선택 필드 `api`를 넣어요.

```json
{
  "version": 1,
  "name": "환경 검사",
  "api": {"version": 1, "requires": ["editor.eqs.run"]},
  "inputs": [],
  "actions": [{
    "id": "query", "label": "검사", "method": "editor.eqs.run", "output": "json",
    "params": {"target": "Director", "asset": "Assets/EQS_Search.hbeqs.json", "visualize": true}
  }]
}
```

명시한 API 버전·필수 명령과 액션의 명령이 맞아야 실행해요. 알 수 없는 버전·미지원 명령은 실행 전에 알려요. `api`가 없는 기존 도구는 그대로 사용하고, 다른 버튼의 미지원 명령 때문에 지원되는 버튼까지 막지 않아요. 등록된 공용 명령만 호출해요. 기존 배치·선택·문서 수정·뷰포트·창 명령에 `editor.eqs.run/read/view`를 추가했어요. 명령 이름·코드 자체를 템플릿으로 만들 수 없어요.

`$input`, `$context`, `$revision`을 실행 준비 단계에서 해석해요. 입력·액션 템플릿·클릭 시점의 장면/문서/선택을 복사하고, 같은 문서 경로의 revision은 한 번만 읽어요. revision을 기다리는 사이 장면·문서 정체성·플레이 모드·도구 정의가 바뀌거나 창이 닫히면 명령 전송 전에 취소해요. 등록 함수가 교체돼도 오래된 함수를 호출하지 않아요. 실제 편집은 공용 명령의 CAS/revision·Undo 규칙을 따라요.

한 도구 창은 한 번에 하나의 액션을 준비/실행해요. 입력·버튼·정의 적용을 함께 잠그며 실패 뒤 풀어요. AI의 동시 실행 요청도 거절하고 자동 재시도하지 않아요. **이미 전송한 명령은 해당 명령의 실제 성공/실패를 그대로 반환해요.** 창을 닫았다고 실행된 수정을 되돌렸다거나 취소했다고 보고하지 않아요. 닫힌 창에는 늦은 결과·오류 표시를 붙이지 않아요.

기본 결과 표시는 기존처럼 비워요. 액션에 `output:"json"`을 넣으면 결과를 최대 4000문자의 선택 가능한 텍스트로 보여요. 표시 준비도 깊이 6·항목 64·노드 512로 제한하며 원본 결과는 바꾸지 않아요. 임의 HTML을 삽입하지 않고 `aria-live`와 실행 중 상태를 공유해요. 위 숫자는 표시 예산이며 명령의 실제 결과를 줄이는 기능은 아니에요.

AI는 기존 `editorTool.run`을 사용하고, `editorTool.inspect({path})`로 현재 revision·API 버전·필수/미지원 명령·입력·액션·실행 상태·최근의 짧은 결과를 읽어요. `schema.editorTools`와 `hb context "편집기 도구 API" --symbol runEditorTool`에서 계약과 소유자를 확인해요.

도구 파일은 편집기 전용 에셋이에요. Windows·웹·Android·iOS의 공용 콘텐츠 검사에서 게임 payload에 넣지 않아요. 콘텐츠 브라우저·프로젝트 저장/읽기에서는 유지하고, 런타임 데이터가 이 파일을 참조하면 명확한 오류로 알려요. 도구를 배포하려면 게임 출력이 아니라 프로젝트의 도구 에셋을 전달해요. 네이티브/임의 코드 플러그인 설치·배포 시스템을 추가한 뜻은 아니에요.

이 계약은 데이터 도구용이에요. 네이티브/임의 코드 확장 ABI·배포/서명, 여러 명령의 원자 워크플로, 이미 전송된 임의 명령의 취소/롤백은 별도 잔여예요. 소유 DOM·명령 레지스트리와 공용 EQS 소스 검사는 실제 사용자 창/네이티브 바이너리·설치 검증을 뜻하지 않아요.
