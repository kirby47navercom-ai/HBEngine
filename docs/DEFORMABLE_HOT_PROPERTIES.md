# 천·로프의 실행 중 물성 변경

기존 Cloth/3D 로프/Rope2D 컴포넌트의 인장 주파수(`frequency`), 굽힘 주파수(`bendFrequency`), 내부 감쇠 비율(`dampingRatio`), 추가 반복(`iterations`), 마찰·반발·레이어·마스크는 실제 활성 soft body에 갱신해요. 입자 위치/속도·원래 형상·실행 중 고정점·강체 연결·물리 세대와 콜라이더 핸들을 유지해요. 제약과 접촉을 다시 평가하도록 물리를 깨우며, 표시도 새 프레임을 받아요. 값이 같으면 재질이나 콜라이더 설정을 다시 만들지 않아요.

```cpp
hb::Components::SetFloat(rope, "Cloth", "frequency", 73.f);
hb::Components::SetFloat(rope, "Cloth", "dampingRatio", 1.4f);
hb::Components::SetFloat(rope, "Cloth", "iterations", 6.f);
```

BP의 **컴포넌트 수치 지정**과 같은 typed component 실행 경로예요. 재질은 공용 Rapier의 `setMaterial`, 반복은 `setAdditionalPgsIterations`, 표면은 현재 콜라이더의 설정과 기존 대칭 레이어/마스크 접촉 훅을 사용해요. 이미 바닥에 닿아 있던 로프에서 마스크를 끄면 세대를 다시 만들지 않고 통과해 떨어져요.

모든 물성이 이 방식은 아니에요. 질량·입자/형상·저작 고정 설정·두께·자체 충돌·선형 감쇠(`drag`)·중력 배율·절전 가능 여부·표면 존재는 현재 백엔드의 직접 setter 범위 때문에 기존 재생성 경로를 유지해요. 내부 감쇠 비율과 선형 감쇠는 다른 값이에요. 중력/감쇠를 임의의 보정 힘이나 속도 근사로 바꾸지 않아요. `schema.deformableProperties`에서 구분을 조회해요.

기존 범위/자료형 검증을 먼저 수행해요. 잘못된 값은 재질을 일부 적용하기 전에 거절해요. 물리 백엔드 자체의 임의 오류/외부 setter 부작용까지 원자적으로 롤백한다고 주장하지 않아요. 새 소유자나 교체된 컴포넌트는 여전히 이전 물리를 정리하고 새 세대를 만들어요.

소유한 실제 2D/3D Rapier 물리에서 재질 값·콜라이더·입자/속도/고정/연결 보존과 접촉 재필터를 대조해요. 공용 VM 명령 재생 및 C++ typed setter 흐름과 묶어 검사하며, 새 GUI/렌더러 픽셀·기기·사용자 설치 검증과 구분해요.

스키마의 hot/역할 목록은 사본을 반환하고 실행 분류 상수는 고정해요. Node 호출자가 반환 목록을 바꿔도 물성 재생성 분류나 허용 효과 역할을 바꾸지 않아요.
