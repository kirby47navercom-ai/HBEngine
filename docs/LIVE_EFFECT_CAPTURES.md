# 실시간 효과 속성 캡처

효과 수정자의 속성 입력에 `snapshot:false`를 지정하면 출처·대상 속성이 바뀔 때 지속 효과의 크기를 다시 계산해요. 생략하거나 true이면 기존처럼 적용 시 숫자를 고정해요. 효과 편집기의 **적용 시 고정** 체크도 같은 필드를 편집해요.

```json
{"attribute":"Health","operation":"add","magnitude":-2,"magnitudeSource":{"type":"attribute","owner":"source","attribute":"Power","basis":"current","snapshot":false}}
```

기존 C++/BP `ApplyEffectSpec`의 source와 에셋을 그대로 사용해요. 뒤에 선택적인 instigator·causer 인자를 추가했고 생략하면 source를 사용해요. 예전 호출과 노드의 기존 입력 핀은 유지해요. current/base 입력, 파생 속성 계산, 레벨 커브·호출 인자, 스택·효과 만료·능력 비용·세트 재적용이 같은 공용 `AbilitySystem` 흐름으로 반영돼요.

- 입력 변경은 연결된 종속 소유자만 따라가요. 유휴 프레임에는 캡처·커브·에셋을 다시 읽지 않아요.
- 여러 소유자와 파생 속성을 지나는 순환, 범위 초과, 필요한 속성을 제거하는 세트 변경은 시작한 작업과 영향을 받은 효과·진단·Cue를 함께 되돌려요.
- 출처는 ID와 소유자 세대로 식별해요. 출처 액터를 제거·풀 반환하면 마지막 입력 숫자를 유지하고, 같은 ID의 새 액터에 붙지 않아요. 대상 자체의 실시간 입력은 계속 갱신돼요. 출처 액터 객체를 효과에 보관하지 않아요.
- `runtime.effect` 페이지에 고정/실시간 입력 값과 `captureSource`, `sourceAlive`를 반환해요. 사람이 보는 활성 효과 표에도 같은 캡처 방식을 표시해요. `schema --section effectCaptures`로 계약을 좁혀 읽을 수 있어요.

즉시 효과는 적용 순간에 한 번 계산해요. 주기 효과는 실행할 주기가 있을 때 source/target 입력을 다시 읽고 기존 누적 횟수·스택·주기 기준점으로 실행해요. 대기 프레임과 출처 속성 변경 때 미리 재계산하지 않아요. 지연된 여러 주기를 한 번에 처리할 때는 현재 입력을 한 번 샘플링해 해당 묶음에 사용해요. 과거 출처 값 복원이나 그 묶음 안에서의 매 주기 대상 자기 피드백 재구성은 별도 잔여예요.

적용 시 source·target·instigator·causer의 ID와 태그 목록을 각각 복사해요. 발동자와 직접 원인은 AbilitySystem이 없는 투사체·Director 등도 지정할 수 있어요. 비동기 로딩 중 사라지거나 교체된 지정 객체의 효과는 적용하지 않아요. 태그는 적용 시 기록이고 나중에 액터의 태그가 달라져도 바뀌지 않아요. `runtime.effect`의 application과 적용·주기·제거 Cue 인자에도 같은 값의 사본을 돌려줘요. 효과에는 액터 참조를 보관하지 않아요. 큰/깊은 종속 그래프의 실기기 부하 검증은 별도예요.
