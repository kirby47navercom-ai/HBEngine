# 태스크 실행별 메모리

행동트리 태스크가 시작될 때 받은 실행 핸들에 임시 JSON 메모리를 저장할 수 있어요. 같은 트리·같은 태스크 이름이어도 오브젝트와 실행 핸들이 다르면 값을 공유하지 않아요. 블랙보드와 별개이고 처음 쓰기 전에는 메모리 본문을 할당하지 않아요.

BP의 **태스크 메모리 읽기·지정·지우기**는 대상 오브젝트와 실행 핸들을 받아요. C++는 같은 기능의 `hb::AI::GetTaskMemory`, `SetTaskMemory`, `ClearTaskMemory`를 사용해요. 메모리는 기존 게임 JSON의 객체·깊이·크기 검증을 거치며 잘못된 쓰기는 기존 값을 바꾸지 않아요. 읽기는 독립된 JSON 텍스트를 반환해요.

시작·틱 콜백에서 저장한 값은 완료 콜백과 중단 정리에서도 읽을 수 있어요. 지연 중단은 `FinishAbort`로 정리가 끝날 때까지 유지하고, 완료·리셋·강제 중단·오브젝트/트리 교체 뒤의 핸들은 거부해요. 다시 실행한 태스크에는 새로운 핸들과 빈 메모리가 주어져요. 중단된 비동기 콜백이 늦게 돌아와도 예전 핸들로 새 실행에 쓸 수 없어요. 중첩 트리에서도 실제 핸들을 소유한 실행을 찾아요.

C++는 현재 태스크 자원을 다루는 실행 질의로 메모리를 읽고 써요. 같은 호출 안의 지정 뒤 읽기도 즉시 새 값을 보고, 메모리 질의는 월드 스냅샷을 복사하지 않아요. 태스크·트리 진단 스냅샷에는 본문을 넣지 않으므로 메모리가 커져도 매 프레임 모두 직렬화하지 않아요. 기존 실행 질의 예산은 유지해요. 쓰기는 즉시 적용되며 이후 C++ 코드가 실패해도 자동으로 롤백하지 않아요.

AI 스키마의 `behaviorTaskMemory`에 소유권·수명·페이로드·실행 경로가 있어요. 이는 태스크 실행별 데이터 기능이고, 네이티브 `BTTask` 상속 클래스나 별도 C++ 태스크 객체 모델을 구현했다는 뜻은 아니에요.

핸들 기반 메모리·완료·중단 상태는 [실행 소유자 색인](BEHAVIOR_TASK_LOOKUP.md)으로 현재 활성화를 찾고, 노드 메모리 전체를 매번 순회하지 않아요. 자식 호출의 접근 범위는 그 자식의 하위 트리로 제한해요.
