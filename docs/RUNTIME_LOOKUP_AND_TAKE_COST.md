# 오브젝트 조회와 Take 표본 비용

BP 실행기의 `object(id)`는 이미 찾았던 숫자 슬롯의 현재 오브젝트 ID를 확인하고 재사용해요. 슬롯이 달라지면 기존 검색으로 돌아가요. 같은 위치의 새 오브젝트, 배열 정렬·삭제·추가·이름표 ID 변경, 같은 ID의 재생성을 이전 코드와 대조해요. `self`와 없는 ID의 의미, ID 대소문자 구분을 유지해요. 장면의 고유 ID 계약을 전제로 해요.

오브젝트 개수를 제한하지 않아요. 캐시는 실제 현재 배열 길이 이하로 유지하고, 월드 배열을 WeakMap 키로 사용해 이전 장면 배열을 붙잡지 않아요. 없는 ID는 지속 캐시에 넣지 않아서 나중에 생성한 대상을 찾을 수 있어요. 첫 오브젝트만 찾는 경우에는 인덱스 자체를 만들지 않아요.

고정 대상 Take는 선택한 대상의 참조만 표본 시작 시 확보해요. 새 대상들을 찾을 때 월드를 한 번만 순회하고, 이미 확인된 슬롯은 검증해서 재사용해요. 매 표본마다 전체 월드의 오브젝트 Map을 새로 만들지 않아요. 한 번의 캡처 콜백 중 다른 대상이 제거되어도 그 표본의 대상 참조는 기존 방식대로 유지해요. 생성된 오브젝트를 계속 편입하는 모드는 기존 월드 순회와 편입·수명 규칙을 사용해요.

## 값 스냅샷

`recordableRuntimeValues`는 원래부터 값을 읽고 검증한 참조를 반환해요. 복사는 TakeRecorder가 키를 보관할 때 해요. 일정한 구간을 압축할 때는 기존 두 키와 현재 값을 먼저 비교하고, 단순히 끝 시간을 늘릴 수 있으면 버릴 복사를 만들지 않아요.

변한 값과 실제로 보관할 키는 계속 별도의 스냅샷을 소유해요. 같은 배열을 제자리에서 수정하거나 순서를 바꿔도 기록해요. 원본 배열을 녹화 뒤 수정해도 완성된 Take가 변하지 않아요. 자료형·키·메모리 예산과 녹화/재생/복원 계약을 줄이지 않아요. 일반 변경 배열의 필수 복사·형 검증·골격 전체 캡처·생성 편입 순회까지 없앴다는 뜻은 아니에요.

## 측정 범위

- 실제 타입 검증을 통과하는128개 구조체 배열을600표본 녹화하고, 기존 Git 코드와 키·보간 결과를 같게 유지하며 직접 payload 복사를600회에서6회로 줄였어요.
- 4096오브젝트에서32개 ID를2048회 조회한 표본의 ID 읽기는 기존8,356,864회에서132,592회 수준으로 줄었어요. 실제 결과는 검사 영수증을 우선해요.
- 고정 Take 대상32개를300표본 읽은 경우 전체 ID 읽기는1,228,800회에서13,664회로 줄었어요. 없는 대상만 지정한 경우에는 한 대상마다 월드를 다시 훑지 않고 기존과 같은 전체 순회 횟수 범위예요.

이는 작업량 계수와 해당 표본의 결과예요. 게임 FPS·전체 메모리·모바일 성능 수치로 환산하지 않아요. 실제 편집기 Take 저장·재생과 패키지 실행은 별도 gate에 기록해요.

소유자는 `runtime-object-lookup.js`, 호출자는 `blueprint-runtime.js`와 `take-recorder.js`예요. `hb context 런타임 --symbol lookupRuntimeObject` 또는 `--symbol primeRuntimeObjectLookup`으로 관련 구현만 읽을 수 있어요.
