# 실제 게임 프레임 비용 절감 — 058

동일한 고정 게임 사본 `frame-regression-Y3u0Qb/candidate-Game`의 Test_Valen(실행432개)을 현재 엔진의 release Game.exe로 빌드했다. 현재 Auric 원본의 최신 작업과 이 사본을 동일하다고 가정하지 않는다. 사본의 Assets/Source608개 전체 SHA와 원본 바이트는 보존했다. PC120/fixed,1280×720, 대기3초·F9/마우스 공격6초, 각 렌더러의 이전/현재/현재/이전 순서다. CPU 프로파일러를 켠 첫 탐색과 최종 비용 대조를 구분했다.

## 공용 구현

- 물리: 부모가 없는 오브젝트의 포즈는 위치·회전·크기9개 숫자가 동일하면 재사용한다. 직접 배열 수정, 부모 연결/이동/분리, 강체 깨우기와 질의는 유지한다. 부모 계층의 포즈는 매 동기화에서 해석한다.
- UI: 바인딩 값이 바뀔 때 렌더 갱신한다. 명시적 UI 함수·애니메이션은 즉시 반영하며 터치/마우스 장치 전환과 가상 조작의 프레임 처리는 유지한다.
- C++ 입력: 다른 모듈의 nativeClass/nativeProperties가 없는 일반 actor 행을 임시 복사하지 않는다. 외부 모듈의 상태 격리와 실제 JSON 스냅샷/변경 전송은 유지한다.
- Android 검증 도구의 전체 GPU probe 경로가 새 gpuProof를 최종 결과에도 기록하도록 고쳤다. Android를 다시 부팅해 이미 확인한 adapter-null 결과를 반복하지 않았다.

## 전체 프레임 대조

각 항목의 두 실행 평균이며 GPU 표시 지연은 아니다. 작업 p95의 평균은 합쳐진 표본의 p95가 아니다.

| 렌더러 | 구간 | 이전 FPS | 현재 FPS | 이전/현재 작업 중앙값 | 이전/현재 작업 p95 |
| --- | --- | ---: | ---: | --- | --- |
| GL | 대기 |107.76|119.52|7.40/5.70ms|9.35/7.15ms|
| GL | 공격 |105.01|119.81|7.60/5.90ms|11.15/8.50ms|
| GPU | 대기 |115.50|117.76|6.95/6.45ms|9.65/8.70ms|
| GPU | 공격 |95.04|103.17|8.55/7.95ms|15.75/12.70ms|

실행 간 변동이 크다. GL 이전 대기95.83→119.70, GPU 현재 공격112.91/93.43fps다. 표의 평균을 보장 성능이나 변경의 순수 효과로 단정하지 않는다. 모든 공격에서 Swings19, 실제 스프라이트·한글 HUD·오류0·자기 프로세스 종료0을 확인했다. 목표 판정은 **false**다. 모든 프레임4ms, 항상120fps, 모바일60fps, 장시간 RAM 성장 해결을 이 결과로 주장하지 않는다. 이전 사용자 측정 및 8시간 실패를 그대로 유지한다.

## 재현/증거

- `node tools/check-auric-frame.mjs <고정 게임 폴더> --cpu-profile`: 측정/CPU 탐색. 기본 GL/GPU/GPU/GL이며 `--single`은 각1회다.
- `--compare=<완료한 auric-frame-* 폴더>`: 동일 사본 SHA를 확인하고 그 폴더의 이전 패키지와 새 패키지를 각 렌더러별ABBA로 실행한다. 사용자 창은 건드리지 않는다.
- 첫 탐색: `native/build/auric-frame-jhRxKa/acceptance.json`, CPU 샘플에 nativeRowJSON·물리 sync·UI update가 나타났다.
- 최종 전체 게임 대조: `native/build/auric-frame-Id8pIC/acceptance.json`. 각 패키지 런타임 SHA/PNG/프레임/C++ 수치/자연 JS heap/종료가 별도 기록된다. 자연 heap은 짧은 표본이며 장시간 성장률 검증이 아니다.
- `check-physics.mjs`: 실제 Rapier2D/3D164항목·부모/직접 회전·크기·질의·실제 C++ 통과.
- `check-native-world-patch.mjs`: 모듈 상태 격리/일반 행 재사용·직접 중첩 변경·삭제·실패/reset/worker 복구 통과.
- `check-ui-audio.mjs`: 180유휴 프레임 갱신0, 입력 프레임180, 바인딩 변경/즉시 함수/다음 프레임 바인딩 복원 및 기존 BP/C++/믹서 통과.
- 실제 UI Player `ui-render-window-vTBPlJ`: SVG1.5배·한글·안전 영역·버튼→BP·유휴 UI 터치/마우스 전환·원본/종료 통과.

스프라이트 애니메이션 교체 때 매번 생성되는 GPU 머테리얼/파이프라인 비용과 전체 게임 잔여 CPU/RAM 및 누적 선행 작업을 이어간다. 설치본은 누적 선행 작업의 검증 뒤 갱신한다.
