# 1050–1062 — 인스턴스 반사와 월드 제작 비용 묶음

기존 인스턴스 반사 경계 개선에 지형·폴리지 제작 경로를 함께 연결했어요. 기능별 네이티브 재빌드/설치 반복을 피하고 공용 코드가 바뀐 범위만 묶어서 확인해요.

## 제작과 실행

- 인스턴스 행렬/개수/정점 버전으로 현재 경계를 캐시하고 브라우저·DirectX 반사 후보와 컬링에 사용해요. 원점 밖의 실제 glTF/폴리지 인스턴스도 후보가 돼요. 변형체와 인스턴스별 다중 프로브 선택까지 확장한 것은 아니에요.
- 지형 높이는 위치·인접 노멀만, 레이어 칠하기는 색만 갱신해요. 면 인덱스/UV/기하/머테리얼은 재사용해요. 노멀은 영향받는 정점의 모든 인접 면을 다시 합쳐 기존 전체 계산과 맞춰요. 해상도·크기·구멍 위상 변경은 기존 안전한 전체 교체 경로를 사용해요.
- 폴리지는 바뀐 행렬만 업로드해요. 추가 시 필요한 인스턴스 버퍼만 기하급수적으로 늘리고 메시/머테리얼은 유지해요. 이전 인스턴스 버퍼는 해제하고 장면 소유권을 새 버퍼에 연결해요. 삭제·빈 목록·재사용·안정 ID 선택을 유지해요. 추가 오브젝트 개수 제한은 넣지 않았어요.
- 렌더 전에 여러 편집이 들어와도 앞선 미전송 범위를 보존해요. 범위 목록이 과하게 쌓이면 하나로 합쳐요. 변경이 없으면 attribute 버전과 GPU 전송을 늘리지 않아요.
- 지형 브러시 광선은 정규 격자를 따라 후보 셀만 검사해요. 격자 선/모서리·구멍 경계는 이웃 셀도 검사해요. 폴리지 배치 브러시는 폴리지 전체를 raycast하지 않고 지면을 사용해요. 폴리지 선택 모드는 기존 정확 메시 선택을 유지해요.
- 연속 미리보기 요청은 마지막 데이터로 합치고 오래된 비동기 결과는 해제해요. 선택 ID 검증의 중첩 선형 검색과 소거의 중복 전체 복사도 줄였어요.
- 장면에서는 변경 에셋의 실제 종속 오브젝트만 갱신해요. 충돌이 붙은 오브젝트나 구조/종속 변경은 기존 전체 경로로 돌아가요. 장면 모델 소유 ID·해제·변경 통지를 유지해요.

## 조작과 AI

공용 프로필/재지정에 월드 제작 명령 15개를 추가했어요. F/Home 프레이밍, B/Q 폴리지 브러시/선택, Ctrl+D/Delete 복제/삭제, 대괄호 반경, Shift+1~8 지형 도구예요. 입력칸·IME·게임 실행·비행 문맥 격리와 기존 키 우회 방지를 공유해요.

`world.preview.read {path,offset?,limit?}`는 실제 준비 상태, 기하 ID·정점/삼각형·인스턴스 용량·행렬 버전, 직전 부분 갱신 수와 선택 ID 페이지를 반환해요. 문서·revision·Undo를 변경하지 않아요. 기존 `world.terrain.brush`, `world.foliage.edit/scatter/erase`는 사람의 동일 미리보기 경로를 사용해요.

## 묶음 확인

- CPU1059: 6가지 지형 편집을 전체 기하/노멀/색 재생성과 대조, 변경 없는 전송 0, 폴리지 성장/삭제/재사용/불변 원본·대기 업로드 범위·최신 요청, 500광선을 Three 전체 삼각형 검사와 독립 대조. 약259ms 관찰.
- CPU1061: 실제 sceneRendering의 지형 재사용, 폴리지 버퍼 성장 시 소유권/이전·현재 해제, 충돌 fallback, 무관 에셋 거부 통과.
- 실제 숨긴 창1060: 사람/AI 편집·Undo·재지정/기존 키/입력칸 격리·조회 revision 불변. GPU 실제 `bufferSubData`: 지형 **408B**, 폴리지 한 개 **64B**, 두 편집 모두 새 `bufferData` **0회**. 캡처에서 지형 변형과 전체 폴리지 표시를 확인했어요.
- 기존 단축키 검사:139명령 통과. 인스턴스3백엔드/실제 C++·BP 이전1057 증거를 재사용하며 이유 없이 전체 셰이더 검사를 반복하지 않아요.

숫자는 해당 fixture의 전송/계산 결과이며 전체 게임 FPS나 100만 개 실시간 편집 성능이 아니에요. 에셋 JSON 복사·검증·변경 탐색은 여전히 전체 데이터 크기의 영향을 받아요. 지형 GPU 계산 브러시, 대규모 선택 가속, 월드 스트리밍·HLOD는 별도 잔여예요. C++/네이티브 ABI를 변경하지 않아 기존 Player1040/Host1041을 소유 지문 대조 후 재사용해요.

참고 범위는 [Three BufferAttribute](https://threejs.org/docs/pages/BufferAttribute.html)의 usage/version/updateRanges 계약과 [InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html)의 생성/인스턴싱 개요, [EXT_mesh_gpu_instancing](https://github.com/KhronosGroup/glTF/tree/main/extensions/2.0/Vendor/EXT_mesh_gpu_instancing)의 지정 변환/접근자 구역이에요. 격자 탐색/부분 노멀 갱신은 HB 자체 구현이며 Unreal/Unity 전체와의 일치나 전체 문서 분석 완료를 주장하지 않아요.
