# 기본 시간 입력의 CPU 매질 캐시 (940–948)

Panner의 Time 핀을 비우면 기존 평가기·GPU IR은 절대 머테리얼 시간을 사용해요. 하지만 CPU 전용 `closedVolume` 의존성 탐색은 명시적인 Time 노드만 인식했어요. Panner→Linear Gradient→Closed Volume 그래프는 직접 평가·새 컴파일에서 시각 0/2에 false/true인데, 같은 머테리얼 캐시는 false/false로 남았어요.

명시적 Time과 기본 Panner Time을 같은 CPU 시계 의존성으로 처리해요. 기존 준비 평가기를 사용하여 해당 볼륨 포트만 다시 평가하고, 같은 시각에는 캐시 객체, CPU 전용 변경에는 GPU 프로그램 배열을 그대로 사용해요. Time을 숫자 0이나 상수 노드로 지정한 경우는 자동 시계로 취급하지 않아요. 관련 없는 Time 노드와 셰이딩에만 연결된 시계도 CPU 볼륨 의존성으로 승격하지 않아요.

사람·AI·C++가 만드는 같은 저장 머테리얼 그래프를 사용하며 노드·에셋 형식·컴포넌트 키·명령 API·GPU 자원을 추가하지 않아요. CPU 매질 시계가 바뀌는 그래프는 기존 전역 이력 보호 조건을 적용해 잘못된 경로 이력을 재사용하지 않아요.

- `material-clock-940-s3Fe5z`: 기본/명시/숫자/연결 상수/관련 없는 Time/셰이딩 전용 6종을 0→2→0→2에서 직접 평가·독립 컴파일과 비교해요. 같은 시각 객체와 CPU 전용 GPU 프로그램 배열의 동일성, 이력 보호, 실제 GeometryGIWorld·장면 계획의 매질 플래그 0→2→0을 확인해요.
- `material-clock-941-native-bjB5B9`: 실제 생성 HLSL·최적화 FXC·D3D11 하드웨어에서 0/2/0의 양방향 매질 스택·IOR·RGB 소멸값 12조건을 확인해요. 실제 기능 매크로와 강제 walker 대조를 모두 사용하여 매크로만 꺼져서 통과한 경우를 배제해요. 최대 오차 1.624e-7 < 기존 4e-5예요. 값 계산 증거이며 게임 화면·FPS를 측정한 것은 아니에요.
- `channel-normal-866-ry6NBo`: 기존 현재/이전 노멀과 시각·폭·코팅의 실제 GL/WebGPU 6조건, 수정 전후 차이 0·해석 오차 4.783e-8을 유지해요.
- `material-clock-regressions-942.json`: 표면 시간 이력·프레임 의존성·표면 계약·밉 캐시 소유권 4종을 묶어 확인해요. 밉 캐시 첫 호출은 필요한 `--expose-gc`가 없어 실행 전 거부됐으며 결과에서 제외하고 올바른 인자로 다시 실행했어요.

설치본의 동일 소스·매질 스택·노멀·C++/블루프린트 게임 대조는 `ENGINE_WORK_946.json`, `USER_INSTALL_948.json`에 기록해요.

## 별도로 남아 있는 FXC 조사

930–937은 기존 합성 역순 호출 오류를 추가 조사했으며 배포 구현 성과로 계산하지 않아요. 같은 기존 패킷에서 이전 IOR→현재 RGBA 호출은 16개 성분이 틀리고, 실제 제작 경로의 현재→이전 순서는 오차 1.624e-7로 유지돼요.

- `seed-loops-931-IThh2u`: loop/fastopt 제거로 해결되지 않아요.
- `seed-loops-932-JPKmFt`: 비활성 0방향 slab 분모 보호·역수 후보로 해결되지 않아요.
- `seed-loops-934-GtrRAy`: 현재 상태만 구조체로 반환한 후보와 직접 두 구조체를 읽은 후보는 해당 패킷에서 통과했으나 다른 조합은 4/16개 성분 오류가 남아요.
- `seed-loops-935-JQcZP2`: count 반환 후보는 4/16개 성분 오류가 남아요.
- `seed-loops-936-Ffja5O`: 구조체 pack 위치를 옮긴 후보에도 4개 오류가 남아 일반적인 수정으로 채택하지 않아요.
- `seed-loops-937-jlhDyl`: 입력 origin의 명시 복사·const 후보로 해결되지 않아요.

930의 중복 loop 속성과 933의 구조체 배열 동적 lvalue 실험은 컴파일 실패여서 값·성능 증거에서 제외해요. 후보는 `native/build/`에 분리했고 생성기는 기존 검증 소스로 복원해 9개 native 소유 SHA가 설치 918과 같은지 확인했어요. 기본 Panner 시계 수정이 이 FXC 오류나 초기 컴파일 지연까지 해결한 것으로 표시하지 않아요.
