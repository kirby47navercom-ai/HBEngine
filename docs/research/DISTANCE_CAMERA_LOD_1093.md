# 거리장 카메라 LOD·교체·정지 비용 1087–1093

카메라의 projected world AABB와 렌더링 버퍼 크기로 기하별 거리장 목표를 선택해요. 같은 기하/인스턴스는 보수적 최대 요구를 공유하고 화면 밖 차폐물은 빼지 않아요. 250ms 낮춤 안정화·상향 목표 갱신·기존 필드 보존·동일 소유자/목표 결과만 채택·취소/입력/교체 페이로드 예약·낮은 정밀도 채택 후 자료 해제를 연결했어요. 고정 모드와 기존 예산 업그레이드는 유지해요.

새 필드는 PostProcessVolume 두 속성이고 사람 상세 패널, C++ Components::SetString/SetFloat, 같은 블루프린트, AI 문서 CAS를 공유해요. 셰이더 수식·네이티브 opcode·버퍼 ABI는 바꾸지 않았어요. 일반 GL/TSL/네이티브가 같은 CPU 소유자가 준비한 atlas를 받아요. 세 API의 실제 렌더와 별도 컴파일 C++·블루프린트 실행으로 확인해요.

기하/인스턴스 버전·월드 포즈·투영 크기를 WeakMap에 저장해 정지 프레임의 경계 투영을 피하고, TAA의 homogeneous 화면 이동도 구분해요. fixed/해제 때 CPU 메모를 놓고 0인스턴스에는 볼륨을 예약하지 않아요. 추가 GPU 자원/패스/운영 readback/디스크 캐시가 없다는 뜻이며 기존 텍스처의 크기 교체/업로드와 작은 CPU 메모까지 없다는 주장은 아니에요.

## 읽은 공식 구역

[Unity LOD Group](https://docs.unity3d.com/6000.0/Documentation/Manual/class-LODGroup.html)의 화면 높이에 대한 LOD 선택 구역을 대조했어요. Unity의 렌더 메시 교체와 HB의 거리장 볼륨 정밀도 선택은 다른 동작이에요. [Unreal Mesh Distance Fields](https://dev.epicgames.com/documentation/en-us/unreal-engine/mesh-distance-fields-in-unreal-engine)의 Quality·Global Distance Field 구역은 정밀도/메모리와 카메라 중심 clipmap을 구분하는 근거예요. HB의 이번 기능은 전역 clipmap을 구현한 것이 아니에요. 본문 읽기 경계는 supplemental1093/read-scope.json에 남겼고 전체 문서/API 분석 gate를 올리지 않아요.

## 근거 범위

1087: 원근/직교·해상도·near 교차/없는 카메라, 독립 상자 투영 크기, 시간 안정화, 정확한 교체 페이로드와 예산 거부, 컴포넌트/볼륨 결합, 잘못된 설정의 원본 보존·TAA 캐시 검증이에요.

1088: 실제 소유 작업 스레드·near/far·상향 중 기존 필드·목표 취소·지연된 낮춤·정지40프레임 재사용·공유/인스턴스·0인스턴스 해제/버전 변경·고정 모드·예산/소유자 종료예요. 표본 볼륨은2048→131072→2048바이트예요.

1089: 실제 GL/WebGPU MRT·AO에서131072→2048→131072바이트 전환, 고정밀 복원 픽셀 일치, 간접광만 차폐·직접광 불변, GL 프로그램 유지와 TAA 정지 투영 재사용을 확인해요. 32×32 정확도 표본으로 전체 FPS를 추정하지 않아요.

1090: 새 패키지 D3D11의 실제 SDK C++가 새 mode/pixel 설정과 카메라 zoom을 바꾸고, 키보드 블루프린트도 같은 mode를 바꿔요. 낮춤/복원 atlas가 실제 native AO에 연결되고 고정밀 픽셀이 복원돼요. 처음 특정 sphere의 축소 결과를 근거 없이16으로 가정한 검사 기대가 틀려45초 timeout이 났어요. 실제12였고, 엔진을 기대값에 맞추지 않았어요. 투영 수식의 독립 정답은1087에 두고, 여기서는 C++ 값64의 전달·상한보다 낮고 최저보다 높은 정밀도 선택·복원·실제 픽셀과 모드 전환을 확인해요.

1092: 실제 상세 모드/조건부 픽셀 필드·Undo·같은 AI CAS/오래된 revision 거부·저장·schema예요. 기존912의 고정 예산/필드 보존·동시 예약·40프레임·취소와913의 계획 회귀도 유지해요. 확정 경로/SHA와 설치 결과는 ENGINE_WORK_1094.json 및 후속 설치 영수증에 연결해요.

## 초기 GL 지연 진단 1086

생성된 물리 레지스터 초기화/재대입을 SSA처럼 바꾸는 후보를 정확한 보유 Complex141 GLSL에 대조했어요. 현재 robust normal decoder로 맞춘 raw GL compile/link ABBA의 path 평균7197.35→7125.40ms, guide5295.55→5233.40ms였어요. 소스는 각각74바이트만 줄고 약1% 차이라 캐시/부하가 통제되지 않은 이 결과로 개선을 입증하지 못했어요. 기본 렌더러에 넣지 않았어요.

초기 보조 픽셀 비교는 관측 가능한 노멀 영향 자체를 확인하지 않아 수치가 같아도 정확도 통과로 계산하지 않아요. 해당 보고서에 promoted=false·pixelObservabilityVerified=false를 명시했어요. 새 제작 기능이나 GL 지연 해결 성과가 아니며, 남은 초기 GL/FXC·장치/필터 비용과 복합 광학 이력은 계속 남아요. 같은 가설의 작은 초기화/SSA 실험을 반복하지 않아요.

TAA를 포함한 두 렌더러 검사를 한 CDP 요청으로 기다린 초기1089는 공통20초 관찰 제한으로 끝났고 엔진 예외는 없었어요. 이후 소유 창 안의 작업 핸들을 시작하고 같은 핸들의 단계/완료를 짧게 조회하도록 바꿔 GL/WebGPU의 high/coarse/restore/TAA를 모두 통과했어요. 이 시간 제한과 재현 자료도 남겨요.
