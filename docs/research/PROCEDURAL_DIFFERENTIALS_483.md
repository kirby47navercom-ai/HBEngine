# 절차적 좌표의 변화량과 Checker 셀 정밀도

Noise·Checker를 텍스처 좌표로 연결할 때, 큰 절대 좌표에 작은 폭을 더하면 float32에서 값이 같아져 밉 계산이 사라질 수 있어요. 두 연산에도 상대 유한 변화량을 전달했어요. 원래 값의 계산과 변화량 계산을 구분하고 현재·이전 프레임의 좌표에 같은 규칙을 사용해요.

좌표와 배율이 함께 변하면 곱의 변화량은 `a·db + da·b + da·db`예요. Checker는 이 변화로 넘어간 셀 수의 홀짝을 계산해요. Noise는 셀 안에서 보간 다항식의 유한 차를 계산하고, 경계를 넘을 때는 가까운 코너 값과 잔차를 사용해요. 경계 바로 왼쪽의 `1−epsilon`을 먼저 만들어 작은 차를 없애지 않도록, 경계에서 떨어진 거리를 별도로 전달해요.

Checker의 기본 값에서도 큰 X 셀과 작은 홀수 Y 셀을 더하면 홀짝이 틀리던 문제를 고쳤어요. 각 축의 홀짝을 먼저 줄인 뒤 더하는 공통 함수를 CPU·GLSL·TSL·DirectX 변환·광선 계산에 연결했어요. `±33554432`와 `±1`의 조합 네 경우에서 이전 GPU 계산의 0과 수정한 1을 실제로 대조했어요.

새 GPU 검사는 세 경로에서 103개 조건을 다뤄요. 셀 내부·경계·음수·배율 변화, 큰 좌표의 작은 폭, 작은 다항식 변화와 `1e-10` 경계 이동을 포함해요. Checker 오차는 0, 다항식은 약 `1.34e-8` 이하, Noise는 약 `7.70e-8` 이하였어요. 작은 경계 이동의 별도 기준은 `1e-24`예요. Noise 검사는 각 GPU에서 별도로 읽은 코너 해시를 독립 계수로 사용하며, 백엔드의 해시 값이 같다고 가정하지 않아요.

실제 큰 좌표의 머테리얼 그래프에서도 두 연산을 노멀 텍스처의 UV로 연결했어요. 현재 패킷과 이동·반전된 장면의 이전 기하·시간 패킷을 GL·WebGPU와 생성 HLSL에서 비교했고, 밉 폭의 변화가 출력에 드러나는지도 검사했어요. 기존 `4e-5` 기준을 유지해요. Checker는 처음 검사 위치가 정확히 경계여서 작은 폭과 큰 폭이 모두 같은 셀 변화를 만들었어요. 경계에서 떨어진 위상과 메시 크기를 반영한 폭을 사용해 관측 가능한 검사로 고쳤어요.

기존 699개 수학 조건은 세 GPU 경로에서 기존 기준으로 통과했어요. 큰 power 출력 한 경우의 `2e-3` 기준도 이전과 같아요. 실제 D3D 전처리 24조건에서는 새 보조 함수도 좌표에 필요한 경우만 남고, 단순 좌표와 셰이딩 전용 그래프에는 추가되지 않는 것을 확인했어요. AI의 불변 좌표 정책은 45개 안정 연산을 공개해요.

처음 WebGPU 검사에 있던 정수 인덱스의 `floor(i32)` 호출은 WGSL 진단을 읽어 검사 코드에서 수정했어요. 본래 수학 기준을 바꾸지 않았어요. 해시의 장치별 근사, 표현할 수 없는 셀 번호와 이웃 좌표, 텍스처 값으로 만든 좌표의 변화량·고정 시선 근사는 잔여 제한이에요. 초기 전체 준비 시간·FPS 개선은 이 수학 검사로 판단하지 않아요. 실제 실행 파일과 설치 검증은 후속 기록으로 연결해요.
