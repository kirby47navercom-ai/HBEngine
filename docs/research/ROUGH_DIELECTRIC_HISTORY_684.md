# 거친 유전체의 현재·이전 입력 폭

682–683은 기존 경로 추적기의 거친 유전체 분기와 보조 가이드의 로컬 광선 폭을 맞춰요. 기능이 켜져 있고 거칠기 ≥0.05, |입사/출사 IOR 비−1| >0.0001이면 반사·투과 모두 기존 radiance의 거칠기²/2 폭을 사용해요. 나머지는 기존 Snell 폭과 TIR 동작을 유지해요. 이전 프레임은 이전 머테리얼의 거칠기와 재생한 매질 비를 사용하고, 두 프레임의 거친/델타 분류가 달라지면 이력을 거부해요.

기존 물리 필드 평가와 스칼라를 재사용해요. 운영 광선 질의·영상·uniform·버퍼·readback은 추가하지 않아요. proxy 방향은 기존 반사/굴절 방향이에요. 확률적으로 샘플링한 GGX 경로의 전역 대응이나 타원형 비등방성·참여 매질 계산의 완료를 뜻하지 않아요. 사람과 AI가 같은 `raySurfaceHistory.opticalSpread.dielectric` 계약을 읽어요.

독립 정답은 카메라 광선과 평면 교차·Snell 식, 기존 radiance의 거칠기²/2 모델로 계산해요. 정적 worldPosition 그래프를 가진 장면과 카메라를 같이 옮겨 현재·이전 입력을 다르게 만들어요. 기능 켬/끔, 낮은 거칠기, 동일 IOR, 거칠기 분기 경계 변경의 5조건을 검사해요. 허용 오차4e-5를 유지해요.

- GL/WebGPU `rough-dielectric-682-hf8FQE`: 30표본, 최대1.63e-6.
- 특화 DirectX `rough-dielectric-683-native-OPzugk`: 15표본, 최대1.31e-6.
- 일반 DirectX `rough-dielectric-683-native-WFQfbv`: 15표본, 최대1.31e-6.
- 첫682 검사는 도구의 import 정규식 escaping 오류였어요. 두 번째는 GL이 자동 선택한 기능 define을 비활성 대조군에서 지우지 않아 실패했어요. 도구를 고친 후 위 검사를 통과했으며 두 실패를 엔진 성과나 통과로 세지 않아요.

681은 설치679의 SDK·패키저·플레이어로 보존된 소유 검사 프로젝트를 실행하고 C++/블루프린트 공개 호출로 시간·렌즈·곡면 가이드를 켰어요. `native-optical-capture-681-WehcBL/native.png`는 CDP 화면이 아닌 D3D `hbCapture` 결과예요. 640×360에서 밝은 픽셀90,104개, 최대225, 평균76.10이며 path/guide/filter/temporal/auxiliary 및 머테리얼/래스터10단계가 ready예요. 준비14,509ms는 미통제 단일 관찰이며 컴파일 개선·FPS 근거로 쓰지 않아요. 장면 픽셀 출력 증거이며 화면 품질과 수식 정확성은 별도예요.

현재·이전 노멀/밉의 독립 대조, 비등방성/회전 입력의 거부·복원, 새 설치본 검증과 누적 렌더링 작업을 이어가요.
