# 반사 프로브 공간 인덱스 — 1157~1162

2026-10-21. 기존 원장 RND-03의 전역 후보 선형 탐색과 CPU 메시 후보 정렬을 함께 바꿨어요. 기존 엔진의 geometry-bvh-core, 프로브 affine/fade/SAT, 브라우저·TSL·D3D atlas 및 변형 메시 경계 소유자를 읽고 연결했어요. 새 UE/Unity 전체 본문·API 분석을 수행하거나 전체 연구 gate를 승격한 기록은 아니에요.

## 구현

GPU에 저장하는 Float32 행으로 affine AABB를 복원하고 dot 연산 오차를 확장해요. 조건이 나쁜 변환은 전체 유한 영역으로 처리해서 공간 가지치기가 잘못된 후보 제외로 이어지지 않게 해요. 공간 분할 순서와 중요도 순서를 분리하고 두 번째 적중 순위보다 좋아질 수 없는 하위 트리를 건너뛰어요. 메모리상의 다음 형제 주소로 이동하므로 픽셀 스택이나 새 compute/render 패스가 필요 없어요.

기존 메타데이터 바인딩에 노드당 float4 세 개를 추가해요. 포인터·리프·최소 순위는 16비트 단어 두 개로 저장해요. TSL 선택 결과는 index+1의 정수(0은 없음)와 가중치 비트를 사용해 부호 없는 -1 변환이나 2²⁴ 위 Float32 ID 손실을 피했어요. DirectX 프로브 개수도 기존 상수의 두 칸에 낮은/높은 단어로 전달해요. D3D 메타데이터 SRV는 float4 stride16이고, 프로브 물리 레코드는 여전히 연속 9행/144바이트예요. 낮은 수준의 SRV를 직접 읽는 사용자 셰이더는 이 행 구조를 따라야 하며 일반 ReflectionProbes C++·BP 호출은 바뀌지 않아요.

CPU 렌더러별 broad phase는 프레임에서 한 번 정렬한 순서를 공유하고 월드 경계가 같은 트리를 유지해요. 기존 SAT/로컬 점 검사로 마지막 후보를 확인해요. 중요도에 의한 상대 순서나 경계가 바뀌면 갱신하고, 밝기·페이드·캡처 이미지 버전만 바뀌면 공간 트리는 재사용해요. GPU 트리 역시 포즈·경계·순서에 필요한 행만 스탬프로 비교해요.

## 묶음 검사

`native/build/probe-spatial-batch-1160.json`은 통과한 검사와 관련 소유자 SHA를 저장해 변경 없는 검사를 다시 실행하지 않아요. 현재 결과는 다음과 같아요.

- CPU 1157-Ip0jVb: affine 513개/1,602점과 희소 4,096개/640점의 공간 선택이 별도 전체 목록 Float32 판정과 같아요. 반전·전단·조건 불량·경계 점을 포함해요. CPU 후보는 기존 SAT/점 검사와 800조건을 대조했어요. C++도 같은 2,242점의 전체 탐색과 일치하며 명시적 해제 후 보유량0이에요.
- 희소 자료에서 리프 정밀 판정은 530회, 계층 방문은 14,438회예요. 이 자료는 점당 최대 하나가 적중하므로 전체 목록 방식은 2,621,440번의 후보 판정이 필요해요. 전체 게임 FPS 또는 GPU 실행 시간 수치로 바꾸지 않아요.
- GPU 1158-QAWPmx: GL·WebGPU·강제 GL 폴백에서 각각 같은 513/4,096 자료와 2,242점을 실제 GPU 전체 목록 선택과 대조했어요. 순위는 정확히 같고 가중치 차이0, 기존 허용2e-5를 유지했어요. 2²⁴ 위 ID의 단어/정수 표현도 확인했어요. 4,096개의 실제 HDR 캡처를 만든 검사는 아니에요.
- 브라우저 atlas 1117-EUpJpG: 세 경로의 기존 54방향/거칠기·금속/코팅, 혼합 해상도·인스턴스·정지 복사/전송·밝기만 변경·해제/복구를 유지했어요. 공간 노드7·재구성 불변도 확인했어요.
- D3D atlas 1119-e7hLIO: 기존 SH/GGX/코팅/IOR/투영·실제 캡처·21방향·네 인스턴스·정지/밝기/갱신·해제를 통과했어요. 색 허용2byte에서 최대1, 노드7·정지 및 밝기 변경의 공간 재구성 불변을 확인했어요. Player1161은 새 네이티브 소스로 한 번 빌드했어요.

검사 도구의 첫 실패는 GCC 실행 환경 PATH 누락, 마지막 수를 읽은 뒤 정상 eofbit를 오류로 판단한 조건, GPU 검사에서 기본 Camera를 사용한 부분이었어요. 도구만 고쳤고 공간 선택의 기대값·오차는 완화하지 않았어요. count0의 unsigned 루프 방어를 더한 뒤 해당 네이티브 검사만 다시 실행했어요. 이미 통과한 CPU·브라우저 검사는 소유자 SHA가 같은 것을 확인해 재사용했어요.

## 비용·범위

N개 프로브에는 2N−1개 노드/48바이트씩이 추가돼요. 이미지·타깃·바인딩 개수·운영 GPU 읽기·새 렌더 패스는 늘지 않아요. 브라우저 4,096개 공간 자료는 GPU payload393,168바이트, CPU 공간 자료+스탬프 payload688,080바이트예요. CPU broad phase의 JS 객체와 임시 구축 자료·기존 캡처·전체 metadata는 별도예요. D3D 진단은 벡터 capacity를 포함한 보유 payload를 보고해요. 겹침이 큰 최악의 경우는 선형 탐색이 남아요.

실제 C++/BP 게임의 카메라 이동·프로브 밝기·복원 및 설치본은 후속 ENGINE_WORK_1163.json/설치 영수증으로 연결해요. 다수 HDR 캡처 전체 장면의 통제 FPS/메모리, 타일/클러스터와의 비교·혼합, 픽셀 중요도·구형 캡처/lightmap, 임의 변위/모프와 다른 누적 엔진 목표는 남은 원장에서 유지해요.
