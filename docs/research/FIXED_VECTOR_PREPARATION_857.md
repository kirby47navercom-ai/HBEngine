# 843–857: 광선 준비 비용과 현재·이전 문맥 보존

## 적용한 변경

- BVH 경계의 x/y/z 계산을 기존 순서 그대로 고정 성분으로 생성해요. 이전 정점 노멀의 세 가중합도 같은 순서로 생성해요.
- 이전 세계 BVH는 같은 경계 함수를 재사용하고, 네 삼각형 ID는 명시한 성분으로 읽어요. 현재·이전 기하, 머테리얼 입력, 시각, UV, 노멀, 접선, 밉 폭은 합치지 않아요.
- 자원·렌더 타깃·읽기·작업자·캐시·사용자 설정을 추가하지 않아요. `pipelinePreparationContract.glFixedComponents`에서 AI도 같은 계약을 확인할 수 있어요.

## 측정과 독립 대조

- 844 실제 ANGLE 변환 소스에서 동적 vec3 인덱싱이 switch/clamp 보조 함수로 확장되는 것을 확인했어요.
- 843 현재/이전 IR 본문 공유 후보는 평균 4376.4→4354.7ms로 유의미한 개선을 확인하지 못했어요. 런타임에 적용하지 않았어요.
- 845 후보 실험 뒤 실제 구현 848 ABBA는 평균 **4727.95→3825.05ms**, 비율 **0.8090**이었어요. 새 반사·Time·큰 UV 장면 한 종류의 준비 시간 관측이에요. 캐시·컴퓨터 부하를 통제한 전체 콜드 스타트나 FPS 수치, 과거 Complex141의 8초·7초 해소 근거로 사용하지 않아요.
- 848 네 재질 단계의 동적 vec3 보조 함수 호출은 `[24,24,0,26]`에서 모두 0으로 줄었어요. 해당 장면 범위의 결과예요.
- 847 실제 GL 수정 전/후 노멀 차이 0, 해석적 기대값 최대 오차 5.96e-8, WebGPU 대조 3.73e-8이에요. 기하·머테리얼·코팅 × 폭 모드 0/1/2 × 현재·이전·밉 조건을 검사했어요.
- 849 경계 353조건에서 GL 수정 전/후 차이 0, 해석적 거리 대비 상대 오차 최대 1.11e-7이에요. 평행·부호 있는 0·임계 방향·내부/외부·퇴화 경계와 결정적 표본을 포함해요.
- 368 GL/WebGPU와 DirectX에서 이전 기하 63조건, 1/1e-6/1e6 크기 180조건을 통과했어요. 371 GL/WebGPU 중첩 매질 20조건도 통과했어요.
- 369 직교 카메라 검사는 월드 배율 도입 전의 문자열을 치환하고 있었어요. 실제 카메라는 원근인데 직교 플래그만 켜진 검사가 되었어요. 배율을 보존하는 실제 직교 카메라와 일치 개수 단언으로 바로잡았어요. 실제 GL/WebGPU 12조건이 통과했고 원래 허용 오차를 유지했어요.

## 보존한 실패와 경계

853의 합성 DirectX 검사에서 이전 IOR seed를 현재 RGB seed보다 먼저 호출하면 FXC 최적화 결과가 틀리는 현상을 확인했어요. 수정 전 셰이더도 같았어요. 각각 따로 실행하거나 현재 seed를 먼저 실행하거나 최적화를 끈 대조군은 정상이었어요. 입력 위치는 보존됐고 정수 atlas 읽기·loop 변수 분리·배열 초기화·지역 복사·최적화 수준 1/2로는 해결되지 않았어요. 원인은 FXC 최적화와 연관된 것으로 좁혔지만 정확한 잘못된 변환과 일반 해법은 확정하지 않았어요.

371 DirectX 검사는 실제 `path-denoise.js`와 같은 **현재 RGB → 이전 IOR** 순서로 검사하며 10조건 최대 1.63e-7을 통과해요. 이 사실을 역순 호출까지 안전하다는 근거로 쓰지 않아요. 실패·대조 HLSL/입력/보고서는 `native/build/native-atlas-853-*`, `vector-controls-852-FMabnJ`에 보존했어요. 진단용 코드 성공을 기능 완료로 승격하지 않아요.

RND-06 전체 초기 준비 지연, RND-07 전역 투명 경로 대응·복합 매질·이방성/굴절 footprint와 이 합성 FXC 조건은 계속 남아 있어요. 나머지 렌더링·엔진 누적 원장도 유지해요.
