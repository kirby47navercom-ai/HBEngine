# 736–745 현재·이전 노멀 필터 폭과 제작·실행 연결

2026-10-19. 이 기록은 아래에서 실제 대조한 범위이며 누적 엔진 목표 전체의 완료를 뜻하지 않아요.

## 구현

PostProcessVolume의 경로 추적에 `pathTracingNormalFootprint`를 추가했어요.

| 값 | 동작 |
| --- | --- |
| `off` | 기존 경로. 추가 노멀 평가를 생성하지 않아요. 기본값이에요. |
| `geometry` | 노멀맵이 없는 선택 표면의 정점 노멀 변화를 두 축에서 평가해요. 매핑된 기본·코팅 표면은 기존 폭을 유지해요. |
| `material` | 선택한 기본·코팅 노멀을 두 축에서 다시 평가해요. 노멀맵이 없으면 정점 노멀 경로를 써요. |

반사·굴절 광선 두 개 사이의 유한 각도 외피를 기존 cone에 더하고 1.57에서 제한해요. 이웃 광선이 TIR 경계를 넘으면 상한까지 넓혀요. IOR가 같은 앞면의 투과는 정확히 0을 더해요. 곡면 가이드와 실제 경로 추적의 기본·코팅 로브에 연결했어요.

이전 경로는 이전 기하·시각·위치·뷰·밉 폭으로 별도 평가해요. 현재 값을 이전 경로에 복사하지 않아요. 현재 재투영의 대응/이력 거부 정책도 유지해요.

GPU 타깃·uniform·버퍼·정상 프레임 읽기는 추가하지 않았어요. 기존 `pathQuality.w`의 비트21–22를 사용해요. 선택적 모드는 경계마다 현재/이전 문맥 각각 최대 두 번 노멀을 더 평가해요. 코팅 방사 경로는 선택한 중심 노멀·코팅 선택값도 평가해요. 이 비용을 FPS 개선이라고 주장하지 않아요.

전체 경로 검사에서 드라이버 `atan` 오차가 이차 이동 거리에 따라 커지는 것을 발견했어요. 허용치나 장면 거리를 줄이지 않고 두 번 반각 축소와 홀수 급수로 계산했어요. 축소 뒤 `|t|<=tan(pi/16)`; 수학적 급수 절단 오차는 7e-13 미만이고 실제 float 오차는 별도 GPU 검사에 포함돼요.

## 제작·AI·C++

속성창, 포스트 볼륨 해석, 저장 속성, 공유 컴포넌트 명령을 사용해요. 별도 테스트 전용 제작 API를 만들지 않았어요.

```cpp
hb::Components::SetString(volume, "PostProcessVolume",
    "pathTracingNormalFootprint", "material");
```

블루프린트는 기존 `componentSetString`을 사용해요. API의 `raySurfaceHistory.opticalSpread.normalVariation`에 기본값·모드·비용·남은 한계를 불변 계약으로 공개해요. DirectX 실행 진단의 `pathNormalFootprint`는 0/1/2예요. SDK의 `SceneScreenEffects.normalFootprintMode`는 명시 선택이고, 일반 에디터/플레이어는 기존 패킹 비트를 전달해요.

## 근거

- 736: 실제 WEBGL_lose_context 손실·복구 이벤트에서 RGBA8 2D/배열/볼륨/큐브의 동일 버전 하위 밉을 복구했어요. 리소스는 바뀌고 결과는 유지됐어요. 기존734 구현으로 통과해 불필요한 복구 등록기·프레임 스캔을 더하지 않았어요.
- 737/738/739: 독립 reflection=2atan(slope), Snell, equal-IOR 해석값과 실제 GL/WebGPU/D3D11 생성 코드를 대조했어요. 정점 비균일 배율과 기본·코팅 노멀의 위치/시각/폭이 다른 현재·이전 문맥을 검사했어요.
- 740/741: 완전한 보조 가이드의 최종 반환만 검사값으로 바꿨어요. 카메라 cone, 선택 거칠기, 노멀 변화, 이차 수신면 거리로 독립 계산한 현재/이전 폭을 대조했어요. GL/GPU 최대오차 5.15e-7, D3D 최대오차 2.76e-7이에요.
- 743: 실제 전체 방사 경로의 로브 선택 뒤 cone을 검사했어요. 모드별 32개 시드에서 기본·코팅·정점 노멀의 독립 각도 증가와 diffuse/끄기 대조를 확인했어요. 최대오차 8e-9 미만이에요. 서로 다른 API의 난수 분기가 같다고 가정하지 않았어요.
- 742/744: 새 네이티브 플레이어를 빌드하고 독립 프로젝트를 패키징했어요. 실제 C++ SetString, 키보드 블루프린트 Y/U, 모드 전환과 원복, 경로 샘플과 캡처 준비, 작업자 종료를 검사했어요.
- 745: 라이브 API 열거형, 잘못된 값 거부, 포스트 볼륨 선택, 패킹의 낮은 기존 비트 보존, float 정확 표현과 이력 키 변경을 확인했어요.
- 기존362/109/365 계약·밉/이력·선택 노멀 기능, 생성 파일 일치도 통과했어요. 위 GPU 검사 허용치 4e-5는 늘리지 않았어요.

정확한 증거 경로·SHA는 ENGINE_WORK_746.json에 기록해요. 검사 구현 중 잘못된 fixture 속성명, 생성 헤더 누락, 검사 삽입 위치를 수정한 실패는 제품 구현 성과로 세지 않아요.

## 분석 출처와 한계

새 읽기: [Khronos WEBGL_lose_context revision15](https://registry.khronos.org/webgl/extensions/WEBGL_lose_context/)의 반환 본문 전체 121줄. 손실 이벤트 완료 전에 복구를 요청하면 안 된다는 규약을 검사에 적용했어요. 연결 문서 전체를 읽었다고 계산하지 않아요.

재읽기: [PBRT4 Texture Sampling and Antialiasing](https://pbr-book.org/4ed/Textures_and_Materials/Texture_Sampling_and_Antialiasing)의 이번에 반환된 10.1.3 부분, 약200–290줄의 normal derivative와 반사/투과 ray differential 논의. HB는 그 전체 해법을 복제한 것이 아니라 로컬 각도 외피를 따로 구현했어요.

전역 곡면 역해·변경된 투명 경로의 대응, 완전한 이방성/거친 복합 확률 로브·참여 매질 미분, 표현 한계 아래 머테리얼 오프셋과 위상 경계는 남아 있어요. 복잡한 GL 초기 준비 약8초도 이 변경으로 해결됐다고 계산하지 않아요. 텍스처 상주 예산·스트리밍 및 나머지 누적 엔진 항목을 계속해요.
