# 863–874: 고정 채널과 실제 제작·밉 수요

## 엔진 변경

머테리얼의 Split·텍스처 성분 핀은 저작한 그래프에서 이미 정해져 있어요. 이전에는 이 핀도 atlas 값을 읽어 동적으로 선택했어요. 새 레이아웃은 opcode6의 마지막 세 정수에 `[성분,1,0]`을 기록해 GL·WebGPU·생성 HLSL의 값과 차분을 명시한 성분으로 생성해요. `pipelinePreparationContract.staticChannels`에서 같은 계약을 읽을 수 있어요.

- 11정수 레이아웃·12실수 atlas 명령 크기는 유지해요. 기존 `[0,0,0]` 메타데이터는 계속 atlas의 동적 선택을 사용해요.
- 새 성분 번호는 프로그램 키에 들어가요. 핀을 바꾸면 프로그램이 바뀌고, 일반 파라미터·벡터 값 변경은 같은 프로그램을 재사용해요. 채널을 고정해도 입력 벡터를 고정하지 않아요.
- 현재 native/mobile 공용 생성기가 두 형식을 읽고 잘못된 플래그를 거부해요. 새 레이아웃을 예전 바이너리에 전달하려면 실행 파일을 다시 빌드해야 해요. 물리 모바일 검증 완료를 의미하지 않아요.
- GPU 자원·타깃·읽기·작업자·디스크 캐시를 추가하지 않아요. 사용자 화면에 진단용 설명을 추가하지 않아요.

실제 제작 흐름을 연결하면서 두 수요 계산 오류도 재현했어요. Split의 출력은 x/y/z/w인데 CPU 수요 계산이 r/g/b/a를 찾고 있어 UV Split·Combine 그래프를 증명하지 못했어요. 같은 그래프가 최고 해상도 요청으로 돌아갔어요. 또 같은 parameters 객체 내부에서 값을 바꾸면 수요 캐시가 이전 배율을 유지했어요. 실제 핀 이름을 사용하고 관련 스칼라·벡터 값만 스냅샷으로 비교하도록 고쳤어요. 변경 없는 조회에서는 스냅샷을 새로 만들지 않아요. 무관한 값·시각 변경은 기존 힌트를 재사용하고, 증명하지 못한 비선형 좌표의 보수적 요청은 유지해요.

## 검증 근거

- 863: 네 성분의 서로 다른 키, 일반 값 변경의 같은 키, 기존 동적 형식과 잘못된 플래그 거부를 검사했어요.
- 864 실제 GL/WebGPU: 네 성분·기존 형식·atlas 선택 값 반전·일반 벡터 변경·저작한 핀 회전 18조건을 통과했어요. GL 프로그램 동일성을 확인했고 WebGPU 프로그램 동일성은 미측정으로 남겼어요.
- 865 실제 DirectX: 같은 아홉 조건의 출력 오차 0, 잘못된 메타데이터 네 조건 거부를 확인했어요. HLSL에서는 단일 성분의 float4 복제를 네 항으로 생성해요.
- 866 실제 GL/WebGPU: 움직이는 Time/world 노멀·독립 코팅 그래프에 xyzw Split·Combine을 넣고 기존 동적 형식과 비교했어요. 현재/이전/서로 다른 폭·세 모드 여섯 조건에서 변경 전후 차이 0, 해석적 기대 최대 4.79e-8이에요.
- 739 `--channel-roundtrip`: 실제 DirectX의 현재/이전 노멀·폭·반사/굴절 12변형, 해석적 기대 최대 4.79e-8이에요. 허용 오차 4e-5를 유지했어요.
- 867의 별도 ABBA: 해당 새 노멀·Time·채널 그래프 준비 평균 **3060.85→2475.95ms**, 비율 0.8089였어요. 이 장면의 소스는 각 경로·주 가이드·보조 가이드에서 800바이트 줄었어요. 다른 작업과 겹친 최초 측정은 성능 근거로 승격하지 않았어요. 이번 vec4 동적 보조 함수 수는 전후 모두 0이므로 보조 함수 제거 성과로 세지 않아요. 과거 Complex141·전체 콜드 스타트·FPS나 이전 묶음과 합산한 개선율을 뜻하지 않아요.
- 868: 수정 전 최고 해상도 fallback과 변경 후 배율 고정을 각각 재현한 실패 기록을 보존했어요. 최종 스칼라·벡터 객체 내부 변경, 양/음/소수 배율과 독립 LOD 다섯 조건, 무관한 값·시각의 힌트 동일성, 비선형 보수적 요청을 확인했어요.
- 870: 관련 CPU 회귀 13개를 함께 통과했어요. 기존 801의 10만 캐시 조회는 이 실행에서 약 4.18ms였어요. 프로세스 RAM·VRAM·장시간 FPS 측정으로 사용하지 않아요.
- 781 `--channels`: 실제 패키지 GL 게임에 UV Split·Combine을 넣고 C++·블루프린트의 머테리얼 변경, 여섯 가이드 전환, 껐다 켜기와 실제 화면을 확인했어요.
- 804 `--channels`: 실제 패키지 DirectX 게임의 같은 UV 그래프에서 SDK C++·블루프린트 배율 변경으로 밉 수요 0/3/1/0/3, 전체 원본과 래스터·경로 추적 픽셀, 머테리얼 프로그램 재사용을 확인했어요.

검사는 고유 프로젝트·프로필에서 실행했어요. 사용자 원본과 User 프로필을 검사 입력으로 사용하지 않았어요. RND-06/07의 복합 초기 준비·전역 투명 경로 대응, MAT-03의 비선형/국소/이차 광선 수요, FXC 합성 역순 호출 조건과 다른 엔진 누적 목표는 그대로 남겨요.
