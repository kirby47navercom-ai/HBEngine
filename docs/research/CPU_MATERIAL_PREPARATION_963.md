# CPU 머테리얼 평가와 기하 재사용 (951–968)

기하 GI 수집기는 삼각형마다 머테리얼 그래프 전체를 해석·검증하고 사용하지 않는 노멀 입력까지 평가했어요. 같은 머테리얼의 시간·파라미터만 바뀌어도 정점·UV·변형 노멀을 다시 만들었어요. CPU 준비 비용을 줄이면서 기존 기하·머테리얼 패킷 값과 이전 프레임 자료를 보존하는 변경이에요.

## 구현

- 한 번의 동기 수집 안에서 같은 원본 머테리얼은 한 번만 복사·해석해요. CPU 삼각형 자료에 사용하는 출력만 선택하고 노드·입력·연결 조회를 준비해요. 선택 평가기의 복사본에만 조회 계획을 약하게 연결하며, 기본 평가기의 실시간 그래프 변경 동작은 유지해요.
- 읽기 전용 `contextDependencies`가 시간·색 공간뿐인 경우 같은 수집의 평가 결과를 재사용해요. 월드 좌표·노멀·뷰·UV·텍스처 콜백 의존성이 있으면 삼각형 문맥마다 계산해요. 기본 Panner Time, Fresnel 기본 노멀·뷰, 기본 텍스처 UV도 포함해요.
- 머테리얼만 바뀌면 새로운 삼각형 머테리얼 레코드를 만들고 변하지 않은 정점·로컬 정점·노멀·UV·역행렬 배열을 공유해요. 이전 프레임의 색·발광·표면 레코드는 수정하지 않아요. 머테리얼 슬롯은 연속 구간으로 기록해 삼각형별 슬롯 배열을 추가하지 않아요.
- 기하·속성 버전·변환·인스턴스·스킨·모프·그룹·표시 조건·볼륨 순서가 바뀌면 기존 수집 경로로 돌아가요. 속성 및 인스턴스 변경에 필요한 기존 `needsUpdate` 계약은 같아요.
- 사용되지 않는 Time과 상수 Panner가 월드 좌표 IR 때문에 매 프레임 갱신되던 조건도 실제 Time 명령과 CPU 시계 의존성으로 좁혀요. 실제 시간·파라미터·이동은 계속 반영해요.

새 GPU 버퍼·타깃·워커·영구 디스크 캐시·오브젝트 수 제한을 추가하지 않아요. 기존 저장 그래프와 C++·블루프린트 파라미터 API를 그대로 사용해요. `work.preparedMaterialSources`, `surfaceEvaluations`, `surfaceCacheHits`, `materialOnlyMeshes`, `reusedGeometryTriangles`로 마지막 수집 작업량을 읽을 수 있어요.

## 검증 근거

- `geometry-evaluation-953-2qgZxE`: 변경 전 수집기 본문을 고정한 독립 모듈과 전체 삼각형·시그니처·라이트·실제 패킹 Float32·rayInfo를 비교해요. 속성/비속성 × 전송/비전송 4조건, 0→2→0, 음수 스케일, 파라미터 제자리 및 교체 변경, 캐시 재사용과 그래프 없는 머테리얼을 포함해요.
- `geometry-uniform-956-TE2pZm`: 12조건에서 문맥 독립 96개 삼각형의 평가는 1회·재사용 95회예요. 삼각형의 가변 배열은 독립이고 다음 수집의 파라미터 변경은 반영돼요. Fresnel·UV·콜백 의존성은 보수적으로 유지해요.
- `geometry-clock-958-ytjjUK`: 미사용 Time·숫자 Time·상수 연결은 수집 3→1회, 실제 GPU 및 CPU 시계는 3→3회예요. 모든 실제 패킷은 변경 전과 같고 이동·스케일·IOR 수정은 무효화돼요.
- `geometry-reuse-960-l8q06p`: 28개 상태에서 실제 월드 패킹이 변경 전과 같아요. 시간·파라미터·그림자·머테리얼 교체, 숨김/복원, 단일/그룹 전환, position/normal/uv/index, 변환/볼륨 순서, 인스턴스 개수/행렬, 모프·스킨 포즈를 포함해요. 이전 머테리얼 레코드 보존과 변경 없는 기하 배열 공유를 직접 검사해요.
- `material-preparation-regressions-962.json`: 타입·함수·레이어·uniform·텍스처 종류·볼륨·실시간/스냅샷 평가·콜백·빈 선택·소유권 8종이 통과했어요. 선택 평가기의 실제 복사 원본 128개는 평가기를 해제하고 GC 4회 뒤 모두 수거됐어요. 전체 게임 장기 메모리 검증을 뜻하지 않아요.
- `material-clock-941-native-1tvfE1`: 실제 최적화 HLSL·D3D11에서 현재 매질 스택·IOR·RGB 12조건을 유지해요. 최대 오차는 1.624e-7예요.

텍스처 종류 단위 검사의 오래된 Three.ImageLoader 주입은 현재 플랫폼 Image 경로를 덮지 못했어요. 검사에서만 Image 객체를 제공하고 복원하도록 고쳤으며 실제 이미지 디코딩 검증으로 계산하지 않아요. 엔진 이미지 로더는 변경하지 않았어요.

## CPU 비용 관측

`geometry-world-cost-961-inYeWQ`는 같은 그래프·장면에서 변경 전/후를 ABBA 순서로 번갈아 실행했어요. 각 시각의 전체 CPU `GeometryGIWorld.prepare` 결과 Float32·rayInfo·매질 수를 비교하고 프레임 이력을 commit했어요. 노멀 체인 64개는 실제 CPU 삼각형 출력에 사용되지 않아요.

| 조건 | 삼각형 | 변경 전 평균 | 변경 후 평균 |
|---|---:|---:|---:|
| 월드 위치·노멀에 따라 값이 달라지는 머테리얼 | 864 | 5,001.92ms | 48.61ms |
| 같은 값을 사용하는 머테리얼 | 384 | 2,225.07ms | 13.91ms |

이전의 수집만 측정한 957-gSscTd(1,536개 9,026.50→102.77ms, 균일 384개 2,192.75→7.10ms)는 기하 재사용 변경 전 관측이고, 위 961은 최종 전체 CPU 준비 관측이에요. 부하·GC는 완전히 통제하지 않았어요. GPU 렌더 시간, 게임 전체 FPS, 최초 GL·FXC 컴파일이나 과거 Complex141의 8초·7초 문제가 해결됐다는 근거로 사용하지 않아요.

설치본 실제 C++·블루프린트 실행, GL 노멀/표면 전환, D3D 밉·경로 추적, 파일·소유권 대조는 `ENGINE_WORK_966.json`과 `USER_INSTALL_968.json`에 이어 기록해요. 누적 원장의 미검증·잔여 조건은 유지해요.
