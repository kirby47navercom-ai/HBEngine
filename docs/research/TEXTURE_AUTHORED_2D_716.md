# 2D 작성 밉과 가져오기 설정

2D 텍스처도 기본 `images` 한 장과 `mips`의 각 레벨 한 장을 지정해요. 배열·볼륨·큐브와 같은 에셋 편집기의 밉 추가/이하 삭제·Undo를 사용해요. 생성된 밉 대신 작성한 이미지의 색과 알파를 읽으며, 기존 색 공간·녹색 반전·하위 노멀 정규화·커버리지·노멀/거칠기 합성·상위 밉/최대 크기·밉 비활성 설정을 적용해요. 원본 이미지는 보존해요.

작성 체인은 끝까지 크기와 자료를 검사해요. 설정으로 선택한 레벨만 GPU 체인에 남기며 `importReport`는 원래 레벨 수와 선택한 topMip, 실제 저장량을 구분해요. 미리보기와 AI `texture.view`는 선택한 작성 원본 경로도 보여줘요. 스칼라 파라미터를 LOD에 연결하고 C++/블루프린트의 기존 머테리얼 함수를 사용해요. 공용 그래프 로더·네이티브 패키저·광선/베이크 경로를 따로 우회하지 않아요.

큰 2D 작성 체인은 기존 단일 워커 큐를 사용해요. 모든 레벨과 합성 노멀의 버퍼를 한 번씩 전달하고, 빌린 입력은 보존해요. 워커가 전달 후 실패하면 재디코드를 요청해요. 새 입력으로 로컬 복구할 때도 작성한 색을 유지하며 유휴 워커는 종료해요. 기존 자동 생성 경로도 유지해요.

검증은 다음 범위예요.

- 712 CPU: 선형/sRGB 작성색 보존·생성 밉과 차이, topMip/크기, 노멀·커버리지·분산 합성, 원본·잘못된 체인 거부.
- 694 uOzOH4: 실제 GL/TSL6표본, 세 레벨의 작성 원본·픽셀·크기, 가져오기 topMip 편집/Undo와 밉 삭제/복원/저장. 초기 검사는 한 장짜리에 index2를 지정한 fixture 오류였으며 index를 레벨 깊이에서 계산하도록 고쳤어요.
- 695 UYKp98: 실제 D3D 세 레벨과 잘못된 체인5개 거부.
- 696 fEJ13p: 실제19에셋 패키지·C++ LOD/타입 교체·키보드 블루프린트 복원·유휴 업로드 재사용.
- 697 IjHSRD/yrwyFq: 실제 GL/TSL/HLSL의 작성 RGBA8 노멀 체인과 현재·이전 기하/시각, 독립 정답4e-5·이전 재현/백엔드 차이0.
- 714 ZX7omd: 실제 워커의512² 자료/노멀/분산 세 작업·단일 큐·전체 버퍼 전달/차용 보존·유휴 종료·의도한 전달 후 실패와 새 입력 복구. 워커 실패를 정상 렌더링 오류로 숨기지 않고 retry를 확인했어요.
- 기존452/466/543 CPU와453 WAl2AB 자동 생성 워커 회귀도 통과했어요.

새 읽기 범위는 Unity6.0 [Texture2D.SetPixelData](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Texture2D.SetPixelData.html)의 반환된 선언·매개변수·본문·예제예요. 포맷/레벨에 맞는 원본과 GPU 업로드를 구분하고, 예제는 작성한 하위 레벨을 자동 갱신으로 덮지 않아요. 전체 Unity API나 UE 문서의 분석 완료로 세지 않아요.

모든 성능 표현은 정확한 자료량·업로드 재사용·워커 수명에 한정해요. FPS나 전체 메모리 개선율을 측정한 것은 아니에요. 압축·플랫폼 쿠킹·스트리밍·부분 레벨 갱신과 다른 누적 엔진 목표는 이어서 구현해요.
