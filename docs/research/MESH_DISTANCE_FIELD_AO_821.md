# 메시 거리장 AO 구현·검증 원칙

2026-10-19, RND-08·PER-03·AI-03. 기존 화면 깊이 AO와 별도인 실제 기하 거리장 경로예요. 이 기록은 전체 렌더링이나 Unreal·Unity 전체 기능의 완료 선언이 아니에요.

## 자료 대조

Epic 5.8의 [메시 거리장](https://dev.epicgames.com/documentation/unreal-engine/mesh-distance-fields-in-unreal-engine?lang=en-US) 검색 반환 본문 중 원리·품질·제약을 다시 읽었어요. 최근접 표면까지의 부호 거리, 빈 공간 건너뛰기와 원뿔 가시성, 메시별 볼륨 정밀도를 구현 근거로 삼았어요. 연결된 전 문서·API를 읽었다는 뜻은 아니에요.

[DFAO 개요](https://dev.epicgames.com/documentation/en-us/unreal-engine/distance-field-ambient-occlusion-in-unreal-engine)의 화면 밖 차폐·이동하는 강체·큰 메시 정밀도·시간 필터·전역 거리장 항목을 대조했어요. HB는 우선 오브젝트 BVH와 공유 로컬 볼륨을 사용해요. Epic의 클립맵·시간 신뢰도 필터와 동등하다고 주장하지 않아요.

[거리장 속성](https://dev.epicgames.com/documentation/unreal-engine/mesh-distance-fields-properties-in-unreal-engine?lang=en-US)의 생성 메모리·복셀 밀도·해상도·시작 편향·차폐 거리 설정을 대조했어요. HB는 선택한 후처리 볼륨에서 활성화하고, 해상도와 atlas 페이로드 예산을 노출해요. 비활성 장면에는 거리장 생성·텍스처·디스크 캐시가 없어요.

[사용 가이드](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-distance-field-ambient-occlusion-in-unreal-engine)의 SkyLight 연동을 확인했어요. HB는 이미 분리되어 있는 간접광 출력에 차폐를 적용하고 직접광은 보존해요. SkyLight의 모든 방향·반사 모델을 이 구현으로 대체하지 않아요.

## 실제 구현

- 로컬 삼각형 BVH의 최근접 거리와 교차 winding으로 볼륨을 생성해요. 닫히고 방향이 일관된 면은 signed, 열린 면·혼합 방향은 unsigned예요. 중심을 뺀 로컬 좌표로 생성하지만 GPU 월드 좌표의 Float32 정밀도까지 무한해지지는 않아요.
- 취소 가능한 전용 작업 스레드를 공유해요. 활성 요청 취소는 소유한 작업 스레드만 중단하고 다음 요청을 이어가요. 유휴 스레드를 정리하고 전달 버퍼의 인접 데이터를 분리하지 않아요.
- 동일 기하·버전·draw range·해상도에 볼륨 하나를 공유해요. 오브젝트·인스턴스의 이동·회전·반전에는 월드 BVH/역변환만 갱신하고 CPU 볼륨을 재포장하지 않아요. 동적 행이 볼륨과 같은 GPU 행에 있으면 일부 볼륨 바이트가 함께 전송될 수 있어요.
- RGBA32F atlas의 scalar lane과 삼선형 보간을 사용해요. 보간 오차 상한을 뺀 보수 거리, 역변환의 거리 하한과 BVH로 이동해요. 여섯 반구 원뿔·각 48회 최대 전진의 유한 근사예요.
- 후처리의 `aoMode=distanceField`, 거리·편향·세기, 해상도 8–64, atlas 예산을 사용해요. 새 속성도 후처리 볼륨 그룹/블렌드/저장/기존 컴포넌트 C++·블프 함수와 같은 경로예요. 화면 깊이 AO와 중복 적용하지 않아요.
- GL·WebGPU·D3D11에서 같은 atlas를 사용해요. GL 최초/자원 복원 업로드를 보장하고 이후 누적된 변경 행을 유지해요. D3D11은 전용 t15와 숫자 atlas 좌표를 사용하며 뷰포트 색상 샘플 좌표를 혼용하지 않아요.
- `engineSchema().meshDistanceFields`, 실행기·프로파일러의 `distanceFields` 진단으로 준비 상태·제외 원인·페이로드·부분 갱신을 읽을 수 있어요. 객체 수의 임의 상한 대신 명시한 메모리/주소 예산을 적용해요.

## 증거와 승격 기준

810: 분석적 상자 거리 1,008점 최대 오차 4.45e-16, 뒤집힌 면·안쪽 공동·열린 면·퇴화 삼각형·큰 좌표·예산·취소. 볼륨 보간 오차는 별도 상한 이내예요.

812: 실제 숨김 창의 작업 스레드 취소 3종·다음 요청 CPU 바이트 일치·유휴/대기 입력 0.

813: 600개 packed 조회와 독립 역변환/볼륨 표본 대조, 최대 오차 2.37e-7. 공유 볼륨의 1,100개 인스턴스 atlas 196,608B. 정적 쓰기 0, 강체 이동은 prefix 21개 float만 변경, 볼륨 복사 0. 이 수치는 FPS가 아니에요.

814: 실제 GL/WebGPU 각 32점 최대 오차 3.17e-7, 같은 차폐값 0.7261201와 빈 공간 0, 공유 기하·이동·삭제·해제. 실제 GPU 계산을 거친 증거예요.

817: 제작용 MRT/라이팅/후처리 경로에서 GL·WebGPU 간접광 픽셀 132→103, 직접광 픽셀 67 유지, 비활성 소유자 해제. 이 과정에서 기본 MeshStandardMaterial 앞 전처리 지시문 개행 누락도 수정했어요. 32×32 정확성 장면이며 실게임 속도 측정은 아니에요.

818-xdRINL: 패키지 D3D11에서 C++ 활성 픽셀 `[195,205,172]`, 비활성 `[216,224,201]`, 키보드 블루프린트 활성은 C++와 같았어요. 직접광만 남긴 두 화면은 `[118,122,75]`로 같았어요. 강체 이동의 볼륨 복사 0과 비활성 해제도 확인했어요.

822-rgiOmE: 실제 속성 선택으로 거리장 옵션을 표시하고 해상도 17 편집·Undo 13·Redo 17, 같은 문서의 AI CAS 예산 3MB 변경·오래된 revision 거절·파일 저장·API 검색을 확인했어요. 캡처를 직접 확인했어요.

824: 후처리·현재/이전 기하·머테리얼 이력·노멀 계약·경로 상태 소유권·밉 수요 등 11개 CPU/TSL 생성 회귀와 JS 27개 구문 검사를 통과했어요. 예전 304 검사는 새 작업 전부터 바뀐 240개 샘플링 표·중첩 텍스처 미분·0 미분 전달을 반영하지 않아 실패했어요. 실제 구현은 바꾸지 않고 기본 48개 독립 truth table과 새로운 중첩 미분 조건에 맞춰 검사를 갱신했어요. 원래 실패 기록은 통과 증거에서 제외했어요. 실제 GPU 이력 회귀와 설치본 대조는 묶음 기록을 따르세요.

## 남겨두는 구체 항목

전역 클립맵·타일별 후보·거리별/반해상도 재구성·시간 신뢰도·bent normal/방향별 하늘 차폐·지형 heightfield·캡슐/스키닝·모프·변위·마스크/투명 차폐·쿠킹 캐시는 별도 작업이에요. 큰 메시·얇은 특징·큰 비균일 크기에서는 볼륨 정밀도와 자기 차폐 편향 때문에 세부 차폐가 손실될 수 있어요. atlas 예산과 로컬 입력/볼륨 페이로드 진단은 전체 JS/GPU 메모리나 작업 스레드 BVH를 계측한 값이 아니에요.
