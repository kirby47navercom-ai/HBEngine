# 452–472 구현·검증 기록

451에서 대조한 텍스처 가져오기 정책을 2D JSON 에셋, 편집기 상세 창, 공통 밉 생성, 네 렌더 경로, 게임 패키지에 연결했어요. 정본 증거 목록은 `ENGINE_WORK_472.json`이에요. 이 기록은 누적 엔진 전체 완료나 전체 Unreal·Unity 본문/API 분석 완료를 뜻하지 않아요.

공통 생성기는 NPOT 영역 가중치, 선형 색 공간, 양자화 전 알파 커버리지, 원래 알파를 통한 다음 레벨 축소, 선택적 녹색 채널 반전·하위 노멀 정규화, 상위 밉·최대 크기를 처리해요. 생성 정책과 샘플러를 분리하고 원본 파일을 보존해요. 실패한 작업과 입력 소유권을 구분하며 큰 작업은 워커 하나를 공유해요.

사람은 중앙에서 밉·채널·픽셀을 보고 오른쪽에서 원본과 정책을 편집해요. AI는 동일 문서 검증·revision·Undo와 불변 스키마를 사용해요. 머테리얼 노드·함수·레이어·인스턴스의 텍스처 선택, 같은 경로의 정책 변경, 런타임 교체, 참조 변경과 패키징을 연결했어요. DirectX C++에는 하위 밉 업로드 API를 추가했어요.

실제 숨긴 GL·WebGPU 검사에서 생성한 밉의 방향·레벨·색을 읽었어요. DirectX GPU에서는 서로 다른 색의 세 레벨, 84바이트 자원, 잘못된 체인의 거절, sRGB 보간과 JS에서 포장한 자료를 확인했어요. 새 패키지의 기존 raw 참조와 가져오기 참조는 중간 밝기의 두 색에서 각각 `[154,0,0]`, `[0,0,154]`로 같았어요. 런타임 raw/가져오기 교체 후 업로드 수가 안정됐어요.

공통 광선 데이터로 GL·WebGPU와 생성 HLSL의 이전 프레임 입력도 확인했어요. 노멀·색상은 이전 기하·시간과 이동·반전된 현재 기하에서 기존 `4e-5` 기준을 유지해요. 알파가 공간에 따라 바뀌는 자원은 기존 전역 이력 초기화 조건을 유지하며, 커버리지 색상·알파의 이전 기하 비교는 같은 시간에서 검사했어요. 이를 시간 이력 재사용 허용으로 계산하지 않아요.

초기 검사에는 세 가지 구분이 필요했어요. Undo 명령의 이름·revision을 잘못 사용한 검사 코드를 수정했어요. 색상 검사는 이상적인 선형 값의 고정 오차 대신 [Direct3D 11.3 변환 규격 3.2.3.7](https://microsoft.github.io/DirectX-Specs/d3d/archive/D3D11_3_FunctionalSpec.htm)의 sRGB 쪽 0.5 ULP 측정 방식을 적용했어요. 관찰된 최대 선형 오차 약 `0.00102`는 sRGB 쪽 약 `0.171` 단계였어요. 기존 수학·광선 검사 기준은 바꾸지 않았어요.

이력 검사 첫 시도는 물리 필드 0을 색상 필드로 잘못 지정했어요. 색상·알파 필드 1로 고친 뒤에는 시간에 따라 바뀌는 가시성의 기존 초기화 조건이 드러났어요. 노멀·색상 이력과 커버리지의 같은 시간 비교를 분리하고 각각의 허용 조건을 검사했어요. DirectX 브리지의 중첩 C++ 타입 이름과, 머테리얼 콜백이 가져온 sRGB 자원을 선형 자료로 덮는 문제도 실제 패키지 검사 과정에서 수정했어요. 초기 실패 기록은 빌드 증거 폴더에 보존해요.

정책 기능의 추가 GPU 연산이나 프레임별 재생성은 없어요. 자원 생성 때 사용하는 CPU 픽셀·워커와 명시적 밉 저장 비용은 존재해요. 전체 FPS 개선, HDR·압축·배열/볼륨 정책, 스트리밍, 노멀 분산 합성 또는 누적 렌더링 완료는 주장하지 않아요. 초기 컴파일 지연·전역 곡면 대응·매질·GI와 나머지 원장을 계속 진행해요.
