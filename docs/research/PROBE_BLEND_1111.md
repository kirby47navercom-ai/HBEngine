# 브라우저 반사 혼합·변형 경계·수명

2026-10-21. RND-03의 남은 반사 프로브 작업을 진행해요. 최종 SHA와 검사/설치 경로는 ENGINE_WORK_1112.json 및 후속 영수증에 확정해요.

## 공식 본문 대조

[Unity URP Reflection Probes](https://docs.unity.com/en-us/engine/6000.6/manual/lighting-overview/lighting/reflection-probes/introduction)의 볼륨·Blend Distance·후보 선택 본문을 읽었어요. 픽셀의 면 거리, 남는 하늘 비율, 후보의 중요도·볼륨 기준을 대조했어요. 문서의 Forward+/Deferred+ 전역 탐색과 높은 중요도가 완전 점유하는 정책까지 이번 구현으로 주장하지 않아요. HB는 기존 native와 같은 정규화 수식과 후보 순서를 유지해요.

[Epic Reflection Captures](https://dev.epicgames.com/documentation/en-us/unreal-engine/reflections-captures-in-unreal-engine)의 투영 모양·Glossy Indirect Specular·해상도 구역을 읽었어요. 로컬 캡처의 영향 영역·픽셀 혼합과 해상도/메모리의 관계를 대조했어요. 작은 캡처의 픽셀별 우선 점유와 UE의 lightmap 혼합은 별도 범위예요. 처음 reflections-environment URL은 반사 방식 개요로 연결돼, 이를 Reflection Captures 본문 분석으로 세지 않았어요. supplemental1111/read-scope.json은 해당 구역만 기록하고 전체 본문/API gate를 승격하지 않아요.

Three의 설치된 MIT 배포 CubeUV 샘플러/PMREMNode·TextureNode·Position accessor와 직접 대조했어요. GL은 기존 라이선스 샘플러의 배치 상수를 맵별 입력으로 바꾸고, GPU는 같은 textureCubeUV를 사용해요. 원래 환경의 GL/GPU 회전 규약은 각 백엔드 표준 머테리얼 출력과 대조해요.

## 구현 범위

브라우저 두 후보의 affine face fade/정규화/원래 환경 잔여, 기본 반사·간접 확산/다중 산란·코팅과 GPU 굴절의 공용 샘플, 실제 인스턴스 월드 좌표를 연결했어요. GL 프로그램용172032B 앵커와 맵별 배치 uniform, GPU의 독립 샘플 바인딩으로 해상도·후보 변경을 처리해요. 원래 환경의 밝기/회전·원본 버전 필터/해제·공유 머테리얼 외부 교체·굴절 훅 복원을 함께 다뤄요.

CPU 스킨/모프의 실제 현재 정점 경계와 bone/bind/attribute/weight stamp를 추가했어요. 포즈가 그대로면 정점을 다시 읽지 않고, 음수 가중치와 원점 밖 변형도 포함해요. 네이티브 JS 패킷도 이 경계로 후보/컬링을 계산해요. 네이티브 ABI/셰이더/C++ 선언은 바꾸지 않아 Player/Host 재빌드 없이 기존 소유 지문을 대조해요.

## 검사와 수정 기록

1106은 평행 이동 삼각형의 독립 스킨/모프 경계, 음수 가중치·속성 변경·부모 변환·100 정지 프레임의 정점 읽기0, 원점 밖 후보와 독립 혼합 비율을 확인해요.1108은 원본 환경 밝기/회전·버전 필터 교체/해제, 머테리얼 외부 교체와 복제본/앵커 해제·이전 굴절 소유자 보존을 확인해요.

1107은 실제 GL/GPU 물리 조명과 알려진 상수 CubeUV 자료를 사용해 독립 픽셀 비율/흰색 물리 기준을 대조해요. 금속/코팅 오차는 약0.000001 이하이며, 혼합 해상도와 크기 변경 시 GL 프로그램 유지·밝기만 바꿀 때 캡처 유지·실제 인스턴스 표시를 확인해요. 실제 방향별 큐브를 필터링하고 원래 환경의 회전/밝기·복원·재필터 없음도 표준 머테리얼 출력과 대조해요. 후보 하나로 시작한 뒤 두 번째를 추가하는 경우도 검사해요.

초기 GL CubeUV 코드 구분에 배포본에서 제거되는 주석을 쓴 오류를 정의 심볼 경계와 명시 검사로 고쳤어요. 코팅의 GPU 노멀/시선 초기화가 조건문 안에만 생긴 문제는 분기 전 입력 준비로 고쳤어요. 초기 같은 텍스처를 사용하는 GPU 슬롯의 샘플 복제본이 병합되는 문제는 기반 노드의 고정 uniform ID를 유지해 고쳤어요. GL 켜기/끄기 후 같은 프로그램의 uniform이 이전 상태를 가리키던 문제는 약한 머테리얼별 저장소와 참조 비우기로 고쳤어요.

기본 diffuseIntensity=0을 흰색 전체 조명과 비교한 가정, GPU float 읽기의256B 행 패딩을 누락한 가정, +/-0 행렬의 엄격 구별은 검사 오류였어요. 기존994의 intensity=0 기준은 영역 점유를 유지하므로 원래 환경으로 복귀한 픽셀과 달라요. 실제 C++로 영향 높이를0.1로 줄인 무점유 픽셀을 기준으로 사용하고 원래 오차2는 유지해요. 실패를 성과로 세지 않아요.

실제994 --morph 패키지는 원점10 단위 밖의 glTF 상대 모프 표면에서 C++/BP 회전과 원래 환경 기준/복원을 대조해요. 캡처 위치를 바꾸지 않는 범위·회전 편집은 활성 뷰의 캡처1을 유지해요. 임의 shader deformation·전역 후보/우선 점유·전체 FPS/모바일 기기·전체 엔진 완료는 주장하지 않아요.

## UV 없는 머테리얼 노멀 수정

실제 glTF 모프 검사에서 GL의 반사가 간헐적으로 검게 나타났어요. 소유 검사창에서만 프로그램 uniform·텍스처 바인딩·캡처 texel을 읽어, 올바른 맵과 값이 전달됐음을 확인했어요(probe-room-994-X7CU9x/failure.json). 원인은 UV가 없는 표면에서 기존 hbNormal이 0인 접선 벡터를 normalize한 것이었어요. 모델에 UV를 추가하거나 픽셀 오차를 늘려서 우회하지 않았어요. 임시 드로 훅은 최종 검사 도구에서 제거했어요.

GL과 GPU의 기본·코팅 노멀에 유한값/최대성분 정규화, 중립/음수Z/0, UV 없음·영역0·일직선 UV의 기하 노멀 복귀를 연결했어요.1109-rog0AT는 실제 GL/GPU 각각24개 평면 조건을 해석 정답과 오차2e-5로 대조해요. 동적으로 같은 GPU geometry의 attribute schema를 지우고 바꾸는 초기 검사는 Three RenderObject의 attribute 캐시와 충돌했으므로, 독립 geometry/material로 각 입력을 검사해요. 해당 schema 교체 자체의 완료를 주장하지 않아요.

수정 후 실제 모프 패키지는 Native Ftfibr, GL Qn5es9, GPU IWdwOu에서 빨강→무점유 환경→빨강→환경→빨강과 캡처1을 통과했어요. 이후 캡처 전 CPU 포즈 경계 갱신과 해제 직전 외부 머테리얼 교체 보존을 추가했고, 최종 설치본1114에서 세 백엔드 패키지를 다시 확인해요. 현재 소스1106-rsIzi5,1108-mxacl3와1107-PIVBqz 및 정적/API/AI 탐색 근거는1112에 연결해요. 기존 native 소유10개 SHA가 같아 엔진 바이너리를 다시 빌드하지 않아요.

최종 후보 검토에서 GPU의 메시 후보가 아예0개일 때에도 원래 환경을 유지하도록 연결했어요.1107-PIVBqz는0후보에서 시작한 뒤 두 후보로 들어오는 전환까지 해석 기준과 대조해요. 메시 후보가0개인 상태와 후보 볼륨 밖 픽셀을 구분해서 검사해요.
