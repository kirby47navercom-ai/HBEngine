# 목록 제작·실행 확장 1079–1081

사람의 위젯 상세 패널과 AI의 기존 JSON/CAS/Undo 편집에 선택 방식·원본 자료 반영·순서 변경을 연결했어요. 선택은 재활용 DOM 행이 아닌 원본 인덱스/트리 ID에 속해요. Ctrl/Cmd·Shift·Space·전체 선택·초점 이동, 평면 목록의 묶음 이동·중복 값 대응·자료 교체 중 드래그 취소, 형식 보존 own-path 쓰기·원본 불변성, 이벤트의 현재 행 자료와 크기 제한을 함께 다뤘어요.

고정 높이의 평면 행 수정은 기존 offset 배열과 행 풀을 유지해요. 전체 JSON 저장·검증, 자동 측정/트리 레이아웃 재구성은 유지하며 전체 프레임 성능 개선으로 확대하지 않아요. 라이브러리·워커·영구 색인·GPU 자원·네이티브 opcode를 추가하지 않았어요. 자세한 사용자 계약은 WIDGET_CLASSES_AND_LISTS.md에 있어요.

## 원문 대조 범위

[Unity 6 ListView 매뉴얼](https://docs.unity3d.com/6000.0/Documentation/Manual/UIE-uxml-element-ListView.html)의 목록 재활용·부분 refresh/전체 rebuild·높이·순서 변경·선택/초점 구역을 읽고 대조했어요. [bindItem API](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/UIElements.ListView-bindItem.html)의 행 인덱스 연결과 unbind 주의도 확인했어요. HB에서는 기존 행 view 해제/재바인딩에 자료 편집을 붙였어요. 단축키와 트리의 접힌 선택 보존은 HB의 명시 계약이며 Unity 전체와 같은 동작이라고 계산하지 않아요.

Epic UListView 주소도 조회했지만 이번 응답에서 본문을 얻지 못했어요. 이를 신규 Unreal API 본문 분석 완료에 포함하지 않아요. 두 엔진 전체 문서·연결 API·본문 분석 완료나 전체 누적 엔진 완료를 주장하지 않아요. 이번 읽기 경계는 supplemental1081/read-scope.json에 남겼어요.

## 검증

1079는 순수 선택/범위/모드·중복 원시 값 이동·타입/경로 쓰기·원본 공유·프로토타입 거부·문서 검증과 큰 이벤트의 명시 제한을 검사해요. 1080은 실제 숨김 Windows 창에서 상세 편집/Undo, 100000항목 선택/행 풀8, 입력 키 격리, 키보드/합성 DOM drag/drop, TextInput/CheckBox/Slider 자료 반영, 재활용 마지막 행, 스크립트 자료 교체와 기존 서비스, VM custom event 인자를 확인해요. 단일 행 수정이 전체 offset을 재구성하지 않는 것도 검사해요. 합성 드래그는 실기기 터치 검사로 계산하지 않아요.

기존 174(9/9)·181(6/6)·256(4시나리오)와 실제1067의 상속/슬롯/생명주기·긴 논리 스크롤·측정 행·복합 행 풀/폰트/전역 예산 회귀도 묶었어요. 초기 시험의 selector 인용·선택할 트리 요소·이동 기대 인덱스·저장 명령/CAS 실수는 검사 도구 오류였고 통과 성과에 포함하지 않아요. 최종 검사 경로와 SHA는 ENGINE_WORK_1082.json 및 설치 영수증에 연결해요.

## 이어갈 범위

트리/여러 목록 간 재부모화, 터치 재정렬, 전체 screen reader·물리 기기, 복합 중첩 측정·장시간 UI 성능, 디자이너 임의 BP/C++ 실행 및 별도 네이티브 위젯 객체와 3D 깊이/조명은 남아요. 렌더링에서는 GL 일괄 제출·노멀 공유·기존 실패 실험을 다시 대조했지만 이번 변경으로 초기 약8/7초 지연을 줄였다는 근거는 없어요. 렌더링 코드 변경이나 실패 실험을 새 구현으로 세지 않아요.
