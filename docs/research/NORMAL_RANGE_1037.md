# 현재·이전 노멀의 큰/작은 강도 안정성

RGB를 부호 있는 tangent normal로 풀고 XY에 강도를 곱한 뒤 길이를 구할 때, 기존 GPU 계산은 유한한 성분도 제곱 과정에서 overflow/underflow가 날 수 있었어요. 길이가 무한대가 되면 방향이 0으로 줄고, 0이 되면 유효한 방향을 중립 노멀로 바꿨어요. 이전 프레임의 머테리얼 평가와 노멀 기반 UV·밉 문맥도 같은 디코더를 쓰므로 이 문제의 영향을 받을 수 있어요.

GPU 계산은 최대 절대 성분으로 먼저 나누고, 크기가 조절된 벡터의 길이로 정규화하도록 고쳤어요. 원래 0벡터의 중립 tangent normal [0,0,1]은 유지해요. CPU는 이미 안전한 double `Math.hypot`를 사용하므로 공식을 바꾸지 않아요. GL의 일반 머테리얼·레이/이전 필드, TSL의 일반/레이/이전 필드, 같은 GLSL로 생성하는 네이티브 HLSL이 이 정책을 공유해요.

에셋·노드·C++ 함수·변수 형식이나 UI 조작은 추가하지 않아요. 기존 Normal Map 노드와 C++ `hb::Materials::SetFloat`, 블루프린트 `materialFloat`가 같은 파라미터 경로를 사용해요. normalDecode 자동화 계약은 버전2로 범위를 명시해요. 새 GPU 텍스처·렌더 타깃·샘플러·캐시·readback과 프레임별 CPU 처리는 없어요. 노멀 계산의 로컬 GPU 산술만 바꿔요.

## 실패 재현과 독립 정답

1030-NnRtqC는 변경 전 GL·WebGPU 실제 Float32 픽셀을 읽어 각각 49종 중 14종 실패·최대 방향 오차1을 확인했어요. RGB는 [0,1], 강도는 유한한 0/±1/±10³⁰/±10⁻³⁰이에요. 입력을 Float32로 먼저 고정한 뒤 별도 double-hypot 정답을 구해요. 실패 대조는 diagnostic이고 구현 통과로 계산하지 않아요.

- 1030-Jya8Ic는 수정 후 GL·WebGPU 49종 모두 통과하며 최대 오차가 각각 약7.66e-8/1.03e-7이에요.
- 1032-q5QF0f는 실제 생성 헤더의 함수를 최적화한 하드웨어 D3D11 compute로 실행해요. 49종 모두 통과하며 최대 오차는 약7.66e-8이에요.
- CPU402는 중립·양/음 방향·보통/큰/작은 강도56종과 실제 머테리얼 그래프/네이티브 코드 생성·자동화 계약을 확인해요.

## 이전 노멀·밉·움직임

403-ok8vey(큰 강도), 403-pGKpNB(작은 강도)는 Float 노멀 텍스처의 서로 반대인 두 texel과 실제 packed mip 체인을 사용해요. 커밋 전 프레임과 이동·회전·음수/비균일 크기 변경 후 이전 프레임을 같은 지점·같은 footprint로 평가하면 거친 밉의 중립 [0,0,1]이 같아요. 선명한 이전 밉은 [-1,0,0]을 되돌려요. GL/TSL의 실제 필드와 일반 래스터 노드도 확인해요.

네이티브403-mqobh1/403-dpRZKU는 동일 문맥의 실제 HLSL 필드를 실행하고 오차0/약5.96e-8로 통과해요. 큰 강도는 허용된 입력 범위의 Power 노드 1000¹⁰으로 만들어요. 에셋 검증의 기존 숫자 범위를 풀거나 비정상 에셋을 허용하지 않아요. 작은 강도도 정상 노드 입력을 사용해요.

## 실제 제작·SDK 실행

1036-9qS7EC는 새 Player1040의 실제 패키지에서 Power(10, Exponent)→Normal Map→표면 노멀·발광 방향 색상을 연결해요. C++와 키보드 블루프린트가 Exponent를 0/30/-30으로 바꿔 강도1/10³⁰/10⁻³⁰을 만들어요. 일반 래스터 다섯 단계와 경로 추적 다섯 단계의 중심 픽셀은 모두 [227,126,206,255]로 일치하고 래스터 프로그램도 유지돼요. 경로 추적은 실제2샘플까지 실행해요. 브라우저/설치본의 후속 결과는 누적 작업·설치 기록에 연결해요.

## 읽은 근거와 경계

[Microsoft XMVector3Normalize](https://learn.microsoft.com/en-us/windows/win32/api/directxmath/nf-directxmath-xmvector3normalize)의 자체 반환 주의와 Robust 예시 구역에서 최대 절대 성분을 먼저 사용하는 원리를 대조했어요. HB는 0벡터를 중립 tangent normal로 바꾸므로 Microsoft 함수의 0 반환과 구분해요. 원문 SHA·읽기 경계는 supplemental1030/read-scope.json에 있어요. 연결 함수·전체 라이브러리/API 분석을 완료한 것으로 계산하지 않아요.

보장 범위는 유한하고 GPU에서 표현할 수 있는 중간 성분이에요. 곱셈 자체가 이미 overflow하는 값·denormal flush·NaN/Inf 입력, 일반 Normalize 노드의 별도 clamp 의미나 모든 비선형 미분·절차 해시를 이번 변경으로 해결했다고 하지 않아요. 전역 곡면 대응/복합 매질 이력과 실제 Complex141 초기 지연도 별도 잔여예요. 범위를 바꾸지 않고 실패를 재현한 경로의 산술 문제를 고친 것이며 전체 엔진 완료·FPS 향상 주장은 없어요.

1036-LZREpB(WebGL2)와1036-dmnBF2(WebGPU)도 실제 SDK C++/키보드 블루프린트의 래스터5단계·path5단계를 통과했어요. 각 모드 안의 기준 픽셀과 큰/작은 강도 픽셀이 같아요. 브라우저의 검사 API에는 native pathSamples 카운터가 없어 null로 기록하고, 활성 PostProcessVolume·path 파이프라인 준비 완료·실제 레이 기하를 확인해요. 초기 WebGL 검사가 없는 native 카운터를 기다린 실패는 검사 경로 실수로 별도 보존했어요. 브라우저에서2샘플을 직접 셌다는 주장은 없어요.

1042-JZnUE1은 실제 Complex141 캡처 GLSL에서 디코더 한 함수만 이전/수정으로 바꿔 ABBA compile/link를 대조했어요. path7575.45→7403.15ms, 가이드5478.75→5771.10ms로 서로 다른 방향의 차이가 났어요. 가이드 약5.3% 증가 가능성을 남기고 성능 최적화 성공으로 세지 않아요. 정확도 수정의 비용 대조이며 드라이버 캐시·부하 통제가 없는 한 묶음 수치예요. 실제 초기 컴파일 지연은 계속 잔여예요. 수동 머테리얼 입력 변경의 기존 이력 reset 정책도 유지하며 이번 수정으로 모든 이전 입력을 재투영하는 범위가 늘었다고 하지 않아요.
