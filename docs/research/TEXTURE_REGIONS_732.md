# 이전 입력 이력과 텍스처 부분 갱신

현재·이전 프레임의 머테리얼 시각과 공간 차분을 분리했어요. 레지스터의 작성 순서로 공간 의존성을 추적하고 상수·Time·시점 방향의 0 차분만 제외해요. 해당 값의 현재/이전 프레임 평가, IR·키·GPU 자료 배치는 유지해요. 자동 생성 광선 밉은 필터를 끄고 켤 때 같은 기본 float 레벨을 재사용하지만, 이미 반환한 레벨 목록을 늘리지 않아요. 일반 큐브의 여섯 면도 중간 Number 배열 없이 수치를 보존하는 typed array로 연결해요. raw-half 저장값을 새로 디코딩하는 기능은 아니에요.

`Materials::SetTextureRegion(target,parameter,level,origin,size,pixels)`와 같은 선언에서 생성한 `materialTextureRegion` 노드를 추가했어요. 원점·크기는 정수 XYZ, 픽셀은 X→Y→Z 순서의 Color 배열이에요. Color는 저장 색 공간의 0~1 RGBA이며 별도 색 변환을 하지 않아요. 배열·큐브의 Z는 면, 볼륨의 Z는 깊이예요. 원본 파일을 쓰지 않고 현재 실행 중인 명시적 RGBA8 밉을 바꿔요. 서로 다른 저장 포맷, 자동 밉 재생성, 스트리밍/상주 예산은 이 API의 구현 범위와 구분해요.

모든 영역을 검증하고 입력을 복사한 다음 CPU 밉을 바꿔요. 잘못된 뒤쪽 영역 때문에 앞쪽만 적용되지 않아요. 다중 머테리얼도 모든 준비를 마친 다음 적용해요. 텍스처 버전 변경으로 일반 머테리얼/광선 이력을 무효화하며 이미 변환된 이전 float 밉은 보존해요. 마지막 한 배치만 보관해요. 배치가 전체 원본보다 크거나 렌더러가 이전 버전을 놓치면 전체 자료를 다시 올리므로 프레임마다 변경 저널이 쌓이지 않아요.

DirectX는 같은 자원에 `UpdateSubresource`를 써요. 배열/큐브는 면×밉의 subresource, 볼륨은 밉 안의 Z box를 사용해요. WebGPU도 기존 자원의 `writeTexture` box를 사용해요. WebGL은 소유 텍스처의 동기 `initTexture` 동안 그 자원의 전체 전송만 교체하고 바로 원래 메서드를 복원해요. 엔진 실행 연결에서 이 준비를 호출해요. 직접 JS로 쓰면 `writeTextureRegions` 다음 `prepareGPUAuthoredMips(renderer,map)`를 호출해요. 새 draw/frame wrapper나 GPU 표면·운영 readback은 추가하지 않았어요.

WebGL의 아래 밉 업로드 캐시도 버전뿐 아니라 실제 GPU 자원을 확인하도록 고쳤어요. 텍스처를 명시적으로 해제하고 같은 버전으로 다시 만들었을 때 오래된 업로드 기록 때문에 새 자원의 하위 밉이 비는 것을 막아요. 실제 컨텍스트 손실/복구 이벤트와 큐브 재초기화는 다음 검증·구현 대상으로 유지해요.

## 검증 근거

- 722: rgba8/float32/float64/raw-half/plain 큐브의 독립 면/인덱스 값과 `-0` 포함 Float64 수치 해시 일치. 두 포즈×네 밉 모드의 패킹 atlas는 변경 전과 바이트 단위로 같아요. 메모리 수치는 typed payload 바이트이며 V8 heap/FPS 측정이 아니에요.
- 520 gUt4gR / 521 AjYATc: 일반 큐브의 네 밉 모드, 실제 GL/TSL/HLSL 현재·이전 노멀 대조.
- 724/726: 공간 상수 전파·레지스터 덮어쓰기·중첩 샘플 의존성, 네 자료형의 sRGB/선형 기본 레벨 공유와 홀수 면적 평균·버전/해제·이전 목록 길이 보존.
- 520 Utgj28 / 521 YFpj3s: 변경 후 네 자료형×네 모드 실제 현재/이전 입력, 독립 노멀 정답과 기존 4e-5 유지. GL/GPU 차이 및 이전 재현 차이 0.
- 725 TaNK61: 같은 소유 밉 그래프의 실제 전체 GL 준비 ABBA. 소스는 109877→108869, 가이드 96369→95361, 보조 가이드 108672→107664바이트예요. 준비 시간은 이전 4391.4/4253.2ms, 변경 4401.8/4223.7ms예요. 유의미한 속도 향상이나 복잡한 초기 8초 문제 해결로 계산하지 않아요.
- 727: 독립 픽셀 정답, 잘못된 배치의 무적용, 입력 소유권·stale 준비 거부, 이전 float 밉 보존과 누락 버전 fallback.
- 728 XYVy6m: GL/WebGPU의 네 자료형, 변경 픽셀과 다른 밉/면, 실제 부분 업로드 수/바이트, 자원 동일성·유휴 업로드 0, 명시적 해제 후 같은 버전의 하위 밉 재생성. 전송은 자료형별 20/24/20/40바이트이며 전체 84/216/192/504바이트와 구분해요.
- 728 UzPSnL: 2D flipY+sRGB도 부분/전체 업로드 결과가 기존 4e-5 안에서 일치해요. 고정 기능 하드웨어 EOTF와 수학식의 최대 차이는 두 API 모두 약 0.00185908로 별도 기록했어요. 이 경우를 수학식과 4e-5 일치한다고 표현하지 않아요.
- 729 bfSH1e: 실제 D3D11 SDK의 네 자료형/같은 전송 바이트, 독립 색상 정답, 자료형별 잘못된 전체 배치 6개 거부와 앞 영역 무적용, 추가 텍스처 할당 0.
- 696 GxDzNY `--regions`: 새 실제 98에셋 패키지와 Player730r. 네 자료형의 C++ 변경→키보드 블루프린트 변경→원래 값 복원, 각 3회/12바이트와 추가 텍스처 할당 0. 기존 세 LOD·타입별 텍스처 교체/복원도 통과했어요.

초기 검사에서 드러난 미초기화 배치 조회의 optional-chain 조건은 수정했어요. 테스트의 TSL 호환 훅 순서·프로그램 생성까지 세던 할당 계측·누락된 검사 셰이더 선언·기존 밉 fixture의 중복 준비는 엔진 기능의 성공으로 세지 않아요. 수정한 실제 실행 결과와 실패 기록을 따로 보존해요.

## 새로 읽은 범위

[Microsoft의 UpdateSubresource 본문](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-updatesubresource)에서 반환된 선언·매개변수·제약·복사 수명·행/깊이 stride·부분 영역 예제·deferred-context 주의와 요구 사항을 읽었어요. HB는 기존 immediate context를 잠그고 쓰며, 부분 갱신도 자원 경합이 있으면 드라이버 내부 복사가 생길 수 있어요. 전송 바이트 감소를 GPU 전체 비용/FPS 보장으로 바꾸지 않아요. W3C writeTexture 원문은 크기 제한으로 가져오지 못했으므로 읽은 자료로 올리지 않아요. 기존에 읽은 Unity SetPixelData와 로컬 고정 Three 업로드/버전 관리 구역을 대조했어요. 전체 UE/Unity/연결 API 분석 gate는 승격하지 않아요.
