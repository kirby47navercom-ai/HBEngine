# 행동트리 EQS 서비스

행동트리 노드를 선택하고 **EQS 서비스**를 추가해요. 환경 질의 에셋, 결과 키, 결과 종류와 간격을 지정하면 해당 노드가 활성화된 동안 자동으로 질의해요. 기존 이벤트 서비스와 나란히 사용하고 같은 문서의 저장·Undo·JSON/AI 편집을 사용해요. 명령 검색·단축키 프로필에는 **행동트리 EQS 서비스 추가**도 등록돼 있어요.

```json
{"id":"sense","kind":"query","asset":"Assets/EQS_Enemy.hbeqs.json","key":"Target","resultType":"actor","contextKey":"Context","successKey":"Found","interval":0.25,"callOnStart":true,"restartTimer":true}
```

- 결과가 오브젝트이면 블랙보드 키는 object, 위치이면 vec3로 만들어요. 문맥 키는 선택적인 object이고, 성공 키는 선택적인 bool이에요. 자료형은 질의 전에 확인해요.
- 가장 높은 점수의 결과를 기록해요. 빈 결과는 이전 목적지를 유지하고 성공 키에 false를 기록해요. 위치를 임의로 원점으로 바꾸지 않아요.
- 이벤트 서비스의 간격·시간 편차·진입 즉시 갱신·재진입 타이머·활성/비활성 이벤트를 공유해요. 완료 이벤트를 지정하면 queryMatched와 queryCount도 전달해요. 느린 트리 간격보다 서비스가 먼저 기한에 도달하면 트리를 깨워요. 지연 프레임에 같은 질의를 여러 번 몰아서 실행하지 않아요.
- 비활성 분기는 질의하지 않아요. 중단·분기 퇴역·재시작 중에 도착한 이전 결과는 다른 활성화의 블랙보드나 완료 이벤트에 반영하지 않아요. 공용 EQS도 로딩·실행 중 대상/문맥 객체가 교체되면 이전 결과를 공개하지 않아요.
- 기존 query 태스크 및 C++/블루프린트의 행동트리 실행·EQS 명령과 같은 서비스·공간 인덱스를 사용해요. 별도 스레드나 유휴 타이머를 만들지 않아요.

`kind`를 생략한 기존 서비스는 이벤트 서비스로 읽어요. 기존 파일을 다시 저장해야 실행되는 기능이 아니에요. 소스에서 동작을 확인했으며 정적 편집 월드의 TestPawn, 실제 분리 창·실기기, 네이티브 패키지 실행은 별도 검증 범위예요. AI는 `behaviorQueryService` 스키마와 `createBehaviorQueryService` 집중 탐색을 사용할 수 있어요.
