# 네이티브 머테리얼 상수와 초기 준비

표면 입력에 직접 연결된 scalar·vector3·색상 상수는 네이티브 컴파일에서 읽기 전용 값 버퍼로 분리해요. 같은 구조의 색상만 다른 머테리얼은 같은 셰이더 코드를 공유하고 값은 각 머테리얼에 유지해요. 레거시 기본 색상·거칠기 중간 노드는 기존 표면 바인딩으로 바로 연결해요.

원본 그래프는 바꾸지 않아요. 색상 공간 변환, 스칼라의 벡터 확장, 노멀·코팅 노멀은 유지해요. 산술 연결·명시적 파라미터·정적 분기·텍스처는 기존 경로를 사용해요. 런타임에서 바꾸려면 파라미터 노드를 사용해요. 상수를 값 버퍼로 옮겼다고 연결된 표면 속성을 SetFloat/SetVector로 수정할 수 있게 만들지는 않아요. floatKeys/vectorKeys에도 읽기 전용 상수는 노출하지 않아요.

소유자는 `compileMaterial`의 명시적 `uniformSurfaceConstants` 옵션과 `compileNativeMaterial`이에요. WebGL/WebGPU 컴파일은 이 옵션을 켜지 않아요. `nativeSurfaceProgramContract`로 조회할 수 있어요. 영구 별도 색인·스레드·캐시는 추가하지 않아요.

발견 장면의 기본 머테리얼 1개와 발광색이 다른 4개는 서로 다른 소스 5개에서 같은 소스 1개로 줄었어요. 발광 머테리얼 값은 49 float에서 52 float로 12바이트씩 늘어요. 정확한 실제 게임 준비 시간과 색상 픽셀, 코드 해시·검사 범위는 후속 ENGINE_WORK에 기록해요. 장면 준비 시간에는 실행·셰이더·캡처 등이 포함되므로 컴파일 시간이나 FPS로 바꾸어 부르지 않아요.

이는 단순 표면 상수의 소스 공유예요. 복잡한 그래프 전체의 초기 지연, GPU 드라이버 컴파일, 모든 수식의 동적 파라미터화까지 해결했다고 표현하지 않아요.
