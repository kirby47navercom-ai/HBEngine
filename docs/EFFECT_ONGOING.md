# 지속 효과의 현재 태그 조건

효과의 **지속 활성 태그 조건**은 적용 시 캡처 조건과 달라요. `ongoingRequirements`를 추가하면 v4로 확장하며 duration이 0인 즉시 효과에는 지정할 수 없어요. source/target/instigator/causer에 all/any/none/exact를 지정하고 역할 사이에는 AND를 적용해요. 기본값은 계층 태그 비교예요. 해당 역할의 현재 태그와 처음 캡처한 오브젝트 identity/소유 상태 세대를 사용해요. 없어진 역할의 같은 ID 새 오브젝트로 연결하지 않아요.

조건이 꺼지면 **억제**해요. 핸들·스택·레벨·입력 캡처·만료 시각·주기 위상을 유지하면서 수치 변경·부여 태그·면역·주기 실행을 끄고, 조건이 돌아오면 재개해요. 억제 중에도 만료하며 지나간 주기를 소비해요. 재개할 때 과거 피해를 몰아 주거나 executeOnApply를 다시 실행하지 않아요. 스택 refresh/extend의 기존 규칙은 유지해요. 적용 시 modifier/application 태그 조건의 캡처 의미는 그대로예요.

조건부 부여 태그는 기본 태그와 무조건 효과/활성 능력 태그에서 함께 계산해요. 양의 태그 연쇄는 적용 순서에 상관없는 최소 고정점으로 계산해요. 자기 효과가 부여할 태그만으로 자기 조건을 처음부터 충족시킬 수 없어요. none 조건이 서로 켜고 끄는 순환을 만들면 `ONGOING_EFFECT_CYCLE`로 적용/태그/능력 변경 전체를 되돌려요. 매 프레임 상태를 번갈아 바꾸지 않아요. 상태 변경 Cue `inhibit`/`resume`는 실제 전이 때만 한 번 발생하며 최초 적용에는 합성 전이가 없어요.

공용 태그/능력/효과 변경은 즉시 반영해요. 외부 직접 태그 배열 편집·역할 교체는 다음 능력 tick에서 감지해요. opt-in v4 효과가 있을 때만 역할 서명과 참여 월드를 확인해요. 태그/능력/효과 변경 때 조건부 효과의 대상·설정된 역할 소유자·이번 변경 대상/새 역할과 그 실시간 수치 종속자만 복사하고 태그/수치 색인을 갱신해요. 관계없는 오브젝트의 효과·능력 배열과 디버그/태그를 읽거나 다시 공개하지 않아요. 첫 참여 시 기존 직접 태그 편집도 기준 태그와 분리해 보존하고 제거/만료/세트 초기화/소유자 종료 시 참여 색인을 정리해요. 모든 조건부 대상의 최소 고정점은 함께 계산하므로 조건 자체가 아주 많을 때의 비용과 일반 tick의 전체 소유자 수명/시계 순회는 남아 있어요. 레거시 효과만 있는 월드는 기존 영향 소유자 경로를 유지해요. 추가 에셋 읽기·타이머·상시 수치 집계를 만들지 않아요.

사람용 필드와 `effect.ongoing.edit`는 같은 복사·검증·CAS·Undo·저장을 사용해요. AI는 `path`, `expectedRevision`, `requirements` 또는 `clear:true`, 선택 `dryRun`/`includeData`를 전달해요. 기본 dryRun은 요약이에요. 조건 제거는 v4를 유지하며 구버전 엔진은 v4를 거절해요. 런타임 effect 조회와 능력 디버그에는 복사된 조건/억제 상태를 표시해요. 기존 BP/C++ 명령을 바꾸지 않고 공용 능력 서비스에 연결해요.

검사: `node tools/check-effect-ongoing-2445.mjs`. 주기·연쇄·순환 rollback·면역·실시간 입력·역할 수명·사람/AI 편집·저장 후 native-command replay를 확인해요. 새 C++ 바이너리/실제 창·기기 실행, 네트워크 예측·주기별 과거 입력 재구성은 이 검사 범위가 아니에요.

비용 검사: `node tools/check-ongoing-participants-2489.mjs`. 10,003 소유자·조건부 대상 1개·수치 종속자 1개에서 변경 공개는 3개, 무관 소유자 10,000개의 효과/능력 순회를 금지하고 태그/디버그 identity 보존을 확인해요. FPS·전체 tick/힙·실기기 수치로 해석하지 않아요.

2620 이후 일반 tick의 효과/능력 판정은 임시 배열을 만들지 않고 현재 Map을 순회해요. 효과가 없으면 해당 iterator를 열지 않으며 일반 능력 판정은 한 번, 실제 만료 트랜잭션 뒤에는 쿨다운만 다시 확인해요. 종료 경계와 마지막 쿨다운 0 공개를 유지해요. 시계만 게시할 때는 동일 Map/직전 게시의 무한 효과 행과 쿨다운 0 능력 행을 공유하고, 유한 남은 시간·양수 쿨다운은 계속 계산해요. 일반 연산/강제 sync는 다시 구성하고 새 상위 객체와 시간은 계속 공개해요. raw DTO에 getter나 새 포맷을 넣지 않아요.

`ability-tick-work.js`의 `abilityTickWork`/`abilityTickProjection`이 소유자예요. 신규 검사 `check-ability-tick-work-2622.mjs`는 실제 10003 유휴 소유자/2 tick에서 수명 조회 20006회는 유지하면서 효과·능력 iterator/자산 IO/게시 0을 확인해요. 빈 상태의 기존 마지막 게시 시각도 유지해요. 무한·유한 행, 재설정/종료/쿨다운/교체·원자 실패 경계와 공용 native-command replay를 함께 검사해요. 전체 소유자 수명 확인과 조건 고정점은 여전히 필요하므로 이것을 전체 O(1) tick·실측 FPS/heap 개선으로 표시하지 않아요. 추가 projection은 현재 Map/DTO 참조만 보관하고 과거 프레임을 누적하지 않아요.
