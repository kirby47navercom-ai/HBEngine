# C++ 리터럴 include 해석

사람이 편집한 C++ 파일과 AI 파일 묶음은 같은 `nativeIncludeDirectives`를 사용해요. 헤더 반사·타입 이관·소스 감시, 보조 `.cpp`의 자체 헤더 자동 삽입, 예전 인라인 코드의 헤더 제거가 이 해석을 공유해요.

주석·일반 문자열·문자 리터럴·접두어와 사용자 구분자가 있는 raw 문자열의 include 예제는 의존성이 아니에요. 숫자 구분자의 작은따옴표도 문자열 시작으로 보지 않아요. 실제 지시문은 공백·사이 주석·LF/CRLF 줄 연결·`%:` 지시문 표기를 처리해요. 인라인 코드에서 제거하는 것은 실제 따옴표 `.h`/`.hpp` 지시문이며, raw 본문과 줄 수는 보존해요.

프로젝트 의존성 탐색은 기존과 같이 따옴표 헤더를 Source 범위에서 찾고, 더 가까운 누락 후보도 감시해요. 크기·후보 수·경로 검사와 사람 편집 중 CAS 보호는 그대로 적용돼요. 보조 소스의 자체 헤더 판별은 따옴표와 꺾쇠 리터럴을 확인해요. 컴파일러에 전달하는 원본 소스와 전체 파일 기반 캐시 키는 유지해요.

이 기능은 C++ 전처리기를 대신하지 않아요. 매크로로 만든 헤더 이름·조건부 분기 선택·시스템 헤더와 `include_next`는 컴파일러가 처리해요. 조건문 안의 리터럴은 보수적으로 관찰하며, 선언 반사·이관 자체의 지원 범위를 늘렸다는 뜻은 아니에요. 새 파일 형식·명령·상주 색인·감시 타이머는 추가하지 않아요.
