# 121 — 광자 대상 선별·금속 표면 공유

코스틱 광자는 기존 기하 atlas 안에 포장한 후보 삼각형 ID를 추첨한다. ID 네 개를 float4 하나에 담으며 후보당 4바이트를 사용한다. 새 텍스처·렌더 타겟·자동 읽기는 없다. 매끄러운 반사/투과 경계와 거친 순금속·완전 투과 경계가 후보이며, 물리 속성을 계산하는 머테리얼 프로그램은 보수적으로 포함한다. 이동·머테리얼 변경 때 기존 장면 갱신을 따르고, 비활성/세기0에서는 목록을 포장하지 않는다. 목록이 없는 이전 패킷은 전체 삼각형 추첨을 유지한다. 존재하는 빈 목록은 광자를 만들지 않는다.

삼각형 제안 확률의 분모를 전체 삼각형 수에서 후보 수로 바꾸고 광속의 역확률 가중치도 함께 바꾼다. 338개 삼각형 중82개가 후보인 검사에서 불필요한 대상 선택75.74%를 제외했다. 이는 대상 추첨 비율이며 전체 GPU 처리 시간이나 FPS 향상률이 아니다. 면광원/HDRI의 광원 선택·면적 PDF와 기존 광자1024경로·32KiB 캐시는 유지한다. 후보 ID의 범위/정수와 네이티브 목록 주소·개수·flag를 검사한다. 목록은 모션 정점 블록 앞에 배치하며 기존 변경 행 전송을 사용한다.

거친 순금속의 광자 전달은 카메라와 같은 `hbPathSurfaceBRDF`/TSL 표면 평가를 사용한다. 코팅·sheen·비등방성·박막 간섭과 기하 반구 검사를 포함한다. 기존 등방성 GGX 가시 법선 제안을 사용하며 실제 BRDF×출사 코사인/제안 PDF로 광속을 계산한다. 검은 기본 금속에 코팅이 있는 경우를 위해 기본 Fresnel을 곱하기 **전** 광속을 저장한다. 기존 광속을 기본 Fresnel로 나누어 복원하지 않는다. 입사 방향은 진행 방향을 갱신하기 전에 고정한다. 광자 전용 GLSL에는 사용하는 표면 평가 의존성만 넣고 카메라 적분기는 포함하지 않는다.

사람·C++·블루프린트·AI는 기존 머테리얼과 PostProcessVolume 속성을 그대로 사용한다. 후보 목록과 PDF 보정은 실행 중 도출하며 새 에셋 설정이나 AI 전용 옵션은 추가하지 않는다. AI는 기존 문서 ID와 revision을 확인한 `document.patch/files.apply`로 같은 머테리얼을 편집한다.

`check-rendering-121`은 선택 확률의 기대값·동적 물리 필드·배치/모션/갱신을 검사한다. 네이티브121은 실제 compute 셰이더·금속5종·주소 거부9종·세기0 원본 일치를 검사한다. 실제 D3D11/WebGPU/WebGL2는 금속5종과 비후보32개를 더한 면광원 장면을 C++ 노출 함수로 바꾸며 off/on/약한 세기/0 픽셀을 검사한다. 한글 C++/BP 호출·원본 파일 보존·오류/종료/서버 해제도 기존 공용 검사기에 포함한다. 녹색 sheen은 RGB 중 최댓값을 사용하며 붉은 채널만으로 빛이 없다고 판정하지 않는다. 결과·해시·설치 명세는 [기계 기록](research/RENDERING_121.json)에 저장한다.

거친 부분 금속/부분 투과 혼합은 기존 카메라 처리에 남는다. 등방성 제안으로 추가 로브를 평가하므로 매우 날카로운 코팅/극단적 비등방성의 분산은 클 수 있다. 물리 필드 프로그램을 보수적으로 넣으므로 모든 비후보가 제거되지는 않는다. 유한 반경 밀도 추정과119의 곡면·비스듬한 이차 필터 근사는 유지한다.

대조 범위는 [PBRT Conductor BRDF](https://www.pbr-book.org/4ed/Reflection_Models/Conductor_BRDF)의 반사 반구·microfacet 반사 Jacobian·BRDF 평가/PDF 구역이다. 연결 API 전체를 읽었다고 계산하지 않는다. 이 페이지는 추가 코팅 모델 자체의 구현 근거가 아니며, 모델은 기존115의 공용 평가를 재사용한다.
