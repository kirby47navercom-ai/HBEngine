# 행동 트리 태스크의 콜백·정리 수명

기존 `task` 노드의 `onStart/onTick/onFinish/onAbort`와 Blueprint/C++ `GetTaskHandle/FinishTask`를 유지해요. 이벤트의 `task`는 해당 활성화에서 캡처한 핸들이에요. 콜백이 자기 노드를 리셋하거나 트리를 정지한 뒤에는 이전 활성화가 Tick·Finish·running 상태를 새로 기록하지 않아요. 늦게 도착한 이전 핸들과 정리 중인 핸들의 완료는 무시해요.

노드 리셋은 기존 태스크 범위를 끝내고 중단·서비스 비활성화를 정리해요. 중단이나 한 서비스의 콜백이 실패해도 나머지 서비스와 노드 참조를 정리해요. 한 오류는 같은 원인으로 반환하고, 여러 오류는 실행/정리 원인을 담은 `AggregateError`로 반환해요. `throw undefined/null/0/false/""`도 성공으로 오인하지 않아요. 종료는 메모리·활성 노드·감시·재사용 대기·서비스 기한을 비우며 반복 종료로 콜백을 다시 실행하지 않아요.

정리 중에는 중첩 Tick·네이티브 태스크 계획 재개를 막아요. 자기 중단 콜백 안에서 다시 정지하더라도 reset 깊이를 음수로 만들지 않아요. 이전 정리는 캡처한 메모리만 제거하고, 서비스 이벤트에도 이전 태스크 핸들을 전달해요. 외부 리셋 후 필요한 재평가는 기존 Tick에서 진행하고 비활성 가지를 정리했다고 불필요하게 다음 태스크 Tick을 깨우지 않아요. 타이머·작업자·대기용 polling은 추가하지 않아요. 비활성 말단과 서비스가 없는 정리는 빠른 경로를 사용해요.

공용 `BlueprintRuntime`과 네이티브 명령 재생에서 트리 재시작 뒤 오래된 완료를 거절하고 현재 활성화만 완료하는 흐름을 검사해요. 기존 C++ 수명 검사는 현재 SDK로 실제 `TaskProbe`를 빌드해 `GetTaskHandle/FinishTask`와 범위 있는 네이티브 타이머의 취소를 대조해요. 소유 검사 실행 파일 해시·SDK 사용 지문·호출 기록은 해당 작업 원장에 연결해요. 실제 편집기 창·렌더러·사용자 설치본 검사를 뜻하지 않아요.

이 변경은 콜백 세대와 정리 기반이에요. 명시적 지연 `FinishAbort` 프로토콜·전용 native BTTask 클래스, 취소에 협조하지 않는 외부 콜백/latent 작업의 강제 중단·부작용 롤백은 별도 잔여예요. 기존 중단 콜백이 반환한 Promise는 계속 기다리며 임의 외부 I/O를 강제로 종료했다고 주장하지 않아요.
