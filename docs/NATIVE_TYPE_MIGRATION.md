# 저장된 구조체 값의 새 필드 반영

공유 타입 라이브러리에 필드를 추가하고 저장하면, 해당 선언을 사용하는 저장된 제작 값에도 새 멤버 기본값을 채워요. C++ 포함 헤더와 순수 BP의 명시적 타입 가져오기 모두 같은 경로를 사용해요. 기존 수치·문자열·enum 숫자·Actor ID·배열 순서를 유지해요. 이미 새 모양인 값은 다시 바꾸지 않아요.

대상은 선언으로 자료형을 확인할 수 있는 값이에요.

- BP 변수·함수/매크로/디스패처/인터페이스 인자 기본값, 이벤트·Construction·함수·매크로 그래프 입력 리터럴과 분리 핀
- 상속 변수 기본값과 C++ 클래스 기본값
- 장면·프리팹의 BP 변수/C++ 속성 오버라이드와 기존 `nativeProperties`
- 프리팹 변형의 값 패치, 연결 인스턴스의 baseline·충돌 값
- 시퀀스와 Take가 저장하는 구조체 변수·C++ 속성 키

프리팹의 부모·중첩·패치 경로를 유지해요. 변형을 펼친 오브젝트 목록으로 덮어쓰지 않아요. 시퀀스는 실제 대상·변수/클래스 선언으로 자료형을 찾고, 여러 후보가 서로 다른 결과를 내면 저장을 거절해요. 타입 표시가 없는 임의 JSON이나 게임 저장 데이터의 키 모양으로 자료형을 추측하지 않아요.

## 저장·되돌리기

원본 타입·생성 헤더·연관 제작 파일을 기존 파일 트랜잭션 한 묶음으로 저장해요. 오류·취소 때 전체 쓰기를 복원하고, 재시작 시 기존 journal 복구를 사용해요. 외부 편집을 발견하면 그 편집을 덮어쓰지 않아요. 파괴적인 삭제·이름/자료형/배열 여부 변경과 기존 C++ 멤버 순서 변경은 자동 이관하지 않아요.

타입 저장은 연관된 깨끗한 열린 문서도 함께 갱신해요. 다른 연관 문서에 저장하지 않은 편집이 있으면 단일 저장을 거절해요. **모두 저장**을 사용하면 해당 초안과 타입 변경을 한 묶음에 넣어요. Undo/Redo는 파일 묶음과 열린 문서를 같이 되돌리며, 저장 전 초안의 dirty 상태도 보존해요. 저장 중 새 편집이 생기면 디스크 묶음을 복원하고 새 편집은 남겨요.

저장 기록의 역방향 복원만 기존 필드가 줄어드는 것을 허용해요. 일반 API에 보호를 해제하는 플래그는 없어요. 복원할 파일이 journal의 원문·결과와 정확히 일치해야 하고 최종 참조 검증도 통과해야 해요. 새 필드를 사용한 이후 편집이 있으면 복원 전에 충돌을 알려요.

## AI·도구 계약과 비용

`/api/asset/batch`의 `dryRun:true`는 파일을 쓰지 않고 타입 변경에서 파생한 `expanded` 행과 `planRevision`을 돌려줘요. 행에는 `path`, `kind`, `before`, `after`가 있어요. 실제 저장에 `expectedPlanRevision`을 넣으면 미리 확인한 원문·결과와 달라진 계획을 거절해요. 기존 문서 revision과 읽기 fingerprint 검사는 그대로 유지해요. `checkedWrite`의 타입 저장도 `transaction`과 `migration.values/paths`를 반환해 전체 복원에 연결해요.

외부 batch 입력의64파일 제한을 객체 수 제한으로 사용하지 않아요. 타입 변경에서 내부적으로 파생하는 연관 파일은 그 수에 묶지 않고 기존 원본·결과 합계8MiB 예산으로 제한해요. journal 읽기는32MiB 크기 검사를 유지해요. 큰 프로젝트에서 예산을 넘으면 일부 파일을 저장하지 않고 작업 전체를 거절해요.

새 Worker·폴링·런타임/GPU 자원·전역 타입 DB를 추가하지 않아요. 타입 배치 저장 때만 프로젝트의 관련 제작 파일과 필요한 헤더를 읽어요. 이름·설명·값만 바꾸고 필드 배치가 같으면 프로젝트 값 이관을 시작하지 않아요. 실행 중인 네이티브 메모리의 구조체 배치를 바꾸는 hot reload 허용 범위는 넓히지 않아요.

소유자: `native-record-migration.js`는 값 보완, `record-value-sites.js`는 선언 기반 위치, `record-override-values.js`는 프리팹 패치, `tools/native-type-migration.mjs`는 프로젝트 읽기·연관 파일 준비를 맡아요. 실제 쓰기는 기존 `asset-transaction.mjs`와 `ProjectService`가 맡아요. 빠른 탐색은 `hb context 타입이관 --symbol planNativeTypeMigration`을 사용해요.

## 직접 작성한 C++ 헤더

`Source/*.h`·`*.hpp`의 직접 작성한 `HB_STRUCT`에 멤버를 추가하는 저장도 같은 값 이관을 사용해요. 인용한 포함 헤더 안의 구조체와 중첩 구조체 배열을 지원해요. 변경 전·후 헤더를 각각 기존 반사 파서로 읽어 선언을 대조하며, 파서가 지원하는 C++ 문법 범위는 유지해요. 생성된 `Source/HBGenerated` 헤더는 타입 라이브러리 저장으로 관리해요.

`files.apply`에서 헤더·구현 파일을 함께 저장하거나 단일 헤더를 `checkedWrite`로 저장하면, 선언이 확인되는 BP·상속 기본값·함수 입력·장면·프리팹·시퀀스 값에 새 멤버의 기본값을 채워요. 오래된 내장 C++ 메타데이터를 가진 BP는 같은 소스 파일 참조로 정규화해요. 코드와 제작 값의 변경·깨끗한 열린 문서·Undo/Redo는 한 트랜잭션이에요. 연관 문서가 dirty이면 먼저 저장하거나 모두 저장에 포함해야 해요. 편집기의 텍스트 헤더 저장도 같은 파일 묶음 경로를 사용해요.

AI의 `files.apply({entries,dryRun:true})`는 이관의 `migration.values/paths`와 `planRevision`을 반환해요. 실제 요청에 `expectedPlanRevision`을 넣으면 파생된 소비자 값까지 같은 계획인지 확인해요. 문서 revision·읽기 fingerprint·파일 목록 검사와 서버의 저장 직전 계획 검사도 유지해요. 미리보기·충돌·취소는 일부 소비자만 쓰지 않아요.

주석·함수 본문·기본값만 바뀌고 구조체 배치가 같으면 값 이관을 시작하지 않아요. 삭제·이름/자료형 변경의 일반적인 값 변환, 개별 struct/enum 에셋·전역 자동 발견, 외부 IDE가 이미 덮어쓴 이전 헤더의 복구, 실행 중 ABI 재적용은 이 경로의 완료 범위가 아니에요. 원본과 후보 헤더를 함께 가진 검사된 저장 경로에서 처리하며, 사용자의 원래 C++ 파일이나 게임 저장 데이터를 추측해서 다시 쓰지 않아요.

추가 소유자는 `tools/native-source-schema.mjs`의 `nativeSchemaCandidates`·`changedNativeSourceRecords`예요. 새 런타임 캐시·Worker·폴링·GPU 자원은 없으며, 기존 저장 묶음의 8MiB 예산과 복구 journal을 사용해요.
