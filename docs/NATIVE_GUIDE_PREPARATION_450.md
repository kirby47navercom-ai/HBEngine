# 현재·이전 입력과 네이티브 가이드 준비

좌표 보조 함수는 텍스처 좌표에 기여하는 연산만 선택해요. 기존 레지스터 버전을 따라가므로, 셰이딩에만 사용한 거듭제곱이나 이후 덮어쓴 레지스터의 연산은 포함하지 않아요. 고정 LOD 큐브와 고정 공간 필터도 제외해요. GL은 프로그램 변경 시, DirectX는 기존 프로그램 소스 생성 시 계산하며 프레임마다 다시 순회하지 않아요. 이전 standalone 검사에 쓰는 전체 opcode 방식과 전체 라이브러리 디버그 선택은 유지해요.

DirectX의 기본·보조 가이드는 GL에서 사용하던 공통 가이드 생성기를 사용해요. 렌즈가 꺼져 있을 때는 렌즈 샘플과 사용할 수 없는 경로를 컴파일에서 제외해요. 렌즈 가이드에서는 기존 노멀 공유 반복을 사용해요. 렌즈 사용 여부는 해당 가이드 단계의 캐시 키에 포함하고, 머테리얼 프로그램 소스와 좌표 의존 목록은 재사용해요.

실제 DirectX의 16×16 영상에서 기본 반사·코팅 반사, 렌즈 켜짐·꺼짐, 기본·보조 가이드의 여덟 경우를 원래 경로와 대조했어요. 픽셀 차이는 모두 0이고, 이전 입력의 변화·거부·복원도 확인했어요. 같은 셰이더의 세 시간 문맥은 한 번 컴파일한 뒤 상수만 갱신해 검사해요. 가이드 소스는 공통 파일 하나와 조건·SHA 명세로 보존해 중복 저장을 줄여요.

같은 검사에서 기본 가이드 컴파일은 원래 약 1,178–1,600ms, 공통 생성기 경로 약 453–1,148ms였어요. 보조 가이드는 약 2,853–3,548ms와 2,348–3,104ms였어요. 이 값은 부하와 드라이버 캐시를 통제한 벤치마크가 아니며 전체 게임 FPS나 초기 준비 전체의 개선율로 해석하지 않아요.

실제 `ScreenEffectsPass.begin` 검사는 처음 다섯 단계, 렌즈 활성화 때 해당 두 단계만 추가 컴파일, 렌즈 해제 때 기존 바이트코드 두 개 적중을 확인해요. 소스 생성은 한 번이고 반복 프레임에는 추가 컴파일이 없어요. 검사 대상 2×2 가이드 버퍼는 288바이트로 같고 해제 후 0이에요. 기존 8MiB 메모리 캐시를 유지하며 새 GPU 자원·uniform·운영 readback·디스크 캐시는 추가하지 않아요.

AI는 `engineSchema().pipelinePreparation.nativeGuides`와 `raySurfaceHistory.uvFootprint.helperCompilation`에서 같은 정책을 조회해요. 이전 머테리얼·포즈·스무스 노멀/접선·시선·시간·밉 폭과 잘못된 이력의 거부 조건은 유지해요. 혼합 프레임 노멀 실험, 노이즈·체커 좌표, 전역 곡면·변경 투명 경로·참여 매질과 누적 엔진 원장은 별도로 이어서 구현할 대상이에요.
