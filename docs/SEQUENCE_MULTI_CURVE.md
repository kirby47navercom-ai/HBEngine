# 여러 시퀀스 곡선 함께 편집

시퀀스 곡선 편집기의 **함께 편집**에서 숫자 트랙을 추가해요. 선택한 트랙을 같은 시간·값 축에 겹쳐 보며, 활성 곡선은 실선, 나머지는 점선으로 구분해요. 트랙 목록에서 활성 대상과 채널을 고르고 각 채널을 숨길 수 있어요. 표시할 트랙 ID는 문서의 보기 상태이고, 게임의 바인딩·키·대상을 바꾸지 않아요. 마지막 한 곡선은 선택을 유지해요.

Ctrl/Command로 서로 다른 트랙의 키를 함께 고르거나, 빈 공간에서 범위를 드래그해 선택해요. Ctrl/Command+A는 표시된 곡선의 키를 선택해요. 드래그는 선택된 키 전체에 공통 시간 이동량을 적용하고 경계에서도 상대 간격을 유지해요. 분수 편집 격자 스냅과 Shift 자유 이동을 사용해요. 시간 입력은 첫 선택 키를 기준으로 묶음의 상대 시각을 유지해요. 값·탄젠트·가중치 편집은 활성 채널 번호를 각 선택 트랙에 적용하며, 스칼라는 0번 채널, 채널 수가 적은 벡터는 마지막 유효 채널을 사용해요. 키별로 서로 다른 채널 축을 동시에 선택하는 기능은 별도예요.

보간·가중 탄젠트·키 삭제·곡선 도구를 여러 소유 트랙에 한 번의 Undo로 적용해요. 베이크·축약처럼 전체 곡선을 대상으로 하는 도구는 표시된 곡선에 적용하고, 선택 키 대상 도구는 선택이 있는 곡선에 적용해요. 전체 문서의 시간·자료형·키 예산 검증 중 한 곡선이라도 실패하면 아무 트랙도 바꾸지 않아요. Euler 필터는 회전 곡선만 허용해요. 곡선별 소스·오브젝트·속성·클립은 유지해요.

여러 트랙의 키를 복사하면 `hb.curve.group` 버전 1에 곡선별 키와 공통 시작점에 대한 상대 시각을 담아요. 붙여넣기는 같은 ID를 우선하고, 다른 문서에서는 같은 이름·자료형의 유일한 곡선을 찾아요. 대상 누락·이름 중복·자료형·범위·예산 오류는 전체 붙여넣기를 거절해요. 단일 곡선 클립보드도 유지하고, 그룹 클립보드는 시퀀스 곡선 편집기에만 붙여넣어요. 비동기 클립보드 응답 중 문서나 활성 트랙이 바뀌면 원래 편집을 취소해요.

AI는 `schema.sequenceMultiCurve`와 `editSequenceCurves`의 정확한 소유자를 읽어요. 기존 `sequence.curve.tool`에 `tracks:["TrackA","TrackB"]`를 주면 같은 도구 파라미터를 원자적으로 적용해요. 기존 `track` 하나도 호환돼요. `tracks`를 명시하면 우선하며, 중복/없는 대상은 거절해요. expectedRevision·dryRun·Undo·저장은 기존 문서 편집 경로를 공유해요. 편집한 값은 원래 시퀀스 평가를 사용하므로 C++와 BP의 Play/Seek에도 그대로 반영돼요.

기존 TimelineEditor를 재사용하며 새 렌더러·타이머·워커·시퀀스 복사본을 만들지 않아요. 선택 보존은 키 집합 조회를 사용하고, 묶음 편집은 선택한 트랙만 준비해요. 곡선 표시의 화면 열별 키 밀도 제한은 원본 키를 삭제하지 않아요. [값 정규화·쌓기 보기](CURVE_VIEW_MODES.md)는 1889–1891에서 추가했어요. 키별 채널 축 동시 선택은 남겨요.

1883의 새 읽기는 [Epic Curve Editor, UE5.8](https://dev.epicgames.com/documentation/unreal-engine/animation-curve-editor-in-unreal-engine)의 Toolbar25–47, Outliner68–83, Graph/Navigation84–133, Editing/Copy-Paste134–168이에요. 여러 곡선의 선택·공유 값 축·키 변환·상대 시각 붙여넣기를 대조했어요. HB의 트랙 ID/고유 이름 대응과 공용 채널 적용은 자체 편집 계약이에요. 나머지 본문·이미지·링크된 모든 API를 읽었다고 계산하지 않아요.

1885에서는 공용 BP 타임라인의 Clamped Auto 저장 검증도 화면·샘플러와 맞췄어요. 여러 곡선 선택·편집과 같은 보간 모드를 저장하고 원래 평가를 사용해요.
