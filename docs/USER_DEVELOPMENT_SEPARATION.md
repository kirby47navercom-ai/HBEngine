# 사용자용 엔진과 개발 작업 분리

주인님이 게임을 제작하는 동안 엔진 개발도 이어갈 수 있게 실행 파일·설정·캐시·테스트 프로젝트를 분리해요.

## 사용

바탕 화면의 **HBEngine 사용자용** 또는 `C:/Users/kirby/HBEngine/HBEngine.lnk`를 열어요. 프로젝트 허브에서 기존 `.hbproject`를 열거나 새 프로젝트를 만들어요. 기존 프로젝트를 자동으로 옮기거나 변경하지 않아요. 새 게임의 기본 저장 위치는 사용자 문서의 `HBEngine Projects`예요.

| 대상 | 사용자용 | 개발·검증용 |
| --- | --- | --- |
| 실행 파일·리소스 | 저장소 밖 `HBEngine/Versions/<배포본 해시>` | 저장소와 `dist/HBEngine` |
| WebView·로그·최근 목록 | `%LOCALAPPDATA%/HBEngine/User` | 개발 기본 프로필 또는 검사마다 고유한 임시 프로필 |
| C++ 빌드 캐시 | 사용자용 버전의 `native/build` | 개발 저장소 또는 고유 임시 경로 |
| 게임 원본 | 주인님이 선택한 프로젝트 폴더 | 독립 테스트 프로젝트·원본의 읽기 전용 복사 |
| 서버 | 자동 할당 포트 | 별도의 자동 할당 포트 |

`HBEngine.install.json`이 있는 설치본은 EXE를 직접 열거나 `.hbproject`로 열어도 사용자용 기본 프로필과 자동 포트를 사용해요. 명시적인 `HB_USER_DATA_DIR`은 검증·전용 프로필을 위해 우선 적용해요. 게임 Player의 기존 프로필은 바꾸지 않아요.

설치본을 실행 중에 덮어쓰지 않아요. 이후 업데이트는 사용자가 요청하면 새 버전 폴더를 만들고 바로가기를 전환해요. 이전 버전 폴더와 게임 파일은 그대로 남아요. 별도 실행 파일 분리는 게임 데이터 형식의 하위 호환성을 보장하지 않으므로, 향후 형식 변경은 복사본 검증·백업 후 적용해요.

## 설치와 확인

Windows 배포본을 만든 뒤 `npm run desktop:install`로 별도 사용자용 설치본과 바로가기를 만들어요. 목적지를 지정하려면 `node tools/install-editor.mjs C:/사용자용/설치폴더`를 사용해요. 저장소 안 설치는 거절하며, 배포본의 `Projects`와 `native/build`를 복사하지 않아요. 파일별 SHA-256으로 설치 버전을 고정하고 같은 버전의 다른 파일은 덮어쓰지 않아요.

`npm run test:user-install`은 설치 재사용/변조 거절, 두 서버의 동시 실행·포트/파일/최근 목록 분리, 실제 두 EXE의 서로 다른 기본 프로필·프로젝트·종료와 장면 원본 바이트 보존을 검사해요. EXE 검사는 별도 프로젝트를 화면 밖 비활성 창으로 열고 사용자의 현재 창이나 실제 사용자 프로필을 건드리지 않아요. 증거는 `native/build/user-install-*/acceptance.json`에 남겨요.

같은 PC의 CPU·GPU·메모리는 여전히 공유해요. 주인님이 사용할 때 대량 컴파일과 성능 스트레스 검사는 미루고, 창·서버를 조작하지 않는 가벼운 백그라운드 작업을 이어가요. 이 분리는 동시 사용 중 성능 저하가 전혀 없다는 증명은 아니에요.
