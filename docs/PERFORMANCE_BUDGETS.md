# HBEngine 경량화 요구와 측정

가벼움은 기능 추가와 함께 유지하는 엔진 요구다. 2D·2.5D·3D, 사용자 C++/블루프린트, 물리, 저작 도구와 AI 편집 계약을 유지하면서 불필요한 복사·직렬화·자원 재생성을 줄인다. 기능을 끄거나 탄환을 정지시킨 측정은 개선으로 계산하지 않는다.

## 기준

- PC 배포의 대표 게임 경로는 60회/초, 작업 시간 p95 16.7ms를 목표로 한다. 큰 C++ 장면에도 같은 목표를 적용한다. 목표와 현재 측정값은 구별한다.
- 기능 변경 때 같은 하드웨어·배포 구성·해상도·슬롯·활성 수·입력·실행 기능으로 전후 비교한다. C++가 없는 경로도 확인한다. 기능별 비용을 추가할 때 대표 장면에 그 기능을 켠 조건을 더한다.
- CPU 작업, 완료된 루프 간격, GPU 제출, 프로세스 메모리와 패키지 크기를 구별한다. V8 heap만 보고 엔진 전체 메모리라고 하지 않는다. 측정점만으로 최대치·장시간 무누수·모바일 발열을 보장하지 않는다.
- 검증용 캐시/표본은 수를 제한한다. 장면/Play 종료 뒤 과거 장면 스냅샷을 계속 보관하지 않는다. 새 런타임 비용 때문에 큰 의존성을 추가할 때는 실제 측정 근거가 필요하다.
- PC와 모바일의 목표 하드웨어별 메모리 예산은 실제 기기 측정으로 정한다. 데스크톱 WebView2 표본을 Android/iOS 앱 성능으로 바꾸지 않는다. 기능 추가 뒤 회귀가 생기면 측정·원인·해결을 기록한다.

## C++ 브리지 변경

`workerProtocol:3`의 브라우저→host→worker 입력은 첫 전체 스냅샷 다음 변경분을 보낸다. 같은 Play VM에서 같은 worker token을 쓰는 여러 BP는 한 전송 상태를 공유한다. 새 VM은 새 worldId를 사용한다.

host는 worldId와 증가하는 sequence를 확인한 다음 변경 경로만 복사해 완성된 입력을 검증한다. 성공 응답의 sequence 확인 후에만 양쪽 기준을 갱신한다. 실패·유실 응답·reset은 다음 명시적 호출의 전체 스냅샷으로 복구한다. 부작용 있는 사용자 함수를 자동 재시도하지 않는다. worker 재시작은 host가 복원한 전체 입력을 다시 보낸다.

작업 4,096개/경로 4,096자/깊이 64 한도를 넘는 차이는 전체 스냅샷을 사용한다. 중첩 사용자 JSON·배열·속성·컴포넌트·타일맵을 유지한다. 알 수 없는 데이터를 임의로 제거해 속도를 얻지 않는다. 변경이 없는 데이터는 내부 불변 스냅샷끼리 공유하고, 실제 게임 객체와는 구별한다.

worker는 nlohmann JSON의 `patch_inplace`로 입력 캐시의 불필요한 전체 복사를 줄인다. 함수 결과의 `objects`에는 달라진 C++ Transform/공개 속성만 넣는다. 같은 함수 안의 물리 질의는 기존 전체 상태의 조회 경로를 유지한다. clock/reset 요청은 장면 데이터를 보내지 않는다. 기존 프로토콜 1/2와 전체 요청 caller는 유지한다. C++ 선언·BP 핀·편집 에셋의 버전/ID는 바꾸지 않는다.

## 재현

```powershell
npm run test:native-world
npm run test:editor-api-window
npm run test:player-acceptance -- --release
node tools/check-performance-comparison.mjs BEFORE/acceptance.json AFTER/acceptance.json comparison.json
```

Player 검사는 별도 임시 프로젝트/프로필과 화면 밖 비활성 창에서 실행한다. 기존 사용자 작업창을 새로고침하지 않는다. 480개 슬롯/모든 활성 탄환 이동, C++ Update/프레임, 30초 이상·96회 풀 재사용, 마우스·한글 UI·음향·멀티터치를 함께 확인한다. 비교 도구는 같은 조건, C++ 480개의 루프 속도 개선/작업 p95 감소와 C++ 없는 경로의 10% 이상 속도 회귀를 검사한다. 60회/초 목표 달성 여부는 별도로 출력한다.

Windows 프로세스 표본에는 소유한 Game/Node/WebView2/C++ worker의 자식 트리를 포함한다. 표본 수집은 프레임 타이밍 구간 밖에서 수행한다. working set 합계는 공유 페이지가 중복될 수 있고 private bytes는 전용 커밋량이다. GPU 메모리/피크/운영체제 전체 사용량은 아니다. `acceptance.json`, CPU profile, 스크린샷은 ignored `native/build/player-acceptance-*`에 남긴다.

## 실측 기록 — 2026-10-04

측정 조건과 전후 수치는 [입력·모바일·풀 기록](INPUT_MOBILE_POOL.md)의 후속 C++ 경량화 절에 기록한다. 최초 새 EXE의 `awaitnativeWorldClient` 오타로 시작이 실패한 `9Sv81F`는 성공 근거에 포함하지 않는다. 단위 검사만으로 실행을 통과했다고 판단하지 않고 실제 창에서 발견/수정했다.

남은 주 비용은 큰 장면의 변경 검색, host 검증, C++ 게임용 세계 동기화와 프로세스 왕복, 물리/렌더 제출이다. WebView2와 Node의 기본 메모리도 포함해 계속 측정한다. 이 변경으로 전체 엔진 성능 목표나 모든 누적 기능을 완료했다고 표시하지 않는다.
