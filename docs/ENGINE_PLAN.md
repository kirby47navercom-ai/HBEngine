# HBEngine 제작 기획

## 목적과 편집 경험

C++ / Win32 / DirectX 11 기반 자체 2D·2.5D·3D 엔진을 만든다. 알만툴처럼 기본 작업을 쉽게 시작하고, Unity처럼 장면·계층·속성을 한 화면에서 확인하며, Unreal처럼 C++와 노드 로직을 함께 사용한다. 현재 저장소의 브라우저 구현은 이 경험을 확인하는 UI 프로토타입이다.

기본 화면은 왼쪽 계층/블루프린트 목록, 가운데 뷰포트/그래프/타임라인, 오른쪽 속성, 아래 에셋/로그로 구성한다. 작업 공간을 바꿔도 배치와 용어를 유지한다. 조작 결과는 즉시 보이고, 되돌리기·진행률·오류 위치·검색이 모든 편집기에 필요하다. 도움말과 기능 상태는 실제 구현 범위를 정확하게 보여준다.

## 에셋 파이프라인

사용자가 변환 도구를 골라 실행하는 대신 파일을 넣으면 엔진이 적절한 임포터를 선택한다. 확장자와 실제 내용이 맞는지 검사하고, 실패한 파일은 원인과 해결 방법을 표시한다. 모든 존재하는 파일 형식을 무조건 지원한다고 약속하지 않는다. 지원되는 형식은 자동 변환하고, 지원하지 않는 형식은 필요한 임포터를 안내한다.

| 입력 예시 | 변환 결과와 편집 작업 |
| --- | --- |
| JPG/PNG 등 이미지 | 색 공간/알파/압축 설정이 있는 텍스처, 스프라이트·타일셋 선택 |
| HDR/EXR 등 환경 이미지 | 선형 환경 텍스처·환경광 데이터 |
| FBX/GLB/OBJ 등 모델 | 메시·머테리얼·스켈레톤·애니메이션을 분리하고 연결 |
| AVI/MP4 등 영상 | 코덱 검사 후 엔진 재생 형식으로 변환, 포스터 프레임 |
| WAV/MP3/OGG 등 오디오 | 런타임 오디오 데이터, 루프·스트리밍 설정 |

원본과 변환 캐시는 분리한다. 소스 변경을 추적하고 재가져오더라도 사용자가 설정한 머테리얼 연결과 ID를 유지한다. 영상 코덱·모델 형식별 변환기는 실제 네이티브 파이프라인 구현 시 지원·라이선스·품질을 확인한다.

## C++와 노드, AI 편집

게임 오브젝트는 C++ 컴포넌트를 가진다. 공개된 속성과 함수의 메타데이터를 Inspector와 노드 팔레트에서 함께 사용한다. 노드에서는 실행 핀과 데이터 핀을 분리하고, 같은 타입/배열 여부만 연결한다. 구조체는 필드로 나누고 참조 타입은 공개 멤버를 조회한다.

함수는 입력·반환 인터페이스와 독립 그래프를 갖는다. 매크로는 여러 실행 경로와 지연 흐름을 묶어 호출 위치에 확장하는 방향이다. Construction Script는 컴포넌트를 만든 뒤 편집/생성 시 구성을 적용하며, 게임의 BeginPlay/Tick과 구분한다. 현재 프로토타입은 그래프 편집과 저장을 구현했고 이 런타임 의미를 실행하지 않는다.

장면·그래프·머테리얼·임포트 설정은 버전이 있는 텍스트 데이터로 저장한다. 사람이 UI로 변경한 결과와 AI가 파일로 변경한 결과가 같은 검증을 통과해야 한다. 안정적인 ID, 타입, 연결, 기본값을 명시하며 화면 좌표와 실행 의미를 분리한다. 네이티브 단계에서는 동일 모델을 사용하는 명령/API와 오류 진단을 제공해 화면 클릭에만 의존하지 않게 한다.

## 구현 순서와 확인 기준

1. **편집 경험 확인**: 현재 브라우저 프로토타입으로 화면 배치·검색·맵 환경·타입 핀·변수·함수/매크로·저장 흐름을 직접 확인한다.
2. **네이티브 연결**: Win32 창과 DirectX 11 뷰포트, C++ 장면/컴포넌트, 실제 프로젝트 저장/복원, 오브젝트 편집을 구현한다. 저장 후 재실행했을 때 동일 장면이 보이는지 확인한다.
3. **실제 게임 루프**: 입력·충돌·오디오·C++ 생명주기와 노드 실행을 연결한다. 같은 로직의 C++와 그래프 결과가 일치하고 Construction/게임 실행 상태가 구분되는지 확인한다.
4. **제작 도구 완성**: 에셋 변환·재가져오기, 머테리얼 셰이더 컴파일, 애니메이션·타일맵·UI·기본 게임 컴포넌트를 완성한다. 작은 2D 게임과 2.5D/3D 장면을 외부 엔진 없이 제작한다.
5. **배포와 안정성**: 실행 파일 패킹, 빌드 진단, 성능/메모리 확인, 프로젝트 복구와 데이터 버전 변환을 검증한다.

단계는 개발 순서이며 전체 기능을 포기하는 범위 제한이 아니다. 프로토타입의 시뮬레이션 기능을 실제 구현이라고 표시하지 않는다.
