# 환경 질의 배치

기존 `EnvironmentQuery::Run`은 가변 월드를 매번 새로 읽어요. 여러 질의를 같은 액터 상태에서 계산하려면 `RunBatch(target, assets, context, debug)` 또는 **환경 질의 묶음 실행** BP 노드를 사용해요. assets는 작성한 `.hbeqs.json` 경로의 순서 있는 배열이에요. `BatchResults`는 마지막으로 확정한 결과 배열을 JSON 문자열로 읽고 `CancelBatch`는 진행 중 요청의 확정을 취소해요.

액터 생성기를 포함한 배치는 공간 색인을 한 번 동기화한 뒤 액터 ID·월드 위치·태그·원본 순서를 분리해서 보유해요. 같은 배치에서 projection을 기다리는 동안 원본 액터를 직접 바꾸어도 다른 질의가 섞인 액터 상태를 읽지 않아요. 다음 배치는 변경된 현재 월드를 새로 캡처해요. ring/grid만 있는 배치는 액터 생성기 색인을 만들지 않아요. 프레임 캐시나 월드 감시자를 만들지 않아요.

XY/XZ 생성·거리·앞 방향·진단과 평면별 내비게이션 투영은 기존 질의 규칙을 사용해요. **액터 생성용 스냅샷**이며 물리·내비게이션 전체를 동결하는 기능은 아니에요. 충돌 trace와 내비게이션은 공용 실행 서비스를 사용해요. 결과는 actorSnapshot=true / traceSnapshot=false로 이 구분을 표시해요.

모든 자산을 검증하고 모든 질의를 끝낸 뒤 한 번에 결과를 확정해요. 자산 오류·취소·이후 요청·소유자/기준 대상 종료는 오래된 결과의 확정을 막아요. 이전에 확정한 결과는 유지해요. private 색인은 성공·실패·취소 후 정리해요.

`gameplayDebug.eqsBatch`는 serial·assets·results·actorSyncs·actorSync를 제공해요. 각 결과에는 자산 경로와 rows가 있고 debug를 켜면 기존 한도 있는 진단도 있어요. 기존 단일 질의의 eqs 결과는 덮어쓰지 않아요. C++ RunBatch/CancelBatch는 기존 VM 큐 명령이며 BatchResults는 마지막으로 확정한 상태를 읽어요. 동일 C++ 함수에서 아직 적용되지 않은 큐 명령의 미래 결과를 반환한다고 가정하지 않아요.

WORK2960에서 10000액터·8질의의 액터 동기화 수는 별도 8회/80000순회 대신 배치 1회/10000순회였어요. 이 수치는 액터 색인 갱신만 비교해요. 결과 후보·투영·trace·내비게이션 탐색 비용과 전체 FPS·RAM은 포함하지 않아요. 일반 Run의 O(N) 가변 월드 동기화는 유지해요.

실제 공용 실행·native-operation·진단·혼합 평면·순서·현재 태그와 다음 배치 갱신·최신 요청/취소/오류의 원자적 확정을 검사했어요. 실제 C++는 RunBatch·CancelBatch 큐 전달과 확정 결과 읽기까지 확인했어요. GPU·실제 창·기기·설치 검증은 포함하지 않아요.
