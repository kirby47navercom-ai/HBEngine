# HB 애니메이션과 Transform 채널

HB 애니메이션 클립의 위치·회전·크기는 직접 TRS 트랙 및 Transform 컴포넌트 트랙과 같은 액터·필드 채널을 사용해요. 기존 시퀀스 편집기와 `document.patch`, C++ `LevelSequence` 및 블루프린트 제어를 그대로 사용해요. 새 에셋 형식이나 공용 API는 필요하지 않아요.

- 여러 시퀀스는 필드별 우선순위·시작 순서·정규화 가중치로 중재해요. 다른 필드는 독립적이에요. 회전은 공통 반구를 맞춘 쿼터니언 혼합을 사용해요.
- 한 시퀀스에서는 기존처럼 액터별 마지막 활성 애니메이션 클립을 선택해요. 선택한 클립과 직접 트랙이 같은 필드를 쓰면 트랙 작성 순서에서 뒤의 값이 적용돼요. 해당 마지막 트랙의 완료 정책을 사용해요.
- 클립 공백은 더 이상 쓰지 않는 변환 필드만 양보해요. 같은 시퀀스의 직접 트랙이나 다른 시퀀스의 활성 값은 유지돼요. 새 필드의 원래 값은 이전 재생기를 보관하거나 현재 트랙을 쓰기 전에 캡처해요.
- 복원할 때 공용 필드부터 처리하고 이전 애니메이션의 현재 보관 시각을 표시해요. 일반 외부 HB 재생기는 자기 시각을 계속 진행해도 활성 공용 변환 값을 덮어쓰지 않아요. 직접 트랙이 최종 종료되면 외부 재생기의 현재 화면을 다시 반영해요. 이전 `마지막 값 유지` 포즈는 캡처한 실제 값으로 복원해요.
- 루트 클립의 위치·회전에는 직접 트랙과 같은 시퀀스 기준점을 적용해요. 붙어 있는 액터는 로컬 좌표를 유지해요. 기준 액터를 움직이는 클립을 종속 대상보다 먼저 평가하고, 같은 트리에서 기준 액터의 부모를 움직이는 순환은 거절해요.

준비한 활성 클립 설명과 첫 필드 캡처의 vec3만 보관해요. 일반 직접 트랙만 있는 시퀀스는 기존 어댑터를 재사용해요. 애셋 원문·키 배열을 수정하거나 숨은 원본 곡선을 만들지 않아요. 타이머·워커·추가 GPU 작업은 없어요. 이는 비용 구조 설명이며 FPS 향상 측정은 아니에요.

`hb context --symbol prepareSequenceAnimationTransforms`가 관련 소유 파일을 가리켜요. 가져온 전체 골격 포즈는 SEQUENCE_IMPORTED_POSE_ALIASES.md, 액터 루트·모델 하위 TRS는 SEQUENCE_IMPORTED_TRANSFORM_ALIASES.md의 공용 채널을 사용해요. 인덱스 단위 변환·렌더러 속성 별칭 및 임의 비동기 setter·시뮬레이션 부수효과 되돌리기는 남아 있어요.
