# 197 — 포즈 계산 분산·선택형 지연 보간

Runtime LOD의 기본 **포즈 계산 시점 분산**은 안정 액터ID로 갱신 위상을 나눈다. 첫 포즈는 바로 계산하고 이후 주기만 분산한다. 시간/Notify를 생략하거나 객체 수 상한을 추가하지 않는다. 끄면 기존 같은 시점 갱신을 사용한다.

**포즈 보간 (한 주기 지연)**은 기본 꺼짐이다.195의 안전한 로컬 뼈 그래프에서 두 계산 포즈 사이를 매 표시 프레임에 위치 선형/회전 slerp로 보여 준다. 한 갱신 주기의 표시 지연을 받아들이는 선택이며, 액터/물리/루트 모션·곡선·상태 머신/슬롯/리타게팅 등의 보호 조건은 유지한다. 스프라이트 전용 그래프는 뼈 보간을 사용하지 않는다.

켜진 안전 그래프에서만3개 포즈 버퍼를 재사용한다. 끄기·전체 빈도·Hz 변경·외부 포즈 이식·종료 때 소유 버퍼를 해제한다. 기존64MiB 포즈 예산에 여유가 없으면 계산 생략을 유지하며 보간만 건너뛴다. 기본 추가 포즈 버퍼0·상시 타이머0·새 라이브러리0이다. 진단에 interpolated/interpolationDelay/interpolationBudgetLimited가 포함된다.

CPU5군에서1200액터의 필수 첫 계산 이후 동일 주기 피크1200회가90–111회로 분산됐고120프레임 전체 계산12000회는 유지됐다.1200은 표본 크기이며 엔진 제한이 아니다. 한 뼈의 위치/회전·논리 시간/Notify·표시 지연·추가168바이트·해제/예산 부족 보호를 확인했다.179/195 기존 CPU 회귀도 통과했다. [근거](research/ENGINE_WORK_197.json).

이후 사용자 런타임이 종료된 것을 확인한 뒤, 낮은 부하의 격리 기본 표본으로 실제 속성 클릭/Undo/저장·DirectX/WebGPU 게임·공용 C++ 전환·색상 픽셀·보간 진단을 확인했다. 두 플레이어는30FPS로 제한했으며 성능 스트레스 검사가 아니다. 사용자 설치 전환은 다음 누적 묶음에서 별도로 확인한다.195에 등록한 공식 본문 구역을 재사용했고 새 전체 문서/API 분석 승격은 없다.
