# 재사용 위젯과 오브젝트 추적 UI

Widget 요소에서 다른 위젯 에셋을 참조하고 인스턴스별 글자·값·색·표시/활성을 편집한다. 일반 요소 입력과 기본값 복원을 제공하고 고급 연결에서 속성/이벤트/변수 JSON을 편집한다. 중첩 참조를 안정 ID와 이름 경로로 펼치며, 상위 오버라이드가 우선한다. 순환·잘못된 대상/값·공유 예산을 적용 전에 거부하고 원본 에셋을 수정하지 않는다. 같은 참조 파일은 한 번 읽지만 인스턴스 상태는 분리한다. 미리보기·Undo·스타일·지역화와 기존 UI SDK를 공유한다. 예: UI::SetText(actor,"HUD","Player/Label","체력 75").

UIWidget 상세 속성의 배치 공간을 월드 위치 추적으로 바꾸면 오브젝트·부모 변환/로컬 보정 위치를 화면에 투영한다. 표시 크기·기준점·최대 거리·원근/직교 거리 배율을 설정한다. 카메라 뒤/화면 밖/비활성 상태에서는 숨기고 터치 누름을 해제한다. 화면에 투영하는 카메라 방향 UI이며, 깊이 차폐/조명을 받는 3D 메시 UI와 구별한다.

고정32개 인스턴스 제한을 UI Budget의 설정 가능한 인스턴스/펼친 요소 예산으로 바꿨다. 비동기 표시의 늦은 응답·취소·오브젝트 교체/종료·동시 예산 초과를 거부하며, 잘못된 새 위젯이 기존 UI를 지우지 않도록 읽기/조합 검증을 먼저 수행한다. 새 의존성·자동 GPU 읽기는0이다.

[CPU9군·실제 Win32 제작/Undo·D3D 출시/WebGPU 플레이](research/ENGINE_WORK_174.json). 실제 마우스 좌표 클릭→재사용 이벤트 매핑→블루프린트 글자 변경→C++ 내부 요소 글자 변경과 오브젝트 이동/가림/복원을 확인했다. 두 실행기에서173 네트워크의 실제 호스트/클라이언트 생성·삭제/관심 영역도 함께 확인했다. 편집기에서 일반 글자 입력·미리보기·Undo와172 병합/Git 작업을 함께 검사했다. 원래 임시 카메라로 화면 위가 잘린 초기 표본과 잘못된 검사 입력 선택자 실패를 보존했고, 최종 표본은 화면 경계와 전체 그림을 확인했다.

남은 경계: 위젯 클래스 상속/명명 슬롯·3D UI 메시/차폐·자동 내용 높이·대규모 UI DOM 풀·전체 스크린리더 입력 검증. 전체 UI/UE/Unity 완료로 승격하지 않는다.

대조: [Unity UXML 재사용](https://docs.unity.com/en-us/engine/6000.3/manual/uitoolkits/uielements/uie-structure-ui/uie-uxml/uie-reuse-uxml-files)의 참조/중첩 오버라이드·제약과 [Unreal Widget Components](https://dev.epicgames.com/documentation/unreal-engine/widget-components-in-unreal-engine)의 공간·크기·기준점을 참고했다. 전체 연결 API와 미디어를 읽은 것으로 계산하지 않는다.
