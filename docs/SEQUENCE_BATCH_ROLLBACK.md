# 시퀀스 관리 채널의 묶음 적용 실패

`SequenceChannels.writeBatch`는 변환·부모·컴포넌트·가져온 애니메이션 등 기존 관리 필드의 공용 경로예요.

- 같은 객체·필드를 여러 번 쓰면 마지막 작성 값만 적용하고 원래 값·소유권은 한 번만 잡아요. 서로 다른 객체의 같은 필드는 독립적이에요.
- 전체 검증이 끝난 뒤에만 채널 소유권과 값을 공개해요. 동기·비동기 setter가 중간에 실패하면 실패한 샘플을 제거하고 이전 소유자·혼합·원래 값으로 관리 필드를 복원해요. 기존 소유자를 갱신하던 경우에는 그 이전 샘플을 복원해요.
- 기다리는 사이에 다른 소유자나 같은 소유자가 새 값을 적용했으면 그 최신 샘플은 보존해요. 실패한 이전 소유권만 제거하고 현재 presentation을 다시 적용해요.
- 단일 setter의 세 번째 인자 `current()`는 아직 해당 적용이 유효한지 확인해요. 비동기 어댑터는 `await` 다음에 실제 값을 쓰기 전 이를 확인해야 해요. 기존 묶음 어댑터의 각 행에도 같은 `current()`가 있어요. 객체 제거와 전체 `clear()`는 버전을 퇴역시켜 오래된 쓰기를 막아요.
- 원래 예외를 그대로 전달해요. 외부 setter가 복원마저 거절하면 원래 예외와 복원 예외를 `AggregateError`에 함께 보존하고 실패한 외부 상태를 성공으로 표시하지 않아요.

보장 범위는 읽기·적용·복원이 가능한 관리 채널의 묶음 쓰기예요. [단일 `write`의 실패 복원](SEQUENCE_SINGLE_WRITE_RECOVERY.md)도 이후 연결했어요. 소유자 설정 변경·release 전체의 트랜잭션, 임의 notify 콜백·이미 실행한 외부 작업·취소된 latent 작업을 되감는 기능은 별도예요. `current()`를 무시하고 복원 뒤에도 계속 쓰는 외부 비동기 작업이나 복원 자체가 실패한 외부 장치는 원자적으로 되돌렸다고 할 수 없어요.

이 경로는 묶음 적용 동안 이전 관리 샘플 참조를 보관하고 실패 때 복원해요. 매 프레임 전체 장면을 복사하거나 별도 타이머를 만들지 않아요.
