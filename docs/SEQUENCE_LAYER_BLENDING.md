# 시퀀스 레이어 혼합

시퀀스 상세 속성의 **재생 설정 → 혼합 방식**에서 `가중 혼합`을 선택하고 **가중치**를 0~1로 정해요. 기존 파일은 `우선순위` 방식 그대로 재생돼요. 예를 들어 같은 대상의 위치10과90을 각각 .25와 .75로 재생하면 위치70이에요. 가중치 합이1이 아니어도 활성 레이어끼리 정규화해요.

```json
{"blendMode":"normalized","weight":0.25}
```

가장 높은 우선순위의 활성 필드부터 선택해요. 그 승자가 `normalized`이면 같은 우선순위·같은 혼합 자료형의 normalized 소유자들을 섞어요. 승자가 `override`이면 기존처럼 그 소유자의 값만 사용해요. 같은 우선순위의 시작 순서는 이 승자를 정하며, 가중치 편집·Seek는 시작 순서를 바꾸지 않아요. 가중치0인 normalized 연속 필드는 아래 우선순위에 양보하고, 아무 활성 소유자가 없으면 공유된 원래 값으로 돌아가요.

지원하는 연속 필드는 위치·회전·크기, 시간 배율, 광원 밝기, 머테리얼 숫자 파라미터, BP/C++의 float·vec2·vec3·color 단일 값, 컴포넌트의 연속 숫자·벡터·색상이에요. 컴포넌트 전체 상태 녹화도 연속 속성마다 같은 혼합 채널을 써요. 직접 위치와 Transform 컴포넌트 위치는 같은 필드예요. 회전은 XYZ 각도를 단위 quaternion으로 바꿔 가중치가 가장 큰 샘플의 반구에 맞춘 가중 합(동률은 승자 기준)을 정규화해요. 170°와 -170°의 중간은180° 부근이에요. 구면 선형 보간과 같은 알고리즘이라는 뜻은 아니에요.

가시성·정수·열거형·참조·배열·부모·카메라 선택·컴포넌트 존재·애니메이션 클립은 기존 우선순위 방식을 유지해요. 시퀀스 가중치는 이벤트나 소리를 음소거하거나 게임 시뮬레이션을 중지하는 설정이 아니에요. 골격은 뼈마다 별도로 정규화해 위치·크기와 반구 정렬 quaternion을 섞어요. 먼저 각 트랙의 `poseWeight`로 공유된 원래 포즈와 섞은 뒤, 그 결과를 시퀀스 가중치로 섞어요. 서로 다른 뼈를 제어하는 레이어는 간섭하지 않아요. 같은 원본 트랙도 서로 다른 하위 시퀀스 시각으로 평가할 수 있어요. 모델을 교체하면 새 뼈 identity에 다시 연결하고 새 모델의 제어 직전 포즈로 복원해요. 여러 애니메이션 mixer action의 경쟁 가중치와 골격/애니메이션 간 별칭은 아직 별도의 잔여 범위예요.

하위 시퀀스의 실제 가중치는 상위 실제 가중치×자신의 자산 가중치×구간 가중치예요. 작성 가중치가 없으면1이에요. 구간을 선택한 뒤 **구간 가중치**와 **구간 혼합**을 편집하면 같은 원본 자산을 재사용하는 구간마다 다른 설정을 줄 수 있어요. 구간 혼합의 `시퀀스 설정`(`inherit`)은 하위 자산 설정, 상위 설정 순서로 따르고, `override`·`normalized`는 그 구간에 우선 적용돼요. 기존 계층 우선순위·Shot 선택 규칙은 유지돼요.

AI의 `sequence.section.edit`는 optional `section.weight`와 `section.blendMode`를 같은 원자적 검증·revision·Undo 흐름으로 받아요. 각 값을 `null`로 업데이트하면 그 선택 설정을 제거해요. 앞부분 자르기도 구간 가중치·모드를 유지해요. `runtime.sequenceTree`는 요청한 페이지만 실제 `weight`·`blendMode`와 작성된 `sectionWeight`·`sectionBlendMode`를 돌려줘요. 구간 가중치는 정적인 값이며, 자동 fade 곡선이나 오디오 gain 설정은 아니에요.

**가중치 곡선**을 켜면 이 정적인 가중치에 시간별 곡선 값을 곱해요. 곡선은 상위 시퀀스의 구간 경과 시간을 사용하므로 원본의 반복·역재생·시간 리매핑과 독립적이에요. 선형·계단 보간과 증가·감소·봉우리 프리셋, 키 추가·삭제·값 편집을 지원해요. 서로 겹치는 두 normalized 구간에서 한쪽을 감소시키고 다른 쪽을 증가시키면 혼합 비율이 바뀌어요. 활성 normalized 레이어가 하나이면 양수 가중치의 크기와 관계없이 그 값 전체를 사용하므로, 단독 레이어를 원래 값이나 오디오와 페이드하는 기능으로 해석하지 않아요.

```json
{"weightCurve":[{"time":0,"value":1},{"time":2,"value":0,"interpolation":"step"}]}
```

키 시각은 구간 기준 초이며 첫 시각0, 이후 오름차순, 값0~1이에요. 키 앞뒤는 끝값을 유지해요. 구간 끝을 줄여도 이후 키를 보존할 수 있고, 앞부분 자르기는 자르는 시각의 값과 보간을 새0초 키로 만든 뒤 나머지 키를 옮겨 원래 곡선을 유지해요. `sequence.section.edit`로 곡선 전체를 쓰거나 `weightCurve:null`로 제거할 수 있어요. 이 키들도 기존 조절 가능한 `keyBudget`에 포함되고, 개별 곡선은 기존 트랙의65536키 규칙을 사용해요. 사람의 속성 목록과 그래프는32키 페이지로 표시하고 타임라인의 이전·다음 키 이동도 곡선 경계를 포함해요.

`runtime.sequenceTree`의 `sectionCurveWeight`는 해당 구간 시각의 곡선 값이에요. C++·BP의 기존 Play/Pause/Seek와 루트 가중치 변경도 같은 계산을 사용해요. 매 프레임 기존 하위 구간 순회에서 변한 소유자만 갱신하므로, 전체 컴포넌트 상태 트랙의 값이 캐시되어 있어도 혼합 비율이 바뀌어요. 곡선이 없으면 상수1 경로를 쓰고, 있으면 원본 키 배열을 참조하는 약한 캐시와 이진 검색을 사용해요. 키 재정렬·전체 복사·새 타이머·worker를 매 프레임 만들지 않아요.

```cpp
hb::LevelSequence::SetBlendMode(this, "normalized");
hb::LevelSequence::SetWeight(this, 0.5f);
float weight = hb::LevelSequence::GetWeight(this);
std::string mode = hb::LevelSequence::GetBlendMode(this);
```

같은 공용 노드가 블루프린트에도 생성돼요. 재생 중 루트 설정 변경은 현재 샘플을 다시 계산하고, 시각 이동·이벤트 실행·재생 순서 변경·자산 수정 없이 이미 소유한 필드와 하위 시퀀스에 반영해요. typed 컴포넌트 묶음은 게시 전에 검증하고, 실패한 제어 변경은 이전 가중치/모드로 복원해요. 임의 비동기 외부 setter의 부작용까지 되돌리는 기능은 아니에요.

기여하던 시퀀스를 정지하면 남은 레이어들의 마지막 샘플로 즉시 다시 섞어요. 최종 정지는 기존 `completionMode`·`restoreState`·`forceRestore` 규칙을 따라요. 가중치0 상태에서도 원래 값의 lease를 유지하므로 다시 양수로 켤 때 현재 혼합 값을 원래 값으로 잘못 캡처하지 않아요. 임의 외부 시뮬레이션/변수의 변경 이력 전체를 되돌리는 기능은 아니에요.

기존 override 필드의 반복 샘플은 O(1) 승자 경로를 유지해요. normalized 혼합은 해당 필드의 경쟁 소유자 수만큼 평가하며, 회전과 벡터의 혼합 출력에는 작은 임시 값이 생겨요. 골격 혼합은 활성 track/time별 준비와 bone 이름 색인을 공유하고, 한 번의 채널 게시에 뼈마다 월드 행렬을 다시 제출하지 않아요. 전체 월드 스냅샷·상주 worker·타이머·GPU 리소스는 추가하지 않아요. 이 구조가 실제 프레임 시간 개선을 측정했다는 뜻은 아니에요.
