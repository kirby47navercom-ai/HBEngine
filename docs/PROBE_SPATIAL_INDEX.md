# 반사 프로브 공간 탐색

반사 프로브가 여러 공간에 흩어져 있을 때 모든 픽셀과 메시에서 전체 후보를 반복 검사하지 않도록 공간 BVH를 사용해요. 공간 순서가 중요도 순서를 대신하지 않아요. 적중한 후보 가운데 원래 중요도·영역 크기·안정 ID 순위가 가장 높은 둘을 선택해요. 기존 affine 영역·페이드·기본 환경의 남은 비율·코팅·굴절 정책은 유지해요.

CPU 후보 탐색은 렌더러마다 하나의 인덱스를 유지해요. 프레임의 후보 목록을 한 번 정렬하고, 메시 경계와 겹치지 않는 가지를 건너뛴 뒤 기존의 정확한 SAT 또는 로컬 좌표 검사를 수행해요. 같은 경계·순위는 재사용하며 밝기만 바뀌면 공간 자료를 다시 만들지 않아요. 브라우저와 네이티브 장면 패킷 작성이 같은 소유자를 사용해요.

GL·WebGPU·DirectX 픽셀 탐색은 스택 없는 BVH예요. 각 노드는 월드 AABB·다음 형제 주소·최소 원래 순위·선택적 리프 순위를 담아요. 이미 찾은 두 번째 순위보다 좋은 후보가 없는 가지도 건너뛰어요. 겹치는 영역이 많으면 최악의 경우에는 여전히 선형 비용이 들 수 있어요.

GPU에 실제 저장한 Float32 affine 행을 역변환해 경계를 만들어요. dot 연산의 오차를 역행렬 노름으로 보수적으로 확장하며, 조건이 나쁜 변환은 유한 전체 영역으로 처리해서 후보를 섣불리 제외하지 않아요. 주소는 두 개의 16비트 유한 수로 저장해요. WebGPU 선택 결과는 정수 ID와 가중치 비트를 분리해 Float32의 2²⁴ 정수 정밀도 한계로 순위가 바뀌지 않게 해요.

기존 캡처 이미지와 메타데이터 바인딩을 사용해요. 이미지 타깃·렌더 패스·GPU 읽기 호출은 추가하지 않아요. 프로브가 N개이면 공간 노드는 2N−1개, 노드마다 float4 세 개(48바이트)를 기존 메타데이터 뒤에 더해요. 브라우저는 행 끝 패딩, DirectX는 144바이트 레코드 패딩이 생길 수 있어요. CPU에는 공간 자료와 모양 스탬프도 남으므로 추가 메모리가 0인 최적화는 아니에요. 임의 프로브 개수 상한을 두지 않고 장치 텍스처·버퍼 한도를 초과하면 오류로 알려요.

실행 진단의 브라우저 `renderer.probes.atlas.spatial`·`renderer.probes.candidates`, DirectX의 `probeAtlasSpatialNodes`·`probeAtlasSpatialBuilds`·`probeAtlasSpatialCPUBytes` 및 `probeCandidates`로 소유량과 재구성을 확인해요. CPU 후보 방문 수는 마지막 바인딩 갱신부터의 수치이며 GPU 픽셀 방문 횟수나 FPS가 아니에요. 사람과 AI는 기존 ReflectionProbes C++ 함수·생성 블루프린트 노드·같은 씬 JSON을 사용해요. 새로운 저수준 렌더 코드로 게임을 다시 작성할 필요는 없어요.

검사는 구현을 묶은 뒤 한 번 수행해요. 선택기·혼합 이미지·네이티브 실행·실제 제작 경로의 증거는 각각 기록해요. 선택기만 4,096개 레코드로 검사한 결과를 4,096개 HDR 캡처를 포함한 전체 게임 성능으로 해석하지 않아요.
